The architecture check found that the condition AD-13 set for revisiting the package split has now arrived: the second environment is being planned. The split-into-packages triggers fire too:
- 5 pipelines, more than the guideline of 3;
- about 14 components, more than 12;
- PyTorch would now be used by two components, not just one.

The process says to settle the package shape before placing anything, so one question first.

**Q: Should `rllab` stay one package for the tank stage, or split now?**

- **My recommendation: stay one package.** I'd revise AD-13 to cover S2 and revisit at a third environment.
  - It's still one user and one install, with nothing deployed separately.
  - The things a split would enforce are already enforced by import-linter: shared pieces see only `core`, and only the learner components import PyTorch. That just gains one entry for the new policy learners.
  - A split would mean a workspace with several package files, plus architecture, contract, pipeline and test docs per package, and a build-setup rework. That's real overhead for a solo learning project.
- **The alternative** is to split now into roughly three packages:
  - **`rllab-core`:** `core`, `train`, `evaluate`, `replay`, `plots`;
  - **`rllab-envs`:** `snake`, `corridor`, `tank`, plus the bots;
  - **`rllab-learners`:** `tabular`, `net`, and the new policy learners.

  `lab` would sit in a small top package, or in one of the three. The boundaries would be cleaner, and the docs work roughly doubles.

**Default:** stay single.

**What I'd design under that default:**
1. **The shared core becomes batched.** Every environment steps a batch of agents (Snake and the corridor have a batch of 1). Actions are either one choice from a list or a capped 2D vector. Rewards and "caught" flags come per agent. The environment also reports the game's score.
2. **Replays store simple drawable scenes,** grid cells or circles, so the shared viewer draws Snake and the tank without knowing either.
3. **Agents expose an "explanation"** in place of "3 move values": move values, direction probabilities, or a steering mean with its spread and a critic estimate.
4. **New components:**
   - **`tank`:** the physics and the two fish views;
   - **`fishbots`:** the random and scripted fish;
   - **`pg`:** REINFORCE and PPO, sharing their policy code. PyTorch is allowed here and in `net`.
5. **M1's plan gets revised** so T01 freezes these generalised interfaces. Snake's golden cases keep their values; their tests read agent 0 of a batch of 1.

Reply "stay single" (or "split") and I'll write the draft architecture and contract for your review.
