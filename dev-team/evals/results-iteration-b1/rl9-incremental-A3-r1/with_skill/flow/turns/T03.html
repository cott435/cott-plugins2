### AD-14: Self-play through opponent pools inside the shared training loop
**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `selfplay`, `train`
- **Context:** SELF-01–SELF-04 need co-learning and pool-based self-play. CORE-07 forbids a training loop of predator-prey's own. SELF-05–SELF-06 need cross-play and ratings over saved generations.
- **Decision:** A new `selfplay` component owns `OpponentPool` (the latest policy with probability `pool_latest`, otherwise a uniformly drawn past generation, loaded once and frozen), `cross_play` and `ratings`. `train` saves each learner's generation every tenth of the run through `runs.RunWriter.save_generation`, adds it to the other team's pool, and asks the pool for each game's opponent. Both teams learn in the same loop with their own PPO agents.
- **Alternatives:** A separate self-play trainer — duplicates the loop, and the spec forbids it. Opponent sampling per step instead of per game — opponents would switch mid-chase, which is unrealistic and noisier.
- **Consequences:** `train` gains generation and pool handling, guarded by settings, so single-team runs are unaffected. Cross-play costs 100 cells × 50 games of up to 1,000 steps. It's a separate command, not part of training time.

- **Full-grid timing (QR-03):** the CNN rung may need more than 60 CPU minutes to beat random. Mitigation: run the timing test first in that rung's milestone. Fall back to the flattened-grid MLP (AD-05), then to rented hardware within QR-05.

- **Escape too easy or too hard (EVAL-07):** if fish at 0.8 × the ball's speed survive the cap easily, or never, the rungs can't separate from the scripted fish. Mitigation: the spec's numbers are tank constants; a measurement run of the two baselines comes first in S2's build, and a change to the numbers goes back through spec-writing.

**Status:** Proposed · **Date:** 2026-10-18 · **Scope:** `evaluate`, `train`, `reference`, `lab`
- **Context:** M1's interface task froze `evaluate.evaluate(make_env, agents, *, team, player, train_seed, n_games, record)`, which has 7 parameters. - **Decision:** `evaluate.EvalOptions` is a frozen dataclass of `team` (default `SOLO`), `n_games` (200) and `record` (0). `evaluate` takes `make_env`, `agents`, `player`, `train_seed` and `options: EvalOptions = EvalOptions()`. It now has 5 parameters.
- **Alternatives:** A `PLR0913` exception for this one function — keeps the call sites short, but it's the first exception to a bar rule the project has had no other reason to bend. Folding `player` and `train_seed` into the options as well — one argument fewer, but the options would then stop being shareable between the players of one comparison.
- **Consequences:** Callers that keep the defaults don't change. Callers that set the team, game count or recordings build an `EvalOptions`. The frozen interface's type, samples and fake change with it, in a re-freeze interface task.
- **Probe:** none — an internal signature, no external API.
