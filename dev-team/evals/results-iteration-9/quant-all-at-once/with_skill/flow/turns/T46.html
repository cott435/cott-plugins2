**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `data`

Free scraped constituents (Wikipedia, EODHD free tier) — accurate only back to about 2000 per those sources, and no delisted prices.
- **Consequences:** History starts 1998, so DATA-01's 15 years holds with ~13 to spare. The adapter is the only Sharadar-aware code; a switch touches `data.vendors` only. Delisting returns depend on what ACTIONS records (AD-08).

### AD-08: Returns built from unadjusted prices, actions and the exchange calendar
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `data`
- **Context:** VALID-05 needs adjusted returns equal to economic total return within 0.01 pp; PANEL-03 needs delisting returns (cash payout, or −100% flagged estimated); PANEL-04 forbids filled gaps; DATA-05 and VALID-03 need the exchange calendar. RF-03 counts horizons in rows, which spec FCST-01 forbids. Test planning (2026-10-17, TC-02, TC-03, TC-05) found two cells unspecified: the return on the first session after a missing bar, and which session carries the delisting return when the index removal takes effect that same session.
- **Decision:** Daily total return = (unadjusted close × split factor + cash dividend) / previous unadjusted close − 1, with spin-offs taken from Sharadar's `closeadj` ratio on the ex-date; VALID-05 cross-checks every action day against `closeadj`. Delisting return: the recorded payout or final price versus the last close; with neither, −100% and `estimated=True`. Trading days come from `exchange_calendars` XNYS; a date where SEP has bars for most members but XNYS says closed (or the reverse) fails validation.
  - *Gaps:* sessions with no bar stay NaN (PANEL-04). The first session with a bar after a gap carries the multi-session total return from the last close before the gap, with the split factors and cash dividends whose ex-dates fall in the gap or on that session, so a holder's price move over the gap isn't lost.
  - *Delisting session:* the delisting return sits on the first XNYS session after the stock's last bar, the session a holder at the last close is paid on. It is carried only when the stock was a member on its last bar's session, and it is the one return allowed where `member` is False: `member` keeps following the index (the removal takes effect that session, as `membership_as_of` reports), so a position held at the last close still earns the payout or the −100%. Every later cell is NaN.
- **Alternatives:** Use `closeadj` returns directly — no independent check of VALID-05 and no delisting payouts. A hand-maintained holiday list — error-prone for special closures. NaN on the first session after a gap — loses the price move a holder had over the gap. The delisting return folded into the last bar's session, or `member` set True on the removal session — misdates the payout, or makes the panel disagree with `membership_as_of`.
- **Consequences:** Every return in the platform comes from `data.returns_panel`; horizons everywhere count XNYS sessions (AD-15). A cell after a gap spans several sessions, so a per-session statistic (volatility, covariance) sees one larger move rather than missing days; gaps are rare and VALID-03 reports each one. Consumers apply a session's return to the positions held at the previous close, not to that session's `member` mask, or they drop every delisting return.
- **Probe:** PB-01 — whether ACTIONS gives payouts determines how many delisting returns are `estimated`.
