# Record: results come back

`probes_results` lists a probe whose `evidence/results.json` is newer than its Last run, or the user says "ran it". Use the shape in `entry.md` and the rules in `safety.md`.

1. **No new evidence.** Every run writes `results.json`, a failed one too, so a "ran it" that leaves `probes_results` empty means no script ran, or the leak scan stopped the write. Say so, give the README's next step with its exact command and its `evidence NOT written` advice, and stop. On the second such "ran it", or the second run with the same `error`, don't patch, re-stamp or re-read anything: say the runs left nothing new, and offer at once to waive the probe (their words) or pause it (stays Ready; build-planning waits, pipeline-design and test-planning go on).
2. **Scan.** `dt probes --scan`. On a hit, stop: name the file and the pattern, and ask the user to look at it themselves. The fix is a narrower allow-list (Revise) and a re-run. Don't open the matched value.
3. **Check the code.** `script_hash` in `results.json` must equal the entry's Hash. If it doesn't, the results are for other code (`probes_stale`): go to Revise and ask for a re-run. Record nothing.
4. **A failed run.** `results.json` has an `error`: copy `run_at` to Last run, fill no Result, keep `Ready`, and give the fix at the gate. `usage`: the README command, with its step. `missing`: the key names to put in `.env`. `exception`: the step and class; a missing file from another probe's `out/` means that probe runs first, and its README order goes in through Revise, as any code fix does.
5. **Read `results.json` only.** Never `out/`, never the raw responses, never the terminal output the user ran. A check ID in the file that isn't in the table is an error to report, not to record.
6. **Fill the entry.** Each check's Result from its record, `pass` or `fail` with the observed value in a few words; a check with no record stays `—`. `Last run` is `run_at`, copied verbatim. Verdict: `pass` when every check passed, else the failed checks and why, in one line. A `null` pass is a measurement: judge it against the row's Pass cell yourself and say so at the gate. A measure-only check that met its threshold by its requirement's own terms passes, with the note (a card opened 3 months ago).
7. **Manual checks.** A `user (manual)` row's Result is what the user reported in chat. Ask for any that is missing, one at a time.
8. **Not all run yet** (a day-2 check is still waiting): fill what came back, leave the rest `—`, keep `Ready`, and say at the gate which checks are left and when. The probe is Answered only when every row has a Result.

## Gate

Besides SKILL.md's gate, show:
- **Free text** that reached evidence (masked merchant descriptions), every line, for the user to approve before it is committed. Lines they reject are removed by fixing the script's filter and re-running, never by editing evidence.
- **Hand-offs**, one line each, by result:

| Result | Goes to |
|---|---|
| Every check passes | architecture-design Revise: cite the finding in the decision's Context ("PB-01, 2026-10-20: 6 of 6 institutions link; 13–24 months"), set it Accepted, delete the Risks line |
| A check fails, and an option still meets the requirements | architecture-design Revise: revise or supersede the decision |
| A check fails, and no affordable option meets a requirement | spec-writing, on the user's word: name the requirement and the finding. Never edit the spec |
| Observed fields differ from a contract type | architecture-design Revise: the type's fields and invariants follow the evidence; `**Cases:**` can name the samples |
| Spent resources must be kept (Items, tokens) | architecture-design Revise: the decision's Consequences say the build adopts them |

On an unambiguous yes: set `Answered · pass|fail · <date>`, and offer to commit `docs/probes.md` and the probe folder. **Stop.** Next is architecture-design Revise.
# The probe entry and its folder

Every mode writes to this shape. `dt` parses it, so keep the field names and order exactly.

## Index template: `docs/probes.md`

````markdown
# <Project> — Probes

**Last updated:** YYYY-MM-DD

### PB-01: <the claim being checked, as a sentence that can be true or false>
**Folder:** `probes/PB-01-<slug>/` · **Hash:** — · **Status:** Draft · **Milestones:** S<n> · **Last run:** —
- **Question:** <what the decision needs to know, in the user's terms>
- **Informs:** <AD-NN, …> · <requirement IDs> · <contract types, `<component>.<Type>`>
- **Docs read (YYYY-MM-DD):** <the official pages, one per question, never a homepage>
- **Spends:** <Items, paid calls, a subscription month, settings fixed for good; "nothing" only after looking>
- **Checks:** table below
- **Verdict:** —
- **Caveats:** <what a builder must not reuse as is: no retries, localhost-only, placeholder samples>

| Check | What | How | Pass | Runner | Result |
|---|---|---|---|---|---|
| C1 | <one unknown> | <endpoint, page or comparison> | <the threshold, from the requirement it informs> | agent | — |

## Retired
````

- **Title** states the claim ("Plaid Trial covers my institutions with 12–24 months of history"), so a fail reads as the claim being false.
- **Folder** is `probes/PB-NN-<slug>/`, slug in lower-case kebab.
- **Hash** stays `—` until `dt probes --stamp` writes it. Never type one. It covers every file in the folder except `evidence/`, `out/`, dot-files, `__pycache__/`, `*.pyc` and `*.md`, so an input such as `decommissioned_meters.csv` counts and a README edit doesn't.
- **Milestones**: the stage or milestone whose plan waits on the probe, as in `docs/references.md`: `S<n>`, `M<n>`, `all` or `—`. `dt` routes the probe's code to that milestone's tasks like an `RF-NN` entry.
- **Last run** is the `run_at` of the `results.json` that Record last read, copied verbatim (`2026-10-21T08:40:02Z`); `dt` compares the two.
- **Informs** lists only IDs that exist (`probe-informs` lint). The contract types are the ones whose fields the evidence could change.
- **Docs read** names the pages behind every claim the entry settles without a check, with the date read.
- **Checks**, one row per unknown, addressable as `PB-01.C3`. Every row has a **Pass** cell. A measure-only check states the threshold it is compared with, taken from the requirement. A check only a person can see has runner `user (manual)`; a check that runs on a sandbox key has `user (sandbox key)`. Runners are defined in `safety.md`.
- **Result** is `—` until a run, then `pass`, `fail` or `pass, note` in a few words ("13–24 months; a4: 3, opened 3 months ago").
- **Verdict** is `pass` when every check passed. A fail names the checks and why, in one line.
- **Size:** about 8 lines plus one line per check.

## Status

`Draft` (spec waiting for approval) → `Ready` (approved, code written, waiting for a run) → `Answered · pass|fail · YYYY-MM-DD`, or `Waived · YYYY-MM-DD — <the user's reason>`.

- A decision that cites a Ready probe stays `Proposed`. build-planning won't plan a milestone the probe reaches until it is Answered or Waived.
- Waiving is only ever the user's call, in their words. The decision's Risks line stays.
- A withdrawn probe collapses to one struck line under `## Retired`: `- ~~PB-04: The weather API serves hourly history from 2015~~ Retired 2026-11-02: AD-04 dropped weather features`. Its folder is deleted after the user agrees, and the ID is never reused. Omit the heading until the first retirement.

## Folder

```
probes/PB-NN-<slug>/
  probe.py          the user's checks; reads keys through load_env()
  public.py         optional: the agent's checks; no os.environ, getenv or .env anywhere in it
  probe_kit.py      copied from templates/, unchanged
  README.md         from templates/README.md: who runs what, in order, and what each step spends
  .env.example      variable names only
  evidence/         committed, written only by the scripts: results.json, schema.json, samples/
  out/              gitignored, 0700: raw responses, tokens, hashed ids, the user's own lists
  .env              gitignored, written by the user
```

- **Small.** Each function answers one check. No retries, config layers, classes or abstractions beyond what a check needs. `dt lint` warns over 400 code lines (`probe-large`).
- **Raw HTTP.** Stdlib `urllib` against the documented endpoints, so the evidence is the payload the adapter will see. When an SDK is unavoidable, declare it in PEP 723 inline metadata and run with `uv run`. `pyproject.toml` never changes.
- **Settings from the environment, real by default:** `os.environ.get("PLAID_BASE_URL", <real host>)`, `PLAID_ENV`. The evals point a probe at a fake vendor this way. `.env` holds keys only (`safety.md`).
- **Use the build's settings** wherever a setting can't be changed later (Plaid's `days_requested`).
- **One entry per check** in the code: a `cN_<what>()` function that ends in `record("CN", …)`. A step is a function calling checks in the README's order, and returns rather than exits. The script ends in `run({"<step>": function, …}, keys=[…])`, which runs `probe.py <step>` and writes evidence once, also when the run fails.
- **Order across probes.** A step that reads another probe's `out/` is named in both READMEs' "Steps, in order", with the step it waits for.
- Errors print the HTTP status and the vendor's error code, never headers, URLs with keys in them, or bodies.

## Evidence

`evidence/results.json`, written by `write_evidence()`, is the only file Record reads:

```json
{"probe": "PB-01", "script_hash": "5c1e09ab", "run_at": "2026-10-20T18:02:11Z",
 "runner": "user", "env": "production", "base_url": "https://production.plaid.com",
 "checks": {"C2": {"pass": true, "observed": {"listed": 6, "found": 6}, "note": "brokerage: investments only"}}}
```

`pass` is `true`, `false`, or `null` for a measured check the script leaves to Record to judge against the Pass cell. A failed run adds `error`: `{"kind": "usage", "steps": […]}` for a missing or unknown step, `missing` with the key names, or `exception` with the step, the class, and an HTTP status or file name when there is one. A re-run of the same code keeps the checks it didn't record again, so a second-day run adds C6 and C7 to the first day's. A run of changed code replaces them all. `samples/<name>.json` holds shape-faithful rows from `shape_sample()`. `schema.json` lists each field path seen, with its types and null count. Contract `**Cases:**` cells and adapter tests cite samples as `PB-01 samples/sync_added.json#0`.
# Runners, secrets and personal data

The agent never sees a secret, and the script redacts, never the agent. Every mode keeps these rules.

## Runners

| Runner | Allowed when | Examples |
|---|---|---|
| **agent** | The check reads no credential, or only one the vendor publishes for everyone, and touches nothing of the user's | Public docs and pricing pages (WebFetch); keyless endpoints; a weather API's published `demo` key on its sample city |
| **user** | The check needs any key the user holds, sandbox keys included; or the user's accounts; or it spends something | Plaid sandbox or production; a paid subscription's API |
| **user (manual)** | Only a person can see the answer | A Dashboard's plan page; the licence terms for the user's plan |

- The agent's checks go in `public.py` and the user's in `probe.py`. `public.py` contains no `os.environ`, `environ`, `getenv`, `load_env`, `dotenv` or `.env`, docstrings included (`probe-runner` lint), so "the agent may run this" can be checked without trusting the agent. Run it with an empty environment: `env -i PATH="$PATH" python3 probes/PB-NN-<slug>/public.py`.
- Sandbox keys stay with the user. One rule, "any key → the user runs it", can be checked.
- The user runs their checks when they can, on their own time. When they're done they say "ran it". They paste nothing: Record reads `evidence/results.json`.

## Keys

- Scripts read keys through `load_env()`: the environment, else the probe's `.env`. `.env` holds keys only, because every value in it is treated as a secret. Settings (`PLAID_ENV`, a base URL) are read with `os.environ.get(name, default)` and set in the shell. Never from command-line arguments, which end up in shell history. Never printed, logged or echoed in an error.
- The user writes `.env` from `.env.example`. Neither the skill nor the README asks them to paste a key into chat. If they paste one anyway, say it should be rotated, and don't repeat it.
- `dt guard` denies Read, Edit and Write on `**/.env`, `**/.env.*` (not `.env.example`) and `probes/*/out/**`, and Edit and Write on `probes/*/evidence/**`. Through Bash, never `cat`, `grep`, `head`, `source`, `ls -la` or copy those paths either: the guard can't cover every shell command, so the rule is yours to keep.
- `out/` is created `0700` and its files `0600`.

## .gitignore

At the first probe, add whichever of these lines are missing:

```
.env
.env.*
!.env.example
probes/*/out/
probes/*/.env
```

The gate runs `git check-ignore` on each probe's `.env` and `out/` and stops if either isn't ignored.

## Redaction, in the script

- **Allow-list.** `allow(obj, fields)` keeps only the named fields (dotted paths reach inside). Into `record()` go counts, booleans, dates at month resolution (days only when a check needs them), enum values, field names and types. Never amounts, balances, names, masks, ids, tokens or free text.
- **Free text** only when a check asks for it (merchant descriptions for a normalization rule). The check bounds the count, masks digits, and skips person-to-person and payroll rows by category and pattern. The user reviews every line at the Record gate before it is committed.
- **Ids** are salted hashes kept in `out/`, for checks that ids stay stable across runs. Evidence holds counts of ids, never ids.
- **Samples.** `shape_sample(name, rows, keep=(enum fields…))` keeps field names, types, nulls and the named enum values. Numbers become `1` or `1.0` with the sign kept, strings `"<str:N>"`, id-like fields `"<id>"`, and dates move by whole weeks to 2001, keeping weekday and order. The real rows go to `out/<name>.raw.json`.
- **Floats** in `observed` are rounded (4 places), so no long digit run reaches the scan.
- **Scan, fail closed.** `write_evidence()` scans everything it is about to write for token shapes, secret keys (`sk-…`), credentials in URLs, hex runs of 24 or more, mixed base64 runs of 32 or more, runs of 8 or more digits and card-like groups, emails, phone numbers, and every value in `.env` or passed through `load_env()`. On a hit, nothing reaches `evidence/`: the output goes to `out/evidence.rejected.json`, and the script names the pattern and exits 1. Fix the allow-list, never the pattern. `dt probes --scan` runs the same check on committed evidence (`evidence_leaks`).
- **Licensed data.** Vendor terms usually allow personal local storage and forbid redistribution. Market-data samples keep the shape and a few rows with values replaced, and real values stay in `out/`. Record the terms that were checked in Spends or Caveats.

## Spending

A probe can spend what the build needs. Spends names it, and the user agrees at the New gate before anything runs.

- **Check cheaply before spending.** A free lookup (`/institutions/search`) or a free sample goes first, and its failure stops the run before anything is spent.
- **Use the build's exact settings** where a setting can't be changed later.
- **Keep what was spent.** Items that count against a cap stay in `out/`, and the decision's Consequences say the build adopts them. Tokens move to the service's secret store; they never pass through docs.
- **Money.** Name the amount: a subscription month taken before the decision is Accepted is the user's call.
