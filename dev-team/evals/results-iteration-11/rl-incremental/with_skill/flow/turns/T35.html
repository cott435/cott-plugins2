# The spec: template, writing rules, hygiene check

Read before writing or extending `docs/spec.md`, and again for the hygiene check at the Review Gate.

## Template

```markdown
# [Project Name] — Spec

**Status:** Draft · **Last updated:** YYYY-MM-DD · **Brief:** [brief.md](brief.md)

## Summary
[2-3 sentences: what is being built. Link to the brief for why — don't repeat it.]

## Users
| User | What they need to do |
|---|---|
| [Primary user] | [...] |

## Scope
**In scope:** [features, by name]
**Out of scope:** [what we're not building — include everything on the brief's Not Doing list, plus anything decided during clarification]

## Features

### [Feature name] (`CODE`)
**Serves:** Goal 1, Goal 3
**Stage:** S2
**Source:** [ideas/<slug>.md](ideas/<slug>.md) *(extend mode only — omit for features from the original brief)*
**Behavior:** [2-4 sentences or a short numbered flow describing what the user experiences.]

**Requirements**
- **CODE-01** [One testable statement of what the system does.]
  - Given [context], when [action], then [observable result].
  - Given [...], when [...], then [...].
- **CODE-02** [...]
  - Given [...], when [...], then [...].

**Edge cases & errors**
- [Situation] → [expected behavior]

## Data requirements
*(Data and ML projects only — omit otherwise.)*
- **DATA-01** [What data the system needs: content, coverage, history, frequency, freshness — not which vendor.]
  - Given [...], when [...], then [...].

## Quality requirements
- **QR-01** [Measurable non-functional requirement: speed, reliability, accessibility, privacy, security, cost, licence.]
  - [How it's checked.]

## Assumptions
- [Assumptions the user confirmed]

## Open questions
- [Unresolved items, each with who can answer it. Omit if none. A question about what an external source really returns is "answered by a probe during architecture".]

## Changelog
| Date | Change | Source | IDs |
|---|---|---|---|
| YYYY-MM-DD | Initial spec | brief.md | all |
```

**Writing rules:**

- **One requirement, one behavior.** If a requirement contains "and", it's probably two.
- **Every requirement has at least one acceptance criterion** in Given/When/Then form. If you can't write one, the requirement isn't clear yet.
- **Describe behavior, not implementation.** "The customer sees their usual order" — not "the app queries the orders table."
- **Use exact numbers.** "≤ 2 seconds", "up to 50 regulars", never "fast" or "many".
- **Every feature names one stage.** Its `**Stage:**` line holds only the ID of the roadmap stage that first builds it. `dt lint` fails a feature with no stage, or one naming no stage row.
- **Requirement IDs are permanent.** `CODE-NN`, numbered within the feature, never reused or renumbered.
- **Quality requirements only when measurable.** Leave out generic wishes ("should be secure"); keep checkable ones ("passwords are never shown in full"). Cost, licence, budget and run-time limits are `QR-` items, each with how it is measured ("data costs ≤ $50 a month"; "the full study runs in ≤ 1 hour", timed on the user's machine), never `DATA-` or feature requirements.
- **No tech stack, libraries, vendors, schemas, endpoints, or file structure, even when the user names them.** Write the behavior the name stands for. The name itself belongs to `architecture-design`, which reads it in `docs/requests.md`.
- **Describe the product as it is now, not how it got here.** Requirement text, scope lists and assumptions carry no change notes, provenance tags ("from the field-photo idea", "UR-03") or process notes ("numbers chosen for review"). History goes in one Changelog row per round, and in git; which requirement honours which request goes in `docs/requests.md` (`dt request trace`).
- **The user's words win over the brief's.** Where a `spec` request is more specific than the brief or idea file ("circular tank", "one predator"), the requirement says what the request says, or the user approves the change.

**Data and ML projects — extra rules:**

- **Specify the data, not the source.** `DATA-NN` requirements say what the data must contain and guarantee ("hourly readings for every meter in the service area, including decommissioned ones, since 2015"; "every record is stamped with the date it became known"). Which API, vendor, or dataset meets them is an architecture decision, made by checking candidates against these requirements. Name a source only when the brief makes it a fixed constraint (our own database, a required benchmark).
- **Write data guarantees as testable criteria.** Leakage, look-ahead, selection bias, and coverage gaps are requirements, not hopes: "Given a forecast issued at time T, when the model requests weather, then no value published after T is returned."
- **Model quality is a requirement with a baseline.** Acceptance criteria name the metric, the held-out data, the threshold, and the baseline to beat: "Given the most recent 6 months of plates (never trained on), when ranked, then reviewing the top 20% catches ≥ 90% of scientist-failed plates, and beats ranking by Z′ alone." Never "the model is accurate".
- **No model types or libraries.** "Gradient boosting" or "PyTorch" are architecture decisions; the spec says what the model must achieve.
- **Learning projects: "build it by hand, then compare with a library" is a valid requirement. Write it without the names.** "The hand-written CNN reaches ≥ 90% of the accuracy of an established reference implementation on the same dataset." "The logistic regression is written from basic array operations; a reference library is used only to check its output." The architecture picks the reference.

## Hygiene check

Run on everything above the Changelog before presenting a Draft.

- **The user's words.** `dt request --open --owner spec` is empty, or each one left is a change you ask the user about.

- **Implementation names.** Search for library, framework, vendor, dataset, file-format, database and model-type names, file and function names (a reference's included), including names the user, the brief or the idea file used. Rewrite each one as the behavior or guarantee it stands for: "within 10% of torchvision's ResNet-18" becomes "within 10% of an established reference implementation", and "NumPy only" becomes "written from basic array operations". The only exception is a source the brief makes a fixed constraint.
# The user's words: `docs/requests.md`

Every planning skill follows this. The brief and the spec compress, and the next skill often runs in a fresh session that sees only the docs. `docs/requests.md` keeps what the user actually said, word for word, so the skill whose doc must honour it can. `dt request` writes every line; never edit the file by hand.

## What goes in

One request (`UR-NN`) per concrete statement you could check a doc against:

- facts about the domain, the data or the world ("the tank is circular"), numbers, limits, deadlines, budgets
- tools, libraries, vendors, protocols and data sources the user names ("stream prices over a WebSocket", "use yahooquery")
- choices: an option picked from yours ("Go with A"), and the answer to any question a skill asked
- a block acceptance ("assumptions 1–7 are fine"): one request, its `--about` listing what was accepted
- scope: what must be in, or left out

Not: approval of a whole doc ("approved", "looks good"), wishes with nothing to check ("make it nice"), your own proposals the user hasn't picked, or words already recorded (`dt request` lists them).

## Recording

As you hear it, before you write any doc:

```
dt request add <owner> "<their words>" --skill <this skill> [--about "<what it answers>"] [--replaces UR-NN]
```

- **Verbatim.** Quote the shortest span of their message that carries the fact. Never paraphrase, translate, correct or merge. A message stating three facts is three requests.
- **`--about`** whenever the words don't stand alone: "Go with A" → `--about "AD-22 price source: A = Sharadar, B = yfinance"`; "yes, 3" → what was asked. A bare letter means nothing to the next session, and the same words can pick opposite options in two rounds.
- **Owner** is the doc that must honour it: `brief` (who the user is, their time, budget or experience: context no later doc carries), `spec` (behaviour, numbers, scope the user can observe), `architecture` (tools, libraries, vendors, protocols, data sources, an option for a decision), `pipelines`, `tests`, `plan`, or `constraints` (the quality bar, tooling rules).
- **The user changes their mind:** record the new words with `--replaces` the old UR. A line is never edited or deleted.
- The request that started the run is the user's first message: record it too.

## Honouring

Before you write your doc, read `docs/requests.md` whole; `requests_open` in `dt status` lists the open requests your doc owns. For each:

- **Honour it:** write the requirement, decision, step, case or rule that does what the words say, then `dt request trace UR-NN <ID>…` with the IDs that do it (spec: requirement IDs; architecture: `AD-NN` or a contract ID; the others: their IDs). Honoured by a section with no ID (Out of scope, Assumptions, Constraints): trace its heading, `§Out of scope`.
- **Does what the words say** means the same shape, count, number, tool and goal, and for a named method or concept its mechanism, not its name: "self-play" is training against the opponent's past versions, not two learners at once. A number the words state must appear in the traced text (`request-number` warns).
- **Or change it, with the user's yes:** when it conflicts with another request or can't be met, say so at your gate with your alternative. Only after the user agrees, write the change into every ID it touches, the ones that honoured the old words included (a test case restating the old value too), then `dt request change UR-NN "<what instead>" --approved "<their words>" --skill <this skill> --into <those IDs>`. A doc that cites the request from another ID gets `request-cite`: bring it in line and add it with `dt request change UR-NN --into <ID>`. Never override a request silently, and never record an approval the user didn't give. Headless: leave it open under Open questions and the doc Draft.
- **A value from the user's words** (a golden case's expected output, a limit) cites the request as its Source: `**Source:** UR-04`. A number worked out from their words is not theirs; its Source says how it was derived (`request-source` warns).
- A request another doc owns waits for that doc's skill. Don't copy it into yours (the spec names no tools, even when a request does).

# RL Lab

**Status:** Accepted · **Last updated:** 2026-10-18

## The problem
Reinforcement learning (RL) is how an agent learns by trial and error from rewards. It is easy to read about and hard to really understand. Library code hides the parts that matter, and tutorials stop once the agent "works". The fastest way to learn it is to build small agents from scratch, in small 2D game environments, where each one teaches one idea and you can see it learn.

## Who it's for
Me: a solid Python programmer with some NumPy and PyTorch, who knows the basics of Q-learning (learning the value of each action in each state) and wants to learn RL by building it.

## Goals
1. For each environment, I can explain in my own words why the agent learns, and why each part of the algorithm matters.
2. Every agent is shown to learn: its learning curve beats a random agent and a simple scripted agent on the same games.
3. I can watch a replay of any trained agent playing.
4. A new environment reuses a shared core (environment interface, training loop, logging, replay viewer, learning curves) instead of starting over.

## Constraints
- Laptop CPU only, and under about an hour of training per environment.
- Free tools only.
- Evenings and weekends, a few weeks per environment, no deadline.
- Learning algorithms are written from scratch, not taken from a library.

## What success looks like
- The first environment, Snake, has an agent whose learning curve clearly beats both baselines, plus a replay of it playing.
- Turning off a key part of the agent visibly hurts its learning, and I can say why.
- The second environment, whatever it is, plugs into the shared core with small changes.

## What we're betting on
- Small, hand-picked descriptions of the game state ("danger ahead", "food to the left") are enough for an agent to learn well within an hour on a CPU.
- A shared core designed while Snake is the only example will still fit the next environment without a rewrite.
- Writing the algorithms myself teaches more than tuning a library would.

# Idea: Fish Tank

**Status:** Accepted · **Last updated:** 2026-10-18 · **Brief:** [../brief.md](../brief.md)

## In one sentence
This adds a second environment, a circular tank where several fish learn to steer away from a bouncing ball, so the learner can build policy-gradient methods up to PPO, with continuous control, on the shared core Snake built.

## The problem
Snake teaches value learning over a few discrete moves. With continuous moves (how hard to turn, how fast to swim) there is no list of moves to score, so the agent must learn its policy directly. Policy gradients start there and usually end at PPO, each step fixing a failure of the one before. Building them in order, in a game you can watch, shows why PPO exists.

## Who it's for
The same learner as the brief, once Snake (S1) is done and they move on from value learning to policy learning.

## How it fits
- **Serves:** Goal 1 (explain why each part matters), Goal 2 (beats random and scripted agents), Goal 3 (replay), Goal 4 (reuses the shared core)
- **Touches:** CORE-01–CORE-06 (several agents at once, continuous moves; CORE-03's "number of allowed moves"); BASE, EVAL, ABL, CURVE-03, REPLAY, EXPL, LOG-01 (worded for Snake and its DQN); QR-01–QR-03, QR-05 (Snake-only limits; the hand-written rule). SNAKE and AGENT stay as they are.
- **Brief changes:** Not doing narrowed: the fish tank is planned now; only environments after it wait.
- **Stage:** New S2 (roadmap stage on acceptance), built after S1 is done.

## Recommended direction
**The tank.** A circular tank with one ball bouncing off its wall. Several fish swim in it with continuous movement: each step every fish chooses how to steer and how fast to swim. When the ball touches a fish, that fish is removed. The game ends when every fish is gone. Fish are rewarded for staying alive, so a good fish survives as long as possible.

**What a fish sees.** Only nearby things, through about 8 sensor rays spread evenly around it. Each ray reports how far away the wall, the ball and other fish are along that direction, up to a short range. Nothing beyond the rays' reach is visible.

**One brain, many bodies.** All fish share one policy, each acting on its own observation. Fish don't block or crowd each other, so each is an independent copy of one single-agent problem: the stage stays about policy gradients, not game theory. The build starts with one fish and adds more once it learns.

**The ladder.** The learner writes three agents by hand, each one built on the previous one: REINFORCE (plain policy gradient), then actor-critic (a learned value estimate cuts the noise), then PPO (a limit on how far each update moves the policy). Each added piece has an off switch, as in S1, so turning it off shows what it was fixing.

**The core grows.** The shared core learns to handle continuous moves and several agents at once. Snake keeps running exactly as before.

**Optional extra.** A discrete twin of the tank with 8 compass moves, run by S1's unchanged DQN, to show what continuous control adds. The stage is done without it.

## Alternatives considered
- PPO only — skips the failures that explain each piece, which is the point of the lab.
- Fish that interact (crowding, blocking) — a genuinely multi-agent problem: richer, but a different lesson.
- A curriculum (the ball speeds up, more balls appear) — adds tuning without a new idea; revisit if the tank is too easy.
- A list of the nearest few objects as the observation — rays are fixed-size and closer to "sees only nearby things".

## What success looks like
- Each rung's learning curve beats a random fish and a scripted fish on the same seeded games.
- PPO learns better or more steadily than the rung below it, and turning off each piece visibly hurts, or the notes record that it didn't.
- A replay shows trained fish dodging the ball.
- Snake's results are unchanged after the core grows.

## What we're betting on
- About 8 short rays carry enough information to dodge one ball.
- A shared policy learns well from several independent fish, and the extra fish speed learning up rather than confusing it.
- The full ladder trains within the brief's hour per run on a laptop CPU.

## Not doing
- Fish that affect each other — a multi-agent problem; out of scope.
- A curriculum of harder tanks — not needed to learn the lesson.

## Open questions
- How many fish, how big the tank, how fast the ball, and how long a game may last before it's cut off (a perfect fish would never die).
- The exact steering choice: turn rate plus speed, or a push in x and y, and their limits.
- Ray range, and whether a fish also senses its own speed or heading.
- The reward: +1 per step per living fish, or a penalty when hit as well.
- The scripted fish: swim straight away from the ball, or also steer clear of the wall.
- Which switches the ladder has (for example the critic, the update limit, advantage normalisation), and how ablations are compared with the `null-hypothesis-testing` skill, as in S1.
- Whether the discrete twin is written into the spec now, or left for after the stage.

# RL Lab — Spec

**Status:** Approved · **Last updated:** 2026-10-18 · **Brief:** [brief.md](brief.md)

## Summary
A lab of small 2D game environments where hand-written reinforcement-learning agents learn by trial and error. The first stage builds classic Snake, a hand-written value-learning agent that sees 11 yes/no facts about the game, random and scripted baselines scored on the same games, switches that turn parts of the agent off, learning curves and a replay viewer, all on a shared core the next environment reuses. See the [brief](brief.md) for why.

## Users
| User | What they need to do |
|---|---|
| The learner (sole user) | Train an agent on an environment, compare it with baselines and with its own ablated versions on learning curves, watch any agent play, and write down why it learns |

## Scope
**In scope:** Snake environment, shared core, value-learning agent, ablation switches, baselines, evaluation, run logging, learning curves, replay viewer, explanation notes.

**Out of scope:**
- Learning from raw pixels or the full grid image; the agent sees only the 11 hand-picked facts.
- Comparing against library implementations of the same algorithms (a later step).
- Views beyond learning curves and replays: no heatmaps of the agent's values, no dashboards, no other visualisations.
- Real environments beyond Snake; the next one is chosen once Snake is done. The core is tested with a tiny throwaway test environment only.
- Mastering Snake: the agent sees only nearby danger and may trap itself; no requirement asks it to fill the board.
- GPUs, paid tools and paid services.

## Features

### Snake environment (`SNAKE`)
**Serves:** Goal 2, Goal 3
**Stage:** S1
**Behavior:** Classic Snake on a 20 × 20 grid. The snake starts 3 cells long in the middle of the grid, heading right, with one food on a random empty cell. Each step the agent picks one of 3 moves relative to its heading: straight, turn left, turn right. Eating food grows the snake by 1 and places new food; hitting a wall or its own body ends the game. The score of a game is the number of food eaten.

**Requirements**
- **SNAKE-01** The game is played on a 20 × 20 grid with a snake that starts 3 cells long in the middle, heading right.
  - Given a new game, when it starts, then the snake occupies 3 adjacent cells in the middle of the grid, heading right, and exactly one food is on a cell the snake does not occupy.
- **SNAKE-02** Each step the agent chooses one of 3 moves relative to the snake's heading: straight, turn left or turn right.
  - Given the snake heading up, when the agent picks "turn left", then the head moves one cell left and the heading becomes left.
  - Given any heading, when any of the 3 moves is picked, then the snake never reverses into its own neck.
- **SNAKE-03** Moving the head onto the food grows the snake by 1 cell, adds 1 to the score and places new food on a random empty cell.
  - Given food directly ahead, when the agent moves straight, then the snake is 1 cell longer, the score rises by 1 and a new food appears on a cell the snake does not occupy.
- **SNAKE-04** Moving the head into a wall or into the snake's own body ends the game.
  - Given the head next to the right wall heading right, when the agent moves straight, then the game ends with its current score.
  - Given the head beside its own body, when the agent turns into it, then the game ends.
- **SNAKE-05** A game also ends when the snake goes 100 × its length steps without eating.
  - Given a snake of length 5 that has not eaten for 500 steps, when it takes another step without eating, then the game ends with its current score.
- **SNAKE-06** The agent observes exactly 11 yes/no facts each step: danger straight ahead, danger to the left, danger to the right (danger = wall or body in the adjacent cell); heading up, down, left, right; food is up, down, left, right of the head.
  - Given the head heading right with the wall in the next cell and food above-left, when the agent observes, then "danger straight", "heading right", "food up" and "food left" are yes and the other 7 facts are no.
- **SNAKE-07** Rewards are +10 for eating food, −10 for the game ending by collision or step limit, and 0 for every other step.
  - Given a step that eats food, when the reward is reported, then it is +10; given a step that ends the game, then it is −10; given any other step, then it is 0.
- **SNAKE-08** A game started with the same seed and played with the same moves unfolds identically, including every food position.
  - Given seed 7 and a fixed list of moves, when the game is played twice, then every frame, reward and the final score are identical.

**Edge cases & errors**
- The snake fills every cell → the game ends as a win with its score; no food is placed.
- Food would be placed on the snake → it is placed only on empty cells.
- The agent sends a move other than the 3 allowed → the step is refused with an error naming the allowed moves; the game is unchanged.
- A step is requested after the game has ended → refused with an error saying the game is over.

### Shared core (`CORE`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** Every environment offers the same small set of behaviors: start a game from a seed, take one move and report what happened, say how many facts it observes and how many moves it allows, and draw one frame for the replay viewer. The training loop, logging, learning curves and replay viewer use only these behaviors, so a new environment plugs in without changing them.

**Requirements**
- **CORE-01** Every environment can start a new game from a given seed and returns the first observation.
  - Given any environment and seed 3, when a game is started twice, then both first observations are identical.
- **CORE-02** Every environment takes one move and reports the next observation, the reward and whether the game has ended.
  - Given a running game, when a move is taken, then the next observation, the reward and the game-over flag are all reported.
- **CORE-03** Every environment reports its observation size and its number of allowed moves.
  - Given Snake, when asked, then it reports 11 facts and 3 moves.
- **CORE-04** Every environment draws a frame of its current state for the replay viewer.
  - Given a running Snake game, when a frame is requested, then it shows the grid, the snake, the food, the score and the step number.
- **CORE-05** The training loop trains any agent on any environment that offers CORE-01 to CORE-04, for a set number of games, with a given seed.
  - Given a tiny test environment (a 1 × 5 corridor where reaching the right end gives +1), when the training loop runs on it with no changes to the core, then training completes and the agent reaches the right end in ≥ 9 of 10 evaluation games.
- **CORE-06** Logging, learning curves and the replay viewer work on any environment that offers CORE-01 to CORE-04.
  - Given the tiny test environment, when a run is logged, its learning curve drawn and a game replayed, then each works with no changes to the core.

**Edge cases & errors**
- An environment is missing one of the 4 behaviors → the core refuses it at start-up and names the missing behavior.
- An agent returns a move outside the environment's allowed moves → the run stops with an error naming the move and the game step.

### Value-learning agent (`AGENT`)
**Serves:** Goal 1, Goal 2
**Stage:** S1
**Behavior:** The agent learns an estimate of each move's long-run value from the 11 facts, using a small learned function. It picks moves by mostly taking the best-valued move and sometimes a random one, with the random share shrinking over training. It learns from random batches of remembered past steps, and builds its targets from a periodically refreshed frozen copy of its value estimate. Every part is written by hand.

**Requirements**
- **AGENT-01** The agent estimates, for each observation, a value for every allowed move.
  - Given an observation of 11 facts, when the agent is asked, then it returns 3 values, one per move.
- **AGENT-02** During training the agent takes a random move with a probability that starts at 1.0 and decays to 0.01 over the first half of the training games, and otherwise takes its best-valued move.
  - Given training game 0, when the agent picks moves, then every move is random; given a game in the second half, then about 1% of moves are random.
- **AGENT-03** During evaluation the agent always takes its best-valued move.
  - Given an evaluation game, when the agent picks a move, then it is the move with the highest value, and the same observation always gives the same move.
- **AGENT-04** The agent remembers its most recent 100,000 steps and learns from random batches of them.
  - Given more than 100,000 steps taken, when the agent learns, then its batches come only from the latest 100,000 steps, drawn at random.
- **AGENT-05** The agent's learning targets are the step's reward plus the discounted best value of the next observation (discount 0.9), taken from a frozen copy of its value estimate that is refreshed every 1,000 steps; a game-ending step's target is its reward alone.
  - Given a non-final step with reward 0, when its target is built, then it equals 0.9 × the frozen copy's best value for the next observation.
  - Given a game-ending step with reward −10, when its target is built, then it is −10.
  - Given 1,000 learning steps since the last refresh, when the next one happens, then the frozen copy is replaced by the current estimate.
- **AGENT-06** A trained agent can be saved and loaded back, and the loaded agent picks the same moves.
  - Given a saved agent, when it is loaded and plays an evaluation game with seed 11, then it makes exactly the same moves as before saving.

**Edge cases & errors**
- Fewer remembered steps than one batch → the agent keeps playing and does not learn until it has a full batch.
- A saved agent is loaded for an environment with a different observation size or move count → loading is refused with an error naming both sizes.
- Learning produces a non-number value → the run stops with an error naming the game and step, and the log so far is kept.

### Ablation switches (`ABL`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Three switches each turn off one part of the agent, so the learner can train the agent without it and compare. Each switch is set per run and recorded in the run's log. The comparison of each ablated agent with the full agent is judged by a hypothesis test.

**Requirements**
- **ABL-01** With the memory switch off, the agent learns from only the step it just took, with no remembered steps.
  - Given memory off, when the agent learns, then each update uses exactly the latest step.
- **ABL-02** With the frozen-copy switch off, the agent builds its targets from its current value estimate.
  - Given frozen copy off, when a target is built, then it uses the current estimate's best next value, which changes after every update.
- **ABL-03** With the exploration-decay switch off, the agent's random-move probability stays fixed at 0.1 for the whole run.
  - Given decay off, when the agent picks moves at any point in training, then about 10% are random.
- **ABL-04** Each ablated agent is compared with the full agent with the `null-hypothesis-testing` skill, given the final evaluation scores of both (5 training seeds each, on the same 100 held-out games); the ablation counts as hurting learning only if the full agent's scores are higher at a 5% significance level after correcting for the 3 comparisons.
  - Given finished runs of the full agent and the 3 ablated agents, when the study is run, then each ablation is reported as "hurts learning" or "no detectable difference", with its test result.
- **ABL-05** When no switch hurts learning, the study is still complete: the result is recorded as a finding in the notes, and S1 doesn't count as failed.
  - Given a study report where all 3 ablations show "no detectable difference", when the stage is checked, then it passes, and the notes page records that no switch hurt learning as a finding (EXPL-02).

**Edge cases & errors**
- Several switches are off in one run → allowed; the run's log records every switch's state.
- An ablated run fails before finishing → the study reports that ablation as missing, never as "no detectable difference".

### Baselines (`BASE`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Two non-learning agents play the same seeded games as the learning agent: a random agent and a simple scripted agent. Their scores set the bars the learning agent's curve must clear.

**Requirements**
- **BASE-01** The random agent picks each move uniformly at random from the allowed moves.
  - Given 10,000 moves by the random agent, when counted, then each of the 3 moves is picked 30–37% of the time.
- **BASE-02** The scripted agent moves toward the food along the axis with the larger gap, and when that move is immediately fatal it takes any non-fatal move, preferring straight.
  - Given food straight ahead and no danger ahead, when the scripted agent moves, then it goes straight.
  - Given food straight ahead and a wall ahead, when it moves, then it turns to a side that is free.
- **BASE-03** Both baselines are scored on the same 100 held-out games as the learning agent.
  - Given the 100 held-out seeds, when each baseline plays them, then each records one score per seed, and its mean and spread are logged.

**Edge cases & errors**
- Every move is fatal → the scripted agent goes straight and the game ends.

### Evaluation (`EVAL`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Every training run is checked at regular points on a fixed set of 100 games it never trains on, with exploration off. The final check of the full agent is compared with both baselines on those same games.

**Requirements**
- **EVAL-01** Training games and evaluation games come from separate seed sets that never overlap.
  - Given any training run, when its training and evaluation seeds are listed, then no seed appears in both.
- **EVAL-02** Every 50 training games, the agent plays the same 100 held-out games with exploration off and its mean score is logged.
  - Given a run of 1,000 training games, when it ends, then 20 evaluation results are logged, each over the same 100 seeds.
- **EVAL-03** The full agent's final evaluation scores are compared with each baseline's scores with the `null-hypothesis-testing` skill, given 5 training seeds × the 100 held-out games for the agent and the same 100 games for each baseline; the agent beats a baseline only if its scores are higher at a 5% significance level after correcting for the 2 comparisons.
  - Given finished runs of the full agent and both baselines, when the comparison is run, then the report says, for the random agent and for the scripted agent, whether the agent beats it, with the test result.
- **EVAL-04** The full agent's learning curve beats both the random baseline and the scripted baseline.
  - Given the EVAL-03 report, when it is read, then the agent beats both baselines.

**Edge cases & errors**
- A run stops early → its completed evaluation points are kept and shown; it is left out of the final comparison, which names it as incomplete.

### Run logging (`LOG`)
**Serves:** Goal 2, Goal 4
**Stage:** S1
**Behavior:** Every run, whether training or baseline, keeps a record of its settings and results, so curves can be redrawn and agents replayed without training again.

**Requirements**
- **LOG-01** Each run records its environment, agent, every setting including the ablation switches, and its seed.
  - Given a finished run, when its record is opened, then the environment, the agent, every setting and the seed are listed.
- **LOG-02** Each run records the score and length of every training game.
  - Given a run of 1,000 games, when its record is read, then it holds 1,000 scores and game lengths.
- **LOG-03** Each run records every evaluation result and the training loss every 50 games.
  - Given a finished run, when its record is read, then each evaluation point has its mean score and spread, and each 50-game point has its average loss.
- **LOG-04** Each training run saves its final trained agent next to its record.
  - Given a finished training run, when its record is opened, then the saved agent can be loaded (AGENT-06).
- **LOG-05** A run's record is kept on disk while the run is in progress, at least after every evaluation point.
  - Given a run stopped at game 430, when its record is opened, then results up to game 400 are present.

**Edge cases & errors**
- Starting a run with the same name as an existing one → refused, naming the existing run; nothing is overwritten.

### Learning curves (`CURVE`)
**Serves:** Goal 2, Goal 1
**Stage:** S1
**Behavior:** From saved run records, the learner draws learning curves: evaluation score against training games, with the baselines as flat reference lines. Curves for several runs can share one chart, so the full agent and its ablations can be compared at a glance.

**Requirements**
- **CURVE-01** A learning curve shows the mean evaluation score against training games for one or more runs.
  - Given one run's record, when its curve is drawn, then the chart shows one line of mean evaluation score at each evaluation point.
- **CURVE-02** Runs of the same agent and settings with different seeds are drawn as one line of their mean, with a band showing their spread.
  - Given 5 seeds of the full agent, when drawn, then the chart shows one mean line and one band.
- **CURVE-03** The random and scripted baselines' mean scores appear on every Snake chart as labelled flat lines.
  - Given any Snake chart, when drawn, then two labelled flat lines show the random and scripted baselines' mean scores.
- **CURVE-04** The full agent and each ablated agent can be drawn together on one chart, each labelled by its switches.
  - Given the full agent and 3 ablation runs, when drawn together, then 4 labelled lines appear.
- **CURVE-05** Curves are drawn from saved records only, never by training again.
  - Given saved records and no training running, when a chart is drawn, then it appears in ≤ 10 seconds.

**Edge cases & errors**
- A record has no evaluation points yet → it is skipped with a note naming it; the other curves are drawn.
- Records from different environments are drawn together → refused, naming the environments.

### Replay viewer (`REPLAY`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** The learner picks any saved agent, or a baseline, and a seed, and watches it play that game frame by frame in a simple grid view, with pause, single-step and speed controls.

**Requirements**
- **REPLAY-01** The learner can watch any saved trained agent, the random agent or the scripted agent play a game from a chosen seed.
  - Given a saved agent and seed 42, when a replay is requested, then the agent's game on seed 42 is shown from the first frame to game over.
- **REPLAY-02** Each frame shows the environment's drawing (CORE-04) plus the step number and score.
  - Given a Snake replay, when any frame is shown, then the grid, snake, food, step number and score are visible.
- **REPLAY-03** The learner can pause, step one frame forward and change the playback speed between 1 and 30 frames per second.
  - Given a playing replay, when paused and stepped, then exactly one frame advances; when the speed is set to 30, then 30 frames show per second.
- **REPLAY-04** Replaying the same agent on the same seed shows the identical game every time.
  - Given a saved agent and seed 42, when replayed twice, then every frame and the final score match.
- **REPLAY-05** The final score of a replayed game matches that game's score in the agent's evaluation.
  - Given a held-out seed scored in evaluation, when it is replayed with the same saved agent, then the replay's final score equals the logged score.

**Edge cases & errors**
- The saved agent doesn't exist or can't be loaded → an error names it; no window opens.
- The game never ends → it ends by the step limit (SNAKE-05), so every replay has a last frame.

- **EXPL-03** The notes page includes the learning-curve chart comparing the full agent, its ablations and the baselines.
  - Given the notes page, when opened, then the CURVE-04 chart with the CURVE-03 baseline lines is shown on it.

**Edge cases & errors**
- An ablation shows no detectable difference → its section still exists and explains why that part may not matter on Snake.

# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-18 · **Brief:** [brief.md](brief.md)

## Summary
A lab of small 2D game environments where hand-written reinforcement-learning agents learn by trial and error, all on one shared core. The first stage builds classic Snake and a hand-written value-learning agent that sees 11 yes/no facts. The second builds a circular fish tank, where several fish share one policy, see only through 8 short rays and learn continuous steering away from a bouncing ball, through a hand-written ladder of three policy-gradient agents. Every environment has random and scripted baselines scored on the same games, switches that turn parts of the agent off, learning curves, a replay viewer and a notes page. See the [brief](brief.md) for why.

## Users
| User | What they need to do |
|---|---|
| The learner (sole user) | Train an agent on an environment, compare it with baselines, with the rung below it and with its own ablated versions on learning curves, watch any agent play, and write down why it learns |

## Scope
**In scope:** Snake environment, fish tank environment, shared core, value-learning agent, policy-gradient ladder, ablation switches, baselines, evaluation, run logging, learning curves, replay viewer, explanation notes, the optional discrete tank.

**Out of scope:**
- Learning from raw pixels or the full grid or tank image; Snake's agent sees only the 11 hand-picked facts and each fish only its rays.
- Comparing against library implementations of the same algorithms (a later step).
- Views beyond learning curves and replays: no heatmaps of the agent's values, no dashboards, no other visualisations.
- Real environments beyond the fish tank; the next one is chosen once the tank is done. Beyond Snake and the tank, the core is tested only with tiny throwaway test environments.
- Mastering Snake: the agent sees only nearby danger and may trap itself; no requirement asks it to fill the board.
- Fish that affect each other: no crowding, blocking or pushing between fish.
- A curriculum of harder tanks: no speeding ball, no extra balls.
- GPUs, paid tools and paid services.

## Features

### Snake environment (`SNAKE`)
**Serves:** Goal 2, Goal 3
**Stage:** S1
**Behavior:** Classic Snake on a 20 × 20 grid. The snake starts 3 cells long in the middle of the grid, heading right, with one food on a random empty cell. Each step the agent picks one of 3 moves relative to its heading: straight, turn left, turn right. Eating food grows the snake by 1 and places new food; hitting a wall or its own body ends the game. The score of a game is the number of food eaten.

**Requirements**
- **SNAKE-01** The game is played on a 20 × 20 grid with a snake that starts 3 cells long in the middle, heading right.
  - Given a new game, when it starts, then the snake occupies 3 adjacent cells in the middle of the grid, heading right, and exactly one food is on a cell the snake does not occupy.
- **SNAKE-02** Each step the agent chooses one of 3 moves relative to the snake's heading: straight, turn left or turn right.
  - Given the snake heading up, when the agent picks "turn left", then the head moves one cell left and the heading becomes left.
  - Given any heading, when any of the 3 moves is picked, then the snake never reverses into its own neck.
- **SNAKE-03** Moving the head onto the food grows the snake by 1 cell, adds 1 to the score and places new food on a random empty cell.
  - Given food directly ahead, when the agent moves straight, then the snake is 1 cell longer, the score rises by 1 and a new food appears on a cell the snake does not occupy.
- **SNAKE-04** Moving the head into a wall or into the snake's own body ends the game.
  - Given the head next to the right wall heading right, when the agent moves straight, then the game ends with its current score.
  - Given the head beside its own body, when the agent turns into it, then the game ends.
- **SNAKE-05** A game also ends when the snake goes 100 × its length steps without eating.
  - Given a snake of length 5 that has not eaten for 500 steps, when it takes another step without eating, then the game ends with its current score.
- **SNAKE-06** The agent observes exactly 11 yes/no facts each step: danger straight ahead, danger to the left, danger to the right (danger = wall or body in the adjacent cell); heading up, down, left, right; food is up, down, left, right of the head.
  - Given the head heading right with the wall in the next cell and food above-left, when the agent observes, then "danger straight", "heading right", "food up" and "food left" are yes and the other 7 facts are no.
- **SNAKE-07** Rewards are +10 for eating food, −10 for the game ending by collision or step limit, and 0 for every other step.
  - Given a step that eats food, when the reward is reported, then it is +10; given a step that ends the game, then it is −10; given any other step, then it is 0.
- **SNAKE-08** A game started with the same seed and played with the same moves unfolds identically, including every food position.
  - Given seed 7 and a fixed list of moves, when the game is played twice, then every frame, reward and the final score are identical.

**Edge cases & errors**
- The snake fills every cell → the game ends as a win with its score; no food is placed.
- Food would be placed on the snake → it is placed only on empty cells.
- The agent sends a move other than the 3 allowed → the step is refused with an error naming the allowed moves; the game is unchanged.
- A step is requested after the game has ended → refused with an error saying the game is over.

### Fish tank environment (`TANK`)
**Serves:** Goal 2, Goal 3
**Stage:** S2
**Source:** [ideas/fish-tank.md](ideas/fish-tank.md)
**Behavior:** A circular tank with a ball bouncing around inside it and several fish swimming in it. Movement is continuous: each step every living fish chooses how far to turn and how fast to swim. Each fish sees only nearby things, through 8 short sensor rays. When the ball touches a fish, that fish is removed; the game ends when every fish is gone or the time limit is reached. Fish earn a reward for every step they stay alive, so a good fish survives as long as possible. The fish never affect each other.

**Requirements**
- **TANK-01** The tank is a circle of radius 10 units holding one ball of radius 1 that moves at a constant 0.25 units per step and bounces off the wall, leaving it at the same angle it arrived.
  - Given the ball moving straight out along a radius, when it reaches the wall, then it comes back along the same line in the opposite direction, still at 0.25 units per step.
  - Given the ball arriving at the wall at 30° to it, when it bounces, then it leaves at 30° on the other side of the line to the centre.
- **TANK-02** Each step every living fish chooses two continuous controls: a turn of −15° to +15° and a speed of 0 to 0.3 units per step; the fish turns first, then swims forward.
  - Given a fish at the centre heading east, when it chooses turn 0° and speed 0.3, then it ends 0.3 units east of the centre, still heading east.
  - Given the same fish, when it chooses turn +15° and speed 0, then it stays in place and its heading turns 15° anticlockwise.
- **TANK-03** A game holds a set number of fish, from 1 to 10 (5 unless set otherwise); the ball starts at the centre in a random direction, and each fish starts at a random spot at least 3 units from the ball, with a random heading.
  - Given 5 fish and seed 2, when a game starts, then 5 fish are inside the tank, each at least 3 units from the ball.
  - Given 1 fish, when a game is played, then it runs exactly as a several-fish game does, with one fish.
- **TANK-04** Fish never affect each other: they pass through one another, and no fish's move changes another fish's position.
  - Given two fish on the same spot, when both move, then each ends exactly where its own move would take it if it were alone.
- **TANK-05** A fish the ball touches (centres closer than 1.3 units: ball radius 1 plus fish radius 0.3) is removed, and the episode ends when all are gone.
  - Given a fish whose centre is 1.2 units from the ball's centre after a step, when the step is reported, then that fish is removed and is no longer asked for moves.
  - Given the last living fish is removed, when the step is reported, then the game has ended.
- **TANK-06** A game also ends after 1,000 steps, with every fish still alive counted as surviving all 1,000.
  - Given 2 fish alive at step 1,000, when the step is reported, then the game has ended and both fish survived 1,000 steps.
- **TANK-07** Each fish sees through 8 rays spread evenly around its heading, 45° apart, each reaching 4 units. Each ray reports the distance to the wall, to the ball and to the nearest other fish along it, each scaled from 0 (touching) to 1 (nothing within reach); the fish also senses its own current speed, scaled 0 to 1. A fish's observation is these 25 numbers.
  - Given a fish heading east with the ball's edge 2 units straight ahead and nothing else within 4 units, when it observes, then the forward ray's ball reading is 0.5 and every other wall, ball and fish reading is 1.
  - Given the ball 6 units away, when the fish observes, then every ball reading is 1.
- **TANK-08** A fish that swims into the wall stops at the wall, with no other effect.
  - Given a fish 0.1 units from the wall heading straight at it, when it swims at speed 0.3, then it ends touching the wall, inside the tank, with its heading unchanged.
- **TANK-09** Each fish earns +1 for every step it survives and 0 on the step it is removed; a game's score is the average number of steps its fish survived.
  - Given 2 fish where one is removed at step 100 and the other survives to step 1,000, when the game ends, then its score is 550.
- **TANK-10** A game started with the same seed and played with the same moves unfolds identically, including every ball and fish position.
  - Given seed 7 and a fixed list of moves, when the game is played twice, then every frame, reward and the final score are identical.

**Edge cases & errors**
- A move outside a control's limits → the step is refused with an error naming the control and its limits; the game is unchanged.
- A move is sent for a removed fish, or a living fish has no move → the step is refused with an error naming the fish.
- A step is requested after the game has ended → refused with an error saying the game is over.
- Two fish are removed on the same step → both are removed; if no fish is left, the game ends on that step.
- The ball touches a fish on the step the time limit is reached → the fish is removed first, so it survived 999 steps.

### Shared core (`CORE`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** Every environment offers the same small set of behaviors: start a game from a seed, take one move for each of its acting agents and report what happened to each, say how big an observation is and what moves are allowed, and draw one frame for the replay viewer. The training loop, logging, learning curves and replay viewer use only these behaviors, so a new environment plugs in without changing them, whether its moves are a few choices or continuous controls, and whether it has one agent or several. Growing the core leaves Snake running exactly as before.

**Requirements**
- **CORE-01** Every environment can start a new game from a given seed and returns the first observation.
  - Given any environment and seed 3, when a game is started twice, then both first observations are identical.
- **CORE-02** Every environment takes one move for each of its acting agents (Snake: the snake; the tank: each living fish) and reports, for each, its next observation and reward, plus whether the game has ended.
  - Given a running Snake game, when a move is taken, then one next observation, one reward and the game-over flag are reported.
  - Given a tank game with 3 living fish, when 3 moves are taken, then 3 next observations, 3 rewards and the game-over flag are reported.
- **CORE-03** Every environment reports its observation size and its allowed moves: either a number of choices, or a number of continuous controls with each control's limits.
  - Given Snake, when asked, then it reports 11 facts and 3 choices.
  - Given the tank, when asked, then it reports 25 numbers and 2 controls: turn −15° to +15°, speed 0 to 0.3.
- **CORE-04** Every environment draws a frame of its current state for the replay viewer.
  - Given a running Snake game, when a frame is requested, then it shows the grid, the snake, the food, the score and the step number.
  - Given a running tank game, when a frame is requested, then it shows the tank, the ball, each living fish with its heading, the number of fish left and the step number.
- **CORE-05** The training loop trains any agent on any environment that offers CORE-01 to CORE-04, for a set number of games, with a given seed.
  - Given a tiny test environment (a 1 × 5 corridor where reaching the right end gives +1), when the training loop runs on it with no changes to the core, then training completes and the agent reaches the right end in ≥ 9 of 10 evaluation games.
- **CORE-06** Logging, learning curves and the replay viewer work on any environment that offers CORE-01 to CORE-04.
  - Given the tiny test environment, when a run is logged, its learning curve drawn and a game replayed, then each works with no changes to the core.
- **CORE-07** The training loop, logging, learning curves and replay viewer work on an environment with continuous controls and several agents at once.
  - Given a tiny continuous test environment (2 points on a line from 0 to 5, each pushing itself −1 to +1 per step, +1 for reaching 5), when a policy-gradient agent trains on it with no changes to the core, then training completes, both points reach 5 in ≥ 9 of 10 evaluation games, and the run is logged, drawn and replayed.
- **CORE-08** When an environment removes one of its agents mid-game, the training loop stops asking that agent for moves and the game continues for the rest.
  - Given the continuous test environment where one point reaches 5 first, when the next step is taken, then only the other point is asked for a move.
- **CORE-09** Growing the core leaves Snake's results unchanged.
  - Given a 200-game Snake run with seed 1 recorded before the core grew, when it is repeated after, then every logged evaluation score is identical.

**Edge cases & errors**
- An environment is missing one of the 4 behaviors → the core refuses it at start-up and names the missing behavior.
- An agent returns a move outside the environment's allowed choices or limits → the run stops with an error naming the move and the game step.
- An agent built for choices is given an environment with continuous controls, or the other way round → refused at start-up, naming both kinds.

### Value-learning agent (`AGENT`)
**Serves:** Goal 1, Goal 2
**Stage:** S1
**Behavior:** The agent learns an estimate of each move's long-run value from the 11 facts, using a small learned function. It picks moves by mostly taking the best-valued move and sometimes a random one, with the random share shrinking over training. It learns from random batches of remembered past steps, and builds its targets from a periodically refreshed frozen copy of its value estimate. Every part is written by hand.

**Requirements**
- **AGENT-01** The agent estimates, for each observation, a value for every allowed move.
  - Given an observation of 11 facts, when the agent is asked, then it returns 3 values, one per move.
- **AGENT-02** During training the agent takes a random move with a probability that starts at 1.0 and decays to 0.01 over the first half of the training games, and otherwise takes its best-valued move.
  - Given training game 0, when the agent picks moves, then every move is random; given a game in the second half, then about 1% of moves are random.
- **AGENT-03** During evaluation the agent always takes its best-valued move.
  - Given an evaluation game, when the agent picks a move, then it is the move with the highest value, and the same observation always gives the same move.
- **AGENT-04** The agent remembers its most recent 100,000 steps and learns from random batches of them.
  - Given more than 100,000 steps taken, when the agent learns, then its batches come only from the latest 100,000 steps, drawn at random.
- **AGENT-05** The agent's learning targets are the step's reward plus the discounted best value of the next observation (discount 0.9), taken from a frozen copy of its value estimate that is refreshed every 1,000 steps; a game-ending step's target is its reward alone.
  - Given a non-final step with reward 0, when its target is built, then it equals 0.9 × the frozen copy's best value for the next observation.
  - Given a game-ending step with reward −10, when its target is built, then it is −10.
  - Given 1,000 learning steps since the last refresh, when the next one happens, then the frozen copy is replaced by the current estimate.
- **AGENT-06** A trained agent can be saved and loaded back, and the loaded agent picks the same moves.
  - Given a saved agent, when it is loaded and plays an evaluation game with seed 11, then it makes exactly the same moves as before saving.

**Edge cases & errors**
- Fewer remembered steps than one batch → the agent keeps playing and does not learn until it has a full batch.
- A saved agent is loaded for an environment with a different observation size or move count → loading is refused with an error naming both sizes.
- Learning produces a non-number value → the run stops with an error naming the game and step, and the log so far is kept.

### Policy-gradient ladder (`PG`)
**Serves:** Goal 1, Goal 2
**Stage:** S2
**Source:** [ideas/fish-tank.md](ideas/fish-tank.md)
**Behavior:** Three hand-written agents learn the fish's steering policy directly, each one built on the one before and each fixing a failure of the rung below. Rung 1, plain policy gradient, makes moves that were followed by high returns more likely. Rung 2, actor-critic, also learns a value estimate and credits each move only with how much better it did than expected, which cuts the noise. Rung 3, the limited-update agent, reuses each game's steps several times but caps how far each update can move the policy, so reuse doesn't wreck it. All fish in a game share one policy, each acting on its own observation. Each rung is compared with the rung below it.

**Requirements**
- **PG-01** Every rung's policy gives, for each observation, a spread of likely moves for each control (a centre and a width), and during training each move is drawn from it.
  - Given the same observation twice during training, when moves are drawn, then they can differ, and over 1,000 draws their average is within 0.05 of the policy's centre for each control.
- **PG-02** During evaluation every rung takes the centre of its policy for each control.
  - Given an evaluation game, when the agent picks a move, then the same observation always gives the same move.
- **PG-03** Every move a rung sends lies within the environment's limits, even when the drawn move falls outside them.
  - Given a drawn turn of +20°, when it is sent to the tank, then the tank receives +15°.
- **PG-04** All fish in a game share one policy: each fish acts on its own observation, and every fish's steps feed the same updates.
  - Given a game with 5 fish, when the agent learns from it, then one policy is updated, from the steps of all 5 fish.
- **PG-05** Every rung learns once after each training game, from all the steps of all its fish, with discount 0.99.
  - Given a training game of 3 fish surviving 40, 70 and 120 steps, when the game ends, then the agent makes one learning update from those 230 fish-steps.
- **PG-06** Rung 1, plain policy gradient, makes each move more or less likely in proportion to the discounted return that followed it, up to that fish's end.
  - Given a fish whose rewards were +1, +1, 0 before it was removed, when its steps are weighted, then the weights are 1.99, 1 and 0.
- **PG-07** Rung 2, actor-critic, learns a value estimate of each observation and weights each move by its advantage: how much better things went than the estimate expected, blending one-step and longer look-aheads with a blend factor of 0.95.
  - Given a fish's last step before removal with reward 0 and a value estimate of 2, when its advantage is built, then it is −2.
  - Given the value estimate after learning from many games, when it is checked on 100 held-out games, then it predicts the discounted return better than predicting the average return for every step.
- **PG-08** Rung 3, the limited-update agent, learns like rung 2 but reuses each game's steps for 10 passes in random batches of 64, and stops rewarding any move whose probability has already moved more than 20% up or down from the policy that played the game.
  - Given a move whose probability under the current policy is 1.3 × its probability when played, with a positive advantage, when the next pass updates, then that move gains nothing from becoming more likely.
- **PG-09** Rungs 2 and 3 rescale each game's advantages to an average of 0 and a spread of 1 before learning.
  - Given a game's advantages, when they are rescaled, then their mean is 0 and their standard deviation is 1, to within 0.001.
- **PG-10** Each rung's final evaluation scores are compared with the rung below it with the `null-hypothesis-testing` skill, given 5 training seeds × the same 100 held-out games for each rung; a rung counts as better only if its scores are higher at a 5% significance level after correcting for the 2 comparisons. The report also gives each rung's spread across its 5 seeds.
  - Given finished runs of all 3 rungs, when the ladder comparison runs, then the report says, for rung 2 against rung 1 and rung 3 against rung 2, "better" or "no detectable difference", with the test result and each rung's spread.
- **PG-11** A rung that is not better than the one below it is recorded as a finding in the notes, and S2 doesn't count as failed.
  - Given a ladder report where rung 3 shows "no detectable difference", when the stage is checked, then it passes, and the notes page records it as a finding (EXPL-04).
- **PG-12** A trained rung can be saved and loaded back, and the loaded agent picks the same moves.
  - Given a saved rung, when it is loaded and plays an evaluation game with seed 11, then it makes exactly the same moves as before saving.

**Edge cases & errors**
- A game ends by the time limit → returns and advantages for the surviving fish stop at step 1,000; nothing is counted beyond it.
- A game where every fish is removed on the first step → the agent learns from those steps alone; it does not stop.
- A saved rung is loaded for an environment with a different observation size or controls → loading is refused with an error naming both.
- Learning produces a non-number value → the run stops with an error naming the game and step, and the log so far is kept.

### Ablation switches (`ABL`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Each environment has three switches, each turning off one part of its top agent, so the learner can train the agent without it and compare. On Snake they turn off the value-learning agent's memory, frozen copy and exploration decay; on the tank they turn off the limited-update agent's value estimate, update cap and advantage rescaling. Each switch is set per run and recorded in the run's log. The comparison of each ablated agent with the full agent is judged by a hypothesis test.

**Requirements**
- **ABL-01** With the memory switch off, the agent learns from only the step it just took, with no remembered steps.
  - Given memory off, when the agent learns, then each update uses exactly the latest step.
- **ABL-02** With the frozen-copy switch off, the agent builds its targets from its current value estimate.
  - Given frozen copy off, when a target is built, then it uses the current estimate's best next value, which changes after every update.
- **ABL-03** With the exploration-decay switch off, the agent's random-move probability stays fixed at 0.1 for the whole run.
  - Given decay off, when the agent picks moves at any point in training, then about 10% are random.
- **ABL-04** Each ablated agent is compared with the full agent of its environment (Snake: the value-learning agent; the tank: the limited-update agent) with the `null-hypothesis-testing` skill, given the final evaluation scores of both (5 training seeds each, on the same 100 held-out games); the ablation counts as hurting learning only if the full agent's scores are higher at a 5% significance level after correcting for the 3 comparisons in that environment.
  - Given finished runs of the full agent and the 3 ablated agents of one environment, when the study is run, then each ablation is reported as "hurts learning" or "no detectable difference", with its test result.
- **ABL-05** When no switch hurts learning, the study is still complete: the result is recorded as a finding in the notes, and S1 doesn't count as failed (nor S2, for the tank's switches).
  - Given a study report where all 3 ablations show "no detectable difference", when the stage is checked, then it passes, and the notes page records that no switch hurt learning as a finding (EXPL-02).
- **ABL-06** With the value-estimate switch off, the limited-update agent weights each move by the discounted return that followed it, as rung 1 does, and learns no value estimate.
  - Given value estimate off, when a fish's rewards were +1, +1, 0, then its moves are weighted 1.99, 1 and 0 before rescaling.
- **ABL-07** With the update-cap switch off, the limited-update agent still makes its 10 passes over each game's steps, with no limit on how far a move's probability can move.
  - Given cap off and a move already 1.3 × as likely as when played, with a positive advantage, when the next pass updates, then that move still becomes more likely.
- **ABL-08** With the rescaling switch off, the limited-update agent uses each game's advantages as built, without rescaling.
  - Given rescaling off, when a game's advantages are used, then they equal the advantages as built.

**Edge cases & errors**
- Several switches are off in one run → allowed; the run's log records every switch's state.
- An ablated run fails before finishing → the study reports that ablation as missing, never as "no detectable difference".
- A switch is set on an agent that doesn't have that part (the tank's switches on rungs 1 or 2's missing pieces, Snake's switches on a tank rung) → the run is refused at start-up, naming the switch and the agent.

### Baselines (`BASE`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Two non-learning agents play the same seeded games as the learning agents in each environment: a random agent and a simple scripted agent. Their scores set the bars every learning agent's curve must clear.

**Requirements**
- **BASE-01** The random agent picks each move uniformly at random from the allowed moves: one of the choices, or each control anywhere within its limits.
  - Given 10,000 moves by the random agent on Snake, when counted, then each of the 3 moves is picked 30–37% of the time.
  - Given 10,000 moves by the random agent in the tank, when counted, then turns are spread evenly over −15° to +15° and speeds over 0 to 0.3, each tenth of either range holding 9–11% of moves.
- **BASE-02** On Snake, the scripted agent moves toward the food along the axis with the larger gap, and when that move is immediately fatal it takes any non-fatal move, preferring straight.
  - Given food straight ahead and no danger ahead, when the scripted agent moves, then it goes straight.
  - Given food straight ahead and a wall ahead, when it moves, then it turns to a side that is free.
- **BASE-03** Both baselines are scored on the same 100 held-out games as the learning agent.
  - Given the 100 held-out seeds, when each baseline plays them, then each records one score per seed, and its mean and spread are logged.
- **BASE-04** In the tank, the scripted fish swims at full speed, turning as far as it can away from the ray that sees the ball closest; with no ball in reach it swims straight, and when the wall is within 1 unit straight ahead it turns as far as it can toward the side whose rays see more room.
  - Given the ball seen only on the front-left ray and no wall within 1 unit ahead, when the scripted fish moves, then it turns −15° (to the right) at speed 0.3.
  - Given no ball in reach and the wall 0.5 units straight ahead with more room on the left, when it moves, then it turns +15° at speed 0.3.

**Edge cases & errors**
- Every move is fatal → the scripted agent goes straight and the game ends.
- The scripted fish sees the ball equally close on two rays → it turns away from the one further left.
- The scripted fish sees the ball and the wall ahead at once → it avoids the wall.

### Evaluation (`EVAL`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Every training run is checked at regular points on a fixed set of held-out games it never trains on, with exploration off, and ends with a final check on all 100 held-out games. Each learning agent's final check is compared with both baselines of its environment on those same games.

**Requirements**
- **EVAL-01** Training games and evaluation games come from separate seed sets that never overlap.
  - Given any training run, when its training and evaluation seeds are listed, then no seed appears in both.
- **EVAL-02** During training the agent plays held-out games at regular points with exploration off and its mean score is logged: on Snake every 50 training games over all 100 held-out games; in the tank at every tenth of training over the same 20 of its 100 held-out games. Every run ends with a final check over all 100.
  - Given a Snake run of 1,000 training games, when it ends, then 20 evaluation results are logged, each over the same 100 seeds.
  - Given a tank run, when it ends, then 10 evaluation results over the same 20 seeds and one final result over all 100 seeds are logged.
- **EVAL-03** Each learning agent's final evaluation scores are compared with each baseline's scores of its environment with the `null-hypothesis-testing` skill, given 5 training seeds × the 100 held-out games for the agent and the same 100 games for each baseline; the agent beats a baseline only if its scores are higher at a 5% significance level after correcting for every comparison in that environment (2 on Snake: the full agent against 2 baselines; 6 in the tank: 3 rungs against 2 baselines).
  - Given finished runs of the full agent and both baselines, when the comparison is run, then the report says, for the random agent and for the scripted agent, whether the agent beats it, with the test result.
  - Given finished runs of all 3 rungs and both tank baselines, when the comparison is run, then the report says, for each of the 6 pairs, whether the rung beats the baseline, with the test result.
- **EVAL-04** On Snake the full agent's learning curve beats both the random baseline and the scripted baseline; in the tank every rung's learning curve beats both the random fish and the scripted fish.
  - Given the EVAL-03 report for Snake, when it is read, then the agent beats both baselines.
  - Given the EVAL-03 report for the tank, when it is read, then each of the 3 rungs beats both baselines.

**Edge cases & errors**
- A run stops early → its completed evaluation points are kept and shown; it is left out of the final comparison, which names it as incomplete.

### Run logging (`LOG`)
**Serves:** Goal 2, Goal 4
**Stage:** S1
**Behavior:** Every run, whether training or baseline, keeps a record of its settings and results, so curves can be redrawn and agents replayed without training again.

**Requirements**
- **LOG-01** Each run records its environment, agent, every setting including the ablation switches, and its seed.
  - Given a finished run, when its record is opened, then the environment, the agent, every setting and the seed are listed.
- **LOG-02** Each run records the score and length of every training game.
  - Given a run of 1,000 games, when its record is read, then it holds 1,000 scores and game lengths.
- **LOG-03** Each run records every evaluation result and the training loss every 50 games.
  - Given a finished run, when its record is read, then each evaluation point has its mean score and spread, and each 50-game point has its average loss.
- **LOG-04** Each training run saves its final trained agent next to its record.
  - Given a finished training run, when its record is opened, then the saved agent can be loaded (AGENT-06).
- **LOG-05** A run's record is kept on disk while the run is in progress, at least after every evaluation point.
  - Given a run stopped at game 430, when its record is opened, then results up to game 400 are present.

**Edge cases & errors**
- Starting a run with the same name as an existing one → refused, naming the existing run; nothing is overwritten.

### Learning curves (`CURVE`)
**Serves:** Goal 2, Goal 1
**Stage:** S1
**Behavior:** From saved run records, the learner draws learning curves: evaluation score against training games, with the environment's baselines as flat reference lines. Curves for several runs can share one chart, so the full agent and its ablations, or the three rungs of the ladder, can be compared at a glance.

**Requirements**
- **CURVE-01** A learning curve shows the mean evaluation score against training games for one or more runs.
  - Given one run's record, when its curve is drawn, then the chart shows one line of mean evaluation score at each evaluation point.
- **CURVE-02** Runs of the same agent and settings with different seeds are drawn as one line of their mean, with a band showing their spread.
  - Given 5 seeds of the full agent, when drawn, then the chart shows one mean line and one band.
- **CURVE-03** The random and scripted baselines' mean scores of the chart's environment appear on every chart as labelled flat lines.
  - Given any Snake chart, when drawn, then two labelled flat lines show the random and scripted baselines' mean scores.
  - Given any tank chart, when drawn, then two labelled flat lines show the random and scripted fish's mean scores.
- **CURVE-04** The full agent and each ablated agent can be drawn together on one chart, each labelled by its switches.
  - Given the full agent and 3 ablation runs, when drawn together, then 4 labelled lines appear.
- **CURVE-05** Curves are drawn from saved records only, never by training again.
  - Given saved records and no training running, when a chart is drawn, then it appears in ≤ 10 seconds.
- **CURVE-06** The 3 rungs of the ladder can be drawn together on one chart, each labelled by its rung.
  - Given 5 seeds of each rung, when drawn together, then 3 labelled mean lines with bands appear.

**Edge cases & errors**
- A record has no evaluation points yet → it is skipped with a note naming it; the other curves are drawn.
- Records from different environments are drawn together → refused, naming the environments.

### Replay viewer (`REPLAY`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** The learner picks any saved agent, or a baseline, and a seed, and watches it play that game frame by frame in a simple view of the environment, with pause, single-step and speed controls.

**Requirements**
- **REPLAY-01** The learner can watch any saved trained agent, the random agent or the scripted agent play a game from a chosen seed.
  - Given a saved agent and seed 42, when a replay is requested, then the agent's game on seed 42 is shown from the first frame to game over.
- **REPLAY-02** Each frame shows the environment's drawing (CORE-04) plus the step number and score.
  - Given a Snake replay, when any frame is shown, then the grid, snake, food, step number and score are visible.
  - Given a tank replay, when any frame is shown, then the tank, the ball, each living fish with its heading, the number of fish left and the step number are visible.
- **REPLAY-03** The learner can pause, step one frame forward and change the playback speed between 1 and 30 frames per second.
  - Given a playing replay, when paused and stepped, then exactly one frame advances; when the speed is set to 30, then 30 frames show per second.
- **REPLAY-04** Replaying the same agent on the same seed shows the identical game every time.
  - Given a saved agent and seed 42, when replayed twice, then every frame and the final score match.
- **REPLAY-05** The final score of a replayed game matches that game's score in the agent's evaluation.
  - Given a held-out seed scored in evaluation, when it is replayed with the same saved agent, then the replay's final score equals the logged score.

**Edge cases & errors**
- The saved agent doesn't exist or can't be loaded → an error names it; no window opens.
- The game never ends → it ends by the environment's limit (SNAKE-05, TANK-06), so every replay has a last frame.

### Explanation notes (`EXPL`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Each environment has a notes page, written by the learner in their own words, explaining why the agent learns, what each ablated part does and, in the tank, what each rung of the ladder fixes, next to the evidence from that environment's study.

**Requirements**
- **EXPL-01** Each environment has a notes page with a section explaining why the agent learns there.
  - Given Snake is finished, when its notes page is opened, then it has a "Why it learns" section written by the learner.
- **EXPL-02** The notes page has one section per ablation switch, giving that ablation's study result and the learner's explanation of it.
  - Given the ablation study report, when the notes page is read, then each of the 3 switches has a section with its result (ABL-04) and an explanation.
- **EXPL-03** The notes page includes the learning-curve charts comparing the full agent, its ablations and the baselines, and in the tank also the 3 rungs and the baselines.
  - Given the Snake notes page, when opened, then the CURVE-04 chart with the CURVE-03 baseline lines is shown on it.
  - Given the tank notes page, when opened, then the CURVE-04 chart and the CURVE-06 chart, each with the CURVE-03 baseline lines, are shown on it.
- **EXPL-04** The tank's notes page has one section per rung above the first, saying which failure of the rung below it fixes, with its ladder result (PG-10).
  - Given the ladder report, when the tank notes page is read, then rungs 2 and 3 each have a section with their result and the learner's explanation.

**Edge cases & errors**
- An ablation shows no detectable difference → its section still exists and explains why that part may not matter in that environment.
- A rung shows no detectable difference from the one below → its section still exists and explains why the fix may not matter in the tank.

### Discrete tank (`TWIN`)
**Serves:** Goal 1
**Stage:** S2
**Source:** [ideas/fish-tank.md](ideas/fish-tank.md)
**Behavior:** An optional twin of the fish tank where each fish picks one of 8 compass moves at full speed instead of steering continuously, trained by the unchanged value-learning agent, so the learner can see what continuous control adds. S2 is complete without it.

**Requirements**
- **TWIN-01** The discrete tank is the fish tank with each fish choosing one of 8 compass directions (north, north-east, …, north-west) each step and swimming 0.3 units that way; everything else is as in the fish tank.
  - Given a fish at the centre, when it picks north-east, then it ends 0.3 units north-east of the centre, heading north-east.
- **TWIN-02** The value-learning agent trains on the discrete tank with no change to how it learns, treating each fish's steps as its own remembered steps.
  - Given the discrete tank with 5 fish, when the value-learning agent trains on it, then training completes, and its run is logged and drawn against the tank's baselines.

**Edge cases & errors**
- The discrete tank is left unbuilt → nothing else in S2 depends on it.

## Quality requirements
- **QR-01** Every training run of a learning agent finishes in under ~1 hour (≤ 60 minutes) on the learner's laptop CPU: the value-learning agent on Snake, and each rung and ablation in the tank with 5 fish.
  - Timed on the learner's laptop with no GPU, for the default number of training games.
- **QR-02** Each environment's full study runs unattended to completion with one command: Snake's (full agent and 3 ablations × 5 seeds, plus baselines) in ≤ 10 hours; the tank's (3 rungs and 3 ablations × 5 seeds, plus baselines) in ≤ 15 hours.
  - Started once on the learner's laptop, it finishes without intervention; total time read from the run records.
- **QR-03** Every learning algorithm is written by hand: the value targets, remembered steps, frozen copy, exploration and update step of the value-learning agent, and the move spreads, returns, value estimate, advantages, update cap and update step of the ladder; no reinforcement-learning library is used. General array math with automatic gradients is allowed.
  - Checked by reading the project's dependency list and the agents' code.
- **QR-04** The lab uses only free tools and needs no paid service or account.
  - Checked by reading the dependency list: every item is free to use.
- **QR-05** On the same machine, a training run repeated with the same seed and settings produces the same logged results.
  - Two runs of 200 games with seed 1 give identical evaluation scores.

## Assumptions
- The learner is the only user; the lab runs on their laptop.
- Tiny test environments exist only to prove the shared core; they are not lab environments.
