Next is adding the idea to the spec. Nothing is written into the spec until you've answered the questions below.

## 1. Conflicts with the approved spec
- **Out of scope:** the line "Return prediction, signal research, return-seeking backtests and paper trading" now conflicts. I propose: "Trading on forecasts: return-seeking backtests, portfolios built from forecasts, and paper trading (later stages). The variance portfolios take no expected-return input." I'd also add "Deep learning and automated feature search" and "Horizons other than the one tested" to the out-of-scope list.
- **STRUCT-05 (S2's market-mode diagnostic):** I recommend leaving it unchanged. It still says portfolios never use residuals, which stays true. The S3 target is a separate computation in a new feature: loadings fitted on the trailing window and applied to the *following* month.
- **EVAL-03 (S2's significance tests):** unchanged. S3 gets its own family of tests, so S2's correction count doesn't change.
- **Summary, Users and Scope** get rewritten for three stages. QR-09 (S2's 60-minute study) stays as is, and S3 gets its own time limit.

## 2. Goal → feature mapping (all Goal 4, Stage S3)
| Feature | Code | What it covers |
|---|---|---|
| Residual target | `RESID` | Next-month residual returns: factors and loadings fitted on the trailing window only, ranked across names |
| Candidate features | `FEAT` | The 7 features, computed from data known at each rebalance date, plus 2 calibration features |
| Walk-forward model | `FMOD` | A model trained only on earlier months, predicting later ones |
| Feature tests | `FTEST` | Rank-correlation tests and model-gain tests through `null-hypothesis-testing`, as one corrected family; characterisation through `data-analysis` |
| Procedure check | `FSYN` | Synthetic data with one planted feature and several noise features, run before any real-data test |
| Development and holdout | `HOLD` | Development and holdout periods, and a holdout that runs once |
| Feature report | `FREP` | Per-feature verdicts, effect sizes, the test used and the family size; reproducible |

## 3. Assumptions (correct me or I'll go ahead)
1. **Dates and universe:** S2's monthly rebalance dates and its eligibility rule (STRUCT-01 and STRUCT-02). A name that stops trading counts its residual return up to its last trading day.
2. **Feature definitions**, in trading days, all ending at the rebalance date:
   - reversal: the last 21 days' total return;
   - momentum: days −252 to −21;
   - volatility: standard deviation of daily returns over 63 days;
   - idiosyncratic volatility: the same over the trailing residuals;
   - volume shock: log of (mean dollar volume over 21 days ÷ over 252 days);
   - maximum return: the largest daily return in the last 21 days;
   - beta: the loading on the first market factor.

   A name lacking a feature's lookback is left out of that feature's test that month.
3. **Calibration features:** independent noise from a fixed seed, and momentum shuffled across names within each date.
4. **Model training:** retrained each January on all earlier development months, with a one-month gap, and predicting the next 12 months. Predictions start in 2005, after 3 years of training.
5. **Model gain:** the drop in the model's out-of-sample rank correlation with the target when that feature is shuffled within each date.
6. **Test family:** 9 features × 2 methods = 18 claims at 5% after correction. The `null-hypothesis-testing` skill picks the test and the null, keeping stocks' same-day co-movement and the autocorrelation over time intact.
7. **Synthetic check:** about 295 months × 490 names, one planted feature with a rank correlation of 0.05 and 8 noise features. The planted feature must be found and no noise feature may pass.
8. **Characterisation:** `data-analysis` covers feature distributions, how the features correlate with each other, and rank-correlation stability by 5-year block, on development data only.

## 4. Questions
1. **Horizon:** one month only, or also one week? Adding one week doubles the test family to 36 and roughly halves each test's power.
2. **Model against baseline:** should the model as a whole have to beat the best single feature on the holdout, tested as one more claim in the family? My proposal is yes, so the ML layer earns its place.
3. **Factors removed for the target:** S2's factor count at each date (at least 1), or always just the market factor? My proposal is S2's count, so sector-like moves leave the target too.
4. **Holdout:** from 2021-01 to the last complete month, run once per frozen feature list. A second run is refused unless you start a new registered list, and the report lists every holdout run. The report would also state the smallest rank correlation the holdout can detect, about 0.025. OK?
5. **Time limit:** a full real-data run, including model training and every test, within 2 hours on your machine?
