# Reference Intake Examples

The index template, the subagent prompt, then the GridLoad worked example: three files arrive while stage S2 is being specced.

`dt` below means `python3 ../../scripts/dt.py`, run from the project root.

---

## Index template: `docs/references.md`

````markdown
# <Project> — References

**Status:** Draft · **Last updated:** YYYY-MM-DD

### RF-01: <What the file is, in a few words>
**File:** `references/<file>` · **Hash:** — · **Kind:** code · **Milestones:** S<n>
- **Purpose:** <what it is for, one line>
- **Key parts:** `<function>(<args>)`, `<Class>`, … (the parts a builder would look at)
- **In → Out:** <input shape or type> → <output shape or type>
- **Use for:** <the step, case or decision it can inform; PL or TC IDs once they exist>
- **Caveats:** <what not to reuse as is, or "none found">

## Retired
````

- **Hash** stays `—` until `dt references --stamp` writes the first 8 hex digits of the file's sha256. A later mismatch puts the file under `references_changed`.
- **Kind** is `code` or `doc`.
- **Milestones** holds stage IDs `S<n>` (or `M<n>` for one slice of a cut stage; comma-separated), `all`, or `—`.
- **Retired** holds one struck line per removed file: `- ~~RF-04: Old loader~~ Retired 2026-12-01: file removed; superseded by RF-05`. Omit the heading until the first file is retired.

<Changed files only>

<entry>
</Changed files only>

The project's stages (from docs/roadmap.md):
<S1: name — outline — Skills: …>
<S2: …>

Return exactly this, nothing else:

### RF-02: Sequence-model window builder (`references/tft_dataset.py`)
- **Purpose:** turns the panel into encoder/decoder windows for a temporal-fusion-transformer style forecaster, with static, known and observed inputs kept separate.
- **Key parts:** `WindowSpec` (lookback 63, horizon 5, stride 1), `add_calendar_features`, `encode_static`, `normalise_observed`, `build_windows`, `split_by_origin`.
- **In → Out:** a (ticker, date) panel plus forward targets → window arrays (static, known, observed, target), split by forecast-origin date.
- **What not to reuse as is:**
  - **Split leakage:** `split_by_origin` leaves no gap between periods, so training targets run into the validation period.
  - **Full-sample fit:** the static-input vocabulary is built on the whole sample, using each name's first sector.
  - **Silent drops:** short-lived and delisted names are dropped without warning.
  - **Rows, not dates:** windows are cut by row, so gaps sit inside windows.
  - **Faked zeros:** missing values are filled with 0.
  - **Holidays:** `days_to_month_end` ignores exchange holidays.
  - **Ticker keys:** keyed by ticker rather than a permanent company id, so reused tickers can mix.
  - **Sector field:** relies on a sector field the project's data has no decision for.

### RF-03: Forward return and volatility labels (`references/tft_targets.py`)
- **Purpose:** forward log returns and realised volatility over the next h days, from adjusted closes.
- **Key parts:** `log_returns`, `forward_return`, `forward_volatility`, `make_targets` (horizons 1, 5, 21), `demean_cross_section`, `drop_incomplete`.
- **In → Out:** (ticker, date, adj_close) → forward return and volatility columns per horizon.
- **What not to reuse as is:**
  - **Rows, not dates:** shifts count rows, so missing days look consecutive.
  - **Delisting tail lost:** each name's last days are dropped, losing the run-up to a delisting.
  - **Crude market adjustment:** the cross-sectional mean isn't over the point-in-time members.
  - **Overlapping labels:** walk-forward splits need a gap of h days.
  - **Adjusted closes:** it uses adjusted closes rather than the project's point-in-time total returns.
  - **No input checks:** zero or negative prices and duplicate rows aren't caught.
  - **Ticker keys:** keyed by ticker.
