1:# RL Lab — Architecture
5:## Overview
6:One Python package, `rllab`. Every environment and every agent sits behind the protocols in `core`. The training loop, evaluation, run records, curves and replay viewer use only those protocols, so they never import Snake. A training run plays seeded games with a hand-written DQN agent. Every 50 games it scores the agent greedily on 100 held-out seeds, and it rewrites its JSON record after each of those checks. The study command trains the full agent and its 3 ablations, 5 seeds each, scores both baselines, and runs the `null-hypothesis-testing` comparisons. It then writes a report and a chart for the learner's notes page. The notes command reads that page and reports missing sections and broken links; no code ever writes it (AD-10). Charts are drawn only from saved records. A replay re-plays a saved agent on a seed, so it never depends on frames saved during training.
28:## Tech stack
31:| Language | Python 3.12 | AD-01 |
32:| Value network and gradients | PyTorch 2.5, CPU wheels; `torch.nn.Linear`, autograd and `torch.optim.Adam` only | AD-02, AD-03 |
33:| Numerics | NumPy ≥ 2.0 | AD-02 |
34:| Run records | JSON (stdlib) plus a `torch.save` state dict per agent | AD-05 |
35:| Learning curves | Matplotlib 3.9, Agg backend, PNG | AD-07 |
36:| Replay viewer | pygame-ce 2.5 | AD-06 |
37:| Study parallelism | `concurrent.futures.ProcessPoolExecutor` (stdlib) | AD-03 |
43:## Components
57:| `study` | The full study as one command: 4 variants × 5 seeds, both baselines, then the comparisons run with the **`null-hypothesis-testing`** skill; writes the report and chart for the notes page, and checks the learner's notes page without writing it (AD-10) | ABL-04, ABL-05, EVAL-03, EVAL-04, EXPL-01–EXPL-03, QR-02 | `agent`, `train`, `evaluate`, `runs`, `registry`, `curves` |
60:Every dependency points one way. `core` imports nothing internal. Only `registry`, `baselines` and `cli` may import `snake` or `corridor`. Import-linter enforces both rules (`build-setup`). The seam for later: `core`, `evaluate`, `runs`, `train`, `curves` and `replay` never name an environment, so they could move out as a shared package together if a second environment needs one.
62:## Interfaces
65:## Data
66:- **Seeds (AD-04):** training game seeds are drawn from `[0, 1_000_000)` by a generator built from the run seed. The 100 held-out seeds are fixed at `1_000_000–1_000_099`. The two ranges can't overlap (EVAL-01), and every agent and baseline is scored on the same held-out games (BASE-03, EVAL-03).
67:- **Run folder (AD-05):** `runs/<name>/record.json` holds the config, one score and length per training game, the evaluation points (mean, spread and per-seed scores), the average loss per 50 games, the status and the elapsed time. Next to it, `runs/<name>/agent.pt` holds the state dict, sizes and config. Baselines get `runs/baseline-random/` and `runs/baseline-scripted/`, each with one evaluation point. Study runs are named `<variant>-s<seed>`, for example `no-memory-s3`.
68:- **Study output:** `runs/study-<env>/report.md` (every comparison with its test result, missing or incomplete runs, and the finding line ABL-05 asks for) and `runs/study-<env>/curves.png`. The learner's own `notes/<env>.md` (EXPL-01–EXPL-03) links both. The code reads the notes page (`study.check_notes`) but never writes it, so the learner's words are never overwritten (AD-10).
70:## Cross-cutting concerns
72:- **Speed (QR-01, QR-02):** each run uses one CPU thread (`torch.set_num_threads(1)`). The study runs up to `os.cpu_count() - 1` runs at once in separate processes (AD-03). The default of 1,000 training games is checked against the 60-minute limit by a timing test on the learner's laptop.
73:- **Reproducibility (QR-05, SNAKE-08, REPLAY-04):** no global random state anywhere. Each environment, agent and run owns a `np.random.Generator` or `torch.Generator` built from its seed. Deterministic torch algorithms and a single thread give identical logged results on the same machine (AD-04).
74:- **Hand-written learning (QR-03):** `agent` may import `torch` and `numpy` only. No gymnasium, stable-baselines or other RL library is a dependency, and a dependency check enforces it (`build-setup`).
77:## Project layout
85:## Decisions
86:### AD-01: Python 3.12, one package `rllab`
88:- **Context:** The user said "Single package, go with your recommendation." (UR-28). This is research code with one user, one laptop and one install (brief Constraints). The user already knows Python, NumPy and PyTorch (UR-07).
89:- **Decision:** One package, `rllab`, on Python 3.12, with one folder per component.
90:- **Alternatives:** Several packages (core, envs, agents): no separate install, release or runtime justifies the split, and the core's seam is already named. Python 3.13: PyTorch CPU wheels and pygame-ce lag on new versions.
93:### AD-02: A hand-written DQN on the 11 facts; PyTorch only for the network and its gradients
100:### AD-03: CPU only; one thread per run, separate processes for the study
105:- **Consequences:** A run's time doesn't depend on the other runs, as long as there are enough cores. On a 4-core laptop the study takes about 7 rounds of 3 runs. QR-02 holds only if one run takes under about 80 minutes when 3 run in parallel, so the timing test measures that case too.
107:### AD-04: Seeds owned per object, fixed held-out range
114:### AD-05: Run records as one JSON file per run, rewritten atomically
121:### AD-06: The environment draws a toolkit-free `Frame`; the viewer is pygame-ce
125:- **Alternatives:** A Matplotlib animation: no extra dependency, but timing at 30 fps and keyboard control are unreliable across backends. A Tkinter canvas: in the standard library, but the event loop and timing take more code. A terminal view: no colour grid on every terminal.
126:- **Consequences:** One extra dependency, used only by `replay`. Frames are plain data, so replay tests check frames without opening a window.
128:### AD-07: Learning curves with Matplotlib from saved records
132:- **Alternatives:** Plotly HTML: interactive, but not needed, and a PNG embeds cleanly in a Markdown notes page. Seaborn: one more dependency to draw a mean and a band.
135:### AD-08: The environment is passed to `Agent.act`, so the scripted baseline reads the true Snake state
142:### AD-09: The comparisons use each side's finished seeds; only an ablation with a failed seed is missing
149:### AD-10: The notes page is the learner's; the code checks it and never writes it
156:## Risks and open questions
158:- **Settings the spec leaves open:** network 11 → 256 → 3, Adam lr 1e-3, batch 64, Huber loss, one update per step and linear ε decay are tutorial defaults, not tested here (AD-02). If the full agent doesn't beat the scripted baseline (EVAL-04), tune these before questioning the design.
159:- **Comparison method:** the test statistic, how the 5 seeds × 100 games are paired and the multiple-comparison correction are left to the `null-hypothesis-testing` skill when `study.compare_scores` is built. The contract passes it the raw per-seed, per-game scores so the skill can pair by game seed; each side may have fewer than 5 seeds (AD-09).
