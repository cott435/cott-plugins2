```mermaid
# data — Architecture

**Package:** data · **Status:** Approved · **Last updated:** 2026-10-17 · **System:** [../../architecture.md](../../architecture.md)

## Overview
  ```
- **Universe scope:** every `permaticker` that appears in SP500 additions, removals or snapshots since 1998; bars from 252 sessions before first membership (DATA-02).
- **Known dates:** backfilled rows are `assumed_ref_date`; rows first seen by an update, and every revision, are `observed` at the run's date (INGST-04, PANEL-01).
- **Returns (AD-08):** total return from unadjusted close, split factor and cash dividends; spin-offs via `closeadj`; delisting payout or −100% `estimated`.

## Cross-cutting concerns
- **Errors:** `CoverageError` (outside history, names the range), `SnapshotError` (unknown, unpromoted when one is required, or mixed), `CredentialsError` (before any fetch), `VendorError` per stock (recorded, run continues).
- **Context:** `data.Membership` and VALID-06's check require 495–510 members on every session (UNIV-01), but PL-09's `SyntheticSource` planted 20 stocks, so M1's synthetic download → validate → promote could never promote and `membership_as_of` broke its own invariant on synthetic data (test-planning route, 2026-10-17).
- **Decision:** `SyntheticSource` plants 505 members on every session over 3 years (about 382k price rows). Each planted removal (the cash delisting, the bankruptcy) is paired with an addition on the same session, so the count never leaves 495–510. The planted events stay on a handful of named stocks; the rest are plain seeded price paths. The 495–510 bounds stay fixed in the contract and the check.
- **Alternatives:** Bounds taken from the source or settings (synthetic: its planted count) — keeps fixtures small, but every reader and the check carry a parameter only tests use, and the synthetic run no longer tests the bound real data faces.
- **Consequences:** M1's synthetic pipeline promotes a snapshot under the same checks as Sharadar data; synthetic fixtures grow to ~382k rows, still seconds to generate. Tests that need a small panel select stocks from a synthetic snapshot rather than building one with fewer members.
