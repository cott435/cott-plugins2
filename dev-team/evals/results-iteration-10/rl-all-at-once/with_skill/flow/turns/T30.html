# runs — Architecture

**Package:** runs · **Status:** Approved · **Last updated:** 2026-10-18 · **System:** [../../architecture.md](../../architecture.md)

## Overview
The only writer and reader of run folders (AD-08) and of every report saved in them (AD-14). It hands learners a `Recorder`, closes runs with their end state and cost, and lists and compares runs.

## Components
| Module | Responsibility | Covers |
|---|---|---|
| `folder` | Start and finish runs; `Recorder` | RUNS-01–RUNS-03, RUNS-05 |
| `read` | `open_run`, curves, signals, saved steps, training seeds | RUNS-01, RUNS-02 |
| `verdicts` | Verdicts and the saved reports: evaluation, cross-play, swing | EVAL-05 |
| `listing` | Run list with status, verdicts and rented cost per world | RUNS-06 |
| `compare` | Differing settings and curves of several runs | RUNS-07 |

## Interfaces
See [contract.md](contract.md).

## Data
`runs/<world>/<run_id>/` holds `run.json` (spec, code version, start, duration, status, cost), `curve.csv` (step, side, score per finished episode), `signals.csv` (step, side, name, value), `train_seeds.npy`, `agents/<side>/step_<n>.pt` (or `.zip` for a library agent), `eval/<id>.npz`, `verdicts/<name>.json`, and for predator & prey `swing.json` and `crossplay.npz`. `run.json` is written at the start with status "running" and the process id, and rewritten at the end. NumPy only.

## Project layout
```
src/rllab/runs/   → pipeline.py (PL-03) folder.py read.py verdicts.py listing.py compare.py
../../tests/intent/runs/ ../../tests/unit/runs/ → its tests at the repo root, folders only; files are planned in pipelines.md
```
