# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [brief.md](brief.md)

## Summary
A personal reinforcement learning lab. The first environment is Snake on a small grid, used to teach value-based learning: a ladder of three hand-written agents, two baseline players, a library comparison, ablations, and a replay viewer. All of it sits on a shared core that a trivial second environment, a 1-D corridor, also runs through.

## Users
| User | What they need to do |
|---|---|
| The learner (sole user) | Train an agent, compare it against baselines and a library version, remove one piece to see its effect, and watch the agent play |

## Scope
**In scope:** Snake game, Baseline players, Value-learning agents, Evaluation, Library comparison, Ablations, Training runs & logs, Replay, Shared core (including the 1-D corridor)
**Out of scope:**
- Designing environments beyond Snake and the corridor. Each gets its own refinement later.
- Learning from screen pixels. Agents receive the game state directly.
- Polished graphics or a web app.
- Large hyperparameter searches or multi-machine training.
- Multi-agent or competitive games.
- Using a reinforcement learning library inside the lab's own agents. A library is used only for the comparison.

## Features

### Snake game (`SNAKE`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Classic Snake on a 10×10 grid. Each step the agent picks one of three moves relative to its heading. Eating food grows the snake. Hitting a wall or itself ends the game. The game can describe itself to an agent in two ways: a compact view or the full grid.

**Requirements**
- **SNAKE-01** A new game places a length-3 snake and one food on a 10×10 grid.
  - Given a new game, when it starts, then the snake has length 3, lies fully inside the grid, and the food is on a cell the snake does not occupy.
- **SNAKE-02** Each step takes one of three actions: go straight, turn left, or turn right, relative to the current heading.
  - Given the snake heading up, when the action is "turn left", then the head moves one cell left and the heading becomes left.
- **SNAKE-03** Moving onto the food grows the snake by 1 and adds 1 to the score.
  - Given the head next to the food, when it moves onto it, then length and score each increase by 1, and new food appears on an empty cell.
- **SNAKE-04** Moving into a wall or the snake's own body ends the game.
  - Given the head at the right edge heading right, when the action is "go straight", then the game is over.
  - Given the head next to its own body, when it moves into the body, then the game is over.
- **SNAKE-05** A game ends after 100 × current length steps without eating.
  - Given a length-3 snake that has not eaten for 299 steps, when it takes one more step without eating, then the game is over.
- **SNAKE-06** Rewards default to +1 for food, −1 for game over, and 0 otherwise. Each run can set its own values.
  - Given default settings, when the snake eats, then the reward is +1. When the game ends by collision or starvation, the reward is −1.
  - Given a run that sets food to +10, when the snake eats, then the reward is +10.
- **SNAKE-07** Games are reproducible from a seed.
  - Given the same seed and the same actions, when two games are played, then every snake position, food position and reward is identical.
- **SNAKE-08** The compact view gives 11 yes/no values: danger straight, left and right; heading (one of four); and whether the food is left, right, above or below the head.
  - Given a wall directly ahead and food above-right of the head, when the compact view is read, then "danger straight", "food right" and "food up" are yes, and the other danger and food values are no.
- **SNAKE-09** The full-grid view shows every cell's contents: empty, snake head, snake body, or food.
  - Given any game state, when the full-grid view is read, then exactly one cell is marked head, one is marked food, and the body cells match the snake's body.

**Edge cases & errors**
- The head moves into the cell the tail is leaving this step → legal, and the game continues.
- The snake fills every cell → the game ends as a win, with no −1 reward.
- An action is given after the game is over → it is refused with a clear error, and the game state doesn't change.

### Baseline players (`BASE`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** Two non-learning players set the bar every agent is measured against.

**Requirements**
- **BASE-01** The random player picks each of the three actions with equal chance.
  - Given 30,000 random-player steps, when the actions are counted, then each action's share is between 32% and 35%.
- **BASE-02** The scripted player steps toward the food if that move is safe. Otherwise it takes any safe move. If no move is safe, it goes straight.
  - Given food directly ahead and no danger ahead, when the scripted player moves, then it goes straight.
  - Given food to the left but danger to the left, and the right is safe, when it moves, then it turns right.
- **BASE-03** Baselines are evaluated with the same protocol as agents (EVAL-01).
  - Given an evaluation report, when it is read, then it lists both baselines' scores next to every agent's.

### Value-learning agents (`AGENT`)
**Serves:** Goal 1, Goal 2
**Stage:** S1
**Behavior:** Three agents form a ladder, each learning how good each action is in each situation:
1. A table-based learner on the compact view.
2. A neural-network learner on the compact view.
3. A neural-network learner on the full grid.

All three are written by hand.

**Requirements**
- **AGENT-01** The table-based agent keeps one learned value per compact-view situation and action. It updates that value after every step, from the reward plus its estimate of the next situation.
  - Given a step that earns +1 food reward, when the agent updates, then the value for that situation and action moves toward the reward.
- **AGENT-02** While training, each agent sometimes takes a random action instead of its best one. That chance falls over training to a set minimum.
  - Given a run's exploration settings, when training reaches the end of the decay period, then the random-action rate equals the set minimum.
- **AGENT-03** The compact-view neural agent learns from batches drawn at random from a memory of past steps.
  - Given a full memory, when a training batch is drawn, then it holds steps from more than one game.
- **AGENT-04** The compact-view neural agent computes its learning targets from a separate copy of itself. That copy is refreshed only at set intervals.
  - Given a refresh interval of N steps, when fewer than N steps have passed since the last refresh, then the target copy is unchanged.
- **AGENT-05** The full-grid neural agent learns from the full-grid view, using the same memory and target-copy behavior as AGENT-03 and AGENT-04.
  - Given a full-grid run, when training starts, then the agent receives only the full-grid view, never the compact view.
- **AGENT-06** The agents are written from basic array and tensor operations, including automatic gradients. They contain no reinforcement learning library code.
  - Given the agents' code, when it is reviewed, then it uses no reinforcement learning library.
- **AGENT-07** During evaluation, agents always take their best-valued action and never explore.
  - Given an evaluation game, when the agent acts, then no action is random.

### Evaluation (`EVAL`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** Every agent and baseline is measured the same way. Claims about "beats" or "not worse than" are statistically tested, never judged by eye.

**Requirements**
- **EVAL-01** An evaluation plays 200 games for each of 5 training seeds, on evaluation seeds never used in training. It reports the mean score and its spread.
  - Given a trained agent, when it is evaluated, then 1,000 games are played and the report shows the mean score and spread for each seed and overall.
- **EVAL-02** Every agent significantly beats the random player. This is tested with the `null-hypothesis-testing` skill on the EVAL-01 scores, and passes only if significant at 5% after correcting for the number of comparisons.
  - Given the three agents' and the random player's scores, when tested, then each agent's corrected result is significant at 5%.
- **EVAL-03** The compact-view neural agent is not significantly worse than the scripted player, tested with the `null-hypothesis-testing` skill at 5% after correction.
  - Given both players' EVAL-01 scores, when tested for "agent worse than scripted", then the result is not significant.
- **EVAL-04** At least one agent significantly beats the scripted player, tested with the `null-hypothesis-testing` skill at 5% after correction.
  - Given all three agents' EVAL-01 scores, when each is tested against the scripted player, then at least one corrected result is significant.
- **EVAL-05** The report states whether the full-grid agent significantly beats the scripted player. This is a stretch target, not a pass condition.
  - Given the full-grid agent's scores, when the report is produced, then it shows that test's result and labels it "stretch".
- **EVAL-06** Each agent's learning curve shows evaluation score against training steps, with the two baseline means drawn as reference lines.
  - Given a finished run, when its curve is shown, then both baseline lines appear on the same chart.

### Library comparison (`REF`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** An established reference implementation of neural-network value learning trains on the same Snake setup. The hand-written agent has to come close to it.

**Requirements**
- **REF-01** The reference implementation trains on the compact view with the same rewards, number of training steps and training seeds as the compact-view neural agent. It is evaluated with EVAL-01.
  - Given a reference run, when its settings are compared with the agent's, then game, view, rewards, steps and seeds match.
- **REF-02** The compact-view neural agent's mean score is at least 90% of the reference's mean score.
  - Given both EVAL-01 results, when compared, then agent mean ≥ 0.9 × reference mean.
- **REF-03** The compact-view neural agent is not significantly worse than the reference, tested with the `null-hypothesis-testing` skill at 5% after correction.
  - Given both EVAL-01 score sets, when tested for "agent worse than reference", then the result is not significant.

### Ablations (`ABL`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Remove one piece, retrain, and see what changes. Each ablation is a full agent with one behavior switched off.

**Requirements**
- **ABL-01** The compact-view neural agent can run with no memory, learning only from its most recent step.
  - Given the no-memory switch, when training, then each update uses only the latest step.
- **ABL-02** The compact-view neural agent can run with no separate target copy, computing targets from itself.
  - Given the no-target-copy switch, when training, then the targets come from the current agent at every step.
- **ABL-03** The table-based agent can run with no exploration, always taking its best-valued action.
  - Given the no-exploration switch, when training, then no action is random.
- **ABL-04** Each ablation trains with the same seeds and step budget as the full agent. Its learning curve is shown on one chart beside the full agent's.
  - Given a finished ablation, when the comparison is shown, then both curves share one chart and the report gives each one's EVAL-01 mean.

### Training runs & logs (`RUN`)
**Serves:** Goal 1, Goal 5
**Stage:** S1
**Behavior:** Each training run is launched from one settings description. It leaves behind a complete record of what happened.

**Requirements**
- **RUN-01** A run is fully described by its settings: environment, view, agent, rewards, exploration, step budget and seed.
  - Given a settings description, when a run is launched from it, then no other input is needed.
- **RUN-02** Each run saves its settings, its seed, its learning-curve data, a final checkpoint, and recorded evaluation games.
  - Given a finished run, when its record is opened, then all five are present.
- **RUN-03** The same settings and seed on the same machine produce the same learning curve.
  - Given two runs with identical settings and seed, when their curves are compared, then they match exactly.
- **RUN-04** During training, progress is shown at least every 30 seconds: steps, games, recent mean score, and elapsed time.
  - Given a running training job, when 30 seconds pass, then a progress line has appeared.
- **RUN-05** A saved checkpoint can be reloaded and evaluated without retraining.
  - Given a finished run's checkpoint, when it is evaluated, then the scores match the run's own evaluation.

**Edge cases & errors**
- A run is interrupted → what was saved so far is kept, and the run is marked incomplete.
- The settings name an unknown environment, view or agent → the run refuses to start and names the bad setting.

### Replay (`REPLAY`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** Any recorded game can be watched step by step, showing the grid, score and step count.

**Requirements**
- **REPLAY-01** Any recorded game from any saved run can be played back, showing the grid, the score and the step number.
  - Given a saved run, when one of its games is replayed, then each frame matches the recorded game state.
- **REPLAY-02** Playback can be paused, stepped one frame at a time, and sped up or slowed down.
  - Given a paused replay, when "step" is pressed, then exactly one frame advances.
- **REPLAY-03** New games can be recorded from any saved checkpoint and then replayed.
  - Given a checkpoint and a seed, when games are recorded, then they can be replayed like any other recorded game.

**Edge cases & errors**
- A recording is missing or unreadable → a clear error that names the run and the game.

### Shared core (`CORE`)
**Serves:** Goal 5
**Stage:** S1
**Behavior:** Every environment presents the same interface. Training, logging, evaluation and replay work with any environment that presents it. A trivial 1-D corridor proves this by running through the core unchanged.

**Requirements**
- **CORE-01** Every environment offers the same two operations. Starting a game from a seed returns the first observation. Taking an action returns the next observation, the reward, whether the game is over, and extra information.
  - Given Snake or the corridor, when a game is started and stepped, then both return the same kinds of result.
- **CORE-02** Training, logging, evaluation and replay work with any environment that offers CORE-01's interface.
  - Given the corridor, when it is trained, evaluated and replayed, then it uses the same training, logging, evaluation and replay as Snake.
- **CORE-03** The corridor is a row of 10 cells. The agent starts at the left end and moves left or right. Reaching the right end gives +1 and ends the game. A game also ends after 50 steps.
  - Given the agent at cell 9 of 10, when it moves right, then the reward is +1 and the game is over.
  - Given the agent at the left end, when it moves left, then it stays in place.
- **CORE-04** The table-based agent, trained on the corridor through the core, reaches the right end in ≥ 95% of evaluation games, in at most 12 steps.
  - Given a trained corridor agent, when evaluated, then ≥ 95% of games reach the right end within 12 steps.
- **CORE-05** Adding the corridor needs no change to the shared core.
  - Given the core as Snake uses it, when the corridor is added, then the change touches only corridor code.

## Data requirements
- **DATA-01** Evaluation games never reuse a seed used in training.
  - Given any evaluation, when its seeds are checked against the run's training seeds, then none overlap.
- **DATA-02** All training and evaluation data comes from the lab's own environments. No outside datasets are used.
  - Given any run, when its inputs are listed, then they are only settings and environment output.

## Quality requirements
- **QR-01** Training the table-based Snake agent takes ≤ 10 minutes per seed on the learner's laptop (Apple Silicon, processor only).
  - Timed from the run's own elapsed-time log.
- **QR-02** Training the compact-view neural agent takes ≤ 60 minutes per seed on the same laptop, processor only.
  - Timed from the run's own elapsed-time log.
- **QR-03** Training the full-grid neural agent takes ≤ 60 minutes per seed, on the laptop or on rented hardware within QR-05.
  - Timed from the run's own elapsed-time log.
- **QR-04** Evaluating one agent (EVAL-01, 1,000 games) takes ≤ 5 minutes on the laptop.
  - Timed during evaluation.
- **QR-05** Rented cloud hardware costs ≤ $5 in total for this stage, and is used only if QR-03 can't be met on the laptop.
  - Checked against the provider's bill.
- **QR-06** Everything runs on a laptop with no NVIDIA graphics card.
  - All runs and tests pass on the learner's MacBook Pro.

## Assumptions
- The learner is the only user. No sharing, accounts or remote access.
- Score means food eaten in one game.
- Agents act with moves relative to their heading (straight, left, right), not with compass directions.
- "Not worse than" is shown by a non-significant test for "worse", not by a separate equivalence test.
