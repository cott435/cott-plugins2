# Grid RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [brief.md](brief.md)

## Summary
A small lab where hand-built reinforcement-learning agents train on 2D grid environments that share one core: an environment interface, a training loop, logging, evaluation and a replay viewer. The first environment is Snake, learned in three levels by a lookup-table Q-learning agent and then a neural-network Q-learning agent (DQN), judged against random and scripted baselines and taken apart by ablation experiments. A toy corridor environment proves the core is reusable. Why: see the [brief](brief.md).

## Users
| User | What they need to do |
|---|---|
| Learner (the project owner) | Train agents on an environment, compare them honestly with baselines, watch replays, and run ablations to explain why the agent works |

## Scope
**In scope:** Environment interface (`CORE`), Snake environment (`SNAKE`), Toy corridor environment (`CORR`), Baseline agents (`BASE`), Tabular Q-learning agent (`TAB`), DQN agent (`DQN`), Training & logging (`TRAIN`), Evaluation & comparison (`EVAL`), Ablation experiments (`ABL`), Replay viewer (`VIEW`).

**Out of scope:**
- Agents from established reinforcement-learning libraries — comparison comes after the hand-built agents work.
- Advanced algorithms (policy gradients, Rainbow-style add-ons) — one concept per environment.
- Observations from raw pixels or the full grid — compact features only.
- Hyperparameter-search tooling, dashboards and experiment-tracking services.
- Packaging, documentation sites, leaderboards or polish for other users.
- GPU training and parallel or distributed training.
- A reward-shaping ablation.
- Environments beyond Snake and the toy corridor.

## Features

### Environment interface (`CORE`)
**Serves:** Goal 4
**Behavior:** Every environment and every agent speaks the same small interface, so the training loop, evaluation, logging and viewer work with any environment without knowing which one it is.

**Requirements**
- **CORE-01** Every environment starts a new episode from a given seed and returns the first observation.
  - Given any environment, when a new episode is started with a seed, then an observation of the environment's declared size is returned.
- **CORE-02** Every environment advances one step for a given action and returns the next observation, the reward, whether the episode ended by termination, whether it ended by truncation, and an info record.
  - Given an episode in progress, when a valid action is taken, then all five results are returned, and termination and truncation are never both true.
- **CORE-03** Every environment declares its number of actions and its observation size.
  - Given any environment, when asked for its sizes, then it reports the action count and observation length without starting an episode.
- **CORE-04** Every environment renders its current state as a frame the viewer can display.
  - Given any environment mid-episode, when a frame is requested, then a frame showing the current state is returned.
- **CORE-05** Every agent chooses an action from an observation in either exploring mode or greedy mode.
  - Given a trained agent and an observation, when asked twice for a greedy action, then it returns the same action both times.
- **CORE-06** Every learning agent can be saved and reloaded.
  - Given a saved agent, when it is reloaded, then it gives the same greedy action as before saving for every observation tried.
- **CORE-07** Training, evaluation, logging and the viewer contain no environment-specific behavior.
  - Given the toy corridor environment, when it is trained, evaluated and replayed, then no change to the training, evaluation, logging or viewer behavior is needed (see CORR-03).

**Edge cases & errors**
- An action outside the declared action range → the step is refused with an error naming the valid range.
- Stepping after the episode has ended → refused with an error saying a new episode must be started.

### Snake environment (`SNAKE`)
**Serves:** Goal 1, Goal 4
**Behavior:** Classic Snake on a square grid. The snake moves one cell per step. It eats food to score and grow, and dies on hitting a wall or itself. The agent sees 11 yes/no features rather than the grid. Three named levels form a curriculum.

**Requirements**
- **SNAKE-01** The environment offers three levels: L1 is 5×5 without growth, L2 is 5×5 with growth, and L3 is 10×10 with growth.
  - Given level L1, when an episode starts, then the grid is 5×5 and the snake's length never changes during the episode.
  - Given level L3, when an episode starts, then the grid is 10×10 and eating food increases the snake's length.
- **SNAKE-02** The snake starts each episode at length 3, lying horizontally in the middle row, heading right.
  - Given any level, when an episode starts, then the snake has length 3, its head is in the middle row, and its heading is right.
- **SNAKE-03** The agent has three actions relative to the snake's heading: go straight, turn left, turn right.
  - Given a snake heading up, when "turn left" is taken, then the head moves one cell left and the heading becomes left.
- **SNAKE-04** Food is always placed on a cell the snake does not occupy, chosen uniformly at random from the empty cells.
  - Given any state, when food is placed, then it is on an empty cell.
- **SNAKE-05** When the head enters the food cell, the food is eaten and new food is placed.
  - Given a level with growth, when food is eaten, then the snake's length increases by 1 and the score increases by 1.
  - Given level L1, when food is eaten, then the score increases by 1 and the length stays the same.
- **SNAKE-06** Moving into a wall or into the snake's own body ends the episode by termination.
  - Given the head next to a wall and facing it, when "straight" is taken, then the episode terminates and the end cause is "wall".
  - Given a move into a body cell, then the episode terminates and the end cause is "self".
- **SNAKE-07** The head may move into the cell the tail is leaving on that step.
  - Given the head next to the tail's cell on a step where the snake does not grow, when the head moves into that cell, then the episode continues.
- **SNAKE-08** Filling every cell of the grid with the snake ends the episode by termination as a win.
  - Given a snake one cell short of filling the grid, when it eats the last food, then the episode terminates and the end cause is "win".
- **SNAKE-09** Going as many steps without eating as there are cells in the grid ends the episode by truncation.
  - Given level L3, when 100 steps pass without food being eaten, then the episode ends by truncation with end cause "starved", not by termination.
- **SNAKE-10** The reward is +1 for eating food, −1 for dying, and 0 for any other step.
  - Given a step where food is eaten, then the reward is +1; given a step into a wall, then the reward is −1; given a truncation step, then the reward is 0.
- **SNAKE-11** An optional reward-shaping setting, off by default, adds a configurable small reward for moving closer to the food and the same penalty for moving away.
  - Given default settings, when the snake moves closer to food without eating, then the reward is 0.
  - Given shaping on with size 0.1, when the snake moves closer without eating, then the reward is +0.1.
- **SNAKE-12** The observation is 11 yes/no features: danger straight, danger left, danger right; heading up, down, left, right; food up, down, left, right (relative to the head).
  - Given the head facing a wall one cell ahead with food to its upper left, when observed, then "danger straight", "food up" and "food left" are yes, and "food down" and "food right" are no.
- **SNAKE-13** An alternative observation leaves out the three danger features, giving 8 features.
  - Given the no-danger observation setting, when observed, then the observation has 8 features and equals the full observation with the danger features removed.
- **SNAKE-14** The info record of each step reports the score, the snake's length, and the end cause when the episode ends.
  - Given an episode that ends by hitting a wall after eating 4 food, then the final info reports score 4 and end cause "wall".
- **SNAKE-15** The same seed and the same actions always produce the same episode.
  - Given two episodes started with seed 7, when the same action sequence is taken, then every observation, reward and food position matches.

**Edge cases & errors**
- No empty cell left for food → that only happens on a win, which ends the episode first.
- "Turn" into the snake's own neck → impossible, because actions are relative and there is no reverse action.
- Food in line with the head (same row) → "food up" and "food down" are both no.

### Toy corridor environment (`CORR`)
**Serves:** Goal 4
**Behavior:** A one-dimensional corridor where the agent starts at the left end and food sits at the right end. It is trivially solvable, so it is used to prove the shared core is reusable and to sanity-check agents before Snake.

**Requirements**
- **CORR-01** The corridor has a configurable length (default 10 cells); the agent starts in the leftmost cell, the food is in the rightmost cell, and the actions are move left and move right.
  - Given the default corridor, when an episode starts, then the agent is in cell 1 of 10 and the food is in cell 10.
- **CORR-02** Reaching the food gives +1 and ends the episode by termination; every other step gives 0; after 4 × length steps the episode ends by truncation.
  - Given the default corridor, when the agent moves right 9 times, then the 9th step gives +1 and terminates.
  - Given the default corridor, when 40 steps pass without reaching the food, then the episode ends by truncation.
- **CORR-03** The corridor runs through the same training, logging, evaluation and viewer as Snake, unchanged.
  - Given the corridor, when a DQN agent is trained, evaluated and its episode replayed, then logs, a learning curve and a viewable replay are produced.
- **CORR-04** Both learning agents solve the corridor as a sanity check.
  - Given the default corridor, when the tabular agent or the DQN agent is trained, then its greedy policy reaches the food in the minimum 9 steps in 100% of 100 evaluation episodes.

**Edge cases & errors**
- Moving left in the leftmost cell → the agent stays put and the step counts.
- Corridor length below 2 → refused with an error.

### Baseline agents (`BASE`)
**Serves:** Goal 2
**Behavior:** Two non-learning agents set the bar every learned agent must clear.

**Requirements**
- **BASE-01** The random agent picks uniformly among the environment's actions.
  - Given 3,000 random-agent steps on Snake, then each action's share is between 30% and 37%.
- **BASE-02** The greedy Snake agent picks, among actions that don't die on the next step, one that moves the head closer to the food.
  - Given food to the right of the head and a safe "turn right", when the greedy agent acts, then it turns right.
- **BASE-03** When no safe action moves closer to the food, the greedy agent picks any safe action; when no action is safe, it goes straight.
  - Given every closer move is deadly and "straight" is safe, when the greedy agent acts, then it goes straight.
- **BASE-04** The baselines are evaluated by exactly the same procedure as the learned agents.
  - Given a comparison report, then baseline and learned-agent results come from the same evaluation seeds and episode count (EVAL-01).

**Edge cases & errors**
- Two safe actions are equally close to the food → the greedy agent picks between them using its seeded random source, so runs are reproducible.

### Tabular Q-learning agent (`TAB`)
**Serves:** Goal 1
**Behavior:** A lookup table holds one value per action for every observation seen, updated by Q-learning. It is the first agent trained on the small levels, and the stepping stone to DQN.

**Requirements**
- **TAB-01** The agent keeps a value for each (observation, action) pair it has seen and updates it with the Q-learning rule.
  - Given a transition with reward 1 into a terminal state, learning rate 0.5, and a starting value of 0, when the agent learns from it, then that value becomes 0.5.
- **TAB-02** Learning targets bootstrap from the next state after a truncation, but not after a termination.
  - Given a truncated transition whose next state has a best value of 2, discount 0.9, reward 0, and learning rate 1, then the updated value is 1.8; given the same transition marked terminal, then it is 0.
- **TAB-03** Exploration is epsilon-greedy, with epsilon decaying linearly from a configurable start to a configurable floor over a configurable number of steps.
  - Given start 1.0, floor 0.05, and decay over 10,000 steps, then epsilon is 0.525 at step 5,000 and 0.05 from step 10,000 on.
- **TAB-04** The learning rate, the discount, and the exploration schedule are configurable.
  - Given a run's configuration, then each of these values is recorded with the run (TRAIN-04).
- **TAB-05** The agent is written from basic array operations, with no reinforcement-learning library.
  - Given the agent's code, then it uses no reinforcement-learning library.
- **TAB-06** The learned table can be inspected: for each observation seen, the value of each action and how often that observation was visited.
  - Given a trained agent, when its table is listed, then each row shows the observation's features in readable form, the three action values, and a visit count.
- **TAB-07** On levels L1 and L2, the tabular agent beats random play.
  - Given 5 training seeds on a level, when each trained agent is evaluated (EVAL-01) and compared with the random agent (EVAL-02), then "no difference" is rejected at 5% after correction and the agent's mean score is higher. The comparison with greedy is reported, but passing it isn't required.

**Edge cases & errors**
- Greedy action for an observation never seen → all values are 0, and the tie is broken by the agent's seeded random source.

### DQN agent (`DQN`)
**Serves:** Goal 1, Goal 2
**Behavior:** A small neural network maps the observation to one value per action, trained by Q-learning with experience replay and a target network. Each piece can be switched off for the ablations. It is the main agent for level L3.

**Requirements**
- **DQN-01** A neural network maps an observation to one estimated value per action.
  - Given any observation, when values are requested, then exactly one value per action is returned.
- **DQN-02** Experience replay stores the most recent transitions up to a configurable capacity and trains on uniformly sampled minibatches of a configurable size.
  - Given capacity 1,000 after 1,500 transitions, then the buffer holds exactly the latest 1,000.
- **DQN-03** Turning experience replay off makes the agent train on each transition once, in order, as it happens.
  - Given replay off, when a transition occurs, then the training update uses only that transition.
- **DQN-04** A target network supplies learning targets and is refreshed from the online network every configurable number of steps.
  - Given a refresh interval of 500 steps, then target values change only at multiples of 500 steps.
- **DQN-05** Turning the target network off makes learning targets come from the online network itself.
  - Given the target network off, then target values are computed from the current online network at every update.
- **DQN-06** Learning targets bootstrap after a truncation, but not after a termination.
  - Given a terminal transition with reward −1, then its learning target is −1.
- **DQN-07** Exploration is epsilon-greedy with the same linear schedule as TAB-03.
  - Given the same schedule settings, then epsilon at each step matches TAB-03.
- **DQN-08** The network size, learning rate, discount, batch size, replay capacity, target refresh interval, and exploration schedule are configurable.
  - Given a run's configuration, then each of these values is recorded with the run (TRAIN-04).
- **DQN-09** The agent is written from basic tensor operations and a general-purpose neural-network toolkit, with no reinforcement-learning library.
  - Given the agent's code, then it uses no reinforcement-learning library.
- **DQN-10** On level L3, the DQN agent beats both baselines.
  - Given 5 training seeds on L3, when each trained agent is evaluated (EVAL-01) and compared with the random agent and the greedy agent (EVAL-02), then "no difference" is rejected at 5% after correction for both comparisons, and the agent's mean score is higher in both.
- **DQN-11** The agent can also train on levels L1 and L2 and on the corridor.
  - Given level L2, when DQN is trained and evaluated, then its results appear in the same report format as the tabular agent's.

**Edge cases & errors**
- Training starts before the buffer holds one minibatch → no update happens until it does; acting continues.

### Training & logging (`TRAIN`)
**Serves:** Goal 3, Goal 4
**Behavior:** One command trains any agent on any environment and level, for a set number of steps and a seed. It logs every episode, evaluates periodically, and saves everything for the run in its own place.

**Requirements**
- **TRAIN-01** One command trains a chosen agent on a chosen environment and level for a given number of steps with a given seed.
  - Given agent DQN, level L3, 200,000 steps, and seed 1, when the command runs, then training runs exactly 200,000 environment steps.
- **TRAIN-02** One command runs the same configuration for a list of seeds, one after another.
  - Given seeds 1-5, then five separate runs are produced.
- **TRAIN-03** Every training episode is logged with its return, score, length in steps, end cause, current epsilon, and mean training loss.
  - Given a finished run, then the log has one row per training episode with all six values.
- **TRAIN-04** Every run is stored in its own place with its full configuration, its logs, the final agent, and recorded evaluation episodes; no run overwrites another.
  - Given two runs of the same configuration and seed, then both are kept separately.
- **TRAIN-05** Every configurable number of steps, training pauses to run 20 greedy evaluation episodes on fixed evaluation seeds and logs their mean score; these points form the learning curve.
  - Given an evaluation interval of 10,000 steps over 200,000 steps, then the learning curve has 20 points.
- **TRAIN-06** At the end of a run, the final evaluation's best and median episodes are recorded for the viewer.
  - Given a finished run, then two recorded episodes are available, labeled "best" and "median".
- **TRAIN-07** Progress is shown while training runs: steps done, episodes done, recent mean score, and epsilon.
  - Given a running training, then the progress display updates at least every 10 seconds.

**Edge cases & errors**
- Training is interrupted → the logs written so far are kept, and the run is marked incomplete.
- An unknown agent, environment or level name → refused with an error listing the valid names.

### Evaluation & comparison (`EVAL`)
**Serves:** Goal 2, Goal 3
**Behavior:** Learned agents and baselines are scored by the same fixed procedure, compared with a proper significance test, and shown as learning curves and a results table.

**Requirements**
- **EVAL-01** Evaluating an agent plays 100 greedy episodes on a fixed set of evaluation seeds, separate from all training seeds, and reports mean, median and maximum score, mean length, and a breakdown of end causes.
  - Given any two agents evaluated on level L3, then both played the same 100 evaluation seeds, and none of those seeds was used in training.
- **EVAL-02** Comparing an agent with a baseline or a variant uses the `null-hypothesis-testing` skill. It is given each training seed's mean evaluation score for the agent (5 values) and the matching evaluation scores for the other side. Its null hypothesis is "no difference in mean score". A comparison passes only if the null is rejected at the 5% level after correction across all comparisons in the same report, and the agent's mean score is higher.
  - Given the DQN-vs-random and DQN-vs-greedy comparisons on L3, then the report shows each one's test result, corrected significance, and pass or fail.
- **EVAL-03** A learning-curve plot shows evaluation score against training steps, with one faint line per seed, a bold mean line, and the random and greedy baselines' scores as horizontal reference lines. It is made following the `dataviz` skill.
  - Given 5 finished L3 DQN runs, when the plot is made, then it shows 5 seed lines, 1 mean line, and 2 labeled baseline lines.
- **EVAL-04** A results table for each level lists every agent and baseline with its mean score ± standard deviation across seeds and each comparison's pass or fail.
  - Given evaluations on L3, then the table lists random, greedy and DQN, with DQN's two comparison results.

**Edge cases & errors**
- Fewer than 5 seeds finished → the comparison still runs, but the report states the seed count and marks the result "underpowered: fewer than 5 seeds".

### Ablation experiments (`ABL`)
**Serves:** Goal 1
**Behavior:** Three variants of the DQN agent each remove one piece, so the learner can see what each piece is for.

**Requirements**
- **ABL-01** Three ablation variants run on level L3 with otherwise identical settings to full DQN: no experience replay, no target network, and no danger features (the 8-feature observation).
  - Given the full DQN configuration, when the ablations run, then each variant's recorded configuration differs from it in exactly one setting.
- **ABL-02** Each variant is trained with the same 5 seeds as full DQN.
  - Given the ablation set, then 15 runs exist, 5 per variant, all using seeds matching the full DQN runs.
- **ABL-03** Each variant is compared with full DQN using EVAL-02. The report says, for each one, whether it is significantly worse, significantly better, or not distinguishable.
  - Given finished ablation runs, then the report lists 3 comparisons, each with one of those three outcomes.
- **ABL-04** One learning-curve plot overlays the mean curves of full DQN and the three variants, following the `dataviz` skill.
  - Given finished ablation runs, then the plot shows 4 labeled mean lines with the baselines as reference lines.

**Edge cases & errors**
- A variant performs no worse than full DQN → reported as found, not treated as a failure. Ablation results are findings, not pass/fail gates.

### Replay viewer (`VIEW`)
**Serves:** Goal 3, Goal 1
**Behavior:** An interactive window plays back a recorded episode step by step, or plays a new episode live from a saved agent. It shows what the agent did and how it valued each choice.

**Requirements**
- **VIEW-01** The viewer opens a recorded episode and draws the environment's frame for each step, with the step number, score, action taken, and reward.
  - Given a recorded Snake episode, when opened, then the first frame shows the grid, the snake with its head distinguishable, the food, and "step 0, score 0".
- **VIEW-02** The viewer has play/pause, step forward, step back, jump to start, jump to end, and a playback speed adjustable from 1 to 30 steps per second.
  - Given a paused episode at step 10, when "step back" is pressed, then step 9 is shown.
- **VIEW-03** For value-based agents, the viewer shows the agent's value for each action at the current step, highlighting the one chosen.
  - Given a recorded DQN episode at any step, then three action values are shown and the chosen action is highlighted.
- **VIEW-04** The viewer can load a saved agent and play and record a new greedy episode from a given seed.
  - Given a saved L3 DQN agent and seed 42, when played live, then the episode is shown and saved as a recorded episode.
- **VIEW-05** A recorded episode can optionally be exported as an animation file.
  - Given a 50-step recorded episode, when exported, then an animation file with 50 frames is produced, and it opens in a standard image viewer.
- **VIEW-06** The viewer plays corridor episodes with the same controls.
  - Given a recorded corridor episode, when opened, then it plays with all VIEW-02 controls.

**Edge cases & errors**
- A recorded episode file is missing or corrupt → an error naming the file; the viewer doesn't crash.
- A non-value-based agent (random or greedy) → the action-value panel shows "n/a".

## Quality requirements
- **QR-01** One DQN training run on level L3 that meets DQN-10 finishes in 15 minutes or less on the project owner's laptop CPU (Apple Silicon, no GPU).
  - Checked by timing a full L3 run with the configuration used for DQN-10.
- **QR-02** A corridor sanity run (CORR-04) finishes in 2 minutes or less for either learning agent.
  - Checked by timing the corridor runs.
- **QR-03** Snake steps at 10,000 steps per second or faster under random play on level L3.
  - Checked by timing 100,000 random steps.
- **QR-04** Running the same configuration with the same seed on the same machine reproduces the same evaluation scores.
  - Checked by running one L2 tabular configuration twice and comparing the evaluation results.
- **QR-05** Everything runs offline: no network access and no accounts.
  - Checked by running a training, an evaluation and a replay with networking disabled.

## Assumptions
- Actions are relative to the snake's heading (straight, left, right).
- The agent sees 11 yes/no features, not the full grid.
- Rewards are +1 for food, −1 for death and 0 otherwise; reward shaping is off by default.
- An episode ends on death, on a win, or after as many steps without food as the grid has cells.
- Food never spawns on the snake; the same seed gives the same game.
- Evaluation uses greedy play, with no exploration.
- Each run stores its outputs separately; runs never overwrite each other.
- The system produces plots, tables and ablation comparisons; the written explanation of why the agent works is the learner's own, outside the system.
