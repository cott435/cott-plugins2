# build — Architecture

**Package:** build · **Status:** Draft · **Last updated:** 2026-10-17 · **System:** [../../architecture.md](../../architecture.md)

## Overview
`build` (Python package `qlab_build`, command `qlab`) is the write side (AD-15). A run downloads into a read-only snapshot, cleans the raw tables into canonical ones keyed by permanent ID, checks rows, derives adjustment factors and returns, checks the dataset, writes the exploratory report, and publishes an immutable version in the layout `data` defines. It also owns the run lock and run log that `server` reads progress from.

## Components
| Component | Responsibility | Covers | Depends on |
|---|---|---|---|
| `sources` | `Source` interface; Sharadar and EODHD clients with retries; raw downloads only | DATA-01–DATA-06, DATA-08, BUILD-08 | `data` |
| `snapshots` | Save downloads as read-only snapshot folders with SHA-256 manifests; verify and merge on read; pick a version's snapshots | BUILD-01, BUILD-04, BUILD-05, QR-04 | `data` |
| `clean` | Read the hand-checked reference lists; raw vendor tables → canonical tables; drop exact duplicates | UNIV-03, UNIV-04, PRICE-01–PRICE-03, PRICE-06, DATA-02–DATA-05, VAL-05 (duplicates) | `data` |
| `validate` | Two phases (AD-14): `validate.rows` before derivation (outcomes, reasons, cross-source, reference lists); `validate.dataset` after (large moves, member count, history, gate, report) | VAL-01–VAL-09, UNIV-02, DATA-01, DATA-06 | `data`, `clean` |
| `derive` | Split and dividend factors, total and price-only returns, delisting returns from the payouts file, multi-day markers | PRICE-04, PRICE-05, RET-01–RET-05 | `data` |
| `eda` | The exploratory report, following the `data-analysis` skill's method | EDA-01–EDA-03 | `data` |
| `publish` | Staging, deterministic fingerprint, atomic rename, registry update | BUILD-04, BUILD-06, LOAD-03, QR-04 | `data` |
| `runs` | Run lock, `RunEvent` log, spawning and cancelling runs, run history | BUILD-01, BUILD-02, BUILD-07, BUILD-09, RUN-02–RUN-07 (build side) | `data` |
| `cli` | `qlab build`, `qlab update`, `qlab rebuild`, `qlab versions`, `qlab diff` | BUILD-09 | every component above |

**Skill routing:** `eda` runs the `data-analysis` skill's method (summary statistics, distributions and tails, missingness, correlation structure over rolling windows, stability over time) on each version; the tasks that build it load that skill. No S1 component makes a beat-chance claim, so `null-hypothesis-testing` has no home here yet.

## Interfaces
See [contract.md](contract.md). Consumes [data's contract](../data/contract.md): the shared types and schemas, `data.trading_days`, `data.resolve_version`, `data.diff_versions`.

## Data
- **Sources:** Sharadar (AD-03) and EODHD (AD-04). Hand-checked inputs in the repo's `reference/`: known corporate actions (VAL-07), known delisted members (DATA-02), delisting payouts (AD-07).
- **Writes:** everything under `QLAB_HOME` in the layout [data](../data/architecture.md) defines; tables validated against `data`'s schemas before publishing.
- **Flow:** sources → snapshots → clean → validate (rows) → derive → validate (dataset) → eda → publish (AD-14).
- **Updates:** last 30 trading days of prices plus full small tables; a full refresh re-downloads everything (AD-08).

## Cross-cutting concerns
- **Determinism:** no wall-clock time or randomness inside tables; stable sorts; rounded floats (AD-09). A test rebuilds from the same snapshots twice and compares fingerprints.
- **Progress:** each step emits `RunEvent`s through a progress callback `runs` passes in; components don't import `runs`.
- **Failure:** a step error aborts the run, deletes staging and leaves the registry untouched (BUILD-06).
- **Secrets:** API keys come from the environment and are never written to snapshots, events or logs.

## Project layout

```
packages/build/src/qlab_build/<component>/   → one folder per component; __init__ exports its contract
packages/build/tests/                         → folders only; files are planned in pipelines.md
```
