# Idea: Features and ML information tests

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [../brief.md](../brief.md)

## In one sentence
This adds candidate price-and-volume features and machine-learning tests so that the researcher can find out, honestly, whether any feature carries information about future residual returns beyond chance.

## The problem
Feature research is where quant work most often fools itself: features computed with future data, targets that overlap so samples look independent when they aren't, and dozens of features or models tried with only the winners reported. Without a gate every claim must pass, a "signal" may be nothing but the number of things tried.

## Who it's for
The researcher, once S2's residual returns exist.

## How it fits
- **Serves:** Goal 5 (find out honestly whether any signal holds up), Goal 3 (reproduce any result), Goal 1 (point-in-time data)
- **Touches:** S2's return structure (STRUC-02, STRUC-03) for removing the market and dominant factors; CMP-02's testing rule; S1's loader (LOAD-01–LOAD-06). The spec's Out of scope line on return prediction and signal research narrows to S2's portfolios
- **Brief changes:** None
- **Stage:** new S3, built after S2's M3

## Recommended direction
**Testing machinery first.** Before any feature exists, the stage builds the gate every claim passes through: walk-forward splits with a gap between training and testing that covers the target's horizon (purging and an embargo), a feature ledger recording every feature and model ever tested, and a holdout lock on the last three years that opens once, at the end, to confirm what survived.

**The target** is each stock's forward residual return over the next 21 trading days (5 days as a variant): its return minus the part explained by the market and dominant factors, with factor loadings estimated on the trailing window only and applied to the future period, never refit with future data.

**Features** come from prices and volume only, each computed from data known on its date: momentum (12-1 month), short-term reversal, volatility, idiosyncratic volatility, beta, maximum daily return, illiquidity (price impact per dollar traded) and turnover.

**Two levels of claim.** Per feature: does it predict residual returns out of sample beyond chance, measured by rank correlation and mutual information against a null that shuffles the feature across stocks within each date. Per model: does a model using the features beat a no-information baseline and the linear model out of sample. Models start with a regularised linear model written by hand, then gradient-boosted trees from an established library. Monthly cross-sectional regressions of residual returns on features are the transparent baseline every result must beat.

Every claim is tested with the `null-hypothesis-testing` skill, with the multiple-testing correction counted over the whole ledger, not only the reported features. Descriptive work on real data (feature distributions, coverage, correlations between features, stability over time) uses the `data-analysis` skill. Output is command-line reports and research code, as in S2.

## Data
S1's point-in-time dataset (daily total returns with delisting returns, volume, S&P 500 membership as of each date) and S2's per-window factor structure. About 20 years of monthly cross-sections of ~500 stocks; the last three years are the holdout. Evaluation is walk-forward with purging and an embargo; the baseline is no information (a zero forecast) and, for models, the regularised linear model.

## Alternatives considered
- Model first, rank by importance — importance scores computed in sample carry no null and are biased; the classic route to false discoveries
- Linear regressions only — kept as the baseline, but the question includes non-linear information
- Judging features by a long-short portfolio — return-based trading, better as a later stage
- Automated model search or a feature store — more searching means more false positives

## What success looks like
- On planted synthetic features, a planted signal is found and pure noise isn't, at the stated error rates
- The ledger shows every feature and model ever tested, and the reported correction covers all of them
- A report on real data states, per feature and per model, supported or not significant, with the holdout result for each survivor

## What we're betting on
- 15–20 years of monthly cross-sections leave enough independent periods after purging to detect a real effect
- Price-and-volume features are a meaningful first test before fundamentals

## Not doing
- Fundamentals, news or alternative data — out of scope for the project
- Trading strategies or portfolios built from the features — a later stage
- Deep learning — linear and tree models first
- Tuning on the holdout — it opens once

## Open questions
- What a feature must show to count as a survivor: the per-feature test alone, or also stability across sub-periods?
- How the holdout result is reported when a feature passed walk-forward but fails the holdout
- Hyperparameter search budget for the tree models, and whether each configuration tried enters the ledger
