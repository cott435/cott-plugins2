The spec is **Approved**, and the idea file is frozen as **Specced**, with its open questions marked resolved. (The roadmap shows S3 as "Designed" for the same misleading reason as S2 did; it corrects itself once S3's own pipelines exist.)

**The Grow check fires a third time.** AD-12 said "stay single through S2, revisit when a third environment's stage is cut", and that's now. After this round the package would hold 3 environments plus the corridor, 6 agent types, self-play and cross-play, and a contract of about 600 lines (the ceiling is 200).

**The question:** split into packages now, or stay single through S3?
- **My recommendation: stay single through S3** and revise AD-12 again.
  - Build agents only ever read per-task context packets, and those stay well under their 2,000-line limit.
  - The import-linter layers already enforce the seams: environments never import agents, and only `dqn` and `pg` import PyTorch.
  - A split costs a workspace, per-package quality bars and multi-package pipelines on every milestone after this, for one learner.
- **The honest counterpoint:** the cheapest moment to split is before any code exists, which is now. If you expect a fourth environment, splitting into `gridlab-envs`, `gridlab-agents` and `gridlab-lab` now avoids moving code later.

If you stay single, here's the design I'll write, so you can veto it in the same answer:
- **`forage` (new environment component):** reuses `tank`'s geometry (moves, wall clamping, ray casting) and adds pellets, teams and catches. It depends on `tank` for geometry only, the same way `baselines` depends on `snake` for the feature layout. It gets a `set_state` test hook (AD-11).
- **`selfplay` (new component):**
  - a `TeamAgent` that routes rows by team label to two policies, each a PPO learner, a scripted baseline or a frozen snapshot;
  - the four schedules, as a setting that decides which side updates;
  - snapshots written into the run folder every 50,000 steps;
  - the opponent pool.

  It sits beside the agents and depends on `core`, `pg` and `baselines`. `core` itself stays unchanged.
- **`xplay` (new lab component):** reference curves, the cross-play matrix and the forgetting score. It reads snapshots through `runstore`, hands its comparisons to `compare` (the skill), and its heatmap to `plots`.
- **Smaller changes:**
  - `baselines` gains the chaser predator, and the flee fish's foraging mode;
  - `evaluate` scores a named side against a named fixed opponent (EVAL-05), and `RunConfig` gains a `side` setting;
  - the viewer gets team colours and pellets;
  - new presets for each schedule.
- **Decisions:**
  - AD-12 revised to extend through S3;
  - a new decision for the self-play design (routing by team label, schedules as a setting, snapshots in the run folder);
  - a new decision for the forgetting score and cross-play measurement.

Stay single through S3, with that design? **(yes / split)**
