# RL Lab — Architecture

**Status:** Approved · **Shape:** Single package · **Last updated:** 2026-10-18 · **Spec:** [spec.md](spec.md)

## Overview
One Python package, `rllab`, run from the command line. A training run builds a Snake environment and one learner (from the registry), plays games from seeds derived from the run seed, and feeds every move to the learner. At each of 20 curve points it pauses training to play the 100 reserved test games greedily, then writes the point to the run's folder. When the run finishes it saves the agent and its test games and marks the run's status last. Comparisons read only complete runs and hand the per-game scores to the `null-hypothesis-testing` skill. The replay viewer rebuilds any saved game by stepping the environment through its saved moves. Training, testing, storage and replay see only the `core` protocols, so a second environment plugs in through `Env` (AD-04).

- **Alternatives:** A fixed Welch t-test in code: replaces the procedure the skill owns. Explanations stored in run folders: they belong to comparisons, not runs.
- **Consequences:** The test can change without touching the report. A comparison waits until both sides have 5 complete runs (EVAL-04).

### AD-09: Learning curves as Matplotlib PNGs following the dataviz skill

### AD-10: Every run saves its learner's full settings
**Status:** Accepted · **Date:** 2026-10-18 · **Scope:** system
- **Context:** RUN-03 reruns a run from its saved settings, and AD-03 refuses a ladder pair whose saved settings differ beyond the added piece (DQN-05, SHAPE-05). Pipeline design found that nothing filled a learner's defaults before `store.begin_run` writes `settings.json`, so a run using defaults would save an incomplete `params`. UR-37: "Go ahead with the five contract changes."
- **Decision:** `registry.default_params(learner)` returns every setting of a learner, flattened. `cli.main` merges the user's overrides into it before `train.train_run`, so `RunSettings.params` is always complete; `registry.make_agent` rejects missing keys.
- **Alternatives:** `make_agent` fills defaults and `StagedRun.finish` rewrites `settings.json` from `Learner.settings()`: a crash before finish leaves the run's settings incomplete. Defaults hard-coded in `cli`: they'd drift from the learners'.
- **Consequences:** a changed default never changes what an old run's folder says it used; the four `dqn-*` defaults differ only in `rung`.
- **Probe:** none — no external API.

## Risks and open questions
- One CPU thread might not fit a DQN run plus 20 × 100 test games inside 60 minutes (QR-01). Mitigation: the first DQN task times 10,000 moves and one round of test games, and the step budget is set from that. Test games can be batched per move if needed.
- The table learner sees at most 2^11 situations but only a few hundred occur; it may plateau well below the scripted bot. That is a result to explain (EVAL-06), not a defect.
- Determinism (RUN-03) holds only on the same laptop and library versions. `settings.json` records them, and the rerun check compares like with like.
