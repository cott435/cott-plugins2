# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-18 · **Brief:** [brief.md](brief.md)

## Summary
A lab of three small 2D worlds (Snake, a fish tank, and predator & prey in that tank), each with a learning method written by hand. Every agent is checked against a hand-written player and a trusted reference implementation of the same method, on games it never trained on. Every run is saved with its settings, learning curve and trained agent, so it can be replayed and compared. Why: see the [brief](brief.md).

## Users
| User | What they need to do |
|---|---|
| Me (the learner) | Train an agent in a world, check whether it really learned, watch it play next to its learning curve, and compare runs to see what a change did |

## Scope
**In scope:** Snake world, value learner, fair evaluation, run log, replays (S1); fish tank world, policy learner (S2); predator & prey world, both sides learning at once, training against past opponents (S3).

**Out of scope:**
- Learning from screen pixels. Agents get positions and distances.
- Evolving populations of agents.
- 3D worlds or physics engines.
- A public demo or web app. Replays are for me.
- Fish competing in the tank. They share one brain, and competition waits for predator and prey.
- A ladder of learning methods on Snake (an optional detour with no stage yet).
- Rented computing beyond the limit in QR-02.

## Features

### Snake world (`SNAKE`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Classic Snake on a grid. The snake moves one cell per step, eats food to grow, and dies when it hits a wall or itself. The agent sees positions and distances, never the screen.

**Requirements**
- **SNAKE-01** The world is a 12 × 12 grid bounded by walls.
  - Given a new game, when it starts, then the grid is 12 × 12 cells and the snake is 3 cells long.
- **SNAKE-02** Exactly one piece of food is on the grid at a time, on a cell the snake does not occupy.
  - Given a game in progress, when any step ends, then exactly 1 food is on the grid and it is not under the snake.
- **SNAKE-03** Eating food grows the snake by one cell.
  - Given the snake's head moves onto the food, when the step ends, then the snake is 1 cell longer and new food has appeared on a free cell.
- **SNAKE-04** Each step the agent picks one of three moves: turn left, go straight, or turn right.
  - Given any game state, when the agent asks for its allowed moves, then it gets exactly these 3.
- **SNAKE-05** The game ends when the head hits a wall or the snake's own body.
  - Given the head moves into a wall or a body cell, when the step ends, then the game is over and no further moves are accepted.
- **SNAKE-06** The game ends after 200 moves in a row without eating.
  - Given the snake has made 200 moves since it last ate, when the 200th move ends without food, then the game is over.
- **SNAKE-07** A game's score is the number of food pieces eaten.
  - Given a game that ended after eating 7 food, when its score is read, then it is 7.
- **SNAKE-08** The agent observes the food's position and the nearby walls and body relative to its head, never a picture of the grid.
  - Given any game state, when the agent's observation is read, then it holds only positions, directions and distances.
- **SNAKE-09** A game is fully set by its seed.
  - Given two games with the same seed and the same moves, when both are played, then every food position and the final score match.
- **SNAKE-10** A hand-written "head toward the food" player is available. Each step it picks the move that most shortens the distance to the food, among moves that don't end the game on that step. If no move is safe, it goes straight.
  - Given food to the left and the left cell free, when the player moves, then it turns left.
  - Given the only move toward the food would hit the body, when the player moves, then it picks a safe move instead.

**Edge cases & errors**
- The snake fills every cell → the game ends with the top score of 141, recorded as a full board.
- The agent sends a move that isn't one of the three → it's rejected with an error naming the allowed moves, and the game state doesn't change.

### Value learner (`VALUE`)
**Serves:** Goal 1, Goal 3
**Stage:** S1
**Behavior:** I write a method that learns the value of each move from Snake experience. A reference implementation of the same method trains on the same world as an answer key.

**Requirements**
- **VALUE-01** The value learner is written from basic array and gradient operations and never calls the reference implementation.
  - Given the reference implementation is not installed, when the value learner trains on Snake, then the run completes.
- **VALUE-02** A reference implementation of the same method trains on the same Snake world, with the same time budget and matching settings.
  - Given a value-learner run, when its reference run is started, then both use the same world settings and time budget, and the run log shows the settings side by side.
- **VALUE-03** The trained Snake agent clearly beats the head-toward-food player (EVAL-03).
  - Given a trained value learner, when it is evaluated, then the EVAL-03 verdict against SNAKE-10's player is "pass".
- **VALUE-04** The value learner comes close to the reference (EVAL-04).
  - Given trained value-learner and reference runs, when both are evaluated, then the EVAL-04 verdict is "pass".

**Edge cases & errors**
- The value learner's estimates become infinite or not-a-number → the run stops, is marked "diverged" at the step it happened, and keeps its curve up to that step.

### Fair evaluation (`EVAL`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** Each trained agent, the world's hand-written player, and the reference (if there is one) play the same 200 games, none of which any of them trained on. The checks give each comparison a pass or fail, so I know whether a result is real learning or luck.

**Requirements**
- **EVAL-01** An evaluation plays 200 games with fresh seeds for each player being compared.
  - Given an agent, the hand-written player and the reference, when they are evaluated, then each plays the same 200 seeds.
- **EVAL-02** An evaluation reports each player's mean score and spread.
  - Given a finished evaluation, when its report is read, then it shows the mean, the standard deviation and the per-game scores for every player.
- **EVAL-03** "Clearly beats" is tested with the `null-hypothesis-testing` skill. It is given the paired per-game scores of the agent and the hand-written player on the same 200 unseen games. It passes only if the agent's mean is ≥ 1.5× the hand-written player's and the difference is significant at 5%.
  - Given agent mean 12.0 and player mean 7.0, significant at 5%, when checked, then the verdict is "pass".
  - Given agent mean 10.0 and player mean 7.0 (below 1.5×), when checked, then the verdict is "fail", whatever the significance.
- **EVAL-04** "Close to the library" passes only if the hand-written learner's mean score is ≥ 90% of the reference's on the same 200 unseen games, both trained with the same time budget.
  - Given hand-written mean 9.2 and reference mean 10.0, when checked, then the verdict is "pass" (92%).
  - Given hand-written mean 8.5 and reference mean 10.0, when checked, then the verdict is "fail" (85%).
- **EVAL-05** Each verdict is saved with the run it judges, along with the numbers behind it.
  - Given a judged run, when it is opened later, then its verdicts, means, ratio and significance are shown.

**Edge cases & errors**
- The hand-written player's mean is 0 → the 1.5× ratio is undefined. The verdict rests on significance alone, and the report says so.
- An evaluation seed was also used in training → the evaluation refuses to run and names the overlapping seeds.

### Run log (`RUNS`)
**Serves:** Goal 4, Goal 5
**Stage:** S1
**Behavior:** Every training run is saved with everything needed to understand, repeat or compare it. I can list runs, open one, and put several side by side.

**Requirements**
- **RUNS-01** Every run is saved with its world, its learner, all its settings, its seed, the code version, its start time and its duration.
  - Given a finished run, when it is opened, then all of these are shown.
- **RUNS-02** Every run records a learning curve: the score against training steps, with at least 100 points across the run.
  - Given a finished run, when its curve is read, then it has ≥ 100 points from start to end.
- **RUNS-03** Every run records the learner's internal signals over training: value estimates, loss, how much it explores, and how random its choices are (whichever the method has).
  - Given a value-learner run, when its signals are opened, then value estimates, loss and exploration rate are shown against training steps.
- **RUNS-04** A run on the laptop with the same settings and seed reproduces the same learning curve.
  - Given two laptop runs with the same settings and seed, when their curves are compared, then every point matches.
- **RUNS-05** Every run saves the trained agent at its end, and at regular points during training.
  - Given a finished run, when its saved agents are listed, then the final one and the in-training ones are there, each labelled with its training step.
- **RUNS-06** The run list shows every saved run with its world, learner, date, final score and verdicts.
  - Given 3 saved runs, when the list is opened, then all 3 appear with those fields.
- **RUNS-07** Two or more runs can be compared: the settings that differ, and their learning curves on one chart.
  - Given two runs that differ only in learning rate, when they are compared, then the learning rate is the only setting listed as different and both curves share one chart.
- **RUNS-08** Learning-curve and comparison charts are drawn with the `dataviz` skill. Each shows the hand-written player's and the reference's evaluation scores as reference lines.
  - Given a judged Snake run, when its curve is opened, then lines mark the head-toward-food player's mean and the reference's mean.
- **RUNS-09** A run stops at its time limit and is marked as having hit it.
  - Given a run with a 60-minute limit, when 60 minutes pass, then training stops, the agent at that point is saved and the run is marked "time limit reached".

**Edge cases & errors**
- A run is interrupted (crash, laptop closed) → it is kept, marked "incomplete", with its curve and last saved agent.
- Two runs are compared from different worlds → the comparison is refused with a message naming both worlds.

### Replays (`REPLAY`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** I pick any saved agent from any run and watch it play a fresh game, with the run's learning curve beside it so I can see what it had learned by then.

**Requirements**
- **REPLAY-01** Any saved agent, or a world's hand-written player, can be watched playing a game from a chosen or random seed.
  - Given a run with saved agents, when I choose one and a seed, then the game plays on screen.
- **REPLAY-02** Playback can be paused, stepped one frame at a time, and played at 0.25× to 4× speed.
  - Given a playing replay, when I pause and step, then it advances exactly 1 frame per step.
  - Given a playing replay, when I set 4×, then it plays 4 times faster than at 1×.
- **REPLAY-03** The run's learning curve is shown next to the replay, with a marker at the training step of the agent being watched.
  - Given a replay of the agent saved at step 50,000, when it plays, then the run's curve is beside it with a marker at step 50,000.
- **REPLAY-04** The current score and step count are shown during playback.
  - Given a Snake replay, when the snake eats, then the shown score goes up by 1 on that frame.
- **REPLAY-05** The same saved agent and seed always play the same game.
  - Given one agent and one seed watched twice, when both replays end, then every frame and the final score match.

**Edge cases & errors**
- The saved agent is missing or unreadable → an error names the run and the step, and nothing plays.

### Fish tank world (`TANK`)
**Serves:** Goal 2, Goal 3
**Stage:** S2
**Behavior:** A ball bounces around inside a circular tank. 8 fish move smoothly and see only what's within a quarter of the tank's radius. A fish the ball touches is out. All fish share one brain and try to survive as long as possible.

**Requirements**
- **TANK-01** The tank is a circle, and nothing leaves it.
  - Given any fish or the ball at the tank wall, when it moves outward, then it stays inside the circle.
- **TANK-02** One ball moves in a straight line at constant speed and bounces off the tank wall at the same angle it arrived.
  - Given the ball hits the wall, when the step ends, then its speed is unchanged and its angle out equals its angle in.
- **TANK-03** Each episode starts with 8 fish at random positions, each at least a quarter of the tank's radius from the ball.
  - Given a new episode, when it starts, then there are 8 fish and none is within a quarter-radius of the ball.
- **TANK-04** Fish move continuously. Each step, each fish picks a turn and a speed within set limits, and its top speed is 80% of the ball's.
  - Given a fish asking for more than its top speed, when the step ends, then it moved at its top speed.
- **TANK-05** Each fish sees only the ball, the wall and other fish within a quarter of the tank's radius, as positions and distances relative to itself.
  - Given the ball just beyond a quarter-radius from a fish, when that fish's observation is read, then the ball is absent.
  - Given the ball inside that range, when that fish's observation is read, then the ball's relative position is present.
- **TANK-06** A fish the ball touches is caught and leaves the tank.
  - Given the ball touches a fish, when the step ends, then that fish is gone and its survival time is recorded.
- **TANK-07** An episode ends when all fish are caught or after 60 seconds of tank time.
  - Given 3 fish still alive at 60 seconds of tank time, when that step ends, then the episode is over and each survivor is recorded at 60 seconds.
- **TANK-08** An episode's score is the fish's mean survival time.
  - Given fish surviving 10, 20, …, 80 seconds (capped at 60), when scored, then the score is their mean.
- **TANK-09** All fish share one brain. One learned policy acts for every fish from that fish's own view, and every fish's experience trains it.
  - Given two fish with identical views, when they act, then they get the same choice from the policy (before any randomness).
- **TANK-10** Fish don't affect each other. They can overlap, and no fish changes another's score.
  - Given two fish in the same spot, when the step ends, then both are unaffected.
- **TANK-11** A hand-written "swim straight away" player is available. While a fish sees the ball, it swims at top speed directly away from it. Otherwise it keeps its last heading, and at the wall it slides along it.
  - Given the ball visible to the east of a fish, when the player moves it, then it swims west at top speed.
- **TANK-12** Trained fish clearly beat swim-straight-away fish on mean survival time (EVAL-03).
  - Given a trained policy, when evaluated, then the EVAL-03 verdict against TANK-11's player is "pass".
- **TANK-13** In replays, each fish shows its sight range as a circle.
  - Given a fish tank replay, when it plays, then every live fish has a circle of a quarter-radius drawn around it.

**Edge cases & errors**
- The ball touches two fish in one step → both are caught at the same time.
- A fish sees nothing → its observation says so explicitly instead of holding stale values.

### Policy learner (`POLICY`)
**Serves:** Goal 1, Goal 3
**Stage:** S2
**Behavior:** I write a method that learns a policy directly, choosing smooth turns and speeds for the fish. A reference implementation of the same method trains on the same tank as an answer key.

**Requirements**
- **POLICY-01** The policy learner is written from basic array and gradient operations, chooses continuous turns and speeds, and never calls the reference implementation.
  - Given the reference implementation is not installed, when the policy learner trains on the tank, then the run completes.
- **POLICY-02** A reference implementation of the same method trains on the same tank, with the same time budget and matching settings.
  - Given a policy-learner run, when its reference run is started, then both use the same world settings and time budget.
- **POLICY-03** The policy learner comes close to the reference on mean survival time (EVAL-04).
  - Given trained policy-learner and reference runs, when both are evaluated, then the EVAL-04 verdict is "pass".

**Edge cases & errors**
- The policy collapses to nearly fixed choices early in training → the run's randomness signal (RUNS-03) shows it, and the run continues unless it diverges.
- The policy learner diverges → as VALUE's divergence edge case.

### Predator & prey world (`PREY`)
**Serves:** Goal 2, Goal 3
**Stage:** S3
**Behavior:** The fish tank, with no ball. 6 prey eat food pellets while 1 predator hunts them. Both sides see only nearby things.

**Requirements**
- **PREY-01** The world is the fish tank (TANK-01, TANK-04, TANK-05, TANK-10) with no ball, and with the predator and pellets added.
  - Given a new predator & prey episode, when it starts, then the tank is the same circle with no ball.
- **PREY-02** Each episode has 1 predator and 6 prey at random starting positions, with the predator at least a quarter-radius from every prey.
  - Given a new episode, when it starts, then there is 1 predator and there are 6 prey.
- **PREY-03** 10 food pellets are in the tank at all times. A pellet a prey touches is eaten and reappears at a random spot.
  - Given a prey touches a pellet, when the step ends, then the prey's eaten count rises by 1 and 10 pellets are still in the tank.
- **PREY-04** A prey the predator touches is caught and leaves the tank.
  - Given the predator touches a prey, when the step ends, then that prey is gone and the predator's catch count rises by 1.
- **PREY-05** The predator and each prey see only the predator, prey, pellets and wall within a quarter of the tank's radius.
  - Given a pellet just beyond a quarter-radius from a prey, when that prey's observation is read, then the pellet is absent.
- **PREY-06** The predator's score is prey caught. The prey's score is pellets eaten, minus a set penalty for each prey caught. The penalty is a run setting.
  - Given 12 pellets eaten, 2 prey caught and a penalty of 5, when scored, then the prey score is 2 and the predator score is 2.
- **PREY-07** An episode ends when all prey are caught or after 60 seconds of tank time.
  - Given 6 prey caught at 40 seconds, when that step ends, then the episode is over.
- **PREY-08** All prey share one brain, and the predator has its own.
  - Given two prey with identical views, when they act, then they get the same choice (before any randomness).
- **PREY-09** A hand-written predator is available. It heads for the nearest prey it sees. Otherwise it swims straight and turns at the wall.
  - Given one prey visible to the north, when the hand-written predator moves, then it heads north.
- **PREY-10** Hand-written prey are available. Each one flees the predator when it sees it, else heads for the nearest pellet it sees, else keeps its heading.
  - Given the predator visible to the east and a pellet to the west, when a hand-written prey moves, then it heads west.
- **PREY-11** Against hand-written prey, the trained predator clearly beats the hand-written predator on catches (EVAL-03).
  - Given a trained predator, when both predators are evaluated against hand-written prey, then the EVAL-03 verdict is "pass".
- **PREY-12** Against the hand-written predator, trained prey score higher than hand-written prey, tested with the `null-hypothesis-testing` skill on paired scores from 200 unseen episodes. It passes only if the difference is significant at 5%.

### Both sides learning at once (`COEVO`)
**Serves:** Goal 1, Goal 2
**Stage:** S3
**Behavior:** The predator and prey learn in the same run, each against the other's current version. Saved versions of both sides then play each other, so I can see the two sides chasing each other in circles.

**Requirements**
- **COEVO-01** In "both at once" mode, the default, the predator and prey both update during the same run, each playing the other's current version.

- **COEVO-03** A cross-play chart shows every saved predator against every saved prey. Each cell is the catch rate over 20 unseen episodes. It is drawn with the `dataviz` skill.

- **COEVO-04** Circling is tested with the `null-hypothesis-testing` skill on the cross-play results.   - Given the newest predator catching 70% of recent prey and 30% of older prey, significant at 5%, when checked, then the report says "circling found".
- **COEVO-05** At each save point, the latest predator plays the latest prey for 20 unseen episodes. The run reports the swing: the highest catch rate minus the lowest across the last half of training.
  - Given catch rates between 0.2 and 0.8 over the last half, when the swing is read, then it is 0.6.

**Edge cases & errors**
- One side stops scoring entirely (catch rate stuck at 0 or 1) → the run continues and the report flags "one side dominates" with the step it began.

### Training against past opponents (`POOL`)
**Serves:** Goal 1, Goal 2
**Stage:** S3
**Behavior:** Once I've seen the circling, I switch a run to "past opponents". Each side then trains against frozen copies of the other side's earlier versions. That should settle the chase.

**Requirements**
- **POOL-01** In "past opponents" mode, each side trains against frozen past versions of the other side, never only its current version.
  - Given a past-opponents run, when an episode is played, then the opponent is a frozen saved version.
- **POOL-02** A frozen copy of each side joins its pool at a set interval, and each pool holds up to 20 copies. When a pool is full, the oldest copy is dropped.
  - Given a full pool of 20, when a new copy joins, then the pool still holds 20 and the oldest is gone.
- **POOL-03** Each episode's opponent is drawn at random, with equal chance, from the other side's pool.
  - Given a pool of 10 copies over 10,000 episodes, when opponent picks are counted, then each copy was picked about equally often (no copy outside 800–1,200).
- **POOL-04** A past-opponents run can start fresh, or continue from a saved both-at-once run's final versions and saved copies.
  - Given a finished both-at-once run, when a past-opponents run is started from it, then both pools begin with that run's saved versions.
- **POOL-05** Settling is tested with the `null-hypothesis-testing` skill. It compares this run's swing (COEVO-05) with a both-at-once run of the same world settings and length. It passes only if the swing is ≤ half the both-at-once run's swing, significant at 5%.
  - Given a both-at-once swing of 0.6 and a past-opponents swing of 0.2, significant at 5%, when checked, then the report says "settled".

**Edge cases & errors**
- The pool is empty at the start of a fresh run → the first copy of each side is saved before the first episode, so there is always an opponent.

## Data requirements
- **DATA-01** All experience comes from the worlds themselves, and no outside data is used.
  - Given any run, when its inputs are listed, then they are only the world settings, the seed and the learner settings.
- **DATA-02** Evaluation seeds never overlap training seeds.

## Quality requirements
- **QR-01** Each world's main training run finishes within 1 hour (60 minutes) on the laptop's CPU.
  - Checked from the duration in the run log (RUNS-01) of the run each stage's verdicts come from.
- **QR-02** Rented computing costs ≤ $5 per world in total.
  - Checked against the bill for the stage. A world that would need more is a decision to bring back to me.

## Assumptions
1. Each learner is built from basic array and gradient operations. The reference implementation is only used to compare results.
2. Every run records the learner's internal signals over time, so I can work out why a run failed.
3. "Both at once" or "past opponents" is a setting on each run, and "both at once" is the default.
4. A frozen copy of each side is saved every so often, up to 20 copies, and each episode faces a randomly chosen one.
5. Rerunning with the same settings and seed on the laptop gives the same learning curve.
6. Each world trains in ≤ 60 minutes on the laptop CPU, rented computing is capped at $5 per world, and no outside data is used.
