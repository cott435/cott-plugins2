## Overview
`data` downloads Sharadar, FRED and SEC data into an immutable, bitemporal snapshot store, validates each snapshot and promotes it, and serves every later stage one point-in-time view. `engine` is the shared method every stage is scored with: the walk-forward schedule and look-ahead guard, the hypothesis ledger, the backtest and the portfolio constraints. `lab` holds the S2–S3 research (factors, denoising, covariance ranking, classical portfolios, features, significance) and the final verdict. `models` holds the torch-based S4 work: forecasters, forecast-driven portfolios and PPO agents, trained on the laptop or on a rented GPU. `server` is a local-only HTTP API over `data` that the TypeScript `app` reads for the explorer and the live run monitor.

- **Default if you're unsure:** block. "Warn" would let agents finish with a red gate, and with 27 spines running in parallel in wave 1, that would pile up failures for the checkpoint.
