## What changed
**New package `features`** (`docs/packages/features/architecture.md` and `contract.md`). It depends on `portfolio` and `data` and has 8 modules:

| Module | What it covers |
|---|---|
| `ledger` | The hash chain, checked at every start, and Holm over all walk-forward entries |
| `gate` | Splits with purge and embargo; the holdout fixed at creation; the only path to targets, refusing holdout dates until opened |
| `target` | Forward residual returns, with loadings from the trailing window via `portfolio.analyse_structure` |
| `featureset` | The 8 features, the coverage rule, and ranking |
| `screen` | Rank correlation and k-NN mutual information against the within-date shuffle null, per `null-hypothesis-testing`; sub-period signs; verdicts; the holdout test |
| `models` | Hand-written ridge, the LightGBM grid, inner validation, scores, paired claims, the holdout test |
| `reports` | The three reports, written with `data-analysis` and charted with `dataviz` |
| `cli` | `study`, `screen`, `models`, and `open-holdout`, which asks for confirmation |

Its contract has 14 symbols, including `StudySpec`, `CrossSections`, `Targets`, `Split`, `LedgerEntry`, `Ledger`, `open_ledger`, `open_holdout`, `FeatureVerdict`, `ModelResult` and `StudyResult`.

**Root architecture:**
- **System map:** the overview, diagram, package table and project layout now include `features`.
- **New system pipeline, PL-17: Feature research.** `features` gets windows and factor structure from `portfolio`, plus one `data` load per run for raw closes and volume.
- **Tech stack:** gained LightGBM 4.5, and scikit-learn 1.5 for tests only.
- **New risk:** after purging, the holdout and 5 training years, S3 has roughly 10 to 12 test years. Small real effects may not survive Holm over a growing ledger. The reports state the test's power, and that outcome counts as honest.

**New decisions (Proposed):**
- **AD-22:** the `features` package, and why it reuses `portfolio`'s factor structure rather than copying it.
- **AD-23:** NumPy ridge; LightGBM made deterministic (single thread, fixed seeds, pinned version); scikit-learn only as the test reference for MODEL-01.
- **AD-24:** k-NN mutual information (k = 3) with a seeded tie-break, written by hand.
- **AD-25:** the ledger at `research/features/ledger/<fingerprint>.jsonl`.
  - Entry 0 fixes the holdout, and each entry stores the SHA-256 of the one before.
  - The gate is the only path to targets and refuses holdout dates until an opening entry exists. A second opening is refused.
  - A new dataset version starts a new ledger.

**Accepted decisions revised in place:**
- **AD-18** is now a rule: *research packages import `data` and earlier research packages only through their contracts, never a later one; `data`, `builder` and `server` never import a research package.* The members (`portfolio`, `features`) are listed under Packages.
- **AD-21** is now a rule for every research package: runs go in `research/<package>/<run-id>/`.

**`portfolio` gains public steps for `features`:** `load_returns`, `build_windows` and `analyse_structure` become public, with Boundary lines and named fixture cases. So do the `Returns`, `Window` and `Structure` types. Changing any of them is now a contract change for both packages.

**`data`'s architecture:** its description of the data folder now includes `research/features/` and the ledger.

## Assumptions
- **Names:** `qlab_features`, `qlab-features`, and the feature names `momentum`, `reversal`, `volatility`, `idio_vol`, `beta`, `max_return`, `illiquidity` and `abnormal_volume`.
- **Data loads:** `features` loads returns through `portfolio.load_returns`, plus one `data.Loader.panel` call for raw closes and volume. That's two loader calls per run, both point in time (DATA-09).
- **Run IDs:** a run ID includes the ledger size, so a report is tied to the ledger state it was corrected against.
