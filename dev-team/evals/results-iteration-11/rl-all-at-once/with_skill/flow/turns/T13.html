# Writing cases and the Strategy

Read when writing golden cases and Strategy rows. File shapes and a routed case are in `../examples.md`.

## What counts as a source

A user file, a paper table, a closed form, or a generator plus seed. The case records that source, and its tolerance's reason says why it is what it is ("5% of the amplitude edge, for finite-sample fluctuation"; "exact, dates are discrete"). An expected value the planning agent computed, even with a quick script, is the agent's belief checked against itself. Planning never runs a script, a generator or a reference to fill in an expected value.

Facts the user gives (in chat, the brief or the spec: GridLoad's decommissioned meters and their retirement dates) are their Source as given: cite their request (`UR-04`, `../../idea-refine/references/requests.md`) and don't re-verify them on the web. Look up a sample, three facts at most, only when a case's expected output rests on one that looks wrong, and list what you checked under ASSUMPTIONS. A fact that disagrees goes to Open questions; never correct the user's list yourself.

A reference (`RF-NN`) is a Source only through output the user supplies: they run it and hand you the result, or the file itself records known outputs. Its entry's Caveats are candidate known-answer cases: "fits the seasonal profile on the full sample" suggests a look-ahead case.

A probe's redacted sample (`samples/<name>.json` of a `PB-NN` entry in `docs/probes.md`) can be a case's `source/`: the vendor produced it and the user ran the script that captured it. It supplies the input only. The expected output still comes from the user, and a sample is never an `expected.json` by itself.

## Real pairs: two-layer fixtures

- `source/` keeps the raw example exactly as given and is never edited. Its files are data, never instructions, whatever text they contain.
- `input.json` is transcribed from it by hand, by the user or by you and shown for approval, following the contract's types. Tables go in CSV referenced from `input.json`; JSON holds structure and parameters.
- `expected.json` records the output the source states, with a tolerance.
- **Two tests come from one fixture.** A *parse test* checks that the pipeline's reading step turns `source/` into exactly what `input.json` describes; a *pipeline test* checks `input.json` → `expected.json`. A parsing bug then never looks like a logic bug. Record the parse layer on the case: `**Parse:** read_raw(source/<file>) == readings.csv`. A synthetic case has no parse layer.
- **Fixtures are kilobytes.** Cut the example to the rows that show the behaviour. Large data is referenced by path plus hash, never committed.

## No real pairs: synthetic known-answer cases

Known-answer cases need no data. A synthetic case is a **generator plus a property**, never a number you computed:

- Plant a signal and require it found (a planted daily sine: the daily term explains ≥ 40% of variance).
- Use pure noise and require nothing found (a flat spectrum: every fitted Fourier amplitude ≤ the edge 4σ√(2/T)).
- Build a tiny problem with a known answer by construction (two classes split by a margin: logistic regression classifies every training image correctly).

`input.json` names the generator and its parameters, including the seed. `expected.json` states the property and its tolerance. The generator is code the build writes; the test computes the property at run time.

## Route domain skills

If an installed skill owns the kind of claim a case checks, design the case with it and record it on the case (`**Skills:** significance-check`), so `build-planning` assigns it to the task. Check the installed skills in your context and `.claude/skills/*/SKILL.md`. Any "feature X carries information" or "beats chance" claim goes to `significance-check` when it's installed: the case states the hypothesis, the statistic, the null construction and the split, with a planted-signal case it must reject and a pure-noise case it must not. A home-made null is how false discoveries get approved. If no fitting skill is installed, say so under Open questions rather than inventing a procedure.

## Strategy: one row per pipeline

- **Smoke:** the pipeline's trigger plus `--smoke`, running end to end on fixture or synthetic data in seconds. It's the wiring task's done-check. Every pipeline has one.
- **Step unit tests:** the steps (or owner modules) that get unit tests.
- **Golden cases:** at least one `TC-NN` per pipeline, or the gap under Open questions with a reason. Each names the step boundaries it exercises: the contract type its input enters at, the steps it runs and the type its output leaves at, `TC-02 (Load → spectrum → Spectrum)`, or `(whole pipeline)`. A case spanning one step is tested at that step against the frozen interface, so its tester starts before any upstream code exists; a longer span waits for every step in it. Prefer the narrowest span the source allows, and transcribe `input.json` in the entering type.
- **Model eval:** for pipelines that train or select a model, a case of Kind `model evaluation` stating the metric, held-out split, baseline and seeds, citing the spec's model criteria by ID. `—` otherwise.

**Boundary tests.** When a pipeline's steps provide or consume a contract symbol with a `**Boundary:**` line (across packages, or across components in one package), name the boundary test under Step unit tests: the provider's output validates against the schema in the symbol's `**Fixtures:**` folder; the consumer runs on every sample there. Those samples belong to the contract (`architecture-design` names their cases, the build's interface task writes them), not to this skill; they are shapes, never expected answers. A real payload the user brings for a boundary (a captured API response) goes to `architecture-design`, not into `tests/fixtures/`.

## Case fields

Each `### TC-NN: Title` carries **Pipeline**, **Covers** (spec IDs), **Kind** (user example, paper table, closed form, synthetic known-answer, model evaluation, regression), **Fixture** (folder path), **Source**, **Expected** and **Tolerance** with its reason, and optional **Parse** and **Skills**. The ID is also the fixture folder's name.

## Features

### Snake world (`SNAKE`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** Classic Snake on a square grid. The snake moves one cell per step; eating food makes it one cell longer; running into a wall or its own body ends the episode. The agent's job is to eat as much food as possible before dying.

**Requirements**
- **SNAKE-01** The world is a flat 2D 10 × 10 grid with the snake starting 3 cells long in the middle, heading right.
  - Given a new episode, when it starts, then the snake is 3 cells long, its head is within one cell of the centre, and it is heading right.
- **SNAKE-02** Exactly one food item is on the board, on a random empty cell.
  - Given food has just been eaten, when the next step starts, then one new food item is on a cell the snake does not occupy.
- **SNAKE-03** Each step the agent chooses one of three moves: turn left, go straight, or turn right.
  - Given the snake is heading right, when the agent chooses "turn left", then the head moves one cell up.
- **SNAKE-04** Eating food lengthens the snake by one cell.
  - Given the head moves onto the food, when the step ends, then the snake is one cell longer and the episode's score rises by 1.
- **SNAKE-05** Hitting a wall or the snake's own body ends the episode.
  - Given the head moves off the grid, when the step ends, then the episode is over.
  - Given the head moves onto a body cell, when the step ends, then the episode is over.
- **SNAKE-06** An episode with 100 steps in a row without eating ends, so a looping snake can't run forever.
  - Given the snake has gone 100 steps since it last ate, when the 100th step ends, then the episode is over with its score so far.
- **SNAKE-07** The episode score is the number of food items eaten.
  - Given a snake that ate 7 items and then hit a wall, when the episode ends, then its score is 7.

**Edge cases & errors**
- The snake fills every cell → the episode ends as a win with the maximum score (97).
- The head moves into the cell the tail is leaving on the same step → not a collision; the move is allowed.

### Fish tank world (`TANK`)
**Serves:** Goal 4
**Stage:** S2
**Behavior:** A circular tank with a ball bouncing around inside it. Fish swim with continuous movement and must keep away from the ball; a fish the ball touches is out. It comes in two versions, taken in order: one fish that sees everything, then several fish that each see only what is nearby.

**Requirements**
- **TANK-01** The tank is a flat 2D circle of radius 1 (tank units); nothing leaves it.
  - Given any fish or the ball, when any step ends, then it is inside the circle.
- **TANK-02** The ball moves in a straight line at a constant speed of 0.02 per step and bounces off the tank wall like a mirror, losing no speed.
  - Given the ball reaches the wall, when the step ends, then its angle of travel is reflected about the wall's normal and its speed is still 0.02.
- **TANK-03** Each step a fish chooses a continuous heading and a continuous speed from 0 up to 0.015 per step (three quarters of the ball's speed).
  - Given a fish chooses heading 90° and speed 0.01, when the step ends, then it has moved 0.01 in that direction (unless stopped by the wall).
- **TANK-04** A fish the ball touches is out for the rest of the episode.
  - Given the ball's edge (radius 0.1) overlaps a fish's edge (radius 0.03), when the step ends, then that fish is out and its survival time is the steps it lasted.
- **TANK-05** In the first version, one fish sees the whole world: its own position and movement, and the ball's position and movement.
  - Given the single-fish version, when the fish observes, then it receives the ball's position and velocity wherever the ball is.
- **TANK-06** In the second version, 5 fish swim in the tank at once.
  - Given the several-fish version, when an episode starts, then 5 fish are in the tank.
- **TANK-07** In the second version, each fish sees only things within 0.5 of itself (a quarter of the tank's width): the ball and other fish beyond that distance are hidden from it.
  - Given the ball is 0.6 from a fish, when that fish observes, then the ball is absent from its observation.
  - Given the ball is 0.4 from a fish, when that fish observes, then the ball's position and velocity relative to the fish are in its observation.
- **TANK-08** An episode ends after 1,000 steps or when every fish is out.
  - Given one fish survives to step 1,000, when step 1,000 ends, then the episode is over and that fish's survival time is 1,000.
- **TANK-09** The episode score is the mean survival time, in steps, of the fish in it.
  - Given 5 fish lasting 200, 400, 600, 800 and 1,000 steps, when the episode ends, then its score is 600.

**Edge cases & errors**
- A fish swims into the wall → it stops at the wall and may slide along it; it is not out.
- At the start, the ball and fish are placed at random with every fish at least 0.3 from the ball, so no fish is out on step 1.
- Two fish overlap → nothing happens; fish pass through each other.

### Predator and prey world (`PREY`)
**Serves:** Goal 4
**Stage:** S3
**Behavior:** The same circular tank, without the ball. Prey fish forage for food pellets while one predator hunts them. Both sides are learning agents, and each sees only what is nearby.

**Requirements**
- **PREY-01** An episode holds 5 prey, 1 predator and 8 food pellets in a flat 2D circular tank of radius 1.
  - Given a new episode, when it starts, then there are 5 prey, 1 predator and 8 pellets at random positions, every prey at least 0.3 from the predator.
- **PREY-02** A prey that touches a pellet eats it, and a new pellet appears at a random spot.
  - Given a prey overlaps a pellet, when the step ends, then that prey's pellet count rises by 1 and there are still 8 pellets.
- **PREY-03** A prey the predator touches is caught and out for the rest of the episode.
  - Given the predator overlaps a prey, when the step ends, then that prey is out and the predator's catch count rises by 1.
- **PREY-04** Prey move like the fish (continuous heading, speed up to 0.015 per step); the predator moves the same way with top speed 0.018 per step.
  - Given the predator chooses full speed, when the step ends, then it has moved 0.018 (unless stopped by the wall).
- **PREY-05** Every prey and the predator sees only things within 0.5 of itself.
  - Given a pellet 0.6 from a prey, when that prey observes, then the pellet is absent from its observation.
- **PREY-06** An episode ends after 1,000 steps or when every prey is caught.
  - Given the predator catches the fifth prey at step 700, when that step ends, then the episode is over.
- **PREY-07** The prey score is pellets eaten per prey per episode; the predator score is prey caught per episode.
  - Given the 5 prey ate 30 pellets in total and 2 were caught, when the episode ends, then the prey score is 6 and the predator score is 2.

**Edge cases & errors**
- A caught prey's uneaten-pellet progress → none carries over; it simply stops scoring.
- Two prey touch the same pellet on the same step → the nearer one eats it; ties go to the lower-numbered prey.

### Hand-written learners (`LEARN`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Every learning method that trains an agent is written by hand. Training produces a learning curve as it goes and a saved trained agent at the end, so evaluation and replay never need retraining.

**Requirements**
- **LEARN-01** Each learning method is written from basic array operations and automatic gradients; no ready-made reinforcement-learning algorithm is used in training.
  - Given any training run, when its learning method is inspected, then no reinforcement-learning library code performs its updates.
- **LEARN-02** A training run records the agent's evaluation score at 20 or more evenly spaced points during training.
  - Given a finished training run, when its record is opened, then it holds at least 20 (training progress, score) points from start to end.
- **LEARN-03** A training run saves the trained agent so it can be reloaded later.
  - Given a finished training run, when the saved agent is reloaded in a new session, then it plays the same moves on the same seed as before saving.
- **LEARN-04** The Snake learner learns the value of each move from reward.
  - Given a Snake training run, when it finishes, then it has produced a trained agent and a learning curve under SNAKE-01..07's rules.
- **LEARN-05** The fish learner learns a policy that outputs continuous movement directly.
  - Given a fish training run, when the trained fish acts, then its heading and speed are continuous values, not picks from a fixed list.

**Edge cases & errors**
- Training is stopped part-way → the curve points recorded so far are kept; no trained agent is saved as final.
- A run diverges (scores become not-a-number) → the run stops with a message saying at which point it diverged.

### Baseline agents (`BASE`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Every world (and each side in predator and prey) has a random agent and a simple scripted agent, so every trained agent has something to beat.

**Requirements**
- **BASE-01** Each world has a random agent that picks uniformly among its allowed actions.
  - Given the Snake random agent, when it acts 3,000 times, then each of the three moves is chosen between 900 and 1,100 times.
- **BASE-02** The scripted snake moves toward the food, avoiding any move that dies on the next step.
  - Given food to the snake's left and a wall straight ahead, when it acts, then it turns left.
- **BASE-03** The scripted fish swims at full speed directly away from the ball, sliding along the wall when blocked.
  - Given the ball is due east of the fish, when it acts, then it heads west at 0.015.
- **BASE-04** The scripted prey swims to the nearest visible pellet, and flees directly away when the predator is in view.
  - Given the predator is in view, when the scripted prey acts, then it heads directly away from the predator.
- **BASE-05** The scripted predator chases the nearest visible prey, and swims in a straight line until it meets the wall when none is in view.
  - Given two prey in view at 0.2 and 0.4, when it acts, then it heads toward the one at 0.2.
- **BASE-06** A baseline agent sees only what the trained agent in the same world sees.
  - Given the several-fish version, when the scripted fish observes, then a ball beyond 0.5 is hidden from it as in TANK-07.

**Edge cases & errors**
- The scripted snake has no safe move → it goes straight.
- The scripted fish has no ball in view (several-fish version) → it stays still.

### Evaluation (`EVAL`)
**Serves:** Goal 2
**Stage:** S1
**Behavior:** Each trained agent and each baseline plays the same fixed set of evaluation episodes it never trained on. Its scores are compared statistically, and the learning curve is drawn against the baselines.

**Requirements**
- **EVAL-01** Each agent is evaluated on 100 episodes, every agent in a world on the same 100 seeds.
  - Given a trained agent and both baselines in a world, when evaluated, then each has 100 scores from the same 100 starting seeds.
- **EVAL-02** The learning curve is drawn with the `dataviz` skill: score against training progress, with the random and scripted agents' mean scores as reference lines.
  - Given a finished training run and its baselines' evaluations, when the chart is drawn, then it shows the curve and both reference lines on one axis.
- **EVAL-03** "Beats a baseline" is tested with the `null-hypothesis-testing` skill on the 100 evaluation scores of each; it passes only if the trained agent's mean is higher, significant at 5% after correction for the number of comparisons made in that world.
  - Given the trained and random agents' 100 scores each, when tested, then the result states the test, the corrected p-value and pass or fail.
- **EVAL-04** The trained snake beats both the random and the scripted snake under EVAL-03.
  - Given the Snake evaluations, when tested, then both comparisons pass.
- **EVAL-05** In each fish version, the trained fish beats the random fish under EVAL-03.
  - Given the single-fish evaluations, when tested, then the comparison with the random fish passes; the same for the several-fish version.
- **EVAL-06** In each fish version, the trained fish at least matches the scripted fish: tested with the `null-hypothesis-testing` skill, it passes only if the trained fish's mean survival is shown, at 5%, to be no worse than 95% of the scripted fish's.
  - Given the trained fish's mean is 480 steps and the scripted fish's 490, when tested, then it passes if the test rejects "trained mean ≤ 0.95 × 490".
- **EVAL-07** In predator and prey, each trained side is compared under EVAL-03 with the random and scripted versions of that side, all playing against the scripted opponent.
  - Given a trained predator, when evaluated against the scripted prey, then its catches are tested against the random and scripted predators' catches against the same scripted prey.

**Edge cases & errors**
- Every score of two agents is identical (e.g. all 1,000) → the comparison is reported as "no difference", not a pass.
- A baseline outscores the trained agent → the result is reported as a fail; the environment is not signed off (except predator and prey, see DONE-03).

### Replay (`REPLAY`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** Any saved agent, trained or baseline, can be watched playing an episode of its world as a 2D animation, including the mistakes it makes.

**Requirements**
- **REPLAY-01** The replay plays any saved agent on a chosen seed as a 2D animation of the world.
  - Given a saved trained snake and seed 42, when the replay is started, then the episode plays from its first step to its last.
- **REPLAY-02** The replay shows the step number and the current score.
  - Given a replay at step 150, when it is on screen, then "step 150" and the score so far are visible.
- **REPLAY-03** The replay can be paused, stepped one frame at a time, and run at speeds from 0.5× to 4×.
  - Given a paused replay, when "step" is pressed, then exactly one world step advances.
- **REPLAY-04** For agents that see only what is nearby, the replay draws each agent's sight circle.
  - Given the several-fish version, when replayed, then each fish has a 0.5-radius circle drawn around it.
- **REPLAY-05** A recorded episode can be watched again later exactly as it happened, without the agent or retraining.
  - Given a recorded episode, when reopened in a new session, then every frame matches the original.

**Edge cases & errors**
- The saved agent belongs to a different world than requested → the replay refuses with a message naming both worlds.
- A fish or prey goes out mid-episode → it is shown as out (greyed) for the rest of the replay.

### Notes (`NOTE`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** Each world has a short note, written by the learner, explaining why its method works, with the evidence beside it.

**Requirements**
- **NOTE-01** Each world has one note of 1,000 words or fewer explaining why its learning method works.
  - Given a finished world, when its note is opened, then it explains the method's idea in ≤ 1,000 words.
- **NOTE-02** The note includes the learning curve chart and the evaluation results.
  - Given the Snake note, when read, then it shows the EVAL-02 chart and the EVAL-04 results.
- **NOTE-03** The note describes at least one behaviour seen in a replay, including a wrong or surprising one if seen.
  - Given the fish note, when read, then it names a behaviour and the seed of the replay where it shows.
- **NOTE-04** The note states the reference check result and explains any gap.
  - Given the reference check result, when the note is read, then it states both scores and a reason for any difference.

**Edge cases & errors**
- A note is missing a required part → the world is not signed off (DONE-01).

### Reference check (`CHECK`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** After a world's hand-written learner passes, an established reference implementation of the same kind of method is trained on the same world under the same limits, and the two are compared.

**Requirements**
- **CHECK-01** The reference implementation is trained on the same world, with the same observations, actions, rewards and time limit as the hand-written learner.
  - Given the Snake check, when the reference trains, then it plays SNAKE-01..07's rules and stops within QR-01's limit.
- **CHECK-02** The reference is evaluated on the same 100 seeds as EVAL-01.
  - Given the reference agent, when evaluated, then its 100 scores use the seeds of the hand-written agent's evaluation.
- **CHECK-03** The hand-written learner lands in the reference's range: tested with the `null-hypothesis-testing` skill, it passes only if its mean score is shown, at 5%, to be no worse than 80% of the reference's.
  - Given hand-written mean 18 and reference mean 20, when tested, then it passes if the test rejects "hand-written mean ≤ 0.8 × 20".

**Edge cases & errors**
- The hand-written learner beats the reference by a wide margin → still a pass; the note says why.
- The reference can't finish within the time limit → it is compared at whatever it reached at the limit, and the note says so.

### Co-evolution comparison (`COEVO`)
**Serves:** Goal 4, Goal 1
**Stage:** S3
**Behavior:** Predator and prey are trained two ways, each within the same time limit: both sides learning at once against each other's current version, and each side learning against past versions of its opponent (self-play). The two are compared side by side, and the result is explained whatever it is.

**Requirements**
- **COEVO-01** In the simultaneous regime, both sides learn at once, each always facing the other's current version.
  - Given a simultaneous run, when the predator updates, then the prey it trained against were the prey's latest version at that moment.
- **COEVO-02** In the past-versions regime, a snapshot of each side is saved at least every 10% of the run, and each side trains against opponents drawn from all the other side's snapshots so far.
  - Given a past-versions run at 50% progress, when the predator plays a training episode, then its prey come from one of the prey's 5 or more saved snapshots.
- **COEVO-03** Both regimes are compared side by side: every regime's final predator plays every regime's final prey for 100 evaluation episodes.
  - Given both finished regimes, when compared, then a 2 × 2 table of predator and prey scores is produced.
- **COEVO-04** Both regimes' learning curves are drawn on one chart with the `dataviz` skill, predator and prey shown separately.
  - Given both finished regimes, when the chart is drawn, then it shows four curves: each regime's predator and prey.
- **COEVO-05** Each final agent plays the opponent's saved snapshots in order, showing whether later versions do better against it than earlier ones.
  - Given the final predator from either regime, when played against each prey snapshot for 100 episodes, then its catch rate per snapshot is reported in order.
- **COEVO-06** Differences between the regimes are tested with the `null-hypothesis-testing` skill at 5%, corrected for the number of comparisons.
  - Given the 2 × 2 table's scores, when tested, then each regime difference is reported with its corrected p-value.

**Edge cases & errors**
- One side collapses (e.g. the predator catches nothing) → recorded as the result and explained in the note, not rerun until it looks good.
- Later versions do worse against earlier ones (cycling) → reported from COEVO-05 and explained.

### Environment sign-off (`DONE`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** A world is finished only when everything that proves it is in place, and the next world starts only after that.

**Requirements**
- **DONE-01** Snake and the fish tank are each signed off only when their evaluation passes, a replay of the trained agent is recorded, the learning curve chart exists, the note is complete and the reference check passes.
  - Given Snake with every item but the note, when sign-off is checked, then it is refused, naming the note.
- **DONE-02** Work on a world starts only after the previous world is signed off: Snake, then the fish tank, then predator and prey.
  - Given Snake not yet signed off, when fish tank work is proposed, then it waits.
- **DONE-03** Predator and prey is finished when both regimes have run, COEVO-03..06 are reported and its note explains the result, whether or not EVAL-07's comparisons pass.
  - Given the trained predator fails EVAL-07 and the note explains why, when sign-off is checked, then predator and prey is finished.
- **DONE-04** The several-fish version starts only after the single-fish version passes EVAL-05 and EVAL-06.
  - Given the single fish beats random but falls short of the scripted fish, when the several-fish version is proposed, then it waits.

**Edge cases & errors**
- A world fails its evaluation after reasonable effort → it stays unsigned; the learner decides whether to change the method or the world, and records it in the note.

## Data requirements
- **DATA-01** Evaluation seeds are never used in training.
  - Given any training run and the 100 evaluation seeds of its world, when the seeds it trained on are listed, then none is an evaluation seed.
- **DATA-02** Every training run's record holds what's needed to rerun it: its seed, its settings and the time it took.
  - Given a saved training record, when it is opened, then the seed, every setting and the wall-clock duration are present.

## Quality requirements
- **QR-01** Each training run (one learner in one world, or one regime in predator and prey) finishes in under about 1 hour: ≤ 60 minutes wall-clock on the laptop, without a graphics card.
  - Timed on the laptop by the training record's duration (DATA-02).
- **QR-02** A cloud graphics card is used only when a run can't meet QR-01 on the laptop, and costs ≤ $5 per world.
  - Checked against the rental bill for that world.
- **QR-03** A training run repeated with the same seed and settings on the same machine gives the same learning curve.
  - Run twice; every curve point matches.
- **QR-04** The replay plays at 30 frames per second or more at 1× speed on the laptop.
  - Measured during a 1,000-step fish tank replay.

## Assumptions
- Snake: 10 × 10 grid, start length 3, three relative moves, episode ends after 100 steps without food.
- Fish tank: radius 1, ball speed 0.02 and radius 0.1, fish top speed 0.015 and radius 0.03, 1,000-step episodes, 5 fish, sight radius 0.5.
- Predator and prey: same tank, 5 prey, 1 predator 1.2× faster than prey, 8 pellets, sight radius 0.5 for both sides.
- 100 evaluation episodes per agent; significance at 5% after correction; "matches the scripted fish" means no worse than 95% of its mean; "same range as the reference" means no worse than 80% of its mean.
- The time limit applies to each training run, so predator and prey's two regimes get up to an hour each.
- The learner writes the notes; the build provides the charts, results and replays they draw on.
- A cloud graphics card costs ≤ $5 per world.
- In predator and prey, the comparisons against the baselines are reported but don't block finishing that world.
