# RL Lab — Architecture

**Status:** Draft · **Shape:** Multi-package · **Last updated:** 2026-10-17 · **Spec:** [spec.md](spec.md)

## Overview
Four packages in one uv workspace, layered in one direction. `worlds` holds the three worlds, their baselines and the shared world interface, using NumPy only. `learn` holds the hand-written learners, evaluation, the training loop, run folders and the co-evolution schedules, adding PyTorch. `lab` is what the owner touches: the command line, the replay window, charts and lab-note tooling. `compare` trains the reference library on the same worlds, and is the only package that installs it. Every run, hand-written or reference, ends as a standard run folder that the other packages read.

  compare --> learn
  compare --> worlds

## Cross-cutting concerns
- **Seeds (EVAL-03, QR-03):** training seeds are below 1,000,000, and the 100 evaluation seeds are 1,000,000–1,000,099. Every generator is spawned from the run seed (AD-13).
- **CPU only (QR-02):** every package uses the `cpu` device. No code path checks for a GPU.
- **Speed (QR-01, QR-05):** copies of a world run in lockstep with batched forward passes (AD-06). A benchmark test in `worlds` checks QR-05, and `meta.json` records each run's wall clock for QR-01.
- **Errors:** bad settings, names and actions raise `ValueError` naming the offending value. A learner's NaN stops the run, keeps its logs, and is recorded in `meta.json`.
- **Testing:** pytest per package. Contract fixtures live under `tests/contracts/<pkg>.<symbol>/`, and import-linter runs in CI.

## Decisions
### AD-01: Python 3.12 in a uv workspace
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** The owner works in Python. PyTorch, pygame-ce and Stable-Baselines3 ship wheels for Apple Silicon on 3.12. Four packages need one shared, locked environment.
- **Decision:** Python 3.12 (`requires-python = ">=3.12,<3.13"`). One uv workspace with a single lockfile, where each package is a workspace member under `packages/`. Imports use the `rllab` namespace: `rllab.worlds`, `rllab.learn`, `rllab.lab`, `rllab.compare`.
- **Alternatives:** 3.13 — some wheels lag. conda — heavier, and no dependency needs it. Poetry — weaker workspace support.
- **Consequences:** One `uv sync` sets up the laptop. Installing without `compare` leaves out the reference library entirely.

### AD-02: Four packages, layered worlds ← learn ← lab ← compare
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** Hand-written learners must not lean on a learning library (VALUE-01, VALUE-03, POLICY-01, CMP-03). Worlds must run headless and stay light (WORLD-04). PyTorch, the drawing stack and the reference library are three dependency stacks that the layers below shouldn't carry.
- **Decision:** The packages and rules are as in Packages and Dependency rules. A package depends only on those to its right. Each package's `pyproject.toml` lists only its allowed internal dependencies, and import-linter contracts check the import rules in CI. Anything two packages both need moves down a layer: the ratio check lives in `learn`, and reference runs are written in the standard run-folder format.
- **Alternatives:** One package with import-linter only — one 360-line contract that every task loads, and rules kept in config alone. More packages (worlds split per world) — cost without a boundary worth enforcing.
- **Consequences:** `lab` never sees the reference library, so reference results reach lab notes only as run folders. A new world joins `worlds`, and a new learner joins `learn`.

### AD-03: Own multi-agent world interface, not Gymnasium or PettingZoo
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `worlds`
- **Context:** Tank and Hunt have many agents that drop out mid-episode (TANK-04, HUNT-03). Each agent group has its own observation and action form (WORLD-02, WORLD-03). Gymnasium is single-agent. PettingZoo's parallel API fits, but adds a dependency to every world and hides the loop the owner is here to learn.
- **Decision:** `worlds.World` takes and returns dicts keyed by agent id. Agents belong to named groups (`snake`, `fish`, `predator`, `prey`), and observation and action forms are declared per group. Single-agent worlds have one agent in one group.
- **Alternatives:** Gymnasium — needs wrappers for every multi-agent world. PettingZoo parallel API — close, but an extra dependency for little gain.
- **Consequences:** `compare` needs a small Gymnasium adapter per comparison setting (AD-11). Switching to PettingZoo later is an adapter, not a rewrite.

### AD-04: NumPy for worlds and the lookup table; PyTorch on CPU for network learners
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `worlds`, `learn`
- **Context:** VALUE-01 asks for basic array operations. VALUE-03 and POLICY-01 allow tensor operations, autograd and a standard optimiser. The owner is learning PyTorch.
- **Decision:** `worlds` and the lookup-table learner use NumPy only. The value-network and policy learners use PyTorch tensors, autograd, `torch.nn` layers (`Linear`, activations) and `torch.optim.Adam`. Losses, returns, advantages, clipping and distribution maths are written by hand.
- **Alternatives:** NumPy only, with hand-written backprop — most educational, but it doubles the work per learner. JAX — capable, but a second new framework to learn.
- **Consequences:** Observations cross from NumPy to tensors at the learner's edge. Networks are small MLPs, so CPU is enough.

### AD-05: One training loop, driven by a team of policies per agent group
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `learn`
- **Context:** One loop must serve the lookup table, the value network and the policy learner (TRAIN-01–TRAIN-04), and must also handle frozen opponents and two learners at once (COEV-01, COEV-02).
- **Decision:** A team maps each agent group to a policy: a learner, a baseline from `worlds.baseline`, or a frozen snapshot. The loop calls `act` in batches and passes each step to every learner in the team. Each learner decides when to update: the value learners update every few steps, and the policy learner when its rollout buffer is full.
- **Alternatives:** One loop per algorithm — simpler for each one, but triples the logging and snapshot plumbing (Goal 4).
- **Consequences:** The co-evolution schedules build teams and call the same loop. Learner internals stay private to `learn`.

### AD-06: Copies of a world in lockstep, not natively vectorised worlds
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `learn`, `worlds`
- **Context:** QR-01 allows ≤ 60 minutes per headline run, and QR-05 needs ≥ 5,000 steps per second per world. Batched forward passes matter more for speed than the world code itself.
- **Decision:** Each world is written for one episode, so the rules stay readable. The training loop runs N copies (8 by default) in lockstep, and resets each copy as its episode ends.
- **Alternatives:** Worlds vectorised over episodes in NumPy — faster, but much harder to read and test. Subprocess workers — the overhead outweighs the gain at this size.
- **Consequences:** The batch size per step is N × the agents in each group. If the simultaneous Hunt run misses QR-01, vectorising the fish physics is the first lever.

### AD-07: Run folders with TOML settings, flushed CSV logs and five snapshots
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `learn`
- **Context:** TRAIN-01–TRAIN-04 and TRAIN-06 ask for runs that can be inspected and repeated, and that survive interruption. Reference runs must be readable the same way (CMP-04).
- **Decision:** `runs/<world>/<run-name>/` holds:
  - `settings.toml`
  - `meta.json`: seed, wall clock, git commit, and `reference: true|false`
  - `episodes.csv` and `evals.csv`, flushed per row
  - `snapshots/s000`–`s100`, saved with `torch.save` or as an `.npz` for the lookup table
  - `scores/<policy>__<opponent>.csv`

  `learn.RunWriter` is the only code that writes this layout, and `learn.RunDir` the only code that reads it. Settings are parsed into frozen dataclasses that reject unknown keys.
- **Alternatives:** TensorBoard or Weights & Biases — powerful, but the logs become harder to read straight into charts and notes. Parquet — unnecessary at this size.
- **Consequences:** Every reader works from plain files. A reference run's snapshots are the library's own files, and `RunDir.snapshot` refuses them.

### AD-08: Beats-baseline verdicts built with the `null-hypothesis-testing` skill
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `learn`
- **Context:** EVAL-04, COEV-05–COEV-08 and the learners' "beats" requirements must each be shown to be more than chance, corrected per world.
- **Decision:** `learn.beats` takes the two score arrays paired by evaluation seed, plus the size of that world's comparison family. Its test is built with the `null-hypothesis-testing` skill, which picks the test statistic, null distribution and correction. The verdict records all three.

### AD-13: Seeded generators passed down, deterministic torch on one thread
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** QR-03 needs identical evaluation scores from the same settings and seed on the same machine. EVAL-05 needs noise-free evaluation.
- **Decision:** The run seed spawns child generators for each world copy, each learner and evaluation, through `np.random.SeedSequence`. Torch gets `torch.manual_seed`, `use_deterministic_algorithms(True)` and `set_num_threads(1)`. `act(explore=False)` is deterministic for every policy.
- **Alternatives:** Multi-threaded torch — a little faster on bigger nets, but not bit-reproducible.
- **Consequences:** Results reproduce on the same machine, not necessarily across machines.

### AD-14: Ego-centric, fixed-size fish observations with visibility flags
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `worlds`
- **Context:** TANK-07, TANK-08 and HUNT-07 give fish local sight with a variable number of visible things. Learners need a fixed observation size (WORLD-03).
- **Decision:** Fish observations hold positions and velocities in the fish's own frame (rotated by its heading), scaled by the tank radius. Each slot (ball, the k nearest fish, pellets, predator) carries a visible flag and is zeroed when nothing is there.
- **Alternatives:** World-frame coordinates — simpler, but harder to learn from, because the same situation looks different at every heading.
- **Consequences:** Observation sizes are fixed per group and declared in `worlds.WorldSpec`.

# learn — Architecture

**Package:** learn · **Status:** Draft · **Last updated:** 2026-10-17 · **System:** [../../architecture.md](../../architecture.md)

## Overview
The hand-written learning side. Three learners share one internal `Learner` protocol: a policy plus `observe`, `metrics`, `save` and `load`. One training loop runs a team of policies against N copies of a world (AD-05, AD-06), and writes and reads run folders (AD-07). Evaluation plays any team on the fixed evaluation seeds and turns paired scores into verdicts (AD-08). The co-evolution schedules and the tournament are built on the same loop.

## Components
| Module | Responsibility | Covers | Depends on |
|---|---|---|---|
| `protocols` | Internal `Learner` protocol, and the `Transition` batch the loop hands to learners | — | `worlds` |
| `qtable` | Lookup-table value learner in NumPy; reports `table_entries` | VALUE-01, VALUE-02, VALUE-05 | `protocols` |
| `dqn` | Value-network learner with switchable `replay_memory` and `target_copy` | VALUE-03, VALUE-04, VALUE-06 | `protocols` |
| `ppo` | Clipped policy-gradient learner, Gaussian actions with hand-written log-probabilities; switchable `clip` and `value_baseline`; one shared policy per group | POLICY-01–POLICY-06 | `protocols` |
| `settings` | TOML settings to frozen dataclasses, with each learner's settings type and its switches | TRAIN-01 | `qtable`, `dqn`, `ppo` |
| `runs` | `RunWriter` and `RunDir`: the only writer and reader of the run-folder layout | TRAIN-02, TRAIN-04, TRAIN-06 | `settings` |
| `evaluate` | Evaluation seeds, deterministic evaluation, `beats` (built with the `null-hypothesis-testing` skill), `ratio_check`, and the comparison family per world | EVAL-03–EVAL-05, CMP-02 | `worlds` |
| `loop` | `train`: team assembly, lockstep copies, transitions to learners, periodic evaluation, snapshots, wall clock, seeding | TRAIN-03, QR-01–QR-03 | `runs`, `evaluate`, learners, `worlds` |
| `coev` | Alternating and simultaneous schedules, opponent pool, tournament | COEV-01–COEV-08, COEV-10, COEV-11 | `loop`, `ppo`, `evaluate` |

**Internal types**, frozen here because they cross modules but never leave the package:
- `Transition`: per-row `stream` id (world copy × agent), `obs`, `action`, `reward`, `next_obs`, `done` and `truncated`. A truncated stream bootstraps and is not treated as terminal.
- `Learner(Policy)`: `observe(Transition)`, `metrics() -> dict[str, float]`, `save(path)` and `load(path)`. A learner raises `FloatingPointError` naming the step when a value turns NaN.
- **Settings defaults:**
  - Lookup table: α 0.1, γ 0.95, ε 1 → 0.01 over 200k steps.
  - Value network: two hidden layers of 128, lr 5e-4, γ 0.99, batch 64, memory 100k, target copy every 2k steps, warmup 5k, an update every 4 steps.
  - Policy learner: two hidden layers of 64, lr 3e-4, γ 0.99, λ 0.95, rollout 2,048, 10 epochs, minibatch 256, clip 0.2.

- **Opponent pool (COEV-11):** the current opponent with probability 0.5, otherwise a uniformly chosen earlier snapshot, logged per episode in `episodes.csv`.

- **Reproducibility (QR-03, AD-13):** `loop` spawns all generators from the run seed with `np.random.SeedSequence`, and sets torch to deterministic, single-threaded, CPU.

- **Learner sanity tests:** a 2-state chain world where the learned values must match the exact ones within 1%.

## Overview
The owner's workbench. The `rllab` command trains, evaluates, replays, co-evolves and maintains lab notes by calling `learn`. The replay window draws `worlds.Scene` frames with pygame-ce (AD-09). Charts are matplotlib PNG files styled with the `dataviz` skill (AD-10). Lab-note tooling fills results blocks from run folders and checks note structure (AD-12). Nothing here imports the reference library: reference runs arrive as ordinary run folders.

# lab — Contract

**Package:** lab · **Status:** Draft · **Last updated:** 2026-10-17 · **Architecture:** [architecture.md](architecture.md)

### lab.main: Command line
`def main(argv: list[str] | None = None) -> int` (the `rllab` console script)
- **Invariants:** subcommands are `train`, `eval`, `replay`, `coevolve`, `chart` and `notes refresh|check`; returns 0 on success; `eval` prints each verdict and writes it into the run's `scores/` folder; `notes check` returns 1 if there are any problems
- **Errors:** unknown subcommands and bad arguments print usage and return 2; errors from `learn` and `worlds` are printed with their message and return 1
- **Used by:** the owner, PL-01–PL-04, PL-06

### lab.Panel: type
`@dataclass(frozen=True) class Panel: label: str; world: str; options: dict[str, Any]; team: dict[str, Policy]`
- **Invariants:** `team` covers every group of the world
- **Boundary:** cli · **Fixtures:** tests/contracts/lab.Panel/ · **Cases:** four Snake snapshot panels; one Hunt panel with two snapshots
- **Used by:** cli, PL-03

### lab.play: Replay window
`def play(panels: list[Panel], seed: int, *, speed: float = 1.0, video: Path | None = None, show: bool = True) -> dict[str, float]`
- **Invariants:** 1–4 panels play in step; space plays or pauses, → advances one step, +/− change speed between 0.25× and 4×; each panel shows its step and score, and a finished one holds its last frame marked "done"; returns each panel's final score, equal to its evaluation score on that seed (REPLAY-05)
- **Errors:** `ValueError` for panels from different worlds, more than 4 panels, or `show=False` with no `video`
- **Used by:** cli, PL-03

### lab.learning_curve: Learning curve
`def learning_curve(run: RunDir, baselines: dict[str, float], out: Path) -> Path`
- **Invariants:** evaluation mean over steps for each learning group, with each baseline as a labelled horizontal line on the same axes (TRAIN-05); writes a PNG and returns its path
- **Used by:** cli, PL-01

### lab.overlay: Overlay chart
`def overlay(runs: dict[str, RunDir], baselines: dict[str, float], out: Path, *, group: str) -> Path`
- **Invariants:** every run's evaluation curve for `group` on the same axes, labelled by its key, with baseline lines (LAB-03, CMP-04); reference runs are drawn like any other run
- **Errors:** `ValueError` if the runs come from different worlds or settings
- **Boundary:** compare · **Fixtures:** tests/contracts/lab.overlay/ · **Cases:** an intact run and a break-it run; a hand-written run and a reference run
- **Used by:** compare, notes, PL-05

### lab.tournament_chart: Tournament chart
`def tournament_chart(table: TournamentTable, out: Path) -> Path`
- **Invariants:** both sides' scores for every snapshot pairing, readable at a glance (COEV-09)
- **Used by:** cli, notes, PL-04

### lab.NoteProblem: type
`@dataclass(frozen=True) class NoteProblem: line: int; code: str; message: str`
- **Invariants:** `code` ∈ {`missing-explanation`, `too-few-breakit`, `missing-removed`, `missing-prediction`, `missing-outcome`, `missing-comparison`, `stale-results`}
- **Boundary:** cli · **Fixtures:** tests/contracts/lab.NoteProblem/ · **Cases:** a note with one break-it entry; a note whose results block is stale
- **Used by:** cli, PL-06

### lab.refresh_note: Fill results blocks
`def refresh_note(note: Path) -> int`
- **Invariants:** rewrites only the text between results markers, from the run folders, verdicts and charts; returns how many blocks changed; running it twice changes nothing the second time (LAB-05)
- **Errors:** `FileNotFoundError` naming a cited run that doesn't exist
- **Used by:** cli, PL-06

### lab.check_note: Check a lab note
`def check_note(note: Path) -> list[NoteProblem]`
- **Invariants:** empty only when the note meets LAB-01, LAB-02, LAB-04 and LAB-05 and has a comparison section (CMP-04)
- **Used by:** cli, PL-06

# compare — Architecture

**Package:** compare · **Status:** Draft · **Last updated:** 2026-10-17 · **System:** [../../architecture.md](../../architecture.md)

## Overview
Trains Stable-Baselines3's DQN or PPO on the same world, setting, step budget and seed as a hand-written run (AD-11). It writes the result as a standard run folder through `learn.RunWriter`, evaluates both learners on the evaluation seeds, checks the ratio, and draws the overlay through `lab.overlay`. This is the only package that installs or imports the reference library and Gymnasium (CMP-03).

## Components
| Module | Responsibility | Covers | Depends on |
|---|---|---|---|
| `adapters` | Gymnasium environments over `worlds.World` for the three comparison settings: Snake full view; Tank single fish; Hunt predator against the scripted prey (opponent stepped inside the adapter) | CMP-01 | `worlds` |
| `reference` | Builds the library learner from the hand-written run's budget and seed; logs episodes and evaluations through `learn.RunWriter`; wraps the trained model as a `worlds.Policy` for evaluation | CMP-01, CMP-03 | `adapters`, `learn` |
| `run` | `compare` and the `rllab-compare` console script: train the reference, evaluate both, `learn.ratio_check`, `lab.overlay` | CMP-02, CMP-04 | `reference`, `learn`, `lab` |

## Interfaces
See [contract.md](contract.md).

## Data
- **Reference runs:** `runs/<world>/ref-<hand-run>/`, with `meta.json` `reference: true` and `comparison.json` (ratio, both means and the verdict). The library's own model file is saved in `snapshots/`, readable only by `compare`.
- **Evaluation cadence:** the same `eval_every` as the hand-written run, through a library callback, so both curves share an x-axis.

## Cross-cutting concerns
- **Determinism:** the library model is seeded from the hand-written run's seed and pinned to the CPU device.
- **Smoke check:** a 1,000-step run on each adapter, wrapped in the library's environment checker, is the first test written (Risks in the root doc).

## Project layout
```
packages/compare/src/rllab/compare/   → adapters.py reference.py run.py; __init__ exports the contract
packages/compare/tests/
```

I wrote the architecture as four packages. `dt status` and `dt lint` both pass: every requirement has a home, with no stale items, broken fences or missing contracts.

The design is a root system map plus an `architecture.md` and `contract.md` for each package. Each contract is 20–109 lines, well under the 200-line limit the old single-package contract broke. I removed the old `docs/packages/rllab/contract.md`.

| Package | What's in it | What it adds |
|---|---|---|
| `worlds` | World interface and registry, Snake, Tank, Hunt, shared fish physics, random and scripted baselines | NumPy only |
| `learn` | Lookup table, DQN, PPO, the training loop, run folders, evaluation and verdicts, co-evolution and the tournament | PyTorch |
| `lab` | The `rllab` command, replay window and video, charts, lab-note refresh and check | pygame-ce, matplotlib |
| `compare` | Stable-Baselines3 runs on the same world, budget and seed | The only package with the reference library |

Dependencies run one way only: `worlds` ← `learn` ← `lab` ← `compare`. Six system pipelines describe how a request moves between packages: training, evaluation, replay, co-evolution, library comparison, and lab notes. All 14 decisions (AD-01–AD-14) are Proposed, and none needs a probe.

**Decisions worth a second look:**
- **AD-11 (reference library):** Stable-Baselines3 is single-agent, so the school setting and the both-sides-learning Hunt run have no library comparison. The comparisons are Snake (DQN, full view), Tank (single fish), and Hunt (predator trained against the scripted prey).
- **AD-03:** a hand-written multi-agent world interface instead of PettingZoo, so you write the loop yourself.
- **AD-06:** each world is written for one episode, and 8 copies run in lockstep. Readability wins over raw speed, with vectorising the fish physics kept as the fallback if a run is too slow.
