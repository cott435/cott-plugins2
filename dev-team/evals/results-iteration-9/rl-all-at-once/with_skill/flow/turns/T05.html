**Writing rules:**

- **One requirement, one behavior.** If a requirement contains "and", it's probably two.
- **Every requirement has at least one acceptance criterion** in Given/When/Then form. If you can't write one, the requirement isn't clear yet.
- **Describe behavior, not implementation.** "The customer sees their usual order" — not "the app queries the orders table."
- **Use exact numbers.** "≤ 2 seconds", "up to 50 regulars", never "fast" or "many".
- **Every feature names one stage.** Its `**Stage:**` line holds only the ID of the roadmap stage that first builds it. `dt lint` fails a feature with no stage, or one naming no stage row.
- **Requirement IDs are permanent.** `CODE-NN`, numbered within the feature, never reused or renumbered.
- **Quality requirements only when measurable.** Leave out generic wishes ("should be secure"); keep checkable ones ("passwords are never shown in full"). Cost, licence and budget limits are `QR-` items ("data costs ≤ $50 a month"), never `DATA-` or feature requirements.
- **No tech stack, libraries, vendors, schemas, endpoints, or file structure, even when the user names them.** Write the behavior the name stands for. The name itself belongs to `architecture-design`, which reads the idea file and the conversation.
- **Describe the product as it is now, not how it got here.** Requirement text, scope lists and assumptions carry no change notes, provenance tags ("from the field-photo idea") or process notes ("numbers chosen for review"). History goes in one Changelog row per round, and in git.

**Data and ML projects — extra rules:**

- **Specify the data, not the source.** `DATA-NN` requirements say what the data must contain and guarantee ("hourly readings for every meter in the service area, including decommissioned ones, since 2015"; "every record is stamped with the date it became known"). Which API, vendor, or dataset meets them is an architecture decision, made by checking candidates against these requirements. Name a source only when the brief makes it a fixed constraint (our own database, a required benchmark).
- **Write data guarantees as testable criteria.** Leakage, look-ahead, selection bias, and coverage gaps are requirements, not hopes: "Given a forecast issued at time T, when the model requests weather, then no value published after T is returned."
- **Model quality is a requirement with a baseline.** Acceptance criteria name the metric, the held-out data, the threshold, and the baseline to beat: "Given the most recent 6 months of plates (never trained on), when ranked, then reviewing the top 20% catches ≥ 90% of scientist-failed plates, and beats ranking by Z′ alone." Never "the model is accurate".
- **No model types or libraries.** "Gradient boosting" or "PyTorch" are architecture decisions; the spec says what the model must achieve.
- **Learning projects: "build it by hand, then compare with a library" is a valid requirement. Write it without the names.** "The hand-written CNN reaches ≥ 90% of the accuracy of an established reference implementation on the same dataset." "The logistic regression is written from basic array operations; a reference library is used only to check its output." The architecture picks the reference.

## Hygiene check

Run on everything above the Changelog before presenting a Draft.

- **Implementation names.** Search for library, framework, vendor, dataset, file-format, database and model-type names, file and function names (a reference's included), including names the user, the brief or the idea file used. Rewrite each one as the behavior or guarantee it stands for: "within 10% of torchvision's ResNet-18" becomes "within 10% of an established reference implementation", and "NumPy only" becomes "written from basic array operations". The only exception is a source the brief makes a fixed constraint.

# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [brief.md](brief.md)

## Summary
A set of small 2D reinforcement-learning worlds (Snake, Fish tank, Predator-prey) built on one shared core: a world interface, a training loop, logging with learning-curve charts, a replay viewer, and baseline evaluation. In each world a hand-written learning agent is trained on a laptop, checked against random and rule-based play, watched in replays, and explained in a write-up. See the [brief](brief.md) for why.

## Users
| User | What they need to do |
|---|---|
| The learner (sole user) | Add a world, train agents in it on a laptop, check they beat the baselines, watch replays across training, and write up why the method works and where it struggles |

## Scope
**In scope:** World interface, Training runs, Run logging & learning curves, Replay viewer, Baseline evaluation, Reference check, World write-ups, Snake, Fish tank, Predator-prey.

**Out of scope:**
- 3D physics.
- Learning from screen pixels, or Atari games.
- Reproducing research papers or matching published numbers.
- Web deployment or a hosted demo; everything runs locally.
- Chasing top scores; clearly beating the baselines is enough.
- Hyperparameter search beyond what the learner tunes by hand.
- Written explanations generated for the learner; write-ups are the learner's own words.

## Features

### World interface (`WORLD`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** Every world presents the same face to the rest of the system: it can be reset from a seed, it reports what each agent observes as a short list of numbers, it accepts each agent's action, and it returns rewards, an end-of-episode signal and a world-specific score. It also describes its current state in a form the replay viewer can draw.

**Requirements**
- **WORLD-01** A world starts a new episode from a seed, and the same seed always gives the same starting state.
  - Given a world and seed 42, when two episodes are started, then both starting states are identical.
- **WORLD-02** Given the same seed and the same sequence of actions, a world produces the same sequence of observations, rewards and end signals.
  - Given a recorded episode's seed and actions, when they are replayed into a fresh world, then every observation, reward and end signal matches the recording.
- **WORLD-03** Each agent's observation is a fixed-length list of numbers, never an image.
  - Given any world, when an observation is taken at any step, then it has the same length as at every other step of that world and variant.
- **WORLD-04** A world declares its agents, the observation length and the action format (a choice from a fixed set, or a list of numbers within stated limits) before any episode starts.
  - Given any world, when the training loop asks for its description, then it receives the agent list, observation length and action format without running an episode.
- **WORLD-05** Every world reports a per-episode score with a stated direction (higher is better, or lower is better), used by evaluation and charts.
  - Given a finished episode, when its score is requested, then a single number and the world's direction are returned.
- **WORLD-06** A world reports its drawable state at every step (positions, sizes and kinds of every object) for the replay viewer.
  - Given any step of any episode, when the drawable state is requested, then every object on screen is listed with its position.
- **WORLD-07** A world can hold more than one agent, each agent belonging to a named team.
  - Given a world with agents on two teams, when a step is taken, then each agent receives its own observation and reward, labelled with its team.

**Edge cases & errors**
- An action outside the declared format or limits → the step is refused with an error naming the agent and the bad value; it is never silently clipped.
- An agent that has left the episode (e.g. a caught prey) is sent an action → the action is ignored and the agent receives no further observations that episode.

### Training runs (`TRAIN`)
**Serves:** Goal 1, Goal 4
**Stage:** S1
**Behavior:** The learner starts a training run by naming a world, its variant, the learning method's settings and a seed. The run trains for a fixed budget of environment steps, saves checkpoints of the agent as it goes, and runs periodic evaluations. The same loop runs every world without change.

**Requirements**
- **TRAIN-01** A training run is started from a world, a variant, the method's settings and a seed, and runs for a stated budget of environment steps.
  - Given snake, its default settings, seed 1 and a budget of N steps, when the run is started, then it stops after exactly N environment steps.
- **TRAIN-02** The same world, settings and seed on the same machine give an identical training run.
  - Given two runs with identical inputs, when both finish, then their logged results and final checkpoints are identical.
- **TRAIN-03** A run saves a checkpoint at 10 evenly spaced points in its budget, plus at the start (untrained) and the end.
  - Given a finished run, when its checkpoints are listed, then there are 12, at 0%, 10%, … 100% of the budget.
- **TRAIN-04** A run evaluates its current agent at every 5% of its budget on 20 episodes whose seeds are never used in training.
  - Given a finished run, when its evaluation log is read, then there are 21 evaluation points, each the mean score of 20 held-out-seed episodes.
- **TRAIN-05** Several runs of the same world with different seeds can be started together, one per processor core.
  - Given 5 seeds, when a batch of runs is started, then 5 runs proceed at the same time and each finishes with its own log and checkpoints.
- **TRAIN-06** Every learning method, before it is used in a world, learns the known best behavior in a tiny check world whose best behavior is worked out by hand.
  - Given a learning method and its check world, when it is trained for the check budget, then the trained agent picks the hand-derived best action in at least 95% of check-world states.
- **TRAIN-07** In worlds with more than one team, each team has its own learning method and settings, and all teams learn during the same run.
  - Given predator-prey with a learning method for each team, when a run proceeds, then both teams' agents change between consecutive checkpoints.

**Edge cases & errors**
- A run is stopped before its budget ends → it is marked incomplete, keeps its checkpoints so far, and is left out of learning-curve charts and evaluation unless the learner includes it by name.
- A run's training produces an invalid number (not-a-number or infinite) in the agent → the run stops at once, saves the last good checkpoint, and records the step and the value.
- A run would overwrite an existing run with the same name → it is refused; the learner picks a new name or deletes the old run first.

### Run logging & learning curves (`LOG`)
**Serves:** Goal 1, Goal 4
**Stage:** S1
**Behavior:** Every run records its settings and results as it trains. From a group of runs of the same world and variant, the learner gets a learning-curve chart showing the agent against both baselines, across all runs.

**Requirements**
- **LOG-01** Every run records its world, variant, method settings, seed, budget, start and end times, and whether it finished.
  - Given any finished run, when its record is opened, then every one of those fields is present.
- **LOG-02** Every run logs, for each training episode, the episode's score, length and total reward per team.
  - Given a finished run, when its episode log is read, then it has one entry per training episode with those values.
- **LOG-03** For a world and variant with at least 3 finished runs, a learning-curve chart shows evaluation score against environment steps: the mean across runs as a line, the lowest-to-highest range across runs as a band, and each baseline's mean score as a horizontal reference line.
  - Given 5 finished snake runs, when the chart is made, then it shows one mean line, one band, a random-play line and a rule-based line, with the axes labelled with the score name and "environment steps".
- **LOG-04** Learning-curve charts follow the `dataviz` skill's guidance for form, colour and labelling.
  - Given any learning-curve chart, when it is reviewed against the `dataviz` skill, then it passes that skill's checks.
- **LOG-05** Each world can add its own logged measures (e.g. snake length at death, hits per fish), which are charted the same way as the score.
  - Given a world that declares an extra measure, when its chart is requested, then it is drawn with the same mean line and range band.
- **LOG-06** The learner can view the latest logged values of a run while it trains.
  - Given a run in progress, when the learner checks it, then they see the current step, the latest evaluation score and the time elapsed, no more than 1 evaluation point behind.

**Edge cases & errors**
- Runs with different budgets or settings are asked for in one chart → refused, naming the differing settings; one chart only combines runs that differ by seed.
- Fewer than 3 finished runs → the chart is still drawn, but titled with the run count and a note that the band is not meaningful.

### Replay viewer (`REPLAY`)
**Serves:** Goal 2, Goal 4
**Stage:** S1
**Behavior:** The learner picks a run, one of its checkpoints and a seed, and watches that agent play an episode in a local window. They can pause, step and change speed, and put two checkpoints side by side on the same starting state to see how training changed the behavior.

**Requirements**
- **REPLAY-01** The learner can watch an episode played by any checkpoint of any run, from a seed they choose.
  - Given a snake run's 50% checkpoint and seed 7, when the replay is opened, then the episode plays from its first step to its end.
- **REPLAY-02** Replays are exact: the same checkpoint and seed always show the same episode.
  - Given a checkpoint and seed, when the replay is played twice, then every frame matches.
- **REPLAY-03** The replay can be paused, stepped one step forward or back, and played at 0.25×, 1×, 4× or 16× speed.
  - Given a paused replay at step 30, when the learner steps forward, then step 31 is shown; when they step back twice, step 29 is shown.
- **REPLAY-04** Two checkpoints can be shown side by side on the same starting state, stepping in sync.
  - Given the 10% and 100% snake checkpoints and seed 7, when compared, then both start from the same board and advance one step at a time together; when one episode ends, its last frame stays while the other continues.
- **REPLAY-05** The replay shows the current step, the running score and each agent's latest reward next to the world.
  - Given any frame, when it is shown, then the step number, the score so far and the latest rewards are visible.
- **REPLAY-06** The learner can also watch the random-play and rule-based baselines in the same viewer, including side by side with a checkpoint.
  - Given the rule-based snake and the final checkpoint on seed 7, when compared, then both play side by side as in REPLAY-04.
- **REPLAY-07** A replay can be saved as a video file to keep alongside the write-up.
  - Given an open replay, when the learner saves it, then a video of the whole episode at 1× speed is written and plays in a standard video player.

**Edge cases & errors**
- A checkpoint from a world or variant whose observation length or action format no longer matches → the replay refuses to open and names the mismatch.
- An episode that never ends on its own → the replay stops at the world's step limit and says so.

### Baseline evaluation (`EVAL`)
**Serves:** Goal 1
**Stage:** S1
**Behavior:** For every world and variant there are two baselines: random play and a simple hand-written rule. A final evaluation plays every run's final checkpoint and both baselines on the same held-out seeds and tests whether the learned agent beats each baseline by more than chance.

**Requirements**
- **EVAL-01** Every world and variant has a random-play baseline that picks each action uniformly from the allowed actions.
  - Given any world, when the random baseline plays 100 steps, then every action it takes is within the declared action format.
- **EVAL-02** Every world and variant has a rule-based baseline that the learner writes by hand, described in one sentence in the world's feature below.
  - Given any world, when its rule baseline is listed, then its one-sentence description is shown with it.
- **EVAL-03** Final evaluation plays every final checkpoint and both baselines on the same 100 seeds, none of which was used in training or in-training evaluation.
  - Given 5 finished runs, when final evaluation is run, then 700 episodes are played (5 × 100 learned, 100 random, 100 rule-based), all on the same 100 held-out seeds.
- **EVAL-04** Whether the learned agent beats each baseline is tested with the `null-hypothesis-testing` skill. It is given: the hypothesis "the trained agent scores better than the baseline"; H0 = the learned agent's mean score is no better than the baseline's, H1 = it is better (in the world's score direction); the statistic = difference in mean episode score, learned (averaged over the runs, per seed) minus baseline; the null built by randomly swapping the learned and baseline labels within each held-out seed (paired permutation, 10,000 permutations); α = 0.05 with Holm correction across all baseline comparisons in that world (2 per variant); the EVAL-03 held-out episodes. The learned agent passes only if both nulls are rejected.
  - Given final evaluation results for one variant, when tested, then a report shows, for each baseline, the mean scores, the difference, the corrected p-value and reject/keep.
- **EVAL-05** "Clearly beats" also needs every single run to beat the rule baseline: each run's final mean score is better than the rule-based baseline's mean score.
  - Given 5 runs where 4 beat the rule baseline and 1 does not, when the verdict is made, then the world is marked "not yet beating the baselines" and names the failing run.
- **EVAL-06** Final evaluation produces one summary per world and variant: mean and range of learned scores across runs, both baseline means, the EVAL-04 test results and the EVAL-05 verdict.
  - Given a finished evaluation, when the summary is opened, then all of those values are present.

**Edge cases & errors**
- Fewer than 5 finished runs → the test is not run and the summary says how many more runs are needed.
- A baseline scores better than the learned agent → reported plainly as a failed result, never hidden or re-run with new seeds.

### Reference check (`CHECK`)
**Serves:** Goal 1, Goal 3
**Stage:** S1
**Behavior:** After the hand-written method works in a world, the learner trains an established reference implementation of the same kind of method on the same world and budget, as a check that the hand-written version has no silent bugs.

**Requirements**
- **CHECK-01** The learning algorithms are written by the learner from basic array operations; an established reference implementation is used only for this check, never inside training runs.
  - Given any training run, when it runs, then no outside reinforcement-learning code takes part in it.
- **CHECK-02** For each world and variant, 5 runs of a reference implementation of the same kind of method are trained on the same world, budget and seeds as the hand-written method, and evaluated as in EVAL-03.
  - Given a finished reference check, when its summary is opened, then it shows the reference's mean and range next to the hand-written method's.
- **CHECK-03** The hand-written method passes the check if its mean final score is at least 80% of the reference's (or at most 125% for lower-is-better scores).
  - Given a hand-written snake mean of 18 food and a reference mean of 20, when checked, then it passes; at 15 against 20, it is flagged for investigation.

**Edge cases & errors**
- The hand-written method scores far better than the reference (more than 150% of it) → also flagged, since it may point to a bug in scoring or evaluation rather than a better method.

### World write-ups (`NOTES`)
**Serves:** Goal 3
**Stage:** S1
**Behavior:** Each world has a short write-up, written by the learner, that explains why its learning method works and where it struggles, pointing to the charts and replays that show it.

**Requirements**
- **NOTES-01** Each world has a write-up with three parts: how the learning method works, why it works in this world, and where it struggles.
  - Given a finished world, when its write-up is opened, then all three parts are present and non-empty.
- **NOTES-02** The "where it struggles" part points to at least one saved replay or chart that shows the struggle.
  - Given a write-up, when its struggle part is read, then it names at least one saved replay or chart that exists.
- **NOTES-03** Write-ups are the learner's own words; nothing in the system writes or fills them in.
  - Given a new world, when it is set up, then its write-up starts with only the three part headings.

**Edge cases & errors**
- A write-up points to a replay or chart that no longer exists → the world's finish check lists the broken link.

### Snake (`SNAKE`)
**Serves:** Goal 1, Goal 2, Goal 3
**Stage:** S1
**Behavior:** The classic snake game on a square grid. The snake moves one cell per step, turns left, right or keeps going, grows when it eats food, and dies when it hits a wall or itself. The learner trains a snake that eats steadily and avoids itself, and watches it do so.

**Requirements**
- **SNAKE-01** The world is a 10 × 10 grid with one snake starting 3 cells long in the middle, and one food item on a random free cell.
  - Given seed 3, when an episode starts, then the snake is 3 cells long near the center and one food item is on a cell the snake does not cover.
- **SNAKE-02** Each step the snake chooses one of three actions: turn left, turn right or go straight.
  - Given the snake heading up, when it turns left, then its head moves one cell left.
- **SNAKE-03** Eating food grows the snake by one cell, adds 1 to the score and places new food on a random free cell.
  - Given the head moves onto food, when the step ends, then the snake is one cell longer, the score is up by 1 and new food is on a free cell.
- **SNAKE-04** The episode ends when the head hits a wall or the snake's body, or after 100 steps without eating.
  - Given the head moves into its own body, when the step ends, then the episode is over.
- **SNAKE-05** The score is the food eaten in the episode (higher is better).
  - Given an episode where 12 food items were eaten, when it ends, then its score is 12.
- **SNAKE-06** The snake observes a fixed list of numbers: danger straight ahead, left and right; its heading; the food's direction relative to its head; and its length.
  - Given any step, when the observation is taken, then it has the same length and holds those values.
- **SNAKE-07** The rule-based baseline moves toward the food along the shorter axis, unless that move would end the episode next step, in which case it takes any move that does not.
  - Given the food to the right and a free cell to the right, when the rule acts, then it moves right.
- **SNAKE-08** The trained snake beats both baselines as in EVAL-04 and EVAL-05.
  - Given 5 finished snake runs, when evaluated, then both baselines are beaten.

**Edge cases & errors**
- The snake fills every free cell → the episode ends as a win and the score counts all food eaten.
- Turning back into its own neck is impossible by construction, since actions are relative turns.

### Fish tank (`FISH`)
**Serves:** Goal 1, Goal 2, Goal 3, Goal 4
**Stage:** S2
**Behavior:** A 2D tank with walls and a ball that bounces around at constant speed. Fish move smoothly by choosing how hard to push in each direction, and lose points when the ball hits them. It is built in three variants: one fish that sees everything, many fish that see everything, and many fish that only see nearby things.

**Requirements**
- **FISH-01** The tank is a square with walls; the ball moves in straight lines at constant speed and bounces off walls.
  - Given the ball heading into the right wall, when it touches the wall, then its sideways direction reverses and its speed is unchanged.
- **FISH-02** Each step a fish chooses a push as two numbers between −1 and 1 (left-right and up-down); its speed changes smoothly with the push, up to a top speed below the ball's.
  - Given a still fish pushing (1, 0) for several steps, when its speed is read, then it rises step by step toward its top speed, never above it.
- **FISH-03** When the ball touches a fish, the hit is counted and the fish reappears at a random spot at least one quarter of the tank's width from the ball.
  - Given the ball touching a fish, when the step ends, then the hit count is up by 1 and the fish is at least a quarter-width from the ball.
- **FISH-04** An episode lasts 1,000 steps; the score is hits per fish per episode (lower is better).
  - Given 4 fish and 6 total hits in an episode, when it ends, then the score is 1.5.
- **FISH-05** Variant "one fish": a single fish observes its own position and velocity and the ball's position and velocity.
  - Given the one-fish variant, when an observation is taken, then it holds those values for the fish and the ball.
- **FISH-06** Variant "many fish": 8 fish share the tank; each observes itself, the ball and the 3 nearest other fish.
  - Given the many-fish variant, when an observation is taken for any fish, then it holds its own state, the ball's and the 3 nearest fish's.
- **FISH-07** Variant "local sight": as "many fish", but a fish sees the ball and other fish only within a radius of one quarter of the tank's width; anything outside is reported as "not seen".
  - Given the ball beyond the radius, when a fish's observation is taken, then the ball's entries read "not seen".
- **FISH-08** Fish pass through each other; only the ball can hit them.
  - Given two fish moving onto the same spot, when the step ends, then both are there and no hit is counted.
- **FISH-09** The rule-based baseline pushes each fish directly away from the ball at full strength (from the ball it sees, or randomly when it sees none).
  - Given the ball to the fish's left, when the rule acts, then the push is (1, 0).
- **FISH-10** Every variant's trained fish beat both baselines as in EVAL-04 and EVAL-05.
  - Given 5 finished runs of each variant, when evaluated, then both baselines are beaten in each variant.
- **FISH-11** Fish tank runs through the same training runs, logging, replay viewer and evaluation as snake, and snake's results reproduce unchanged after fish tank is added.
  - Given a snake run repeated with its original settings and seed after fish tank exists, when it finishes, then its results match the original run exactly.

**Edge cases & errors**
- A fish pushes into a wall → it stops at the wall and slides along it; it never leaves the tank.
- The ball starts touching a fish → the episode's start is re-drawn so that every fish starts at least a quarter-width from the ball.

### Predator-prey (`PREY`)
**Serves:** Goal 1, Goal 2, Goal 3, Goal 4
**Stage:** S3
**Behavior:** A 2D arena with food pellets, a team of prey and a team of predators, all moving smoothly as fish do. Prey score by eating food and are removed when caught; predators score by catching prey. Both teams learn at the same time. The learner watches and explains how each side adapts to the other; it may never look "solved", and that is acceptable.

**Requirements**
- **PREY-01** The arena is a square with walls, 6 prey, 2 predators and 10 food pellets; an eaten pellet reappears at a random spot after 50 steps.
  - Given seed 5, when an episode starts, then the counts are 6, 2 and 10, with no two objects touching.
- **PREY-02** Prey and predators move by smooth pushes as in FISH-02; predators' top speed is 1.2 × the prey's.
  - Given both at full speed, when their speeds are read, then the predator's is 1.2 × the prey's.
- **PREY-03** A prey touching a pellet eats it; a predator touching a prey catches it and the prey leaves the episode.
  - Given a predator touching a prey, when the step ends, then the prey is gone and the predator's catch count is up by 1.
- **PREY-04** An episode lasts 1,000 steps or until every prey is caught.
  - Given all 6 prey caught at step 600, when the step ends, then the episode is over.
- **PREY-05** Each team has its own score: prey score = pellets eaten per prey (higher is better); predator score = prey caught per episode (higher is better).
  - Given 18 pellets eaten and 3 prey caught, when the episode ends, then the prey score is 3 and the predator score is 3.
- **PREY-06** Every agent observes itself, and the nearest 2 food pellets, nearest 2 prey and nearest 2 predators within a radius of one third of the arena's width; anything outside reads "not seen".
  - Given a predator beyond the radius, when a prey's observation is taken, then that predator's entries read "not seen".
- **PREY-07** Rule-based baselines: prey flee the nearest seen predator, else move toward the nearest seen pellet; predators chase the nearest seen prey, else wander randomly.
  - Given a prey that sees a predator to its right, when the rule acts, then it pushes left.
- **PREY-08** Each trained team is evaluated against fixed opponents: trained prey against the rule-based predators, compared with random and rule-based prey; trained predators against the rule-based prey, compared with random and rule-based predators. Each passes as in EVAL-04 and EVAL-05.
  - Given 5 finished runs, when evaluated, then a separate verdict is shown for the prey team and the predator team.
- **PREY-09** The learner can play any prey checkpoint against any predator checkpoint from the same run, and see a grid of mean scores for every pairing of the 12 checkpoints of each side.
  - Given a finished run, when the pairing grid is made, then it shows a 12 × 12 grid of prey scores and of predator scores, each cell the mean of 20 held-out episodes.
- **PREY-10** The learning curve shows both teams' scores on the same step axis, so the back-and-forth between them is visible.
  - Given 5 finished runs, when the chart is made, then both teams' mean lines and bands appear against the same environment-steps axis.
- **PREY-11** Predator-prey runs through the same training runs, logging, replay viewer and evaluation as snake and fish tank, and their results reproduce unchanged after predator-prey is added.
  - Given a snake run and a fish run repeated with their original settings and seeds, when they finish, then their results match the originals exactly.

**Edge cases & errors**
- One team stops improving or collapses during co-training (e.g. predators catch nothing for the last half of the budget) → the run still finishes and the summary flags the collapse with the step it began; it is a result to explain, not an error.
- All prey are caught early in most episodes → prey score is still computed per starting prey, so it is never inflated by fewer survivors.

## Quality requirements
- **QR-01** A single training run of any world and variant finishes within 60 minutes on the learner's laptop (Apple Silicon, CPU only).
  - Checked by the run's logged start and end times.
- **QR-02** A batch of 5 runs of one world and variant finishes within 90 minutes on the same laptop, running in parallel.
  - Checked by the batch's first start and last end time.
- **QR-03** Rented GPU time, if a world truly needs it, costs at most $10 per world, and is used only after a laptop run is shown to miss QR-01.
  - Checked against the rental bill, recorded in the world's write-up.
- **QR-04** The replay viewer plays at least 30 steps per second at 1× on the laptop, for every world.
  - Checked by timing a 1,000-step replay.
- **QR-05** Final evaluation (EVAL-03 and EVAL-04) of one world and variant finishes within 10 minutes on the laptop.
  - Checked by timing the evaluation.
- **QR-06** Everything runs locally with no network connection once installed.
  - Checked by running a full train, evaluate and replay cycle with networking off.

## Assumptions
*(Not yet confirmed by the learner — see the list in the review.)*
- "About an hour of training per world" means one run ≤ 60 minutes, with the 5 runs needed for evaluation running in parallel.
- "Several training runs" means 5 runs with different seeds.
- "Clearly beats" means significant at 5% after correction, and every single run beats the rule baseline.
- "Write the core learning algorithms myself" means the learning updates and any function approximator (including how its gradients are computed) are hand-written from basic array operations.
- The reference check is an 80% bar, not a requirement to match a library.
- Fish and predator-prey both use smooth movement; predator-prey reuses the fish movement rules.
- The world sizes, counts and step limits above are starting values the learner may tune before a stage's build.
