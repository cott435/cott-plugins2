I've answered all three parts. The biggest finding is that you were right about Sharadar: it has its own API at api.sharadar.com, and its docs don't mention Nasdaq Data Link at all. My recommendations are Tiingo as the second source and exchange_calendars (XNYS) for the calendar. All pages read 2026-10-17.

**A. Sharadar**

1. **Access.** Sharadar's own docs give a direct REST API at `https://api.sharadar.com/v1.0/data/{table}` with `?api_key=`, plus a query builder, bulk downloads and spreadsheet/database templates. https://sharadar.com/docs/auth: "you or your application must provide an API key." I couldn't confirm the old Nasdaq Data Link route (`/api/v3/datatables/SHARADAR/SEP`) is still live: its documentation page didn't render and its metadata call returned HTTP 429. I found no migration notice either way.
2. **Tables.**
   - **SEP (stocks).** `open`/`high`/`low`/`close`/`volume` are split-adjusted only. `closeadj` is "Adjusted for Splits Dividends and Spinoffs" and `closeunadj` is "Close Price - Unadjusted". So the raw close is `closeunadj`, not `close`. https://sharadar.com/docs/stocks
   - **ACTIONS.** Fields are date, action, ticker, name, value, contraticker, contraname. The page says it "includes ticker changes, stock splits, cash dividends, spinoffs, ADR ratio changes", plus listing/delisting dates, delisting reasons and acquisition counterparties. The only action code shown is `split`; **the docs don't list the full set of codes**, so `dividend`, `delisted`, `acquisitionby`, `bankruptcyliquidation` and `tickerchangeto` are unconfirmed. https://sharadar.com/docs/actions
   - **TICKERS.** permaticker is "a unique and unchanging identifier for a security (share class)". `isdelisted` (Y/N), `firstpricedate`, `lastpricedate`, `category` and `relatedtickers` exist, but **the docs give no description and no category values** for category or relatedtickers. https://sharadar.com/docs/tickers
   - **SP500.** Fields are date, action, ticker, name, contraticker, contraname, note. The only action example is `action=current`; **added/removed/historical are not documented.** https://sharadar.com/docs/sp500
3. **History and delisted coverage.** Prices start December 1997 and cover "active and delisted US public stocks" (https://sharadar.com/docs/stocks). The bundle page gives SP500 and fundamentals from Jan 1998, metrics from Sep 1996 and tickers from Jun 1990 (https://sharadar.com/bundle).
4. **Permaticker across ticker changes and reuse.** It is "unique and unchanging" (https://sharadar.com/docs/tickers). The docs say nothing about ticker reuse, suffixes like "BUD1", or whether a reused ticker gets a new permaticker. Check this against real data.
5. **Bulk and rate limits.** Bulk is `?years=full` (e.g. `.../data/stocks?api_key=...&years=full`, https://sharadar.com/docs/stocks); `qopts.export` was the old Nasdaq Data Link mechanism. https://sharadar.com/docs/bulk showed only "Loading…" without a login, and `/docs/querying` returned 404. **No rate limits are published on any page I read.**
6. **Which subscription has which tables** (https://sharadar.com/bundle):
   - **Prices:** SEP, SFP, ACTIONS, SP500, TICKERS, Metrics, Descriptions.
   - **Fundamentals:** SF1, Daily, Events, ACTIONS, SP500, TICKERS, Descriptions.
   - **Bundle:** all of the above plus Investors.
   - So SP500 is included in Prices, Fundamentals and Bundle. "Core US Equities Bundle" is not Sharadar's own name; it just says "Bundle". No price is shown.

**B. Second source of raw closes**

- **Tiingo — recommended.**
  - Free tier: 50 requests/hour, 1,000/day, 500 unique symbols/month, 1 GB/month, 30+ years of history, "personal use" only. Power tier is $30/month. https://www.tiingo.com/about/pricing
  - EOD endpoint is `api.tiingo.com/tiingo/daily/<ticker>/prices`, returning `close` and `adjClose` (CRSP method), plus `divCash` and `splitFactor`. https://www.tiingo.com/documentation/end-of-day
  - Ambiguity: the page says raw and adjusted prices are both available but never explicitly calls `close` unadjusted.
  - 50 symbols back to 2005 is about 50 requests, which fits the free tier easily.
- **Alpha Vantage.** Free is 25 requests/day (https://www.alphavantage.co/support/). `TIME_SERIES_DAILY` is raw, but "the 'full' outputsize is available to premium keys"; free keys get the last 100 days only (https://www.alphavantage.co/documentation/). Not usable here.
- **EODHD.** Free gives 20 calls/day and 1 year of history; cheapest EOD plan is $19.99/month. https://eodhd.com/pricing
- **Massive (Polygon).** Free gives 5 calls/min and 2 years of history; $29/month gets 5 years. Doesn't reach 2005. https://massive.com/pricing
- **Stooq.** I couldn't find an official API or terms page (https://stooq.com/db/h/ came back empty). A third-party report says an API key, obtained via CAPTCHA, has been required since 2026 (https://github.com/pydata/pandas-datareader/issues/1012). Unclear status, so I wouldn't rely on it.
- **yfinance** is unofficial, as you noted.

**C. Trading calendar**

- **exchange_calendars — recommended.** Current version is 4.13.2 (10 Mar 2026), https://pypi.org/project/exchange-calendars/.
  - Sandy closures 2012-10-29/30 are in `HurricaneSandyClosings`, and `USNationalDaysofMourning` includes 2018-12-05 and 2025-01-09. https://github.com/gerrymanoim/exchange_calendars/blob/master/exchange_calendars/us_holidays.py
  - **The default start is 20 years before today, which is 2006-10-17 now.** For 2005 you must pass `start="2005-01-01"`. https://github.com/gerrymanoim/exchange_calendars/blob/master/exchange_calendars/exchange_calendar.py: `GLOBAL_DEFAULT_START = ... - pd.DateOffset(years=20)`.
- **pandas_market_calendars** 5.5.0 (5 Oct 2026) mirrors exchange_calendars' calendars and adds `schedule()` with open/close times in UTC and early closes. https://pypi.org/project/pandas-market-calendars/ For daily data it adds little.

**Should check yourself:** the full list of ACTIONS and SP500 action codes, permaticker behaviour on reused tickers, API rate limits, and whether Tiingo's `close` really is unadjusted. A small probe against live data would settle all four.
