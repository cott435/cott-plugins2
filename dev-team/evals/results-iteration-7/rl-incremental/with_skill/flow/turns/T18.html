The **Grow check fires again**, and this time it's a real decision. AD-12 said "stay single-package through S1, revisit when Env 2's stage is cut", and Env 2 is here:
- the package would hold 2 environments, 5 learning agents and roughly 13 pipelines (the limit is 3);
- the contract is already 404 lines (ceiling 200) and will grow by about a third;
- PyTorch now has two users, `dqn` and the new `pg`.

**The question:** split `gridlab` into packages now, or stay single?
- **My recommendation: stay single-package through S2.** Revise AD-12 to cover S2, and enforce the seams with import rules instead of package boundaries:
  - the environments (`core`, `snake`, `corridor`, `tank`, `baselines`) never import PyTorch;
  - only `dqn` and `pg` do;
  - the lab components never import each other.

  Reasons:
  - It's one learner and one install.
  - The build agents work from per-task context packets, which stay well under their 2,000-line limit even with a large contract.
  - A split now would mean multi-package pipelines, a workspace config and per-package bars before a single line of code exists.
- **Alternative: split into three packages now.** `gridlab-envs` (core, environments, baselines; NumPy only), `gridlab-agents` (tabular, DQN, policy gradients; PyTorch) and `gridlab-lab` (training, evaluation, storage, comparison, plots, viewer, CLI). It's cleaner for the long run, and there's no code to move yet. But it adds real overhead for a personal project, and it would also redo the pipeline design and the quality bar.

If you agree to stay single, here's how I'll design the rest, so you can veto it at the same time:
- **Core interface** (the part M1-T01 will freeze):
  - an environment takes one action per agent and returns arrays holding one observation, reward and termination flag per agent;
  - the action space is a type that's either "n discrete actions" or "k continuous values with bounds";
  - a frame is a list of shapes (circle or square, with position, size, role and an optional heading);
  - the agent's `action_values` becomes a general readout: action values for DQN; the state value with probabilities, or means and spreads, for PPO.
- **New components:** `tank` (the environment) and `pg` (REINFORCE and PPO), with the flee fish added to `baselines`.
- **Decisions:**
  - a new decision for PPO's design: hand-built rollouts, GAE, the clipped loss, the switches;
  - AD-02 revised in place (still our own interface, now with many agents and continuous actions);
  - a decision for the shape frame and viewer.

Stay single-package through S2? **(yes / split)**
