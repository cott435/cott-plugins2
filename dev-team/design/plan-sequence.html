Around the sequence

How dt next picks the next column

  1. A doc still Draft or Proposed: back to its owner's gate.
  2. Reference files waiting: reference-intake (once a roadmap exists).
  3. Probes cited with no entry, or results waiting: api-probe.
  4. A change in docs/routes.md: its owner's Revise or Extend.
  5. A request the Approved doc doesn't honour: that doc's skill.
  6. Otherwise the first skill in order with work to do. Declined test planning is skipped with --skip test-planning.

What blocks what

  • build-planning New stops until every stage from the brief has Approved pipelines.
  • An open probe blocks planning the milestone it serves, though the cut still runs.
  • A Grow trigger (over 3 pipelines, 12 modules or a 2,000-line context) sends the run back to architecture-design Grow.
  • Each run edits only the docs it owns; a fix to another skill's doc goes through dt route.

After the first milestone

  • build-planning Advance, once every todo item and the exit checkpoint are ticked: the user approves the milestone (Done), then build-setup Ratchet tightens measured values in CONSTRAINTS.md.
  • dt archive moves the plan to tasks/archive/ and stubs tasks/plan.md; Advance writes the next milestone's plan and todo, then build-setup Extend sets a new Base.
  • A new feature starts at idea-refine Extend: docs/ideas/<slug>.md and a new S<n>, then spec-writing Extend edits docs/spec.md, and the same columns follow.
