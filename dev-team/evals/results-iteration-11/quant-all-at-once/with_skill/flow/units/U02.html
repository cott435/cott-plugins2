3	Turns a long panel (one row per ticker and date) into fixed-length training windows. Each window has an
4	encoder part (the lookback) and a decoder part (the forecast horizon), and the inputs are split the way
5	TFT expects them:
6	
7	- static covariates: constant per ticker (sector, listing exchange, ...), categorical, encoded as ints
8	- known covariates: known in advance for every step, including the decoder steps (calendar features)
9	- observed covariates: only known up to the forecast origin (returns, volume, the engineered features)
10	
11	Targets come from a separate frame (see tft_targets.py) joined on (ticker, date).
12	"""

24	    lookback: int = 63
25	    horizon: int = 5
26	    stride: int = 1
27	    static_cols: list[str] = field(default_factory=lambda: ["sector"])

56	def normalise_observed(panel: pd.DataFrame, cols: list[str], window: int = 252) -> pd.DataFrame:
57	    """Per-ticker z-score of observed covariates using a trailing window (no future rows)."""
58	    p = panel.sort_values(["ticker", "date"]).copy()

61	    sd = g.transform(lambda s: s.rolling(window, min_periods=20).std())

- **Purpose:** Turns a long (ticker, date) panel into fixed-length encoder/decoder windows for a TFT-style forecaster, with static, known and observed inputs kept separate, and splits them into train/valid/test.
- **Key parts:** `WindowSpec` dataclass (lookback=63, horizon=5, stride=1, column lists); `add_calendar_features(panel) -> DataFrame`; `encode_static(panel, cols) -> (DataFrame, vocab)`; `normalise_observed(panel, cols, window=252) -> DataFrame`; `build_windows(panel, targets, spec) -> dict[str, ndarray]`; `split_by_origin(arrays, train_end, valid_end) -> dict[str, dict]`.
- **In → Out:** In: a long panel DataFrame (ticker, date, sector, log_ret, log_volume, range_pct) and a targets frame (ticker, date, fwd_ret_1d). Out: static (S, n_static) int64, known (S, L+H, n_known), observed (S, L, n_obs), target (S, H, n_tgt), plus origin (S,) and ticker (S,). These are then split by origin date.
- **Use for:** Building the S4 forecasting dataset: making windows, keeping known and observed inputs apart, trailing per-ticker z-scoring, and a date-based split. It is also a pattern for checking leakage at window and split edges.
- **Caveats:**
  - **No gap at split boundaries:** `split_by_origin` cuts on the origin date only. A train sample with origin at `train_end` has targets reaching up to `horizon` (5) rows into valid, and the same happens at valid/test. A gap of at least `horizon` days (plus the target's own forward span) is needed.
  - **Rows treated as consecutive days:** windows assume each row is the next trading day. The `how="inner"` merge silently drops rows, and missing dates are not checked, so a window can quietly span gaps.
  - **Data silently dropped or filled:** tickers shorter than `lookback + horizon` are skipped without notice. `normalise_observed` replaces NaNs and zero-std cases with 0.0 via `fillna(0.0)`, including the first 19 rows before `min_periods=20` is reached.
  - **Fitted on the full sample:** `encode_static` builds its vocabulary from all dates, so it cannot handle a category it has never seen.
  - **Static values not point-in-time:** `build_windows` takes the ticker's first sector (`iloc[0]`), so later sector changes are ignored.
  - **Calendar shortcut:** `days_to_month_end` uses `np.busday_count` without a holiday calendar.
  - **Memory:** windows are built in Python lists with stride 1. For the S&P 500 this is heavy, because each 68-step window is stored separately.
  - **Empty result:** if no windows are built, each key returns `np.empty((0,))`, which has the wrong shape for downstream code.
  - **Hard-coded defaults:** the column names and the 63/5/252 window lengths are fixed in the code.
  - No instructions addressed to an AI were found in the text.
- **Stage guess:** S4 — it prepares windowed datasets specifically for a neural return forecaster.
