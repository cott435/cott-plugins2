# RL Lab

**Status:** Draft · **Last updated:** 2026-10-18

## The problem
Reading about reinforcement learning (agents that learn by trial, error and reward) doesn't build intuition. Library code hides the parts that matter, and a trained agent with nothing to compare it to proves nothing. This small project is a lab of little 2D worlds. Each world teaches one idea, built by hand and shown working.

## Who it's for
One learner: me. I know Python and am learning reinforcement learning and the quantitative side. I work evenings and weekends.

## Goals
1. I write each learning method myself and understand why it works, well enough to explain it in a short note.
2. Every agent is clearly better than a random agent and a simple scripted agent, so "it learned" is a fact, not a feeling.
3. I can watch any trained agent play, so I can see what it learned, including the wrong things.
4. Each world teaches one new idea. Environments are built in a fixed order: Snake, then fish, then predator and prey. Each is finished before the next starts.

## Constraints
- A laptop, no graphics card. Each environment should train in under about an hour. Renting a cloud GPU for a few dollars is an option if truly needed.
- Evenings and weekends; each environment takes a few weeks.
- Learning methods are written from scratch, then checked against a standard library's version.

## What success looks like
- Snake and the fish tank each have a watchable replay, a learning curve above both baselines, and a note explaining why it works.
- My own versions of the methods land in the same range as a library's on the same world.
- Predator and prey: the two training approaches (both sides learning at once, and training against past versions of the opponent) are run and compared. Whatever the result, it's explained. This environment doesn't decide whether the project succeeded.

## What we're betting on
- These worlds are small enough to learn well on a laptop within an hour.
- A scripted agent can be simple and still be a fair bar. A clever scripted fish that flees the ball may be near-perfect. Then "beats it" may be the wrong test, and "matches it" may be the right one.
- Adding one idea at a time keeps failures diagnosable: one fish that sees everything comes before several fish that see only what's nearby.

## Not doing
- A reusable framework or library for others: this is a learning lab, not a product.
- Realistic physics or 3D: simple 2D rules are enough to teach the ideas.
- Large hyperparameter searches or long cloud runs: they break the one-hour, laptop-first limit.
- A polished app or web interface: a replay I can watch is enough.
- More environments before predator and prey is done.

## Open questions
- Should agents learn from screen pixels, or from a compact description of the world (positions, nearby cells)? Default: compact description only. Pixels are slower to train and teach a different lesson.
