# Milestone shape: interface, step spines, wiring, system

Read when writing a milestone's tasks. Examples: `examples-phase0.md`.

A milestone is planned from its pipelines' steps: each step has one owner, one module and typed `In → Out`, so it is the unit of work. The plan freezes every boundary between steps first, so the work on both sides starts at once instead of queueing behind one spine. Every task carries `**Kind:**`:

```
## Phase 0: Interface              interface (solo, first)       types, signatures, samples, fakes, exports, __main__
## Phase 1: Step spines            spine, one per step           each writes its owner module only
## Phase 2: Wiring and thicken     wiring, one per pipeline      its entry module, smoke test
                                   thicken (tasks.md)            each after its step's spine
## Phase 3: System                 system (solo, last)           fakes swapped for real providers
```

Phases name the usual waves; the dependency graph (`tasks.md` step 9) decides what may start. Tester halves of split tasks start right after the interface.

**a. Interface task** (`**Kind:** interface`, `**Step:** contract`, solo, `**Depends on:** —`). It freezes, as code, every boundary in the milestone whose two sides belong to different tasks:
- each contract `type` section named in a milestone step's `In → Out`, every one, since the step's signature needs it, written into its owner's `types.py`, with a schema (pandera for a frame, JSON Schema across runtimes) and one sample per case in `tests/contracts/<component>.<Type>/`. A case naming a probe sample (`PB-01 samples/sync_added.json#0`) puts `PB-01:samples` in `Read:`; the task derives the type's sample from it, never copies it
- each new step's signature in its owner module, its body `raise NotImplementedError("<task id>")` naming the task that replaces it (Fakes and stubs)
- for each function another pipeline or package calls (its `**Boundary:**` line names that consumer): a fixture-backed fake serving its fixtures, where the caller's tests load it, and its contract's cases as one test that takes the provider
- for each object with behavior a step passes (a Protocol or class: `core.Dataset`, `runstore.RunWriter`) and each call to a function another task builds in the caller's own pipeline and package (a `**Boundary:**` line naming a component too): the Protocol or signature plus a fixture-backed replay double in `tests/contracts/<component>.<Type>/`. The double is that type's sample, not a fake: the system task never swaps it
- each component's `__init__.py` exports, and the package's `__main__.py`: the dispatch from each pipeline's trigger to its entry function, whose signature it stubs naming the wiring task, in that pipeline's own entry module

Not frozen: helpers, private functions, anything one task owns end to end, and boundaries an earlier milestone froze. `Read:` the type and boundary symbols. Acceptance: every sample validates against its type; every signature imports and matches the contract; each fake passes its contract's cases, and each replay double serves its fixtures. A human approval a requirement places before several steps (a design direction) is asked during planning or is this task's acceptance ("direction approved; `design.Theme` sample written"); those steps build on the sample, with no edge to the step that sets it. `Writes:` each component folder as one glob (`src/gridload/profile/**`) plus its contract folders; `task-size` doesn't count them. # RL Lab — Architecture

**Status:** Approved · **Shape:** Single package · **Last updated:** 2026-10-18 · **Spec:** [spec.md](spec.md)

## Overview
Three NumPy worlds (Snake, fish tank, predator and prey) sit behind one `Env` protocol that hands each role a compact observation array, never pixels. Hand-written PyTorch learners (DQN for Snake, PPO for the fish and both predator-prey sides) train against batched world copies on the laptop CPU for a fixed number of environment steps, record a learning curve on held-out curve seeds, and save the agent into a plain-file run folder. Every agent, trained, baseline or reference, is a `Policy`, so evaluation, replay and the statistics treat them alike. A world is signed off when its run folder holds every artefact DONE-01 names and the learner's note passes its checks. Tests can start a world from a planted state and train the learners on small registered test worlds.

```mermaid
  worlds --> core
  baselines --> worlds
  learners --> evaluate
  coevo --> learners
  reference --> evaluate
  evaluate --> store
  replay --> store
  signoff --> store
  store --> core
```

## Data
- **Worlds are generated, not downloaded.** Every episode is set by one integer seed (AD-10), or starts from a planted state in tests (AD-16).
- **Seeds (DATA-01):** per world, evaluation seeds are 0–99, learning-curve seeds 100–119, training seeds 1,000,000 and up; `core.seeds` is the only source, and `learners` refuses a training seed below 1,000,000.
- **Observations** are float32 arrays per role, shape (agents, features): Snake per AD-04, fish and predator-prey per AD-06. Rewards per AD-07.
- **Run folder** `runs/<world>/<run-id>/` (AD-11): `record.json` (seed, settings, duration, curves, status: DATA-02), `policy.pt` only for a finished run (LEARN-03, AD-15), `scores/<agent>.json`, `comparisons.json`, `curve.png`, `recordings/<agent>-<seed>.json.gz`; a prey run adds `snapshots/<regime>/<role>/` (AD-13). Notes live in `notes/<world>.md`, committed; `runs/` is git-ignored.

## Cross-cutting concerns
- **Speed (QR-01):** training steps 16 world copies and makes one batched policy call per step; the loop ends at the run's `total_steps`, set per world from measured steps per second so the run fits the hour, and `time_limit_s` (3,600 by default) is the backstop (AD-18). The duration is recorded. Small MLPs run on CPU (AD-09).
- **Reproducibility (QR-03):** one `np.random.Generator` and one `torch.Generator` per run from the run seed, no global random state; `torch.use_deterministic_algorithms(True)` and a fixed thread count in the settings. The run length and curve points are counted in environment steps, never wall-clock time (AD-18); a run cut short by the time limit says so in its record and doesn't count as a repeat.
- **Errors:** a not-a-number loss or score stops the run with status `diverged` and the curve point where it happened; an interrupted run keeps its curve with status `stopped` and no `policy.pt`. A policy loaded into the wrong world raises `ValueError` naming both worlds.
- **Skills:** `evaluate` runs every significance claim as the `null-hypothesis-testing` skill specifies and draws every chart as the `dataviz` skill specifies (AD-14).
- **Testing:** world rules are tested on planted states from `worlds.from_state` (AD-16; each spec Given/When/Then is a test); learners on test worlds registered with `worlds.register` (AD-17); the reference adapter with SB3's `check_env`.

## Decisions
### AD-01: One Python 3.12 package, `rllab`
**Status:** Accepted · **Date:** 2026-10-18 · **Scope:** system
- **Context:** A one-person learning lab on one laptop, with no separate install, deployment or owner (brief: Not doing, a framework). PyTorch, SB3 and pygame-ce all ship 3.12 wheels for Apple Silicon.
- **Decision:** One package `rllab` with one folder per component. The `reference` component is the seam that carries Stable-Baselines3; it is the only importer of `stable_baselines3` and `gymnasium`, so it could move out if that stack ever gets in the way.
- **Alternatives:** A package per world — no real boundary; the worlds share every protocol. Python 3.13 — wheel coverage lags for some of the stack.
- **Consequences:** `requires-python = ">=3.12,<3.13"`. The import rule (only `reference` imports SB3) is checked by import-linter.
