The S5 spec is approved, and its idea file is frozen as **Specced**. Next is architecture (Extend mode) for S4 and S5 together. They share one environment, so designing them in one round avoids redoing the boundaries. About 55 requirements need a home, and GATE-05, GATE-06 and DATA-09 changed.

## Grow check
The dependency-stack trigger fires: **PyTorch** for the LSTM and TFT forecasters and the PPO networks, plus a GARCH fitter. Nothing in S1 to S3 should carry those. The two stages together have about 10 workflows (naming the benchmark, forecast run, portfolio run, freeze, paper step, settlement, reference check, train, evaluate, agent freeze). That's far past one package's limit.

## The one decision: shape
**My recommendation: three new packages, each depending only downward:**

```
agents   → forecast, trading, portfolio, data     (S5: PPO, agent environment, agents)
forecast → trading, features, portfolio, data     (S4: forecasters, forecast portfolios)
trading  → features, portfolio, data              (S4: environment, costs, benchmark naming,
                                                   paper settlement and verdicts)
```

- **`trading` is the arena with no neural code:**
  - the monthly environment with costs (ENV)
  - S2's strategies as baseline competitors
  - benchmark naming
  - **paper-trading settlement and verdicts** (PAPER-03, PAPER-05), which need only recorded weights and returns
- **`forecast` (PyTorch)** holds the volatility and return forecasters, the forecast portfolios, and **its own paper step**. That step records the frozen forecast models' weights, and `trading` settles them.
- **`agents` (PyTorch)** holds PPO, the agent environment (built on `trading`'s environment, with `forecast`'s portfolios as sleeves), the agents, and **their own paper step**.
- **Why paper trading is split this way:** a single paper step that ran every frozen model would have to import `agents` from `trading`, which is backwards. Splitting "produce weights" (in each competitor's package) from "settle and judge" (in `trading`) keeps every dependency pointing down, with no plug-in registry.
- **Ledger:** all three write to S3's ledger through `features`' contract. `features.LedgerEntry`'s list of entry kinds widens to S4 and S5's kinds (benchmark, forecast test, portfolio claim, freeze, paper month, agent config). That's a small contract change to `features`.
- **Alternatives:**
  - **One `trading` package for S4 and S5:** about 10 pipelines and about 12 modules, which is past the limits again.
  - **Two packages (`forecast` with the environment inside, plus `agents`):** works, but paper settlement would then live with PyTorch code it doesn't need.

## What I'd decide next, unless you object (each becomes a decision record)
- **PyTorch 2.x** for the neural forecasters and PPO networks, deterministic settings, Apple GPU (MPS) when available with CPU otherwise. Seeds are fixed and reported runs record the device.
- **The `arch` library for GARCH(1,1).** HAR and EWMA are written with NumPy.
- **Reference implementation for PPO-01 and PPO-02:** **Stable-Baselines3**, as a test-only and reference-check dependency, never imported by the agents themselves. The control task is **CartPole**, via Gymnasium, also test-only.
- **The TFT is written in PyTorch rather than using pytorch-forecasting.** It's smaller, and it avoids RF-02's pandas pipeline. RF-02 and RF-03 serve as prior art, minus their caveats.
- **Paper-trading deadline (PAPER-02):** checked against the ledger entry's UTC timestamp, converted to 09:30 New York time on the first trading day.

Do you approve the three-package shape (`trading`, `forecast`, `agents`) and the defaults above? (Default: yes.)
