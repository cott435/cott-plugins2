Pipeline design is in **Extend** mode. Like S2, most of S3 rides on the existing workflows:
- **`gridlab train` (PL-01):** the foraging tank, the team agent with its schedules and snapshots, the chaser, and team evaluation (FORAGE, SELF, BASE-06, EVAL-05).
- **Presets (PL-02):** the five schedules and the speed sweep.
- **`gridlab compare` (PL-03):** "learned side vs scripted reference" (XPLAY-06), because a foraging run's final evaluation already scores each side against its reference.

**Cross-play measurement is genuinely new work that you'd run on its own.** Nothing is written yet. Here are the candidates, alongside the existing pipelines:

| # | Workflow | Trigger | What it does | Sits beside |
|---|---|---|---|---|
| A | **PL-10: Cross-play a run set** | `gridlab xplay forage-pool` | For every complete run in the preset: reference curves, cross-play matrix and forgetting scores (`xplay.json` per run), plus one heatmap per run | PL-05 (plots) |
| B | **PL-11: Compare forgetting** | `gridlab compare-forgetting forage-pool forage-simultaneous` | Reads both sets' `xplay.json` files and writes the pool-vs-simultaneous forgetting comparison for the `null-hypothesis-testing` skill. The verdict then goes through the existing `gridlab report` (PL-04). | PL-03 (compare) |

Which do you want?
1. **Both A and B (recommended).** They're separate because the skill runs between them, as with compare and report, and because you'll re-run cross-play on single sets far more often than the comparison.
2. **Only A,** with B folded in as a `--against forage-simultaneous` flag.

Either way, the steps will need a few small contract additions, routed back through `architecture-design` like last time. The likely ones are the `run_xplay` and `run_compare_forgetting` entries, a function to load a run's `xplay.json`, and a plot function for a whole set of heatmaps.
