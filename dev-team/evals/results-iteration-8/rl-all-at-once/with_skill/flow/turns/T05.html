# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [brief.md](brief.md)

## Summary
A lab of three small 2D worlds (Snake, a fish tank with a bouncing ball, and predator-prey foraging) where hand-written reinforcement-learning agents learn by trial and error. A shared core supplies the world interface, training loop, logging, evaluation against baselines, and a replay viewer. Each world ships with a lab note explaining why its learner works, and a comparison against an established library. Why: see the [brief](brief.md).

## Users
| User | What they need to do |
|---|---|
| Learner (project owner) | Train an agent in any world on a laptop, check that it beats random and scripted play, watch it play at several stages of training, and explain why it works |

## Scope
**In scope:** World interface (`WORLD`), Training and logging (`TRAIN`), Baselines and evaluation (`EVAL`), Replay viewer (`REPLAY`), Lab notes and break-it runs (`LAB`), Library comparison (`CMP`), Snake world (`SNAKE`), Value learners (`VALUE`), Fish tank world (`TANK`), Policy learner (`POLICY`), Predator-prey world (`HUNT`), Co-evolution training (`COEV`).

**Out of scope:**
- 3D physics.
- Learning from pixels, and Atari games.
- Reproducing research papers or matching published numbers.
- Web deployment, or any polished app beyond a local replay window.
- Training with a library first. Libraries appear only in the library comparison (`CMP`).
- Fish-to-fish collisions. Fish may overlap.
- Training that requires a GPU.

## Features

### World interface (`WORLD`)
**Serves:** Goal 4
**Behavior:** Every world offers the same way to start an episode from a seed, take actions, and receive observations, rewards and an end-of-episode signal. Worlds with several agents give each agent its own observation and take one action per agent. Training, evaluation and replay work with any world by name.

**Requirements**
- **WORLD-01** Every world starts a new episode from a given seed and returns the first observation for each agent.
  - Given any world and seed 7, when an episode is started twice, then both first observations are identical.
- **WORLD-02** Every world advances one step for a set of actions and returns, for each agent, its next observation, its reward, and whether it is done.
  - Given a running episode, when one action per active agent is given, then exactly one observation, one reward and one done flag come back for each of those agents.
- **WORLD-03** Every world describes its observation size and its action form (a choice from a fixed list, or a vector of numbers within stated bounds).
  - Given any world, when its description is read, then the observation size and the action form are stated, and every observation it produces matches that size.
- **WORLD-04** A world runs with no display attached. Drawing happens only when a replay asks for it.
  - Given a machine with no display, when 1,000 steps of any world are run, then they complete without error.
- **WORLD-05** Training, evaluation and replay can each be pointed at any of the three worlds by name, with no change to their own code.
  - Given the training command, when the world name is switched from Snake to Tank, then training runs on the tank with only the world name and learner settings changed.

**Edge cases & errors**
- An action given for an agent that is already done → that action is ignored, and no observation is returned for that agent.
- An action outside the stated bounds or list → it is rejected with an error naming the world and the bad action.
- An unknown world name → an error listing the valid names.

### Training and logging (`TRAIN`)
**Serves:** Goal 4, Goal 2
**Behavior:** One training loop runs any learner in any world. Each run records its settings, its seed, a learning curve and saved snapshots of the agent, so any run can be inspected, replayed or repeated later.

**Requirements**
- **TRAIN-01** A training run is fully described by a named settings file and a seed, and saves both alongside its results.
  - Given a finished run, when its folder is opened, then the exact settings and seed used are there.
- **TRAIN-02** A training run records, for every episode, the training step count and the episode score.
  - Given a finished run, when its log is read, then every completed training episode has a step count and a score.
- **TRAIN-03** A training run evaluates the agent at regular intervals, at least 20 times per run, and records the mean evaluation score.
  - Given a finished run, when its log is read, then there are ≥ 20 evaluation points, evenly spaced in training steps.
- **TRAIN-04** A training run saves agent snapshots at 0%, 25%, 50%, 75% and 100% of its training steps.
  - Given a finished run, when its snapshots are listed, then those five exist and each can be loaded and played.
- **TRAIN-05** A learning-curve chart, made with the `dataviz` skill, shows the evaluation score over training steps, with the random and scripted baselines drawn as reference lines.
  - Given a finished run, when its chart is made, then the curve and both baseline lines appear on the same axes.
- **TRAIN-06** A training run that is stopped part-way keeps every snapshot and log entry written before it stopped.
  - Given a run interrupted at 60% of its steps, when its folder is opened, then the logs up to that point and the 0%, 25% and 50% snapshots are intact.

**Edge cases & errors**
- A settings file with an unknown or missing setting → the run refuses to start and names the setting.
- A results folder that already exists for the same run name → the run refuses to overwrite it unless told to.

### Baselines and evaluation (`EVAL`)
**Serves:** Goal 2
**Behavior:** Every world has a random baseline and a scripted baseline. Evaluation plays any agent on fixed seeds that training never uses, and decides whether it beats a baseline by more than chance.

**Requirements**
- **EVAL-01** Every world has a random baseline that picks uniformly among allowed actions.
  - Given any world, when the random baseline plays 100 evaluation episodes, then a mean score is reported.
- **EVAL-02** Every world has a scripted baseline, as defined in that world's feature.
  - Given any world, when its scripted baseline plays 100 evaluation episodes, then a mean score is reported.
- **EVAL-03** Evaluation uses a fixed set of 100 seeds that no training run ever uses.
  - Given any training run, when the seeds it used are compared with the evaluation seeds, then none overlap.
- **EVAL-04** Whether an agent beats a baseline is decided with the `null-hypothesis-testing` skill. It is given both sets of 100 evaluation scores on the same seeds. The agent passes only if its mean is higher and the difference is significant at 5%, corrected for the number of comparisons made in that world.
  - Given an agent and a baseline with their 100 scores each, when tested, then the result says pass or fail, with the p-value and the correction used.
- **EVAL-05** Evaluation of a trained agent picks its actions without exploration noise.
  - Given the same agent and the same seed, when evaluated twice, then the scores are identical.

**Edge cases & errors**
- An agent whose 100 scores are all identical to the baseline's → reported as fail, not as an error.

### Replay viewer (`REPLAY`)
**Serves:** Goal 3
**Behavior:** A live window on the laptop plays episodes of any world. It can show snapshots of one run side by side on the same seed, so progress is visible. An episode can also be saved as a video file.

**Requirements**
- **REPLAY-01** The viewer plays an episode of any world for a chosen snapshot and seed in a live window.
  - Given a finished Snake run, when its 100% snapshot is replayed on seed 3, then a window shows the episode moving step by step.
- **REPLAY-02** The viewer shows up to four snapshots of the same run side by side, playing the same seed in step with each other.
  - Given a run's 0%, 25%, 50% and 100% snapshots, when shown together, then four panels play the same seed, each labelled with its snapshot.
- **REPLAY-03** The viewer can play, pause and advance one step at a time.
  - Given a paused replay, when advance is pressed, then every panel moves forward exactly one step.
- **REPLAY-04** The viewer can change playback speed from 0.25× to 4×.
  - Given a playing replay at 1×, when set to 4×, then steps advance four times as fast.
- **REPLAY-05** A replay of a given snapshot and seed matches the evaluation episode on that seed.
  - Given a snapshot whose evaluation score on seed 3 is 12, when seed 3 is replayed, then the score shown at the end is 12.
- **REPLAY-06** Any replay can optionally be saved as a video file instead of, or as well as, being shown live.
  - Given a replay with saving turned on, when it ends, then a video file of the whole episode exists and plays in the laptop's standard video player.
- **REPLAY-07** Each panel shows the current step and the score so far.
  - Given any replay, when it is playing, then each panel shows its step number and score.

**Edge cases & errors**
- Snapshots from different worlds chosen for one side-by-side view → refused with an error.
- A panel whose episode ends before the others → that panel holds on its final frame and shows "done".

### Lab notes and break-it runs (`LAB`)
**Serves:** Goal 1
**Behavior:** Each world ends with a short written lab note, in the owner's own words, explaining why its learner works. It is backed by runs that remove one part of the learning method on purpose and show what breaks.

**Requirements**
- **LAB-01** Each world has a lab note explaining, in plain language, what the learner estimates or optimises and why its updates improve play.
  - Given a finished world, when its lab note is read, then it explains the learner's update and links to that world's headline learning curve.
- **LAB-02** Each world's lab note includes at least two break-it runs. Each removes or disables one named part of the learning method, keeping everything else and the seed unchanged.
  - Given a world's lab note, when its break-it runs are listed, then there are ≥ 2, each naming the one part it removed.
- **LAB-03** Each break-it run's learning curve is drawn on the same chart as the intact run, using the `dataviz` skill.
  - Given a break-it run, when its chart is opened, then the intact and broken curves share the same axes.
- **LAB-04** Each break-it run states what the owner predicted would happen before running it, and what did happen.
  - Given a break-it run, when its entry is read, then it has a prediction and an outcome.
- **LAB-05** The lab note's conclusions agree with the logged results it cites.
  - Given a claim in a lab note, when the cited run's log is checked, then the numbers match.

**Edge cases & errors**
- A break-it run that does not hurt learning → recorded as a finding, with the owner's explanation, not hidden.

### Library comparison (`CMP`)
**Serves:** Goal 1
**Behavior:** When a world is finished, its hand-written learner is compared with an established reference implementation of the same kind of learner, on the same world, with the same training-step budget.

**Requirements**
- **CMP-01** For each world, the reference implementation is trained on the same world, with the same training-step budget and the same training seeds as the hand-written learner.
  - Given a finished world, when its comparison runs, then both learners' settings show the same world, step budget and seeds.
- **CMP-02** The hand-written learner's mean evaluation score reaches ≥ 80% of the reference implementation's, on the 100 evaluation seeds.
  - Given both learners evaluated on the 100 seeds, when their means are compared, then the hand-written mean is ≥ 0.8 × the reference mean.
- **CMP-03** The reference implementation is used only for this comparison. No hand-written learner calls it or uses its code.
  - Given any hand-written learner, when its code is inspected, then it does not use the reference implementation.
- **CMP-04** The comparison is recorded in that world's lab note, with both learning curves on one chart.
  - Given a finished world's lab note, when its comparison section is read, then both curves and both mean scores appear.

**Edge cases & errors**
- Hand-written learner below 80% → the world is not finished. The gap and its suspected cause are recorded in the lab note.

### Snake world (`SNAKE`)
**Serves:** Goal 2, Goal 3
**Behavior:** Classic Snake on a 10×10 grid. The snake moves one cell per step, can turn left, turn right or go straight, grows when it eats food, and dies when it hits a wall or itself.

**Requirements**
- **SNAKE-01** The world is a 10×10 grid with a snake starting at length 3 and one piece of food on a free cell.
  - Given a new episode, when it starts, then the snake is length 3 and exactly one food cell exists, not under the snake.
- **SNAKE-02** Each step the snake chooses one of three actions: turn left, go straight or turn right, relative to its heading.
  - Given a snake heading north, when it turns left, then its head moves one cell west.
- **SNAKE-03** Eating food grows the snake by one cell, adds 1 to the score, and places new food on a random free cell.
  - Given the head moves onto food, when the step ends, then length and score each rise by 1 and new food is on a free cell.
- **SNAKE-04** Moving into a wall or the snake's own body ends the episode.
  - Given the head is next to a wall and moves into it, when the step ends, then the episode is done.
- **SNAKE-05** The episode also ends after 100 consecutive steps without eating.
  - Given 100 steps since the last food, when the 100th step ends without eating, then the episode is done.
- **SNAKE-06** The episode score is the number of food items eaten.
  - Given an episode that ate 7 items, when it ends, then its score is 7.
- **SNAKE-07** The scripted baseline moves toward the food along the shorter axis distance, and never takes a move that ends the episode immediately when a safe move exists.
  - Given food to the east and a body cell directly east, when the baseline chooses, then it does not move east if another move is safe.
- **SNAKE-08** The world offers two observations: a compact summary (danger straight ahead, left and right, plus the food's direction), and a full view of the grid as numbers (snake body, head, food).
  - Given any state, when each observation is requested, then the compact one has the same fixed small size every time and the full one encodes every grid cell.

**Edge cases & errors**
- The snake fills every free cell → the episode ends as a win, with the score counted.
- No safe move exists for the scripted baseline → it goes straight.

### Value learners (`VALUE`)
**Serves:** Goal 1, Goal 2
**Behavior:** Two hand-written learners estimate how good each action is in each situation. The first stores those estimates in a lookup table, on Snake's compact observation. The second learns them with a neural network, on Snake's full observation. A lab experiment shows why the table approach does not scale.

**Requirements**
- **VALUE-01** The lookup-table learner is written from basic array operations and learns on Snake's compact observation.
  - Given the lookup-table learner, when its code is inspected, then it uses no learning library.
- **VALUE-02** The trained lookup-table learner beats the random baseline on Snake (`EVAL-04`).
  - Given its 100-seed evaluation, when compared with the random baseline, then the test passes.
- **VALUE-03** The neural-network value learner is written by hand, using only basic tensor operations, automatic gradients and a standard optimiser. It includes a replay memory of past steps and a separately updated copy of its value estimates as named, switchable parts.
  - Given the network learner's settings, when the replay memory or the separate copy is switched off, then the learner still runs.
- **VALUE-04** The trained neural-network value learner beats both the random and the scripted baseline on Snake (`EVAL-04`).
  - Given its 100-seed evaluation, when compared with each baseline, then both tests pass.
- **VALUE-05** A lab experiment runs the lookup-table learner on Snake's full observation, and reports how many table entries it fills and its evaluation score after the same step budget as the network learner.
  - Given that experiment, when it finishes, then the table size and the score are recorded in Snake's lab note, alongside the network learner's score.
- **VALUE-06** Snake's break-it runs (`LAB-02`) include removing the replay memory and removing the separate copy of the value estimates.
  - Given Snake's lab note, when its break-it runs are listed, then both of those are present.

**Edge cases & errors**
- The value estimates become invalid numbers during training → the run stops, saves its log, and reports the step at which it happened.

### Fish tank world (`TANK`)
**Serves:** Goal 2, Goal 3
**Behavior:** A round tank with one ball bouncing around inside at constant speed. Fish swim with smooth, continuous movement and must avoid the ball. It runs in two settings: one fish that sees everything, and a school of 8 fish that each see only what's nearby. A fish touched by the ball is caught and leaves the tank.

**Requirements**
- **TANK-01** The ball moves at constant speed and bounces off the round wall, with its angle of reflection equal to its angle of incidence.
  - Given a ball hitting the wall, when the bounce is computed, then its speed is unchanged and it stays inside the tank.
- **TANK-02** Each fish's action is a pair of numbers, each within −1 to 1, setting its push forward and its turn. Its speed is capped at a fixed maximum below the ball's speed.
  - Given an action of (1, 0) held for many steps, when speed is measured, then it never exceeds the fish maximum.
- **TANK-03** Fish cannot leave the tank. A fish moving into the wall stops at it.
  - Given a fish pushing into the wall, when the step ends, then the fish is on or inside the wall.
- **TANK-04** A fish touched by the ball is caught, and is removed from the tank for the rest of the episode.
  - Given the ball overlaps a fish, when the step ends, then that fish is done and no longer appears.
- **TANK-05** An episode ends when every fish is caught or after 60 simulated seconds, whichever comes first.
  - Given no fish caught, when 60 simulated seconds pass, then the episode is done.
- **TANK-06** A fish's score is its survival time in simulated seconds. The episode score is the mean across its fish.
  - Given a school where fish survived 10, 20 and 60 seconds, when scored, then the episode score is 30.
- **TANK-07** In the single-fish setting, the fish sees the ball's position and velocity and its own position, heading and velocity.
  - Given the single-fish setting, when an observation is read, then it holds those values.
- **TANK-08** In the school setting there are 8 fish. Each sees only things within one quarter of the tank's width: the ball if it is that close, and up to the 3 nearest fish that close. Each fish always sees its own position, heading, velocity and distance to the wall.
  - Given a ball farther than one quarter of the tank's width from a fish, when that fish's observation is read, then it marks the ball as not visible.
- **TANK-09** The scripted baseline swims directly away from the ball at full speed when it sees the ball, and holds still otherwise.
  - Given the ball to a fish's east and visible, when the baseline acts, then the fish pushes west at full strength.
- **TANK-10** Initial positions of the ball and fish are random but reproducible from the seed. No fish starts within one quarter of the tank's width of the ball.
  - Given any seed, when an episode starts, then every fish is at least that distance from the ball.

**Edge cases & errors**
- Ball and fish start overlapping → not possible (`TANK-10`).
- A fish at the wall with the ball approaching → it can still move along the wall or away from it, never through it.

### Policy learner (`POLICY`)
**Serves:** Goal 1, Goal 2
**Behavior:** A hand-written policy-gradient learner that outputs continuous actions and limits how far each update moves the policy. In the school setting, all 8 fish share one policy, and each acts on its own local observation.

**Requirements**
- **POLICY-01** The policy learner is written by hand, using only basic tensor operations, automatic gradients and a standard optimiser. Its step-size limit on each policy update, and its use of an estimated baseline value to reduce noise, are named, switchable parts.
  - Given the policy learner's settings, when the step-size limit or the baseline value is switched off, then the learner still runs.
- **POLICY-02** The policy outputs a continuous action within each world's stated bounds.
  - Given any observation, when the policy acts, then every action number is within −1 to 1.
- **POLICY-03** In the school setting, one shared policy acts for all 8 fish, each on its own observation, and learns from all of their experience.
  - Given a school training run, when its snapshot is inspected, then it holds one policy, used by every fish.
- **POLICY-04** The trained single fish beats the random and the scripted baseline in the single-fish tank (`EVAL-04`).
  - Given its 100-seed evaluation, when compared with each baseline, then both tests pass.
- **POLICY-05** The trained school beats the random and the scripted baseline in the school tank (`EVAL-04`).
  - Given its 100-seed evaluation, when compared with each baseline, then both tests pass.
- **POLICY-06** The tank's break-it runs (`LAB-02`) include removing the step-size limit and removing the baseline value.
  - Given the tank's lab note, when its break-it runs are listed, then both of those are present.

**Edge cases & errors**
- Every fish in the school is caught early in training → the episode ends normally and training continues.

### Predator-prey world (`HUNT`)
**Serves:** Goal 2, Goal 3
**Behavior:** The same round tank, with 6 prey fish, 1 predator fish and food pellets, and no ball. Prey eat pellets and avoid the predator. The predator catches prey. A caught prey leaves the tank.

**Requirements**
- **HUNT-01** The world reuses the tank's round walls and continuous fish movement, with 6 prey and 1 predator.
  - Given a new episode, when it starts, then there are 6 prey and 1 predator inside the tank.
- **HUNT-02** There are always 10 food pellets in the tank. A pellet a prey touches is eaten, and a new one appears at a random point.
  - Given a prey touches a pellet, when the step ends, then that prey's pellet count rises by 1 and 10 pellets remain.
- **HUNT-03** A prey the predator touches is caught, and leaves the tank for the rest of the episode.
  - Given the predator overlaps a prey, when the step ends, then that prey is done.
- **HUNT-04** The predator's top speed is at most 1.2× the prey's top speed.
  - Given both at full speed, when measured, then the predator's speed is ≤ 1.2× the prey's.
- **HUNT-05** An episode ends when all prey are caught or after 60 simulated seconds.
  - Given 60 simulated seconds pass with prey alive, when the step ends, then the episode is done.
- **HUNT-06** The predator's episode score is the number of prey caught. The prey side's episode score is the mean number of pellets eaten per prey.
  - Given 3 prey caught and prey that ate 4, 2, 0, 6, 1 and 5 pellets, when scored, then the predator scores 3 and the prey score 3.
- **HUNT-07** Every fish sees only things within one quarter of the tank's width: the nearest 3 pellets, the predator (for prey), up to 3 nearest prey, and its own position, heading, velocity and distance to the wall.
  - Given the predator farther than one quarter of the tank's width from a prey, when that prey's observation is read, then the predator is marked as not visible.
- **HUNT-08** The scripted predator chases the nearest visible prey, and otherwise swims toward the tank's centre.
  - Given one visible prey, when the scripted predator acts, then it heads toward that prey.
- **HUNT-09** Scripted prey flee directly away from a visible predator, and otherwise swim toward the nearest visible pellet.
  - Given the predator visible, when a scripted prey acts, then it heads directly away from the predator.

**Edge cases & errors**
- The predator touches two prey in one step → both are caught.
- A pellet appears inside a fish → it can be eaten from the next step on.

### Co-evolution training (`COEV`)
**Serves:** Goal 1, Goal 2
**Behavior:** Predator and prey both learn, using the policy learner. First, one side learns while the other is frozen, and the sides swap, for several rounds. Then both learn at once. A round-robin tournament between saved snapshots shows whether each side kept adapting to the other.

**Requirements**
- **COEV-01** Alternating training runs at least 4 rounds. In each round one side learns and the other is frozen at its latest snapshot, and the side that learns swaps every round.
  - Given an alternating run, when its log is read, then it shows ≥ 4 rounds, alternating predator and prey.
- **COEV-02** Simultaneous training updates predator and prey in the same run.
  - Given a simultaneous run, when its log is read, then both sides' policies change during it.
- **COEV-03** Co-evolution runs save snapshots of each side at ≥ 5 evenly spaced points.
  - Given a finished co-evolution run, when its snapshots are listed, then each side has ≥ 5.
- **COEV-04** A tournament plays every predator snapshot against every prey snapshot from the same run, for 100 evaluation episodes each, and reports a table of predator scores and prey scores.
  - Given 5 snapshots per side, when the tournament runs, then a 5×5 table of both scores is reported.
- **COEV-05** In the simultaneous run's tournament, the final predator catches more of the first prey snapshot than the first predator does (`EVAL-04`).
  - Given the tournament scores, when tested with `null-hypothesis-testing`, then the final predator's catches against the first prey are significantly higher than the first predator's.
- **COEV-06** In the simultaneous run's tournament, against the final predator, the final prey snapshot eats more pellets than the first prey snapshot (`EVAL-04`).
  - Given the tournament scores, when tested with `null-hypothesis-testing`, then the final prey's pellets against the final predator are significantly higher than the first prey's.
- **COEV-07** The trained predator beats the scripted predator against the scripted prey (`EVAL-04`).
  - Given 100 evaluation episodes each, when compared, then the trained predator catches significantly more scripted prey.
- **COEV-08** The trained prey beat the scripted prey against the scripted predator (`EVAL-04`).
  - Given 100 evaluation episodes each, when compared, then the trained prey eat significantly more pellets.
- **COEV-09** The tournament table is shown as a chart, made with the `dataviz` skill.
  - Given a tournament, when charted, then both sides' scores appear for every snapshot pairing.
- **COEV-10** The predator-prey break-it runs (`LAB-02`) include skipping the alternating phase (going straight to simultaneous) and always training against only the opponent's latest snapshot.
  - Given the predator-prey lab note, when its break-it runs are listed, then both are present.

**Edge cases & errors**
- One side wins every episode for a whole round (all prey caught early, or zero catches) → the run continues and the round is flagged in the log.

## Quality requirements
- **QR-01** Each headline training run finishes in ≤ 60 minutes on the owner's laptop CPU. The headline runs are: Snake's network learner, the single fish, the school, the alternating predator-prey run, and the simultaneous predator-prey run.
  - Checked from the wall-clock time recorded in each run's log.
- **QR-02** No run requires a GPU.
  - Every headline run completes on a machine with no GPU in use.
- **QR-03** On the same machine, the same settings and seed produce identical evaluation scores.
  - Run a headline run twice with the same seed; the 100-seed evaluation scores match exactly.
- **QR-04** The replay window plays at ≥ 30 frames per second with four panels at 1× speed.
  - Measured frame rate during a four-panel replay.
- **QR-05** Every world steps at ≥ 5,000 steps per second for a single agent, with no display.
  - Timed over 10,000 steps with random actions.

## Assumptions
- Agents learn from short lists of numbers, never from pixels.
- Evaluation is 100 episodes on fixed seeds that training never uses. "Beats" means a higher mean that is significant at 5%.
- Fish do not collide with each other.
- The school shares one policy across all 8 fish.
- The library comparison happens once per world, as each world finishes.

| Goal | Features |
|---|---|
| 1. You can explain why it works | Value learners (`VALUE`), policy learner (`POLICY`), co-evolution training (`COEV`), lab notes and break-it runs (`LAB`), library comparison (`CMP`) |
| 2. Beats random and scripted play | Baselines and evaluation (`EVAL`), plus a "beats both baselines" check for each learner |
| 3. Watch it play | Replay viewer (`REPLAY`), and the Snake, Tank and Predator-prey world features (`SNAKE`, `TANK`, `HUNT`) |
| 4. Shared plumbing | World interface (`WORLD`), training and logging (`TRAIN`) |

Every "beats" check goes through the `null-hypothesis-testing` skill on the 100 evaluation seeds training never uses. All charts are made with `dataviz`.

**Numbers you didn't confirm.** I chose these to make requirements checkable, so look them over:
- **Snake:** starts at length 3. The lookup-table learner is also run on the full grid view (`VALUE-05`), which is the experiment that shows why tables don't scale.
- **Tank:** fish top speed is below the ball's, and in the school each fish sees up to 3 nearby fish. No fish starts within ¼ of the tank's width of the ball.
- **Predator-prey:** 6 prey, 1 predator, and 10 pellets that respawn when eaten. The predator's top speed is ≤ 1.2× the prey's, and each fish sees the nearest 3 pellets.
- **Co-evolution:** ≥ 4 alternating rounds and ≥ 5 snapshots per side. The pass test compares first and final snapshots in the tournament (`COEV-05`, `COEV-06`).
- **One addition you didn't ask for (`COEV-11`):** in simultaneous training, each side faces the opponent's current policy half the time and an older snapshot the rest of the time. The usual reason is to keep the two sides from just chasing each other in circles. It also gives the break-it run "only ever train against the latest opponent" something to remove.
- **Speed and logging:** the replay window plays four panels at ≥ 30 frames per second, and each world runs ≥ 5,000 steps per second without a display. Every run is evaluated ≥ 20 times, and replay speed ranges from 0.25× to 4×.

**The main risk is the one-hour limit (`QR-01`).** It applies to each of 5 headline runs, including the two predator-prey runs. If the simultaneous run can't show a significant co-evolution result in an hour, you'll either relax that limit for Predator-prey or rent the cloud GPU.
