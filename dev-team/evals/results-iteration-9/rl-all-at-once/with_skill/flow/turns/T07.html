- It only adds a member to a set a shared decision governs (another claim family, another run folder) → add the member where the set is listed and cite the shared decision. Don't revise it (*Shared decisions state a rule*).

6	I want to learn reinforcement learning, where an agent learns by trial and error from rewards. Tutorials show working code but hide why it works and how it breaks. I learn best by building. Small worlds built from scratch, each teaching one idea, would give me understanding I can explain.
7	
8	## Who it's for
9	Me: someone with some neural-network experience who is new to reinforcement learning, working evenings and weekends.
10	
11	## Goals
12	1. In every world, a learning agent clearly beats both random play and a simple hand-written rule.
13	2. I can watch any trained agent play in a replay, and compare it with earlier points in training.
14	3. For every world, I can explain in my own words why its learning method works and where it struggles.
15	4. Each new world reuses one shared core (world interface, training loop, logging, replay viewer) instead of starting over.
16	
17	## Constraints
18	- I write the core learning algorithms myself. Existing libraries are only for checking my results later.
19	- A laptop (Apple Silicon, CPU only), with about an hour of training per world. A few dollars of rented GPU time is acceptable if a world truly needs it.
20	- A few weeks of spare time per world.
21	
22	## What success looks like
23	- Each world has a learning-curve chart showing the agent above both baselines, across several training runs.
24	- A replay of each trained agent that visibly does the intended thing: the snake eats and avoids itself, the fish dodge the ball, the prey forage while fleeing.
25	- A short write-up per world, in my own words.
26	
27	## What we're betting on
28	- Hand-written algorithms can be made correct enough. Bugs in this kind of learning are silent, so the baselines are the main safety net.
29	- Small worlds with simple number inputs can be learned within an hour on a laptop.
30	- One shared core can serve a grid game, smooth movement and two competing teams without bending out of shape.
31	
32	## Not doing
33	- 3D physics — 2D teaches the same ideas.
34	- Learning from screen pixels or Atari games — too slow for a laptop and adds a separate vision problem.
35	- Reproducing research papers — the goal is understanding, not matching published numbers.
36	- Web deployment or a hosted demo — replays run locally.
37	- Chasing top scores — beating the baselines clearly is enough.
38	
39	## Known risk
40	- In the predator-prey world, both sides learn at once, so each keeps changing the other's problem. It may never look "solved." Watching and explaining that behavior counts as success there.

68	## Summary
69	A set of small 2D reinforcement-learning worlds (Snake, Fish tank, Predator-prey) built on one shared core: a world interface, a training loop, logging with learning-curve charts, a replay viewer, and baseline evaluation. In each world a hand-written learning agent is trained on a laptop, checked against random and rule-based play, watched in replays, and explained in a write-up. See the [brief](brief.md) for why.

74	| The learner (sole user) | Add a world, train agents in it on a laptop, check they beat the baselines, watch replays across training, and write up why the method works and where it struggles |

77	**In scope:** World interface, Training runs, Run logging & learning curves, Replay viewer, Baseline evaluation, Reference check, World write-ups, Snake, Fish tank, Predator-prey.

90	### World interface (`WORLD`)
91	**Serves:** Goal 4
92	**Stage:** S1
93	**Behavior:** Every world presents the same face to the rest of the system: it can be reset from a seed, it reports what each agent observes as a short list of numbers, it accepts each agent's action, and it returns rewards, an end-of-episode signal and a world-specific score. It also describes its current state in a form the replay viewer can draw.
94	
95	**Requirements**
96	- **WORLD-01** A world starts a new episode from a seed, and the same seed always gives the same starting state.
97	  - Given a world and seed 42, when two episodes are started, then both starting states are identical.
98	- **WORLD-02** Given the same seed and the same sequence of actions, a world produces the same sequence of observations, rewards and end signals.
99	  - Given a recorded episode's seed and actions, when they are replayed into a fresh world, then every observation, reward and end signal matches the recording.
100	- **WORLD-03** Each agent's observation is a fixed-length list of numbers, never an image.
101	  - Given any world, when an observation is taken at any step, then it has the same length as at every other step of that world and variant.
102	- **WORLD-04** A world declares its agents, the observation length and the action format (a choice from a fixed set, or a list of numbers within stated limits) before any episode starts.
103	  - Given any world, when the training loop asks for its description, then it receives the agent list, observation length and action format without running an episode.
104	- **WORLD-05** Every world reports a per-episode score with a stated direction (higher is better, or lower is better), used by evaluation and charts.
105	  - Given a finished episode, when its score is requested, then a single number and the world's direction are returned.
106	- **WORLD-06** A world reports its drawable state at every step (positions, sizes and kinds of every object) for the replay viewer.
107	  - Given any step of any episode, when the drawable state is requested, then every object on screen is listed with its position.
108	- **WORLD-07** A world can hold more than one agent, each agent belonging to a named team.
109	  - Given a world with agents on two teams, when a step is taken, then each agent receives its own observation and reward, labelled with its team.
110	
111	**Edge cases & errors**
112	- An action outside the declared format or limits → the step is refused with an error naming the agent and the bad value; it is never silently clipped.
113	- An agent that has left the episode (e.g. a caught prey) is sent an action → the action is ignored and the agent receives no further observations that episode.
114	
115	### Training runs (`TRAIN`)
116	**Serves:** Goal 1, Goal 4
117	**Stage:** S1
118	**Behavior:** The learner starts a training run by naming a world, its variant, the learning method's settings and a seed. The run trains for a fixed budget of environment steps, saves checkpoints of the agent as it goes, and runs periodic evaluations. The same loop runs every world without change.
119	
120	**Requirements**
121	- **TRAIN-01** A training run is started from a world, a variant, the method's settings and a seed, and runs for a stated budget of environment steps.
122	  - Given snake, its default settings, seed 1 and a budget of N steps, when the run is started, then it stops after exactly N environment steps.
123	- **TRAIN-02** The same world, settings and seed on the same machine give an identical training run.
124	  - Given two runs with identical inputs, when both finish, then their logged results and final checkpoints are identical.
125	- **TRAIN-03** A run saves a checkpoint at 10 evenly spaced points in its budget, plus at the start (untrained) and the end.
126	  - Given a finished run, when its checkpoints are listed, then there are 12, at 0%, 10%, … 100% of the budget.
127	- **TRAIN-04** A run evaluates its current agent at every 5% of its budget on 20 episodes whose seeds are never used in training.
128	  - Given a finished run, when its evaluation log is read, then there are 21 evaluation points, each the mean score of 20 held-out-seed episodes.
129	- **TRAIN-05** Several runs of the same world with different seeds can be started together, one per processor core.
130	  - Given 5 seeds, when a batch of runs is started, then 5 runs proceed at the same time and each finishes with its own log and checkpoints.
131	- **TRAIN-06** Every learning method, before it is used in a world, learns the known best behavior in a tiny check world whose best behavior is worked out by hand.
132	  - Given a learning method and its check world, when it is trained for the check budget, then the trained agent picks the hand-derived best action in at least 95% of check-world states.
133	- **TRAIN-07** In worlds with more than one team, each team has its own learning method and settings, and all teams learn during the same run.
134	  - Given predator-prey with a learning method for each team, when a run proceeds, then both teams' agents change between consecutive checkpoints.
135	
136	**Edge cases & errors**
137	- A run is stopped before its budget ends → it cannot be resumed; it is marked incomplete, keeps its checkpoints so far, and is left out of learning-curve charts and evaluation unless the learner includes it by name.
138	- A run's training produces an invalid number (not-a-number or infinite) in the agent → the run stops at once, saves the last good checkpoint, and records the step and the value.
139	- A run would overwrite an existing run with the same name → it is refused; the learner picks a new name or deletes the old run first.
140	
141	### Run logging & learning curves (`LOG`)
142	**Serves:** Goal 1, Goal 4
143	**Stage:** S1
144	**Behavior:** Every run records its settings and results as it trains. From a group of runs of the same world and variant, the learner gets a learning-curve chart showing the agent against both baselines, across all runs.
145	
146	**Requirements**
147	- **LOG-01** Every run records its world, variant, method settings, seed, budget, start and end times, and whether it finished.
148	  - Given any finished run, when its record is opened, then every one of those fields is present.
149	- **LOG-02** Every run logs, for each training episode, the episode's score, length and total reward per team.
150	  - Given a finished run, when its episode log is read, then it has one entry per training episode with those values.
151	- **LOG-03** For a world and variant with at least 3 finished runs, a learning-curve chart shows evaluation score against environment steps: the mean across runs as a line, the lowest-to-highest range across runs as a band, and each baseline's mean score as a horizontal reference line.
152	  - Given 5 finished snake runs, when the chart is made, then it shows one mean line, one band, a random-play line and a rule-based line, with the axes labelled with the score name and "environment steps".
153	- **LOG-04** Learning-curve charts follow the `dataviz` skill's guidance for form, colour and labelling.
154	  - Given any learning-curve chart, when it is reviewed against the `dataviz` skill, then it passes that skill's checks.
155	- **LOG-05** Each world can add its own logged measures (e.g. snake length at death, hits per fish), which are charted the same way as the score.
156	  - Given a world that declares an extra measure, when its chart is requested, then it is drawn with the same mean line and range band.
157	- **LOG-06** The learner can view the latest logged values of a run while it trains.
158	  - Given a run in progress, when the learner checks it, then they see the current step, the latest evaluation score and the time elapsed, no more than 1 evaluation point behind.
159	
160	**Edge cases & errors**
161	- Runs with different budgets or settings are asked for in one chart → refused, naming the differing settings; one chart only combines runs that differ by seed.
162	- Fewer than 3 finished runs → the chart is still drawn, but titled with the run count and a note that the band is not meaningful.

164	### Replay viewer (`REPLAY`)
165	**Serves:** Goal 2, Goal 4
166	**Stage:** S1
167	**Behavior:** The learner picks a run, one of its checkpoints and a seed, and watches that agent play an episode in a local window. They can pause, step and change speed, and put two checkpoints side by side on the same starting state to see how training changed the behavior.
168	
169	**Requirements**
170	- **REPLAY-01** The learner can watch an episode played by any checkpoint of any run, from a seed they choose.
171	  - Given a snake run's 50% checkpoint and seed 7, when the replay is opened, then the episode plays from its first step to its end.
172	- **REPLAY-02** Replays are exact: the same checkpoint and seed always show the same episode.
173	  - Given a checkpoint and seed, when the replay is played twice, then every frame matches.
174	- **REPLAY-03** The replay can be paused, stepped one step forward or back, and played at 0.25×, 1×, 4× or 16× speed.
175	  - Given a paused replay at step 30, when the learner steps forward, then step 31 is shown; when they step back twice, step 29 is shown.
176	- **REPLAY-04** Two checkpoints can be shown side by side on the same starting state, stepping in sync.
177	  - Given the 10% and 100% snake checkpoints and seed 7, when compared, then both start from the same board and advance one step at a time together; when one episode ends, its last frame stays while the other continues.
178	- **REPLAY-05** The replay shows the current step, the running score and each agent's latest reward next to the world.
179	  - Given any frame, when it is shown, then the step number, the score so far and the latest rewards are visible.
180	- **REPLAY-06** The learner can also watch the random-play and rule-based baselines in the same viewer, including side by side with a checkpoint.
181	  - Given the rule-based snake and the final checkpoint on seed 7, when compared, then both play side by side as in REPLAY-04.
182	- **REPLAY-07** A replay can be saved as a video file to keep alongside the write-up.
183	  - Given an open replay, when the learner saves it, then a video of the whole episode at 1× speed is written and plays in a standard video player.
184	
185	- **REPLAY-08** In worlds where agents see only nearby things, the replay can show each agent's sight radius as an overlay, switched on or off by the learner.
186	  - Given a local-sight fish replay, when the overlay is switched on, then a circle of the sight radius is drawn around every fish; when switched off, the circles disappear.
187	
188	**Edge cases & errors**
189	- A checkpoint from a world or variant whose observation length or action format no longer matches → the replay refuses to open and names the mismatch.
190	- An episode that never ends on its own → the replay stops at the world's step limit and says so.
191	
192	### Baseline evaluation (`EVAL`)
193	**Serves:** Goal 1
194	**Stage:** S1
195	**Behavior:** For every world and variant there are two baselines: random play and a simple hand-written rule. A final evaluation plays every run's final checkpoint and both baselines on the same held-out seeds and tests whether the learned agent beats each baseline by more than chance.
196	
197	**Requirements**
198	- **EVAL-01** Every world and variant has a random-play baseline that picks each action uniformly from the allowed actions.
199	  - Given any world, when the random baseline plays 100 steps, then every action it takes is within the declared action format.
200	- **EVAL-02** Every world and variant has a rule-based baseline that the learner writes by hand, described in one sentence in the world's feature below.
201	  - Given any world, when its rule baseline is listed, then its one-sentence description is shown with it.
202	- **EVAL-03** Final evaluation plays every final checkpoint and both baselines on the same 100 seeds, none of which was used in training or in-training evaluation.
203	  - Given 5 finished runs, when final evaluation is run, then 700 episodes are played (5 × 100 learned, 100 random, 100 rule-based), all on the same 100 held-out seeds.
204	- **EVAL-04** Whether the learned agent beats each baseline is tested with the `null-hypothesis-testing` skill. It is given: the hypothesis "the trained agent scores better than the baseline"; H0 = the learned agent's mean score is no better than the baseline's, H1 = it is better (in the world's score direction); the statistic = difference in mean episode score, learned (averaged over the runs, per seed) minus baseline; the null built by randomly swapping the learned and baseline labels within each held-out seed (paired permutation, 10,000 permutations); α = 0.05 with Holm correction across all baseline comparisons in that world (2 per variant); the EVAL-03 held-out episodes. The learned agent passes only if both nulls are rejected.
205	  - Given final evaluation results for one variant, when tested, then a report shows, for each baseline, the mean scores, the difference, the corrected p-value and reject/keep.
206	- **EVAL-05** "Clearly beats" also needs every single run to beat the rule baseline: each run's final mean score is better than the rule-based baseline's mean score.
207	  - Given 5 runs where 4 beat the rule baseline and 1 does not, when the verdict is made, then the world is marked "not yet beating the baselines" and names the failing run.
208	- **EVAL-06** Final evaluation produces one summary per world and variant: mean and range of learned scores across runs, both baseline means, the EVAL-04 test results and the EVAL-05 verdict.
209	  - Given a finished evaluation, when the summary is opened, then all of those values are present.
210	
211	**Edge cases & errors**
212	- Fewer than 5 finished runs → the test is not run and the summary says how many more runs are needed.
213	- A baseline scores better than the learned agent → reported plainly as a failed result, never hidden or re-run with new seeds.
214	
215	### Reference check (`CHECK`)
216	**Serves:** Goal 1, Goal 3
217	**Stage:** S1
218	**Behavior:** After the hand-written method works in a world, the learner trains an established reference implementation of the same kind of method on the same world and budget, as a check that the hand-written version has no silent bugs.
219	
220	**Requirements**
221	- **CHECK-01** The learning algorithms (how actions are chosen, what is learned from each experience, and how the agent is updated) are written by the learner; automatic gradient computation may be used, but an established reference implementation of a learning method is used only for this check, never inside training runs.
222	  - Given any training run, when it runs, then no outside reinforcement-learning code takes part in it.
223	- **CHECK-02** For each world and variant, 5 runs of a reference implementation of the same kind of method are trained on the same world, budget and seeds as the hand-written method, and evaluated as in EVAL-03.
224	  - Given a finished reference check, when its summary is opened, then it shows the reference's mean and range next to the hand-written method's.
225	- **CHECK-03** The hand-written method passes the check if its mean final score is at least 80% of the reference's (or at most 125% for lower-is-better scores).
226	  - Given a hand-written snake mean of 18 food and a reference mean of 20, when checked, then it passes; at 15 against 20, it is flagged for investigation.
227	
228	**Edge cases & errors**
229	- The hand-written method scores far better than the reference (more than 150% of it) → also flagged, since it may point to a bug in scoring or evaluation rather than a better method.
230

232	**Serves:** Goal 3
233	**Stage:** S1
234	**Behavior:** Each world has a short write-up, written by the learner, that explains why its learning method works and where it struggles, pointing to the charts and replays that show it.
235	
236	**Requirements**
237	- **NOTES-01** Each world has a write-up with three parts: how the learning method works, why it works in this world, and where it struggles.
238	  - Given a finished world, when its write-up is opened, then all three parts are present and non-empty.
239	- **NOTES-02** The "where it struggles" part points to at least one saved replay or chart that shows the struggle.

241	- **NOTES-03** Write-ups are the learner's own words; nothing in the system writes or fills them in.
242	  - Given a new world, when it is set up, then its write-up starts with only the three part headings.

247	### Snake (`SNAKE`)
248	**Serves:** Goal 1, Goal 2, Goal 3
249	**Stage:** S1
250	**Behavior:** The classic snake game on a square grid. The snake moves one cell per step, turns left, right or keeps going, grows when it eats food, and dies when it hits a wall or itself. The learner trains a snake that eats steadily and avoids itself, and watches it do so.
251	
252	**Requirements**
253	- **SNAKE-01** The world is a 10 × 10 grid with one snake starting 3 cells long in the middle, and one food item on a random free cell.
254	  - Given seed 3, when an episode starts, then the snake is 3 cells long near the center and one food item is on a cell the snake does not cover.
255	- **SNAKE-02** Each step the snake chooses one of three actions: turn left, turn right or go straight.
256	  - Given the snake heading up, when it turns left, then its head moves one cell left.
257	- **SNAKE-03** Eating food grows the snake by one cell, adds 1 to the score and places new food on a random free cell.
258	  - Given the head moves onto food, when the step ends, then the snake is one cell longer, the score is up by 1 and new food is on a free cell.
259	- **SNAKE-04** The episode ends when the head hits a wall or the snake's body, or after 100 steps without eating.
260	  - Given the head moves into its own body, when the step ends, then the episode is over.
261	- **SNAKE-05** The score is the food eaten in the episode (higher is better).
262	  - Given an episode where 12 food items were eaten, when it ends, then its score is 12.
263	- **SNAKE-06** The snake observes a fixed list of numbers: danger straight ahead, left and right; its heading; the food's direction relative to its head; and its length.
264	  - Given any step, when the observation is taken, then it has the same length and holds those values.
265	- **SNAKE-07** The rule-based baseline moves toward the food along the shorter axis, unless that move would end the episode next step, in which case it takes any move that does not.
266	  - Given the food to the right and a free cell to the right, when the rule acts, then it moves right.
267	- **SNAKE-08** The trained snake beats both baselines as in EVAL-04 and EVAL-05.
268	  - Given 5 finished snake runs, when evaluated, then both baselines are beaten.
269	
270	**Edge cases & errors**
271	- The snake fills every free cell → the episode ends as a win and the score counts all food eaten.
272	- Turning back into its own neck is impossible by construction, since actions are relative turns.

274	### Fish tank (`FISH`)
275	**Serves:** Goal 1, Goal 2, Goal 3, Goal 4
276	**Stage:** S2
277	**Behavior:** A 2D tank with walls and a ball that bounces around at constant speed. Fish move smoothly by choosing how hard to push in each direction, and lose points when the ball hits them. It is built in three variants: one fish that sees everything, many fish that see everything, and many fish that only see nearby things.
278	
279	**Requirements**
280	- **FISH-01** The tank is a square with walls; the ball moves in straight lines at constant speed and bounces off walls.
281	  - Given the ball heading into the right wall, when it touches the wall, then its sideways direction reverses and its speed is unchanged.
282	- **FISH-02** Each step a fish chooses a push as two numbers between −1 and 1 (left-right and up-down); its speed changes smoothly with the push, up to a top speed below the ball's.
283	  - Given a still fish pushing (1, 0) for several steps, when its speed is read, then it rises step by step toward its top speed, never above it.
284	- **FISH-03** When the ball touches a fish, the hit is counted and the fish reappears at a random spot at least one quarter of the tank's width from the ball.
285	  - Given the ball touching a fish, when the step ends, then the hit count is up by 1 and the fish is at least a quarter-width from the ball.
286	- **FISH-04** An episode lasts 1,000 steps; the score is hits per fish per episode (lower is better).
287	  - Given 4 fish and 6 total hits in an episode, when it ends, then the score is 1.5.
288	- **FISH-05** Variant "one fish": a single fish observes its own position and velocity and the ball's position and velocity.
289	  - Given the one-fish variant, when an observation is taken, then it holds those values for the fish and the ball.
290	- **FISH-06** Variant "many fish": 8 fish share the tank; each observes itself, the ball and the 3 nearest other fish.
291	  - Given the many-fish variant, when an observation is taken for any fish, then it holds its own state, the ball's and the 3 nearest fish's.
292	- **FISH-07** Variant "local sight": as "many fish", but a fish sees the ball and other fish only within a radius of one quarter of the tank's width; anything outside is reported as "not seen".
293	  - Given the ball beyond the radius, when a fish's observation is taken, then the ball's entries read "not seen".
294	- **FISH-08** Fish pass through each other; only the ball can hit them.
295	  - Given two fish moving onto the same spot, when the step ends, then both are there and no hit is counted.
296	- **FISH-09** The rule-based baseline pushes each fish directly away from the ball at full strength (from the ball it sees, or randomly when it sees none).
297	  - Given the ball to the fish's left, when the rule acts, then the push is (1, 0).
298	- **FISH-10** Every variant's trained fish beat both baselines as in EVAL-04 and EVAL-05.
299	  - Given 5 finished runs of each variant, when evaluated, then both baselines are beaten in each variant.
300	- **FISH-11** Fish tank runs through the same training runs, logging, replay viewer and evaluation as snake, and snake's results reproduce unchanged after fish tank is added.
301	  - Given a snake run repeated with its original settings and seed after fish tank exists, when it finishes, then its results match the original run exactly.
302	
303	**Edge cases & errors**
304	- A fish pushes into a wall → it stops at the wall and slides along it; it never leaves the tank.
305	- The ball starts touching a fish → the episode's start is re-drawn so that every fish starts at least a quarter-width from the ball.

307	### Predator-prey (`PREY`)
308	**Serves:** Goal 1, Goal 2, Goal 3, Goal 4
309	**Stage:** S3
310	**Behavior:** A 2D arena with food pellets, a team of prey and a team of predators, all moving smoothly as fish do. Prey score by eating food and are removed when caught; predators score by catching prey. Both teams learn at the same time. The learner watches and explains how each side adapts to the other; it may never look "solved", and that is acceptable.
311	
312	**Requirements**
313	- **PREY-01** The arena is a square with walls, 6 prey, 2 predators and 10 food pellets; an eaten pellet reappears at a random spot after 50 steps.
314	  - Given seed 5, when an episode starts, then the counts are 6, 2 and 10, with no two objects touching.
315	- **PREY-02** Prey and predators move by smooth pushes as in FISH-02; predators' top speed is 1.2 × the prey's.
316	  - Given both at full speed, when their speeds are read, then the predator's is 1.2 × the prey's.
317	- **PREY-03** A prey touching a pellet eats it; a predator touching a prey catches it and the prey leaves the episode.
318	  - Given a predator touching a prey, when the step ends, then the prey is gone and the predator's catch count is up by 1.
319	- **PREY-04** An episode lasts 1,000 steps or until every prey is caught.
320	  - Given all 6 prey caught at step 600, when the step ends, then the episode is over.
321	- **PREY-05** Each team has its own score: prey score = pellets eaten per prey (higher is better); predator score = prey caught per episode (higher is better).
322	  - Given 18 pellets eaten and 3 prey caught, when the episode ends, then the prey score is 3 and the predator score is 3.
323	- **PREY-06** Every agent observes itself, and the nearest 2 food pellets, nearest 2 prey and nearest 2 predators within a radius of one third of the arena's width; anything outside reads "not seen".

````markdown
**Status:** Draft · **Shape:** Single package · **Last updated:** 2026-10-17 · **Spec:** [spec.md](spec.md)
````

## Overview
Every world implements one multi-agent `World` protocol (AD-04): it resets from a seed, steps on one action array for all agents, and reports per-team scores and a drawable state. `train` drives a hand-written learner per team (AD-03) over a world for a fixed step budget. It plays held-out evaluation episodes through `core.play_episode` and writes everything to a run folder through `runlog` (AD-06). `evaluate` replays final checkpoints and both baselines on the final seeds and runs the paired permutation test. `charts` draws learning curves from run folders. `replay` re-simulates any checkpoint or baseline from a seed into a `Trace`, then shows it in a pygame window or writes it to MP4 (AD-07). `refcheck` trains Stable-Baselines3 on the same world through an adapter, kept away from every training run (AD-08).

```mermaid
  evaluate --> methods & runlog & worlds & baselines
  replay --> methods & runlog & worlds & baselines
  refcheck --> evaluate & train & worlds
  charts --> runlog & evaluate
  methods --> runlog
  worlds & baselines & methods & runlog --> core
```

## Data
No external datasets: every world is simulated. Generated data lives under `runs/<world>/<variant>/<run-name>/` (AD-06):
- `run.json`: the LOG-01 record, the run's config and its status (`running`, `finished`, `incomplete`, `failed` with step and value).
- `episodes.jsonl`: one line per training episode (LOG-02). `evals.jsonl`: one line per 5% evaluation point (TRAIN-04), flushed as written so `rllab watch` reads it live (LOG-06).
- `checkpoints/ckpt_<pct>.pt`: 12 checkpoints (TRAIN-03), each holding the `WorldSpec`, per-team method configs and state dicts.
- Final evaluations under `runs/<world>/<variant>/_eval/<date>/` (`summary.json`, per-episode scores), reference runs under `_reference/`, charts and videos under `reports/<world>/`, write-ups at `notes/<world>.md`.

Seeds come from three disjoint ranges (AD-05): training episode seeds drawn by the run's generator from [0, 10⁶), the 20 in-training evaluation seeds 1,000,000–1,000,019, and the 100 final seeds 2,000,000–2,000,099, shared by every run and baseline.

## Cross-cutting concerns
- **Determinism (WORLD-02, TRAIN-02, REPLAY-02, FISH-11, PREY-11):** no global random state. Each episode seed spawns the world's and the policies' generators, and torch runs single-threaded with deterministic algorithms (AD-05). A committed digest of a short snake run's logs and final checkpoint is checked in CI. A later world that changes it fails the build (FISH-11, PREY-11), and so does a fish digest once S2 lands.
- **No outside RL code in training (CHECK-01):** import-linter forbids `stable_baselines3` and `gymnasium` outside `refcheck`, and a test asserts neither is in `sys.modules` after a training run (AD-08).
- **Speed (QR-01, QR-02, QR-04, QR-05):** world physics is NumPy over all agents at once, learners batch every team's observations into one forward pass, and evaluation spreads seeds over processes. `rllab` logs each run's wall time against the 60-minute budget, and a timing test plays a 1,000-step replay headless.
- **GPU (QR-03):** `device` is a run setting, `cpu` by default; a rented GPU run uses the same code, and its cost goes in the write-up by hand.
- **Offline (QR-06):** nothing imports a network client. ffmpeg comes bundled with imageio-ffmpeg, and fonts come from pygame's built-in one.
- **Errors:** bad actions raise `core.ActionError` naming the agent and value (never clipped). Spec mismatches on checkpoint load raise `methods.SpecMismatchError` naming the field. Mixed-settings charts raise `charts.MixedRunsError` naming the differing settings.
- **Skills:** `charts` follows `dataviz` for every chart (LOG-04). `evaluate.compare` is built and checked with `null-hypothesis-testing`, whose inputs are its signature (EVAL-04).

## Decisions
### AD-01: Python 3.12 in one uv-managed package
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** One learner on an Apple Silicon laptop; PyTorch, pygame-ce and Stable-Baselines3 all ship arm64 macOS wheels for Python. QR-06 needs the whole install to work offline once set up.
- **Decision:** Python 3.12, one `rllab` package with a `uv.lock`. Stable-Baselines3 and Gymnasium go in an optional `check` extra.
- **Alternatives:** Python 3.13: wheels for some libraries lag. Separate `rllab-check` package: a real boundary only if the reference stack becomes a burden, so it is a named seam for now.
- **Consequences:** `requires-python = ">=3.12,<3.13"`. Training can run without the `check` extra installed, which proves CHECK-01 at install level too.

### AD-02: PyTorch for networks and gradients, not for the learning algorithm
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** CHECK-01 allows automatic gradient computation but the learner writes action choice, learning targets and updates. Networks are small MLPs on observations of tens of numbers (WORLD-03). Training is CPU-only (QR-01).
- **Decision:** Learners use `torch.nn` layers, `torch.optim` optimisers and autograd. Replay buffers, exploration, targets, advantage estimation, clipping and update schedules are hand-written in `methods`.
- **Alternatives:** NumPy with hand-derived backprop: teaches backprop, which is not this project's subject, and is slower to debug. JAX: capable, but less familiar CPU tooling and a functional style that hides the update loop.
- **Consequences:** `torch.set_num_threads(1)` per run process (AD-05); small batches stay fast on CPU. The PyTorch install is about 200 MB.

### AD-03: DQN for discrete actions, PPO for continuous ones, one learner per team
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** Snake has 3 discrete actions (SNAKE-02); fish and predator-prey push with two numbers in [−1, 1] (FISH-02, PREY-02). Many-fish has 8 agents (FISH-06), and predator-prey has two teams learning at once (TRAIN-07). The brief wants each world to teach one idea, and wants checking against a reference implementation (CHECK-02).
- **Decision:** `dqn` (replay buffer, target network, ε-greedy, Huber loss) for snake and the discrete check world. `ppo` (Gaussian policy, GAE, clipped objective) for fish, predator-prey and the continuous check world. All agents of a team share one learner (parameter sharing over a batch of agents). Teams have separate learners in the same run. Evaluation and replay act deterministically: greedy for DQN, the mean action for PPO.
- **Alternatives:** PPO everywhere: one method fewer, but snake would not teach value learning. SAC for fish: strong on continuous control, but a third method and harder to explain for many agents. Tabular Q-learning for snake: SNAKE-06 includes length, an unbounded number, so the table would need discretising.
- **Consequences:** Two methods to write, each with a check world (TRAIN-06) and a Stable-Baselines3 equivalent (AD-08). A prey that leaves the episode is masked out of its team's batch.

### AD-04: Our own multi-agent World protocol, not Gymnasium or PettingZoo
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** WORLD-01–WORLD-07 need seeded resets, a declared spec, team-labelled agents, per-team scores with a direction, and a drawable state. The brief bets that one core serves a grid game, smooth movement and two teams.
- **Decision:** `core.World` is a small protocol. Observations, actions, rewards and active masks are NumPy arrays indexed by agent, teams map to agent indices in `WorldSpec`, and `draw()` returns a `DrawState`. "Not seen" entries are a 0/1 flag followed by zeros, so lengths stay fixed (WORLD-03, FISH-07, PREY-06).

### AD-05: Seeds from SeedSequence, disjoint held-out ranges, one process per run
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** WORLD-01, WORLD-02, TRAIN-02 and REPLAY-02 need exact repeats; TRAIN-04 and EVAL-03 need seeds never used in training; TRAIN-05 and QR-02 need runs in parallel, one per core.

- **Consequences:** Identical runs are promised on the same machine only (TRAIN-02). In-training evaluation never touches the training generators, so turning evaluation off for a test leaves training identical.

### AD-06: Run folders of JSON, JSON Lines and torch checkpoints
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** LOG-01 and LOG-02 need a record and per-episode logs. LOG-06 needs them readable while the run writes, at most one evaluation point behind. A stopped run keeps its checkpoints and is marked incomplete. A run name that already exists is refused (TRAIN edge cases). REPLAY edge cases need a checkpoint to carry its world spec.
- **Decision:** One folder per run (see Data). Logs are append-only JSON Lines, flushed at every evaluation point; `run.json` is rewritten atomically (write, then rename) on each status change. - **Consequences:** Charts and evaluation read whole JSONL files; at ~10⁴ episodes per run that is instant. A crashed process leaves `run.json` at `running`; `runlog` reports any `running` run with no live process as incomplete.

### AD-07: Replays re-simulate into a Trace, shown with pygame-ce and saved with imageio-ffmpeg
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** REPLAY-01–REPLAY-08 need any checkpoint or baseline from any seed, step back, 4 speeds, side by side, a sight overlay and video export. QR-04 needs ≥ 30 steps/s; QR-06 needs it offline. Worlds are deterministic (AD-05), so nothing needs recording during training.

- **Consequences:** The `Trace` is testable without a window, so REPLAY-02 is a frame comparison. Memory is one episode of `DrawState`s, under 1,000 frames of a few dozen objects.

### AD-08: Stable-Baselines3 as the reference, isolated in `refcheck`
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** CHECK-02 needs an established implementation of the same kind of method (DQN, PPO; AD-03) trained on the same world, budget and seeds; CHECK-01 forbids it inside training runs. Worlds speak `core.World`, not Gymnasium (AD-04).
- **Decision:** `refcheck` wraps a world as a Gymnasium env (single agent) or as an SB3 `VecEnv` with one slot per agent of the learning team (many-fish: 8 slots stepping one world, matching parameter sharing). It trains SB3 `DQN` or `PPO` for 5 seeds and evaluates on `core.FINAL_SEEDS` through `core.play_episode`. In predator-prey, SB3 cannot co-train two models, so each team's reference trains against the rule-based opponent, the same opponent PREY-08 evaluates against.
- **Alternatives:** CleanRL single-file scripts: easy to read, but they would need editing to fit our worlds, which weakens them as a reference. RLlib: multi-agent native, but a heavy distributed stack for a laptop.
- **Consequences:** SB3's default hyperparameters differ from ours; `refcheck` starts from the hand-written method's settings where SB3 has the same knob. The predator-prey reference answers a narrower question than co-training (see Risks).

### AD-09: Every batch first runs the method's check world
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** TRAIN-06 needs every learning method to learn a hand-derived best behaviour before it is used in a world. Bugs in RL are silent (brief), and methods change while a world is built.
- **Decision:** `train.check_method` trains the method on its check world: for DQN a 6-state corridor where "move toward the goal" is best, for PPO a 1-D point that is rewarded for reaching a target, where the best push is the sign of the offset. It needs ≥ 95% agreement over every check-world state. `train.run_batch` calls it with the batch's method settings before starting any run and refuses the batch on failure. `rllab check <method>` runs it alone.
- **Alternatives:** A recorded pass per method version: saves seconds but goes stale silently when code changes. A test only: passes in CI but not for the settings actually used.
- **Consequences:** Each batch spends under a minute on the check. A check-world settings override exists because a world's tuned settings (e.g. buffer size) may be too large for a 6-state world.

## Risks and open questions
- **Many-fish and predator-prey speed (QR-01, QR-02).** 8–10 agents, 1,000-step episodes and 21 × 20 evaluation episodes may not fit 60 minutes in Python. Mitigation: NumPy physics over all agents, evaluation in a worker process, and a timing check in the first fish build; QR-03's GPU route doesn't help a CPU-bound world loop.
- **Predator-prey reference check (CHECK-02).** SB3 trains each team against the rule-based opponent, not co-trained (AD-08), so CHECK-03's 80% bar compares unlike setups there. Open question for the learner before S3: accept this, or hold the hand-written team against the same fixed opponent for the check.
- **Collapse flag definition (PREY edge case).** Assumed: a team is flagged when its in-training evaluation score stays at or below its random baseline's mean for the last 4 or more consecutive evaluation points; the flag reports the first of them. The learner may prefer another rule.
- **5 parallel runs on mixed cores (QR-02).** Apple Silicon's efficiency cores run slower; 5 runs may not all land on performance cores. Measured in the first snake batch.

## core

### core.ActionSpace: type
`ActionSpace = Discrete(n: int) | Box(dims: int, low: float, high: float)`, both frozen dataclasses
- **Invariants:** `Discrete` actions are ints in `[0, n)`; `Box` actions are `dims` floats in `[low, high]`
- **Boundary:** worlds, baselines, methods, refcheck · **Fixtures:** tests/contracts/core.ActionSpace/ · **Cases:** snake `Discrete(3)`; fish `Box(2, -1.0, 1.0)`

### core.TeamSpec: type
`@dataclass(frozen=True) class TeamSpec: name: str; agents: tuple[int, ...]; score_name: str; direction: Direction`
- **Invariants:** `agents` are indices into the world's agent axis; teams of one world are disjoint and cover every agent
- **Boundary:** worlds, train, evaluate, charts · **Fixtures:** tests/contracts/core.TeamSpec/ · **Cases:** snake's one team; predator-prey's prey (6) and predator (2) teams
- **Used by:** every component reading scores

### core.WorldSpec: type
`@dataclass(frozen=True) class WorldSpec: world: str; variant: str; agents: tuple[str, ...]; teams: tuple[TeamSpec, ...]; obs_len: int; action: ActionSpace; max_steps: int; measures: tuple[MeasureSpec, ...]; sight: float | None`
`MeasureSpec(name: str, team: str, direction: Direction)`
- **Invariants:** available without running an episode (WORLD-04); `sight` is the radius in world units for local-sight variants, else `None`; equality of two specs is field by field
- **Boundary:** worlds, methods, runlog, replay, refcheck · **Fixtures:** tests/contracts/core.WorldSpec/ · **Cases:** snake default; fish local-sight (8 agents, sight set); predator-prey
- **Used by:** all components

### core.Step: type
`@dataclass(frozen=True) class Step: obs: Array; rewards: Array; active: Array; done: bool; truncated: bool`
- **Invariants:** `obs` float32 `n_agents × obs_len`; `rewards` float32 `n_agents`; `active` bool `n_agents`, and an inactive agent's row is zeros with reward 0 (WORLD edge case); `truncated` is true only when `max_steps` ended the episode
- **Boundary:** worlds, methods, refcheck · **Fixtures:** tests/contracts/core.Step/ · **Cases:** a snake mid-episode step; a predator-prey step with one prey caught
- **Used by:** core.play_episode, train, refcheck

- **Boundary:** train, runlog, evaluate, refcheck · **Fixtures:** tests/contracts/core.EpisodeResult/ · **Cases:** a snake episode with 12 food; a predator-prey episode with both team scores

### core.World: type
```python
class World(Protocol):
    spec: WorldSpec
    def reset(self, seed: int) -> Step: ...
    def step(self, actions: Array) -> Step: ...
    def result(self) -> EpisodeResult: ...
    def draw(self) -> DrawState: ...
```
- **Invariants:** same seed → same start (WORLD-01); same seed and actions → same steps (WORLD-02); `actions` has one row per agent, rows of inactive agents ignored
- **Errors:** `step` raises `ActionError(agent: str, value: object)`, a `ValueError`, for an action outside `spec.action`, never clipping it; `step` after `done` raises `RuntimeError`
- **Boundary:** train, evaluate, replay, refcheck · **Fixtures:** tests/contracts/core.World/ · **Cases:** a replay double of a recorded 5-step snake episode from seed 42
- **Used by:** every component that plays episodes

### core.Policy: type
`class Policy(Protocol): def act(self, obs: Array, rng: np.random.Generator) -> Array`
- **Invariants:** `obs` is `k × obs_len` for the `k` agents of one team; returns `k` actions inside the world's `ActionSpace`; deterministic for a given `obs` and `rng` state
- **Boundary:** baselines, methods, evaluate, replay, refcheck · **Fixtures:** tests/contracts/core.Policy/ · **Cases:** a replay double of the snake rule policy over 5 observations
- **Used by:** core.play_episode, train, evaluate, replay, refcheck

### core.play_episode: The one episode loop
`def play_episode(world: World, policies: Mapping[str, Policy], seed: int, *, trace: bool = False) -> Episode`
- **Invariants:** `policies` keyed by team; the seed spawns the world's and each policy's generator (AD-05), so the same inputs give the same `Episode`; stops at `done` or `spec.max_steps`
- **Errors:** `KeyError` naming a team with no policy; `ActionError` propagates from `World.step`
- **Boundary:** train, evaluate, replay, refcheck · **Fixtures:** tests/contracts/core.play_episode/ · **Cases:** snake rule policy, seed 7, traced
- **Used by:** train, evaluate, replay, refcheck

### core.EVAL_SEEDS: In-training evaluation seeds
`EVAL_SEEDS: tuple[int, ...] = tuple(range(1_000_000, 1_000_020))`
- **Invariants:** 20 seeds, disjoint from training seeds `[0, 10⁶)` and from `FINAL_SEEDS` (TRAIN-04)
- **Used by:** train, evaluate

### core.FINAL_SEEDS: Final evaluation seeds
`FINAL_SEEDS: tuple[int, ...] = tuple(range(2_000_000, 2_000_100))`

## train

### train.RunConfig: type
`@dataclass(frozen=True) class RunConfig: name: str; world: str; variant: str; methods: Mapping[str, MethodConfig]; seed: int; budget: int; check_settings: Mapping[str, Settings]; device: str = "cpu"`
- **Invariants:** `methods` has one entry per team (TRAIN-07); `budget` counts world steps, not agent steps; `check_settings` overrides settings for the check world only (AD-09)

### train.run: One training run
`def run(config: RunConfig, root: Path) -> RunRecord`
- **Invariants:** exactly `budget` world steps (TRAIN-01); checkpoints at 0%, 10%, … 100% (TRAIN-03); evaluation of every team on `EVAL_SEEDS` at every 5% (TRAIN-04); same config on the same machine → identical logs and checkpoints (TRAIN-02)

### train.run_batch: Parallel runs
`def run_batch(configs: Sequence[RunConfig], root: Path, *, workers: int | None = None) -> list[RunRecord]`
- **Invariants:** first runs `check_method` for each team's method and settings; then one process per config, up to `workers` (default: the core count), each with one torch thread (TRAIN-05, AD-05)
- **Errors:** `CheckFailedError(result: CheckResult)` before any run starts; a failing run doesn't stop the others
- **Used by:** cli

### train.CheckResult: type
`@dataclass(frozen=True) class CheckResult: method: str; world: str; agreement: float; passed: bool`
- **Invariants:** `agreement` is the share of check-world states where the trained policy picks the best action; `passed` is `agreement >= 0.95` (TRAIN-06)
- **Boundary:** cli · **Fixtures:** tests/contracts/train.CheckResult/ · **Cases:** a passing DQN check; a failing PPO check at 0.80
- **Used by:** cli

### train.check_method: Check-world gate
`def check_method(config: MethodConfig, seed: int) -> CheckResult`
- **Invariants:** trains on the method's check world (`check-discrete` for `dqn`, `check-continuous` for `ppo`) for its fixed check budget; under a minute on the laptop
- **Used by:** train.run_batch, cli
