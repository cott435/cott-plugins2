# RL Lab — Architecture

**Status:** Approved · **Shape:** Single package · **Last updated:** 2026-10-18 · **Spec:** [spec.md](spec.md)

## Overview
One Python package, `rllab`, run from the command line. A training run builds a Snake environment and one learner (from the registry), plays games from seeds derived from the run seed, and feeds every move to the learner. At each of 20 curve points it pauses training to play the 100 reserved test games greedily, then writes the point to the run's folder. When the run finishes it saves the agent and its test games and marks the run's status last. Comparisons read only complete runs and hand the per-game scores to the `null-hypothesis-testing` skill. The replay viewer rebuilds any saved game by stepping the environment through its saved moves. Training, testing, storage and replay see only the `core` protocols, so a second environment plugs in through `Env` (AD-04).

```mermaid
  cli --> train & compare & replay

  registry --> snake & baselines & tabular & dqn
  replay --> registry & evaluate & store
  compare --> store
  store --> evaluate
  snake & baselines & tabular & dqn & evaluate & store --> core
```

## Data
- **Experience (DATA-01):** every game is a `snake.SnakeEnv` started from a seed. Seeds 0–99 are the test seeds (`evaluate.test_agent`); training game seeds are drawn from the run seed's generator in `[1_000, 2^31)`, so they never meet a test seed (AD-05).
- **Run evidence (RUN-02):** `runs/<learner>/<reward>/seed-<n>/<UTC timestamp>-<short id>/` holds `settings.json`, `curve.json`, `agent.npz` (table) or `agent.pt` (DQN), `test_games.jsonl` (seed, moves, per-move scores, food count per move, ending) and `status.json`, written last (AD-06). Baselines are stored the same way under `runs/random/none/` and `runs/scripted/none/`, with no curve.
- **Explanations (EVAL-06):** the learner writes one Markdown file per comparison, `reports/explanations/<comparison id>.md`; `compare` reads them, never writes them.
- **Reports (EVAL-03–EVAL-05):** `reports/report.md` and its PNG charts, rebuilt from the runs on every `rllab compare`.

## Cross-cutting concerns
- **Reproducibility (RUN-03, SNAKE-08):** every random draw comes from a `np.random.Generator` or `torch.Generator` derived from the run seed; PyTorch runs on CPU with one thread and deterministic algorithms (AD-05).
- **Time (QR-01, RUN-07):** `train` checks the wall clock after every move and at every test game; at 60 minutes it stops and saves what it has. Elapsed seconds are saved with each curve point.
- **Errors:** an unknown learner, reward or environment raises `UnknownName` with the valid choices; a disk error while saving marks the run incomplete with the missing evidence listed; Ctrl-C marks it incomplete.
- **Testing:** pytest. RUN-08 is checked with a test-only second environment, a tiny grid walk in `tests/`, trained, tested, stored and replayed through the same code.

## What it catches

```python
# yourpackage/core/engine.py
from yourpackage.cli import main     # violates "core must not import cli"
```
```text
Layers: cli > services > core
  yourpackage.core is not allowed to import yourpackage.cli
```
Why: low-level code that imports high-level code creates cycles, makes testing hard, and defeats the point of splitting into layers. Agents add the "quick" import that creates this.

## Generating contracts from the architecture

Contracts are generated, never hand-written (CONSTRAINTS.md Boundaries says "do not edit"):
- **Source:** single package: each component's `Depends on` column. Multi-package: the package dependency rules. Contracts sit between component subfolders (`pkg.data`) in a single package and between packages in multi.
- **Shape:** order the components so every dependency points down, then write one `layers` contract, top first. Components that don't depend on each other share a layer: `"pkg.a | pkg.b"` (independent siblings).
- **Narrower rules:** if a component may import only some of the layers below it (`reserve` → `profile`, never `data`), add a `forbidden` contract for that pair.
- **Not built yet:** wrap a module that doesn't exist in parentheses, `"(pkg.report)"`. The layer is optional while missing and enforced once it exists (verified). Without that, a fresh skeleton fails with `Missing layer`. `dt status` flags parentheses around a module that now exists; Extend removes them.
- **Grow:** when a component becomes a package, Extend rewrites its component contract as a package contract. The rule is the same, so code that passed keeps passing.

```toml
[[tool.importlinter.contracts]]
name = "Layers: report > profile > data"
type = "layers"
layers = ["(gridload.report)", "gridload.profile", "gridload.data"]
```

## DTZ: naive datetimes (very relevant for meter data)

**DTZ005 `datetime.now()` without tz**
```python
ts = datetime.now()                       # DTZ005 -> datetime.now(tz=UTC)
```

**DTZ007 `strptime` without `%z`**
```python
datetime.strptime(s, "%Y-%m-%d %H:%M")    # DTZ007
```
Why: naive timestamps mix local time, UTC and the meter's own clock. Joins and hourly alignment go wrong around DST changes.

## NPY: NumPy

**NPY002 legacy global RNG**
```python
np.random.seed(0)
x = np.random.rand(10)   # NPY002 -> rng = np.random.default_rng(0)
```
Why: global state makes forecasts and simulations hard to reproduce, especially with parallel work.

**NPY201 NumPy 2.0 removals**
```python
np.float_(1.0)           # NPY201 -> np.float64
np.NaN                   # NPY201 -> np.nan
```
Why: these raise `AttributeError` on NumPy 2.

## PD: pandas-vet

**PD002 `inplace=True`**
```python
df.dropna(inplace=True)  # PD002 -> df = df.dropna()
```
Why: `inplace` rarely saves memory and breaks method chaining. It also causes SettingWithCopy confusion.

**PD011 `.values`**
```python
arr = df["kwh"].values   # PD011 -> .to_numpy()
```
Why: `.values` may return an array or an extension type, depending on dtype. `.to_numpy()` is explicit.

## Errors it catches

**`union-attr`: using a value that might be None**
```python
import re
m = re.match(r"\d+", s)
print(m.group(0))   # error: Item "None" of "Match[str] | None" has no attribute "group"  [union-attr]
```
Why: `re.match` returns `None` when there's no match, and this crashes with `AttributeError` on that input. Fix: `if m is not None:`.

**`arg-type`: wrong argument type**
```python
def rolling_mean(loads: list[float], n: int) -> float: ...
rolling_mean([1.0, 2.0], "20")     # error: Argument 2 has incompatible type "str"; expected "int"  [arg-type]
```
Why: fails later and further away, usually as a `TypeError` inside the function.

**`return-value`: return doesn't match the signature**
```python
def count() -> int:
    return "3"            # error: Incompatible return value type (got "str", expected "int")  [return-value]
```

**`assignment`: incompatible assignment**
```python
x: int = "a"              # error: Incompatible types in assignment  [assignment]
```

**`attr-defined`: attribute that doesn't exist**
```python
"abc".foo()               # error: "str" has no attribute "foo"  [attr-defined]
```
Why: catches typos and use of renamed methods.

**`call-arg`: wrong number of arguments**
```python
def f(a: int) -> None: ...
f(1, 2)                   # error: Too many arguments for "f"  [call-arg]
```

**`no-untyped-def` (strict): missing annotations**
```python
def f(x):                 # error: Function is missing a type annotation  [no-untyped-def]

```
Why: unannotated functions are skipped by the checker, so bugs inside them go unseen.

**`var-annotated`: empty container needs a type**
```python

```

**`import-untyped`: library has no type stubs**
```python
import yaml              # error: Library stubs not installed for "yaml"  [import-untyped]
```

**`unused-ignore`: stale ignore comment**
```python
x: int = 1  # type: ignore    # error: Unused "type: ignore" comment  [unused-ignore]
```
Why: with `warn_unused_ignores` (part of strict), agents can't leave dead ignores behind.

**`override`: subclass breaks the parent's signature**
```python
class A:
    def run(self, n: int) -> int: ...
class B(A):
    def run(self, n: str) -> int: ...   # error: Argument 1 of "run" is incompatible with supertype "A"  [override]
```

# pylint duplicate-code: copied blocks

| | |
|---|---|
| **What it does** | Finds blocks of similar lines repeated across source files (R0801) |
| **Speed** | Seconds on a small codebase; it parses every file |
| **Config** | `[tool.pylint.similarities]` |
| **Hook tier** | `full` only (checkpoints, CI). Ruff does every other lint; pylint runs this one check |

> **Verified** 2026-10-17 with pylint 3.3.8 on a two-file sample: a 9-line episode loop copied under a new function name is reported, and pylint exits 8 (non-zero), so `check.sh full` fails. In config, `fail-under = 0`, `exit-zero = true` and `ignore-patterns` each turn that exit into 0.

## What it catches

```text
src/pkg/b.py:1:0: R0801: Similar lines in 2 files
==pkg.a:[1:10]
==pkg.b:[1:10]
    total = 0.0
    for s in seeds:
        ...
```
Why: builders in parallel worktrees can't see each other's code, so two tasks that need the same loop each write it. The reviewer turns each block into a finding (CR-42); the fix is one function in the owning module.

## Config

```toml
[tool.pylint.similarities]
min-similarity-lines = 8
ignore-imports = true
ignore-signatures = true
ignore-docstrings = true
ignore-comments = true
```

- 8 lines with imports, signatures, docstrings and comments ignored keeps import blocks, dataclass headers and stub signatures out.
- pylint has no whitelist. A block found on existing code is an Exceptions row plus its file in `[tool.pylint.main] ignore-paths`; Ratchet removes the entry once the block is gone.
- Multi-package: the config, and any `[tool.pylint.main] ignore-paths`, live in the root `pyproject.toml`; pylint reads it from where `check.sh` runs.
- `--fail-under=10` on the command line beats a lowered `fail-under` in config. `floor_guard` flags the other ways to silence it: a `# pylint: disable` or `skip-file` comment, `exit-zero = true`, a longer `ignore`, `ignore-patterns` or `ignore-paths`, and a `pylintrc`. Removing `min-similarity-lines` also counts as a loosening, though pylint's default (4) is stricter.
- Tests aren't scanned: they may repeat for readability.

Run: `pylint --disable=all --enable=duplicate-code --recursive=y --score=n --fail-under=10 <src dirs>` (`check.sh full`).
# Claude Code hooks: how the project's checks are wired

Loaded when build-setup writes or changes `.claude/agents/*.md` or `scripts/hooks/*`. Doc claims checked against the Claude Code docs on 2026-10-16 (`design/tooling-verification.md` §7); the scripts are tested by `skills/build-setup/tests/`.

## The contract

1. Claude Code runs the command with **JSON on stdin**: `tool_name`, `tool_input` (`file_path` is always absolute for Edit, Write and Read), `cwd`, and `agent_id` / `agent_type` inside a subagent. Stop and SubagentStop also get `stop_hook_active`.
2. **Exit 0** = fine. **Exit 2** = blocking: PreToolUse blocks the call; PostToolUse shows stderr to the agent (the tool already ran). Any other non-zero exit is a non-blocking error, and the action goes ahead.
3. **Stop blocks with JSON**, not exit 2: print `{"decision": "block", "reason": "…"}` and exit 0. An exit-2 Stop hook whose stderr mentions a missing file ("No such file or directory") is treated as non-blocking, and test output often does.
4. Exit-0 output is not shown to anyone unless it is a `{"systemMessage": "…"}`, and a SubagentStop `systemMessage` doesn't reach the main view either (checked live, Claude Code 2.1.292).
5. Matchers made of letters, digits, `_`, `-`, spaces, `,` and `|` are exact lists: `Edit|Write|MultiEdit|NotebookEdit`. Stop takes no matcher. The default timeout is 600 s; don't set a short one, because a timed-out hook doesn't block.

## Who owns which hook

| Source | Fires | Hooks |
|---|---|---|
| Plugin `hooks/hooks.json` (dev-team2) | every session, **including tool calls inside subagents** | SessionStart `dt status --summary` (doesn't reach subagents), PreToolUse `dt guard` (oracle files → ask), PostToolUse `dt lint` on docs |
| Project `.claude/agents/*.md` frontmatter | only while that agent runs, only in a trusted workspace | the role hooks below. A frontmatter `Stop` becomes `SubagentStop` |
| Project `.claude/settings.json` | main session | optional, on request: Stop → `stop_gate.sh gate` as a last safety net |

- **Plugin subagents ignore `hooks` frontmatter.** That is why the agents are copied into the project's `.claude/agents/`.
- **Workspace trust:** project frontmatter hooks need the trust dialog accepted. `claude -p` in a folder never trusted skips them silently (checked live: the implementer wrote `tests/intent/` unblocked); in a trusted folder they fire under `-p` too. Headless eval runs only exercise them with `--agents`, user-level agents, or a folder trusted beforehand.
- **Commands are absolute:** `bash "$CLAUDE_PROJECT_DIR"/scripts/hooks/<x>.sh`. A missing script is a non-blocking error, so a relative path that breaks after `cd` would silently turn the guard off.
- **The root comes from the input's `cwd`** (`project_root.sh`), walking up to the folder holding `scripts/check.sh`. `CLAUDE_PROJECT_DIR` stays on the main checkout in a worktree; `cwd` follows Claude into worktrees and after `cd`.

## Role hooks

| Agent | PreToolUse | PostToolUse | Stop |
|---|---|---|---|
| tester | `path_guard.sh allow "tests/intent/**"` and `path_guard.sh writes` on edits; `path_guard.sh deny <source globs>` on Read | `post_edit.sh` | `stop_gate.sh collect` |
| implementer (and solo) | `path_guard.sh deny --protected` and `path_guard.sh writes` | `post_edit.sh` | `stop_gate.sh gate` |
| reviewer | none: `tools: Read, Grep, Glob, Bash`, no Edit or Write | — | — |

`--protected` reads the list from `scripts/check.sh protected`, so the guard and the Stop-time diff can't drift apart. That output narrows `tests/contracts/**` to the contract folders at `refs/checks/base` (CR-09): an interface task may write the folder it creates; the next task's base freezes it. `writes` reads `.claude/.task_writes` at the root (one `Writes:` path or folder glob a line, a trailing `/` meaning the folder), so a parallel builder edits only what its task claims; with no file it allows everything.

## Two layers

Every protection has two layers:
1. **PreToolUse guard** stops the normal route (Edit, Write).
2. **Stop-time diff** catches Bash writes (`sed -i`, `echo >`): `check.sh gate` diffs the whole protected list against `refs/checks/base` and lists untracked files; `check.sh collect` does the same for everything outside `tests/intent`.

The orchestrator sets the base with `git update-ref refs/checks/base HEAD` when it commits the tester's work and at each task start. Without it the diff falls back to HEAD, which misses changes the agent already committed. It can also write the task's package to `.claude/.check_pkg`, which `stop_gate.sh` passes on as `--pkg`, and, in each builder's worktree, the task's `Writes:` to `.claude/.task_writes`.

## The scripts

| Script | Event | Does | Fails |
|---|---|---|---|
| `path_guard.sh` | PreToolUse | `allow`/`deny` globs relative to the root, or `writes` from `.claude/.task_writes`; `*` crosses `/`; case-insensitive; deny also matches the absolute path; blocks `..` | closed: bad input, no jq or no protected list → exit 2 |
| `post_edit.sh` | PostToolUse | `check.sh fast <file>`: ruff `--fix`, format, typos, size; exit 2 with the output | bad input → exit 1 (reported; the Stop gate still runs) |
| `stop_gate.sh` | Stop / SubagentStop | `check.sh <mode>`; blocks with JSON and the last 60 lines; `--warn` never blocks | closed: bad input still runs the gate on the fallback root; no jq → exit 2 with a fixed message |
| `project_root.sh` | sourced | sets `$input` and `$root` | falls back to `CLAUDE_PROJECT_DIR`, then `$PWD` |

**Loop guard.** After 3 failed attempts `stop_gate.sh` lets the agent stop and prints a `systemMessage`. The third block tells the agent to start its report with `GATE FAILED: scripts/check.sh <mode>`; that report is the only signal the parent gets, because the `systemMessage` isn't shown in the main view. The counter is `.claude/.stop_attempts_<agent_id or session_id>` (gitignored) and resets on a pass. The orchestrator still re-runs `scripts/check.sh gate` after every subagent returns. Claude Code's own cap (8 continued Stop blocks in a row) resets on every tool call, so the 3-try guard is the real limit.

# A boundary contract is frozen once its folder exists at the base (CR-09): each folder under
