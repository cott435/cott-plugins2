### AD-03: Own environment protocol, shaped like Gymnasium
**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `core`
- **Context:** CORE-01 needs one interface for every environment. REF-01 needs the library agent to train on the same Snake. AGENT-06 keeps library code out of the lab's agents.
- **Decision:** `core.Env` is a small Protocol whose `reset(seed)` returns `(obs, info)` and whose `step(actions)` returns a `StepResult` with Gymnasium's fields (observation, reward, terminated, truncated, info), plus `frame()` for replay. AD-09 sets their batch-first shape over agents. `reference` wraps one single-agent team of a `core.Env`, with every other team played by a frozen agent (AD-15), in a `gymnasium.Env` adapter.
- **Alternatives:** Subclass `gymnasium.Env` directly — no adapter, but every environment and the core then depend on Gymnasium. A bespoke interface unlike Gymnasium's — needs a bigger adapter and teaches a nonstandard shape.
- **Consequences:** Truncation (starvation or the step cap) and termination (a collision or a catch) stay separate, so learning targets bootstrap correctly on truncation. The adapter is checked with Stable-Baselines3's `check_env`.

### AD-04: Stable-Baselines3 DQN as the reference implementation
**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `reference`
- **Context:** For Snake, REF-01–REF-03 need an established implementation trained with the same view, rewards, step budget and seeds as the compact-view neural agent; AD-10 covers the tank. The Stable-Baselines3 DQN docs (https://stable-baselines3.readthedocs.io/en/master/modules/dqn.html, read 2026-10-17) say it supports Discrete actions and Box observations, has `buffer_size`, `target_update_interval`, `exploration_fraction`, `seed` and `device`, and offers `MlpPolicy` for vector observations. The custom-environment guide (https://stable-baselines3.readthedocs.io/en/master/guide/custom_env.html, read 2026-10-17) requires a `gymnasium.Env` with `reset(seed, options) → (obs, info)` and a five-field `step`, checked by `check_env`.
- **Decision:** `reference` trains Stable-Baselines3 DQN with `MlpPolicy` on the compact view through the AD-03 adapter, with `device="cpu"`. Its hidden layers, learning rate, discount, batch size, memory size, target interval and exploration schedule are mapped one-to-one from the same `RunSettings` the hand-written agent uses. Its curve points come from `evaluate`, exactly as the lab's own agents' do.
- **Alternatives:** CleanRL's single-file DQN — very readable, but a script to copy rather than a library to call, so "matching" it blurs into copying it. RLlib — far heavier than one laptop needs.
- **Consequences:** Stable-Baselines3 measures exploration as a fraction of training rather than in decay steps, and updates every `train_freq` steps. The mapping fixes `train_freq=1` and `gradient_steps=1`, and sets `exploration_fraction = decay_steps / steps`. Stable-Baselines3 and Gymnasium are an optional install extra, so the rest of the lab never carries them.
- **Probe:** none — the two pages above settle the spaces, parameters and environment interface. No account or plan is involved.
