88	### AD-01: Python 3.12 in one uv-managed package
89	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** system
90	- **Context:** One learner on an Apple Silicon laptop; PyTorch, pygame-ce and Stable-Baselines3 all ship arm64 macOS wheels for Python. QR-06 needs the whole install to work offline once set up.
91	- **Decision:** Python 3.12, one `rllab` package with a `uv.lock`. Stable-Baselines3 and Gymnasium go in an optional `check` extra.
92	- **Alternatives:** Python 3.13: wheels for some libraries lag. Separate `rllab-check` package: a real boundary only if the reference stack becomes a burden, so it is a named seam for now.
93	- **Consequences:** `requires-python = ">=3.12,<3.13"`. Training can run without the `check` extra installed, which proves CHECK-01 at install level too.

95	### AD-02: PyTorch for networks and gradients, not for the learning algorithm
96	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** system
97	- **Context:** CHECK-01 allows automatic gradient computation but the learner writes action choice, learning targets and updates. Networks are small MLPs on observations of tens of numbers (WORLD-03). Training is CPU-only (QR-01).
98	- **Decision:** Learners use `torch.nn` layers, `torch.optim` optimisers and autograd. Replay buffers, exploration, targets, advantage estimation, clipping and update schedules are hand-written in `methods`.
99	- **Alternatives:** NumPy with hand-derived backprop: teaches backprop, which is not this project's subject, and is slower to debug. JAX: capable, but less familiar CPU tooling and a functional style that hides the update loop.
100	- **Consequences:** `torch.set_num_threads(1)` per run process (AD-05); small batches stay fast on CPU. The PyTorch install is about 200 MB.

102	### AD-03: DQN for discrete actions, PPO for continuous ones, one learner per team
103	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** system
104	- **Context:** Snake has 3 discrete actions (SNAKE-02); fish and predator-prey push with two numbers in [−1, 1] (FISH-02, PREY-02). Many-fish has 8 agents (FISH-06), and predator-prey has two teams learning at once (TRAIN-07). The brief wants each world to teach one idea, and wants checking against a reference implementation (CHECK-02).
105	- **Decision:** `dqn` (replay buffer, target network, ε-greedy, Huber loss) for snake and the discrete check world. `ppo` (Gaussian policy, GAE, clipped objective) for fish, predator-prey and the continuous check world. All agents of a team share one learner (parameter sharing over a batch of agents). Teams have separate learners in the same run. Evaluation and replay act deterministically: greedy for DQN, the mean action for PPO.
106	- **Alternatives:** PPO everywhere: one method fewer, but snake would not teach value learning. SAC for fish: strong on continuous control, but a third method and harder to explain for many agents. Tabular Q-learning for snake: SNAKE-06 includes length, an unbounded number, so the table would need discretising.
107	- **Consequences:** Two methods to write, each with a check world (TRAIN-06) and a Stable-Baselines3 equivalent (AD-08). A prey that leaves the episode is masked out of its team's batch.

145	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** system
