# qdata — Architecture

**Package:** qdata · **Status:** Draft · **Last updated:** 2026-10-17 · **System:** [../../architecture.md](../../architecture.md)

## Overview
The data library and its command line. A download run pulls every source table through a `Source` adapter into a new, immutable snapshot folder. Derived data (identities, adjusted prices, returns) is rebuilt deterministically from a snapshot into a cache beside it. A validation run writes flags for one snapshot. Research code, the exploratory report and `server` all read through `Loader`. Runs execute as their own processes and write an append-only event log that the CLI and `server` both read.

## Components
| Component | Responsibility | Covers | Depends on |
|---|---|---|---|
| `core` | Shared frozen types, IDs and pandera frame schemas | UNIV-01, QUAL-01 | — |
| `calendar` | NYSE trading days for the window | DATA-07, UNIV-05 (non-trading-day errors) | `core` |
| `sources` | `Source` protocol and its adapters: Sharadar (primary), the cross-check source, a synthetic test source; retries and credential handling | DATA-01–DATA-06, DATA-09, SNAP-07 (retries), QR-06, QR-09 | `core` |
| `snapshots` | Create a snapshot atomically, list, open, verify fingerprints; the only writer of snapshot and derived storage | SNAP-01–SNAP-06, PRICE-02, QR-08, QR-11 | `core` |
| `universe` | Permanent identities, dated tickers, share-class links, membership spells, exit records | UNIV-01–UNIV-07 | `core`, `calendar` |
| `prices` | Raw prices, actions, split and total-return adjustment, daily returns | PRICE-01, PRICE-03–PRICE-08 | `core`, `calendar` |
| `validate` | Every flag check, the cross-check, the test-company check, the flag summary | QUAL-01–QUAL-11 | `core`, `calendar`, `universe`, `prices`, `sources`, `snapshots` |
| `runs` | Run records, one-per-kind lock, progress event log, run entry points and the CLI | SNAP-07, SNAP-08, QR-03, QR-04, QR-05 (writer side), QR-09 | `core`, `sources`, `snapshots`, `validate` |
| `loader` | The research-facing read API over one snapshot and its latest validation | LOAD-01–LOAD-07, QR-01 | `core`, `snapshots`, `universe`, `prices`, `calendar` |
| `explore` | The exploratory report, built with the `data-analysis` skill | EXPL-01–EXPL-03 | `loader` |

`explore` runs the `data-analysis` skill's procedure for each section; it is given a `Loader` on one snapshot and passes when EXPL-01's criteria hold.

## Interfaces
See [contract.md](contract.md).

## Data
- **Snapshot folder** (written once by `snapshots`, then made read-only): `manifest.json` (ID, source, download time, coverage, schema version, SHA-256 of every file) and one Parquet file per source table: `securities`, `tickers`, `membership`, `prices_raw`, `actions`, `prices_source_adjusted`, `crosscheck_closes`. Rows keep the source's own fields plus `security_id`.
- **Derived cache:** `derived/<snapshot_id>/<derivation_version>/` holds identities, membership spells, adjusted prices and returns, keyed by the derivation code's version. It is disposable; deleting it forces a rebuild with the same fingerprint (SNAP-05).
- **Validation output:** `validations/<snapshot_id>/<run_id>/` holds `flags.parquet`, `summary.parquet` and `test_companies.parquet`.
- **Runs:** `runs/<run_id>/record.json` and `events.jsonl`; `runs/<kind>.lock` holds the active run of each kind.
- **Expected facts** for the ten test companies are a hand-verified file in `tests/fixtures/qdata/`, written by the user during test planning (DATA-08), never by code.
- All of it lives under one data root (default `~/qdata`), outside the repository (QR-08).

## Cross-cutting concerns
- **Determinism (SNAP-05, QUAL-10, EXPL-01):** stable sort by `(security_id, date)` before every write; the cross-check sample uses a fixed seed over sorted IDs; Parquet written with fixed writer settings so fingerprints repeat.
- **Speed (QR-01, QR-03, QR-04):** price files sorted by `security_id` with row groups per security block, so one security reads alone and the full panel loads as one columnar read; bulk table export for downloads.
- **Errors:** every public error is a `qdata.core.QdataError` subclass with a message naming the input that failed.

packages/qdata/tests/       → folders only; files are planned in pipelines.md

Everything below is importable from `qdata` itself. Dates are `datetime.date`; every frame is a pandas DataFrame checked against the named pandera schema.

### qdata.SecurityId: type
`SecurityId = NewType("SecurityId", str)  # "<source>:<source permanent id>", e.g. "sharadar:199059"`
- **Invariants:** never reused, never changes when the ticker changes; the prefix names the source that minted it (AD-06)
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.SecurityId/ · **Cases:** a current member, a delisted member, the two BUD securities
- **Used by:** every component, server

### qdata.ExitType: type
`class ExitType(StrEnum): CASH_ACQUISITION; STOCK_ACQUISITION; BANKRUPTCY; OFF_EXCHANGE; OTHER`
- **Invariants:** exactly the five spec categories (UNIV-07); an exit the source doesn't classify maps to `OTHER` and raises a flag
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.ExitType/ · **Cases:** one value of each kind
- **Used by:** universe, validate, server

### qdata.Exit: type
`@dataclass(frozen=True) class Exit: last_trading_day: date; exit_type: ExitType; detail: str`
- **Invariants:** `last_trading_day` is an NYSE trading day; `detail` is the source's own wording, kept for inspection
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.Exit/ · **Cases:** LEH (bankruptcy), WYE (stock acquisition), a cash acquisition
- **Used by:** universe, validate, server

### qdata.TickerSpan: type
`@dataclass(frozen=True) class TickerSpan: ticker: str; start: date; end: date | None`
- **Invariants:** a security's spans never overlap; `end` is `None` only for the current ticker of a listed security
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.TickerSpan/ · **Cases:** a single span, a security with a ticker change, BUD's two holders
- **Used by:** universe, loader, server

### qdata.MembershipSpell: type
`@dataclass(frozen=True) class MembershipSpell: entry: date; exit: date | None`
- **Invariants:** member from the close of `entry` until the close of the trading day before `exit`; spells of one security never overlap
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.MembershipSpell/ · **Cases:** an open spell, a closed spell, a security with two spells
- **Used by:** universe, validate, loader, server

### qdata.Security: type
`@dataclass(frozen=True) class Security: id: SecurityId; company_id: str; name: str; share_class: str; tickers: tuple[TickerSpan, ...]; spells: tuple[MembershipSpell, ...]; exit: Exit | None; predecessor: SecurityId | None`
- **Invariants:** `tickers` and `spells` sorted by start; share classes of one company share `company_id`; `exit` is `None` while listed
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.Security/ · **Cases:** a current member, LEH, EK and its successor, a two-class company
- **Used by:** universe, validate, loader, server

### qdata.CorporateAction: type
`@dataclass(frozen=True) class CorporateAction: security_id: SecurityId; date: date; kind: Literal["split", "dividend", "ticker_change", "delisting", "other"]; value: float | None; detail: str`
- **Invariants:** `value` is the split ratio (new shares per old) or cash per share; `date` is the effective trading day (non-trading dates are moved forward and flagged)
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.CorporateAction/ · **Cases:** a 2-for-1 split, a cash dividend, a spin-off kept as `other`
- **Used by:** prices, validate, loader, server

### qdata.PriceFrame: type
`PriceFrame = DataFrame[PriceSchema]  # columns security_id, date, open, high, low, close, volume, close_split_adj, close_tr_adj, ret_price, ret_total`
- **Invariants:** one row per security per trading day it was listed in the window; sorted by `(security_id, date)`; raw columns equal the snapshot; returns are NaN on a security's first day
- **Boundary:** server, explore · **Fixtures:** tests/contracts/qdata.PriceFrame/ · **Cases:** a split day, a dividend day, a gap day, a delisting's final rows
- **Used by:** prices, validate, loader, explore, server

### qdata.Panel: type
`Panel = DataFrame  # index date (trading days, ascending), columns SecurityId, values float64; attrs["snapshot_id"]`

- **Boundary:** explore · **Fixtures:** tests/contracts/qdata.Panel/ · **Cases:** three securities over 10 days, one delisting midway
- **Used by:** loader, explore

### qdata.FlagType: type
`class FlagType(StrEnum): JUMP; STALE; GAP; ADJUSTMENT; CROSSCHECK; CROSSCHECK_NOT_COVERED; MEMBER_WITHOUT_PRICE; ACTION_ON_NON_TRADING_DAY; UNUSED_ACTION; UNCLASSIFIED_EXIT`
- **Invariants:** a new check adds a member; members are never renamed
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.FlagType/ · **Cases:** every member
- **Used by:** validate, loader, server

### qdata.Flag: type

- **Invariants:** `start == end` except for stale runs; never modifies data (QUAL-09)
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.Flag/ · **Cases:** a jump, a 5-day stale run, a cross-check miss with both closes in `detail`

### qdata.SnapshotInfo: type
`@dataclass(frozen=True) class SnapshotInfo: id: str; source: str; downloaded_at: datetime; first_date: date; last_date: date; n_securities: int; fingerprint: str; validated_by: str | None`
- **Invariants:** `id` is `YYYYMMDD-NN`, unique; `fingerprint` is the SHA-256 over the manifest's file hashes; `validated_by` is the latest successful validation run ID
- **Boundary:** server · **Fixtures:** tests/contracts/qdata.SnapshotInfo/ · **Cases:** a validated snapshot, an unvalidated one
- **Used by:** snapshots, runs, loader, server

### qdata.SourceTables: type
`@dataclass(frozen=True) class SourceTables: source: str; securities: DataFrame; tickers: DataFrame; membership: DataFrame; prices_raw: DataFrame; actions: DataFrame; prices_source_adjusted: DataFrame`
- **Invariants:** each frame passes its pandera schema; every row carries `security_id`; rows are as received, never altered
- **Boundary:** snapshots · **Fixtures:** tests/contracts/qdata.SourceTables/ · **Cases:** the synthetic source's full output, a probe-derived slice for the ten test companies
- **Used by:** sources, snapshots

### qdata.Source: Primary data source adapter
`class Source(Protocol): name: str; def fetch(self, start: date, on_progress: Callable[[str, int, int], None]) -> SourceTables`
- **Invariants:** returns every security ever an S&P 500 member since `start`, delisted ones included; retries a temporary error 3 times
- **Errors:** `SourceAuthError` and `SourceUnavailableError` within 60 s; credentials never appear in messages
- **Boundary:** runs · **Fixtures:** tests/contracts/qdata.Source/ · **Cases:** a recorded synthetic fetch, an auth failure
- **Used by:** runs

### qdata.CrossCheckSource: Cross-check closes adapter
`class CrossCheckSource(Protocol): name: str; def closes(self, tickers: Sequence[str], start: date) -> DataFrame  # ticker, date, close (raw)`
- **Invariants:** missing tickers are absent from the result, never an error
- **Errors:** `SourceUnavailableError` after 3 retries
- **Boundary:** validate · **Fixtures:** tests/contracts/qdata.CrossCheckSource/ · **Cases:** a recorded 3-ticker response, a ticker not covered
- **Used by:** validate

### qdata.list_snapshots: Snapshot listing
`def list_snapshots(root: Path | None = None) -> list[SnapshotInfo]`
- **Invariants:** newest first; only complete snapshots (SNAP-06)
- **Errors:** none; an empty root gives `[]`
- **Used by:** loader, runs, server

### qdata.verify_snapshot: Fingerprint check
`def verify_snapshot(snapshot_id: str, root: Path | None = None) -> None`
- **Errors:** `SnapshotTamperedError` naming the snapshot and the first mismatching file; `UnknownSnapshotError`
- **Used by:** runs, server

### qdata.open_loader: Open a snapshot for reading
`def open_loader(snapshot_id: str | None = None, root: Path | None = None) -> Loader`
- **Invariants:** `None` opens the newest snapshot; builds the derived cache on first use
- **Errors:** `UnknownSnapshotError` listing available IDs; `NoSnapshotsError` saying to run a download
- **Used by:** explore, server, research code

# server — Architecture

**Package:** server · **Status:** Draft · **Last updated:** 2026-10-17 · **System:** [../../architecture.md](../../architecture.md)

## Overview
A local-only backend for `cockpit`. HTTP routes answer queries by calling `qdata.Loader`, one cached loader per snapshot. `POST /api/runs` calls `qdata.start_run`, so runs live in their own processes and survive the server and the browser. A WebSocket per run tails `qdata.read_events` and pushes each new event. Every request and message body is a Pydantic model; those models are exported as JSON Schema, which is the contract `cockpit` is generated from (AD-09).

## Components
| Component | Responsibility | Covers | Depends on |
|---|---|---|---|
| `dto` | Pydantic models for every request, response and WebSocket message; conversion from `qdata` types; JSON Schema export | QR-10 | `qdata` (types only) |
| `guard` | Bind to 127.0.0.1; reject requests whose `Host` or `Origin` isn't the local app | QR-07 | — |
| `routes` | HTTP query and run-start endpoints | APP-01–APP-08, SNAP-08 (refusal surfaced), QR-02 | `dto`, `qdata` |
| `progress` | WebSocket per run: replays events after the client's last `seq`, then streams new ones | APP-09, APP-10, QR-05 | `dto`, `qdata` |
| `main` | App assembly, loader cache, settings (data root, port), CLI `qdata-server` | — | `routes`, `progress`, `guard` |

## Interfaces
See [contract.md](contract.md).

## Cross-cutting concerns
- **Latency (QR-02, QR-05):** loaders are cached per snapshot; a price series response is ≤ 1 security × the window, about 5,500 rows. `progress` polls the event log every 100 ms, so an event reaches the browser well inside 1 s.
- **Errors:** every `qdata` error maps to one HTTP status and an `ErrorDto` (`UnknownSnapshotError` → 404, `AmbiguousTickerError` → 409 with candidates, `RunActiveError` → 409 naming the run).
- **Credentials (QR-09):** `server` never reads source credentials; only run processes do.

# Quant Research Platform — Architecture

**Status:** Draft · **Shape:** Multi-package · **Last updated:** 2026-10-17 · **Spec:** [spec.md](spec.md)

## Overview
`qdata` is a Python library and command line that downloads the S&P 500 dataset from Sharadar into immutable snapshots, derives identities, adjusted prices and returns, validates them into flags, and serves everything through one `Loader`. `server` is a local-only Python backend that answers `cockpit`'s queries through that `Loader`, starts runs, and streams their progress. `cockpit` is the TypeScript and React browser app. Runs execute in their own processes and log progress to disk, so the command line and the app see the same runs.

  qdata -- "Source / CrossCheckSource" --> vendors[(Sharadar, Tiingo)]

- **Reproducibility (SNAP-05, QUAL-10, EXPL-01):** derived data is a pure function of snapshot + derivation version; the fingerprint test rebuilds twice.
- **Cost (QR-06):** Sharadar is already paid; Tiingo free tier costs $0; the fallback Tiingo paid tier is $30/month, inside the $50 limit.
- **Testing:** the synthetic `Source` builds a small snapshot covering splits, dividends, reused tickers, a two-spell member and each exit type; every package's tests run on it without network access.

## Decisions
### AD-01: Multi-package monorepo with enforced boundaries
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** Two runtimes (Python, browser TypeScript), a long-running backend, and research code that must not carry a web stack (QR-10; brief constraint). The user chose three packages.
- **Decision:** One repository with `packages/qdata`, `packages/server` (a uv workspace) and `packages/cockpit` (pnpm). Dependency rules are `import-linter` contracts plus the schema-drift check, run by one check script.
- **Alternatives:** Two packages, with the server inside `qdata` — research imports would carry the web stack and the boundary couldn't be enforced. Separate repositories — needless for one person.
- **Consequences:** Every cross-package change goes through a contract; one check script must run both toolchains.

### AD-02: Python stack
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`, `server`
- **Context:** Python everywhere except the app (brief). Frames of ~5–8 million price rows must load in ≤ 5 s (QR-01); types crossing steps need checked schemas.
- **Decision:** Python 3.13; pandas 2 on pyarrow-backed dtypes; pandera schemas for every frame type in the contract.
- **Alternatives:** Polars — faster, but most quant learning material and libraries assume pandas, and pandas meets QR-01 on this size. DuckDB as the query layer — useful at larger scale; not needed for one-security reads from sorted Parquet.
- **Consequences:** Research code gets familiar DataFrames; a move to Polars later stays inside `qdata`.

### AD-03: Snapshot storage
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** Snapshots must be complete, immutable, fingerprinted and never partial (SNAP-01–SNAP-06), ≤ 2 GB each (QR-11), outside the repo (QR-08), with no database server (brief).
- **Decision:** One folder per snapshot under the data root, written to a temporary folder, fingerprinted (SHA-256 per file, plus one over the manifest), then renamed into place and made read-only. Tables are Parquet with fixed writer settings, sorted by `(security_id, date)`. Derived data goes to a disposable cache keyed by snapshot and derivation version.
- **Alternatives:** SQLite — one file with in-place writes, which works against immutability. Incremental patches — rejected by SNAP-02.
- **Consequences:** Rename is atomic on one volume, so an interrupted run leaves only a temp folder, which the next run deletes. Each snapshot stores a full copy (a few hundred MB).

### AD-04: Primary data source: Sharadar API
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** Fixed by the brief (DATA-09). Must meet DATA-01–DATA-05. Sources read 2026-10-17:
  - Access is a REST API at `api.sharadar.com/v1.0/data/{table}` with an API key (https://sharadar.com/docs/auth).
  - SEP covers "active and delisted US public stocks" from December 1997. Its `open/high/low/close/volume` are split-adjusted; `closeunadj` is unadjusted; `closeadj` is adjusted for splits, dividends and spin-offs. A full-history pull is `years=full` (https://sharadar.com/docs/stocks).
  - TICKERS gives `permaticker`, "a unique and unchanging identifier for a security (share class)", plus `isdelisted`, `firstpricedate` and `lastpricedate` (https://sharadar.com/docs/tickers).
  - ACTIONS lists ticker changes, splits, cash dividends, spin-offs, delistings with reasons, and acquirers (https://sharadar.com/docs/actions).
  - SP500 has date, action and ticker per event (https://sharadar.com/docs/sp500).
  - The Prices plan includes SEP, ACTIONS, SP500 and TICKERS (https://sharadar.com/bundle).
- **Decision:** `qdata.sources.sharadar` pulls TICKERS, SP500, ACTIONS and SEP (filtered to every ticker ever in SP500) as full-history bulk requests. The window starts at the earliest date that has both membership and prices.
- **Alternatives:** None considered; the brief fixes the source. The `Source` protocol keeps a switch to one adapter (Goal 5).
- **Consequences:** The window likely starts in 1998, beyond DATA-01's 2005 minimum. Raw open, high, low and volume are not delivered unadjusted (AD-07).
- **Probe:** PB-01. The docs don't settle these, and some depend on the user's own plan:
  - which tables the plan returns;
  - the full SP500 and ACTIONS action codes, including history before 2005;
  - whether reused tickers (BUD, DNA) get new permatickers;
  - whether share classes can be linked to one company;
  - whether all ten test companies are present;
  - rate limits and full-download time (QR-03).

### AD-05: Cross-check source: Tiingo free tier
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** DATA-06 needs independent daily raw closes for ≥ 50 current members since 2005, with new spend ≤ $50/month (QR-06). Read 2026-10-17:
  - Tiingo's free tier allows 50 requests/hour, 1,000/day and 500 unique symbols/month, with 30+ years of history, for personal use. Power is $30/month (https://www.tiingo.com/about/pricing).
  - The end-of-day endpoint returns `close`, `adjClose`, `divCash` and `splitFactor` (https://www.tiingo.com/documentation/end-of-day).
- **Decision:** `qdata.sources.tiingo` implements `CrossCheckSource`, one request per ticker for full history. A validation run fits the free tier (50 requests).
- **Alternatives:**
  - Alpha Vantage: full daily history is premium-only; the free tier gives the last 100 days (https://www.alphavantage.co/documentation/).
  - EODHD: the free tier gives 1 year (https://eodhd.com/pricing).
  - Massive (formerly Polygon): the free tier gives 2 years (https://massive.com/pricing).
  - Stooq: no official API or terms found.
  - yfinance: unofficial.
- **Consequences:** Validation runs in one hour must stay ≤ 50 requests; the adapter caches responses per day. A second key is stored like Sharadar's (AD-14).
- **Probe:** PB-02. The docs don't say outright that `close` is unadjusted, and coverage of the 50 sampled tickers back to 2005 must be checked.

### AD-06: Platform-owned security identity
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** UNIV-01–UNIV-04 need one permanent ID per share class across ticker changes and reuse. LOAD-07 and Goal 5 need IDs that aren't tied to one vendor.
- **Decision:** `SecurityId = "sharadar:<permaticker>"`. Tickers become dated `TickerSpan`s built from TICKERS and ACTIONS ticker changes. `company_id` links share classes using what PB-01 finds. A cross-check ticker maps to a `SecurityId` through the ticker span on the compared dates.
- **Alternatives:** Ticker as key — fails UNIV-02 (BUD, DNA). CUSIP — licensed, and changes on corporate events.
- **Consequences:** A second primary source would mint its own prefix and need a mapping table; that is out of scope now.

### AD-07: Raw prices and platform-computed adjustments
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** PRICE-01–PRICE-08 need raw prices and adjustments computed by the platform. QUAL-05 compares against the source's adjusted close. SEP delivers `closeunadj` raw, but open, high, low, close and volume only split-adjusted, as of the download (AD-04).
- **Decision:**
  - The snapshot stores SEP exactly as received (PRICE-02 holds for every received field).
  - Raw close is `closeunadj`. Raw open, high and low are the received values × (`closeunadj` ÷ `close`); raw volume is divided by that ratio. Both are marked as reconstructed.
  - Split-adjusted and total-return prices are computed backward from raw close, using ACTIONS splits and dividends (PRICE-04, PRICE-05). `closeadj` is used only by QUAL-05.
- **Alternatives:** Use `closeadj` directly — it can't be traced to an action (Goal 2), and it includes spin-offs, which the spec leaves out of adjustments.
- **Consequences:** On spin-off days the platform's total return and `closeadj` differ by design; those adjustment flags say "spin-off" in `detail`.

### AD-08: Runs as their own processes
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`, `server`
- **Context:** Runs start from the CLI or the app, survive the browser closing (APP-10), allow one per kind (SNAP-08), and show progress within 1 s (QR-05).
- **Decision:** `qdata.start_run` spawns a detached `qdata run <kind>` process. It takes `runs/<kind>.lock` (an OS file lock with the run ID inside), writes `record.json`, and appends `ProgressEvent` lines to `events.jsonl`. `server` reads events by `seq`.
- **Alternatives:** A thread inside `server` — dies with the server, and the CLI can't see it. A task queue — needs a broker (brief: no servers).
- **Consequences:** A crashed run releases its OS lock automatically; `list_runs` marks a "running" record with no live lock as failed.

### AD-09: Typed app contract from JSON Schema
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `server`, `cockpit`
- **Context:** QR-10: one shared contract, and a mismatch fails the checks. The two runtimes share no types.
- **Decision:** `server.dto` Pydantic models are the source. A script exports them as JSON Schema into `contracts/server/`, and `json-schema-to-typescript` generates `cockpit/src/api/types.ts`. `cockpit` validates every received body with Ajv against the same schema. The check script regenerates both and fails if the git diff isn't empty.
- **Alternatives:** OpenAPI client generation — covers HTTP but not the WebSocket messages, and brings a generated client. Hand-written TypeScript types — drift silently.
- **Consequences:** Changing a DTO means regenerating and committing the schema; the boundary fixtures in `tests/contracts/server.*` validate against the same files.

### AD-10: Backend framework
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `server`
- **Context:** HTTP queries, a WebSocket per run, Pydantic models (AD-09), local only (QR-07).
- **Decision:** FastAPI on uvicorn, bound to 127.0.0.1, with middleware that rejects any Host or Origin other than the app's local address (this also guards against DNS rebinding).
- **Alternatives:** Litestar — similar, with a smaller ecosystem. Flask — no native async WebSockets.
- **Consequences:** The JSON Schema export comes from the same models FastAPI validates against.

### AD-11: Frontend stack and charts
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `cockpit`
- **Context:** TypeScript and React (brief). Charts must follow the `dataviz` skill and draw ≤ 1 s (APP-11, QR-02). The look must be deliberate, not a dashboard template (APP-11, `frontend-design`).
- **Decision:** Vite, React 19, strict TypeScript, TanStack Query for server state, React Router. Charts are built from d3 modules (scale, shape, axis, zoom) rendered as React SVG. No UI kit; styling uses CSS variables from `theme`.
- **Alternatives:** Recharts or a chart kit — a templated look, and less control over action markers. uPlot — fast canvas, but harder to style to the `dataviz` method, and its speed isn't needed at 5,500 points.
- **Consequences:** More chart code to write; full control over marks, colour and both themes.

### AD-12: Trading calendar
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** DATA-07; gap flags (QUAL-04) and non-trading-day errors depend on it. Read 2026-10-17:
  - exchange_calendars 4.13.2 (https://pypi.org/project/exchange-calendars/) includes the 2012 Hurricane Sandy closures and the 2018 and 2025 days of mourning (https://github.com/gerrymanoim/exchange_calendars/blob/master/exchange_calendars/us_holidays.py).
  - Its default start is 20 years back, so `start` must be passed explicitly (exchange_calendar.py, `GLOBAL_DEFAULT_START`).
- **Decision:** `qdata.calendar` wraps XNYS with `start` set to the window start.
- **Alternatives:** pandas_market_calendars — mirrors the same calendars and adds intraday sessions that daily data doesn't need. Inferring days from the source — circular for gap detection.
- **Consequences:** Validation also reports any date where the calendar and the source's trading days disagree, as gap flags.
- **Probe:** none — the library's source and release page settle coverage.

### AD-13: Exploratory report format
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** EXPL-01–EXPL-03: five sections, named snapshot, identical numbers on regeneration, built with the `data-analysis` skill.
- **Decision:** `qdata.explore` computes every table as a pure function of a `Loader` and renders one self-contained HTML file with matplotlib figures (embedded PNG), using the `data-analysis` skill's procedures per section.
- **Alternatives:** An executed notebook — outputs carry run metadata and are harder to diff. A report page in `cockpit` — duplicates work the app doesn't need.
- **Consequences:** Numbers can be tested directly; figures are static.

### AD-14: Credentials
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** `qdata`
- **Context:** QR-08 and QR-09: keys never in the repo, logs or app.
- **Decision:** Keys are read from the macOS Keychain via `keyring` (service `qdata`, names `sharadar`, `tiingo`), falling back to environment variables. Only run processes read them, and a logging filter redacts their values.
- **Alternatives:** A `.env` file only — easy to commit by mistake.
- **Consequences:** First-time setup is one `qdata auth set <source>` command.

## Risks and open questions
- **Raw open, high, low and volume are reconstructed, not received (AD-07).** PRICE-02 holds for what is received, but PRICE-01's raw open, high, low and volume come from the split ratio. The user should confirm this is acceptable, or the spec should say so.
- **PB-01 (Sharadar plan and behaviour)** gates AD-04 and AD-06. If SP500 history or delisting reasons are missing, the universe or exit records need another source before the build.
- **PB-02 (Tiingo raw close and coverage)** gates AD-05. Fallback: Tiingo Power ($30/month) or another source from AD-05's list.
- **Rate limits are unpublished.** QR-03 (≤ 30 min download) is unverified until PB-01 times a full pull.
- **Share-class company links** may not exist in Sharadar. Fallback: link by shared company name and CIK where present, flagged when unsure.
- **The `dataviz` skill is not installed in the project.** Build agents may not see it; copy it into `.claude/skills/` before the `cockpit` build.

## The decisions that matter most

- **Data access (AD-04):** the Sharadar API, using the SEP, TICKERS, ACTIONS and SP500 tables, downloaded as full-history pulls. Sharadar's docs say prices go back to December 1997 and include delisted stocks, so the window probably starts in 1998.

- **Identity (AD-06):** a security's ID is `sharadar:<permaticker>`. Sharadar documents the permaticker as "unique and unchanging" for each share class. Tickers are stored as dated spans.
- **Prices (AD-07): this needs your attention.** Sharadar sends only the **close** unadjusted. Open, high, low and volume arrive split-adjusted. I'd store everything exactly as received and rebuild raw open, high, low and volume from the split ratio, marking them as rebuilt. Adjustments are computed by the platform; Sharadar's own adjusted close is used only for the check that flags disagreements.
- **Runs (AD-08):** each run is its own process, with a lock file and an event log on disk. That's how the app and the command line see the same runs, how only one run of each kind can be active, and why closing the browser never stops a run.
- **Typed contract (AD-09):** Pydantic models produce a JSON Schema, which generates the TypeScript types. The app also checks every response against the schema as it arrives. If anything drifts, the check script fails.
- **App (AD-10, AD-11):** FastAPI bound to 127.0.0.1 with Host and Origin checks. The frontend is Vite, React 19 and TanStack Query, with charts hand-built from d3 modules as SVG. There's no chart or UI kit, so frontend-design and dataviz control the look.

- **PB-01 (Sharadar):** which tables your plan returns, the full action codes, whether BUD and DNA get new permatickers when their tickers are reused, how share classes link to companies, whether all 10 test names are present, rate limits, and how long a full download takes.
- **PB-02 (Tiingo):** whether its `close` is truly unadjusted, and whether it covers the 50 sampled tickers back to 2005.
