Stage 3 is a new idea, so this is idea-refine again, adding to the existing brief. Nothing is written yet.

## In terms of the existing project
*This adds candidate features and machine-learning tests so that you can find out, honestly, whether any feature carries information about future residual returns beyond what chance would produce.*

- **Serves Goal 5 directly.** This is the "does any signal survive honest testing" question the brief was written for. No brief change looks needed; I'll confirm in the fit check.
- **Touches:**
  - S2's market removal (STRUC-02 and STRUC-03) for residual returns, and CMP-02's testing rule.
  - The spec's Out of scope line *"Return prediction, signal research and paper trading: the S2 portfolios are variance-only."* That gets narrowed when S3 is specced.
- **Data limit:** S1 holds prices, volume and corporate actions only, and *company fundamentals are out of scope*. So features are price and volume based unless you widen that.
- **How might we** screen and model many candidate features without fooling ourselves through look-ahead, overlapping samples, or the multiple testing that comes from trying many features and models?

## The hard parts, up front
1. **Point-in-time residuals.** S2 removes factors *within* each window. For a prediction target, the factor loadings must be estimated on the trailing window and then applied to the *future* returns, never refit with future data.
2. **Counting every test.** If 40 features are tried and 3 reported, the correction has to count all 40. That argues for a **feature ledger**: every feature ever tested is recorded, and the multiple-testing correction runs over the whole ledger.
3. **Overlapping targets.** A 21-day forward return overlaps its neighbours, so walk-forward splits need a gap (purging and an embargo), or the tests look far better than they are.
4. **One untouched holdout.** A final period that is only looked at once, to confirm whatever survived.

## Sharpening questions
1. **Target and horizon:** I'd suggest the forward residual return over the next **21 trading days** (matching S2's monthly rebalance), with **5 days** as a variant. Right?
2. **What "ML for information gain" means to you.** My default is two levels:
   - **(a) per feature:** does it predict residual returns out of sample beyond chance (rank correlation or mutual information, against a null that shuffles the feature across stocks within each date)?
   - **(b) per model:** does a model using the features beat a no-information baseline out of sample?
   
   Models: a regularised linear model first, then gradient-boosted trees. Which, or both?
3. **Feature families,** from prices and volume: momentum (12-1 month), short-term reversal, volatility and idiosyncratic volatility, beta, maximum daily return, illiquidity (price impact per dollar traded) and turnover. Any to add or drop? Do you want to keep fundamentals out?
4. **Holdout:** reserve the **last 3 years** untouched, opened once at the end to confirm surviving claims? (Default: yes.)
5. **Learning style:** for S2 you wanted the maths right. Here, should models be **written by hand first and then compared with an established library**, or **library from the start**? (Default: hand-written linear model, library gradient-boosted trees.)

## Variations
1. **Screen first:** test each feature on its own with a proper null, then model only the survivors. *Why:* simple and interpretable, and it controls false discoveries feature by feature.
2. **Model first:** fit gradient-boosted trees on everything and rank by importance. *Why it's tempting:* fast. *Pushback:* importance scores computed in sample are biased and carry no null, so this is exactly how false discoveries get approved.
3. **Testing machinery first (inversion):** build the walk-forward splits with a gap, the feature ledger, the holdout lock and the null tests before any feature. *Why:* it worked for S2's harness. Every later claim then goes through the same gate.
4. **Linear only (simplification):** cross-sectional regressions of residual returns on features each month, with the average coefficient tested. *Why:* the classic, transparent baseline every ML result should beat.
5. **Expert lens:** walk-forward splits with purging and an embargo, plus statistics deflated for the number of trials. *Why:* the published standard for not fooling yourself in finance ML.
6. **Bridge to portfolios:** judge features by a long-short residual portfolio built from them. *Why it's tempting:* intuitive. *But* that's return-based trading, so better as a later stage.
7. **10x:** a feature store with automated model search. *Why it's here:* to name it and set it aside. More searching means more false positives.

## My early take
**3 + 1 + 5, with 4 as the baseline.** Build the testing machinery first (splits with a gap, the ledger, the holdout lock), then screen features one by one, then model with linear and then gradient-boosted trees. A model only counts if it beats both a no-information baseline and the linear model, under a corrected null test. Every claim goes through `null-hypothesis-testing`, as you asked, and the descriptive work on real data uses `data-analysis`.

Answer what you can, or say "defaults". Questions 2 and 5 are the ones I can't guess.
