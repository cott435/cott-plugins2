# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [brief.md](brief.md)

## Summary
A personal lab of three small 2D worlds (Snake, a fish tank with a bouncing ball, and a predator–prey tank), each paired with a learning algorithm written by hand. A shared core runs, logs, evaluates and replays every world the same way. Each world ends with a lesson note showing that its learner beats simple baselines and lands near an established reference implementation.

## Users
| User | What they need to do |
|---|---|
| Me (the learner) | Train a learner on a world, compare it with baselines and a reference, watch replays, and write up why it works |

## Scope
**In scope:** Environment format, Training runs, Evaluation & baselines, Replay viewer, Lesson notes, Snake, Fish tank, Predator–prey.
**Out of scope:**
- Learning from pixels or Atari games.
- 3D or realistic physics.
- A general RL framework or a collection of algorithms. There is one learner per idea.
- Publishing, a website, or other users.
- More than these three worlds.
- Massive parallel speed-ups beyond what the 60-minute limit needs.
- Resuming an interrupted training run.
- Comparing with a reference implementation when both sides learn at once (Predator–prey Phase B).
- Depending on a GPU for any pass result.

## Features

### Environment format (`CORE`)
**Serves:** Goal 5
**Behavior:** Every world is driven the same way. I start an episode with a seed and get one observation per agent. Then I send one action per active agent and get back each agent's next observation, reward and whether it is done. One, many or two teams of agents all use this same interaction.

**Requirements**
- **CORE-01** Starting an episode takes a seed and returns one observation per agent.
  - Given any world and seed 7, when I start an episode, then I get one observation for each agent, keyed by agent name.
- **CORE-02** A step takes one action per active agent and returns, for each agent, its next observation, its reward and whether it is done.
  - Given an episode in progress, when I send an action for every active agent, then each agent's next observation, reward and done flag come back.
- **CORE-03** The same seed and the same actions give the same episode.
  - Given two episodes started with the same seed, when the same actions are sent in the same order, then every observation, reward and done flag matches exactly.
- **CORE-04** An agent that is done gets no further observations and accepts no further actions for the rest of the episode.
  - Given a fish that was caught at step 40, when step 41 runs, then that fish appears in no step output.
  - Given an action sent for a done agent, when the step runs, then it is rejected with an error naming the agent.
- **CORE-05** Every world states the shape and range of its observations and actions.
  - Given any world, when I ask for its observation and action description, then I get each one's size and allowed range, or its list of discrete choices.
- **CORE-06** A continuous action outside its range is clipped to the range.
  - Given a steering action of (3.0, −2.0) with range [−1, 1], when the step runs, then (1.0, −1.0) is applied.
- **CORE-07** A discrete action that isn't one of the allowed choices is rejected.
  - Given Snake and action 5, when the step runs, then it is rejected with an error listing the allowed actions.
- **CORE-08** Supports one agent, one team of many agents, and two teams.
  - Given Snake (1 agent), Fish tank (8 fish) and Predator–prey (8 prey and 1 predator), when each runs a full episode, then all three work through the same interaction.
- **CORE-09** Any episode can be recorded step by step, with enough detail to replay it exactly.
  - Given a recorded episode, when it is replayed, then the world state at each step matches the original run.

**Edge cases & errors**
- A step is sent after every agent is done → rejected with an error saying the episode is over.
- A step is missing an action for an active agent → rejected with an error naming the agent.

### Training runs (`TRAIN`)
**Serves:** Goal 4, Goal 5
**Behavior:** I start a training run with one command and a named configuration. While it runs it logs progress and saves checkpoints. I can run the same configuration over several seeds with one command.

**Requirements**
- **TRAIN-01** A training run starts with one command and a named configuration.
  - Given the configuration "snake-default", when I run the train command with it, then training starts with no other input.
- **TRAIN-02** Every setting of a run is saved with the run: world, learner, learner settings, seed and step budget.
  - Given a finished run, when I open its saved settings, then I can start an identical run from them alone.
- **TRAIN-03** A run logs each finished episode's return and length.
  - Given a run in progress, when an episode finishes, then its return and length appear in the run's log within 10 seconds.
- **TRAIN-04** A run logs learner diagnostics at fixed intervals: loss, and the world-specific diagnostics in NOTE-02.
  - Given a run with a logging interval of 1,000 steps, when 10,000 steps have passed, then there are 10 diagnostic entries.
- **TRAIN-05** A run saves checkpoints at 0%, 10%, 25%, 50%, 75% and 100% of its step budget.
  - Given a finished run, when I list its checkpoints, then these six are present, each labelled with its training step.
- **TRAIN-06** One command runs one configuration over several seeds, and each seed is its own run.
  - Given seeds 0 to 4, when I run the multi-seed command, then five separate runs exist, each with its own log and checkpoints.
- **TRAIN-07** On the CPU, the same configuration and seed give the same learning curve.
  - Given two runs of "snake-default" with seed 0, when both finish, then their logged episode returns are identical.

**Edge cases & errors**
- A run stops partway (crash or I stop it) → its log and the checkpoints saved so far are kept and usable. It is not resumed.
- An unknown configuration name → the run doesn't start, and the error lists the known configurations.

### Evaluation & baselines (`EVAL`)
**Serves:** Goal 2, Goal 5
**Behavior:** Any checkpoint or baseline can be scored on test episodes the learner never trained on. The lab checks two things: that the learner beats random play and a scripted strategy by more than chance, and that it reaches at least 80% of an established reference implementation.

**Requirements**
- **EVAL-01** Scoring a checkpoint or baseline runs 100 test episodes on seeds that are never used in training. It reports the mean score and the standard deviation.
  - Given a checkpoint, when I evaluate it, then the report shows the mean and standard deviation over 100 episodes, and none of their seeds is a training seed.
- **EVAL-02** Every world has a random baseline and a scripted baseline, scored the same way as learners.
  - Given any world, when I evaluate "random" and "scripted", then both report scores in the same format as a checkpoint.
- **EVAL-03** For every world, the final checkpoints from 5 training seeds are compared with each baseline using the `null-hypothesis-testing` skill. The null hypothesis is "the learner scores no higher than the baseline", tested on per-seed mean test scores at the 5% level with correction for the comparisons in that world. The learner passes only if the null is rejected against every baseline that counts as a bar.
  - Given 5 final checkpoints and a baseline, when the comparison runs, then the report states the test, the p-value after correction, and pass or fail.
- **EVAL-04** For Snake, Fish tank and Predator–prey Phase A, an established reference implementation of the same kind of learner is trained on the same world, with the same step budget and 5 seeds. My learner passes if its mean final test score is at least 80% of the reference's.
  - Given both sets of 5 final checkpoints, when the comparison runs, then the report shows both mean scores, the ratio, and pass or fail at 80%.
- **EVAL-05** Learning curves are drawn with the `dataviz` skill: the mean test score across seeds against training steps, with a band showing the spread, and each baseline's score as a horizontal line.
  - Given 5 runs, when I draw the learning curve, then one chart shows the mean, the spread band and the baseline lines, with labelled axes.
- **EVAL-06** Learners are written from basic array and tensor operations. The reference implementation is used only for EVAL-04.
  - Given any learner, when its code is reviewed, then it does not call a reinforcement-learning library.

**Edge cases & errors**
- Fewer than 5 finished seeds → the comparison doesn't run, and it reports how many seeds are missing.
- The reference beats my learner by more than 20% → the result is reported as a fail, with both curves on one chart for diagnosis.

### Replay viewer (`VIEW`)
**Serves:** Goal 3, Goal 5
**Behavior:** I can watch any recorded episode, or record a fresh one from a checkpoint or baseline. Two checkpoints can play side by side on the same seed, for example early versus late training.

**Requirements**
- **VIEW-01** Plays a recorded episode exactly as recorded.
  - Given a recorded episode, when I play it, then every frame matches the recorded world state.
- **VIEW-02** Records and plays an episode from any checkpoint or baseline, with a chosen seed.
  - Given the 10% checkpoint and seed 3, when I ask the viewer to show it, then a new episode is recorded and played.
- **VIEW-03** Plays two checkpoints side by side on the same seed, in step.
  - Given the 0% and 100% checkpoints, when I compare them, then both play next to each other and their step counters always match.
- **VIEW-04** Supports pause, single-step forward and playback speeds of 0.25× to 4×.
  - Given a paused episode, when I press single-step, then exactly one step advances.
- **VIEW-05** Shows the step count and each agent's running score on screen.
  - Given any playing episode, when a frame is shown, then the step count and the scores are visible.
- **VIEW-06** In the tank worlds, can show each agent's vision radius.
  - Given Fish tank playing, when I turn on vision, then a circle shows each living fish's vision radius.

**Edge cases & errors**
- Two checkpoints from different worlds → the comparison is refused, with an error naming both worlds.
- In side-by-side play, one episode ends first → its last frame stays on screen while the other keeps playing.

### Lesson notes (`NOTE`)
**Serves:** Goal 1, Goal 2
**Behavior:** Each world ends with a short note I write. It explains the idea in my own words, shows results against the baselines and the reference, and describes one failure I saw and fixed. The lab fills in the results and charts. I write the explanation.

**Requirements**
- **NOTE-01** For each world, the lab produces a note draft with the results already filled in: test scores, the EVAL-03 and EVAL-04 outcomes, and the charts. Sections are left for me to write: the idea, why it works, and one failure and its fix.
  - Given a world whose evaluation is complete, when I make its note, then the draft has the results table, the charts and empty explanation sections.
- **NOTE-02** Diagnostic charts are drawn from run logs with the `dataviz` skill:
  - all worlds: episode return and loss;
  - Snake: the learner's average estimated action value;
  - Fish tank and Predator–prey: policy entropy (how much the learner is still exploring).
  - Given finished Snake runs, when I make diagnostic charts, then charts for return, loss and estimated action value exist.
  - Given finished Fish tank runs, when I make diagnostic charts, then charts for return, loss and policy entropy exist.
- **NOTE-03** A world is done only when its note's explanation sections are written.
  - Given a note with an empty explanation section, when I check the world's status, then it is reported as not done.

**Edge cases & errors**
- I make the note again after new runs → the results and charts are refreshed, and my written sections are kept.

### Snake (`SNAKE`)
**Serves:** Goal 1, Goal 2
**Behavior:** Classic Snake on a 10×10 grid. A learner that estimates the value of each action learns to eat food and avoid walls and its own body. This teaches learning values from replayed experience.

**Requirements**
- **SNAKE-01** Each episode starts with a length-3 snake in the middle of the grid, pointing in a direction chosen at random from the seed, and one food item on a random empty cell.
  - Given seed 0, when an episode starts, then the snake is 3 cells long and centred, and the food is on a cell the snake doesn't cover.
- **SNAKE-02** There are three actions: turn left, go straight, turn right, relative to the current heading.
  - Given the snake heading north, when it turns left, then it moves one cell west.
- **SNAKE-03** Eating food gives +1 reward, grows the snake by one cell, and places new food on a random empty cell.
  - Given the head moving onto food, when the step runs, then the reward is +1, the length grows by 1, and new food appears on an empty cell.
- **SNAKE-04** Moving into a wall or the snake's own body gives −1 reward and ends the episode.
  - Given the head next to the east wall heading east, when it goes straight, then the reward is −1 and the episode ends.
- **SNAKE-05** All other steps give 0 reward.
  - Given a move onto an empty cell, when the step runs, then the reward is 0.
- **SNAKE-06** The episode ends after 100 steps in a row without eating.
  - Given 100 steps since the last food, when the 100th step runs, then the episode ends with reward 0 for that step.
- **SNAKE-07** The standard observation is 11 yes/no facts:
  - danger directly to the left, ahead and to the right;
  - current heading (north, east, south or west);
  - food to the north, east, south or west of the head.
  - Given the head at (0, 5) heading north with food at (3, 2), when observed, then "danger left" is true, the heading is north, and food is to the east and the north.
- **SNAKE-08** *(Optional extra)* A full-grid observation shows, for every cell, whether it holds the head, the body, food or nothing. It can be chosen in the configuration instead of SNAKE-07.
  - Given a configuration choosing the full-grid observation, when observed, then there is one entry per cell for each of the four cell kinds.
- **SNAKE-09** The learner estimates the value of each action in each observation. It learns from randomly sampled past experience and compares against a slowly updated copy of its own estimates. It explores by sometimes acting at random, less often as training goes on.
  - Given a run, when the diagnostics are logged, then the exploration rate falls from its start value to its end value over the configured steps.
- **SNAKE-10** The score is the mean food eaten per episode (EVAL-01).
  - Given 100 test episodes, when scored, then the reported score is the mean food eaten.
- **SNAKE-11** The baselines are random moves and a plain greedy snake, which takes the move that brings the head closest to the food with no safety check. Both are bars for EVAL-03.
  - Given food two cells east of the head, when the plain greedy snake moves, then it moves east, even if that cell is a wall or body.
- **SNAKE-12** A safe greedy snake is also scored and reported for reference, but is not a bar. It is the same as the plain greedy snake, except that it never takes a move that dies immediately when a safe move exists.
  - Given the evaluation report, when it is shown, then the safe greedy snake's score is listed and marked "reference only".

**Edge cases & errors**
- The head moves into the cell the tail leaves on the same step → allowed, not a collision.
- The snake fills the whole grid → the episode ends with no further reward. No food can appear.
- Every move from the current position is deadly → the snake dies on its next step whatever it does.

### Fish tank (`TANK`)
**Serves:** Goal 1, Goal 2
**Behavior:** Eight fish swim with continuous steering in a circular tank while a ball bounces around inside. Each fish sees only what is nearby. All fish share one learned policy, which is trained to avoid the ball for as long as possible. This teaches learning a policy directly, and continuous control.

**Requirements**
- **TANK-01** The tank is a circle of radius 1.0. The ball has radius 0.1, moves at a constant 0.02 per step, and bounces off the wall with angle in equal to angle out. Its starting position and direction come from the seed.
  - Given the ball hitting the wall, when it bounces, then its speed is unchanged and its direction is mirrored about the wall's normal.
- **TANK-02** There are 8 fish, each with radius 0.03. They start at random positions inside the tank, at least 0.3 from the ball.
  - Given any seed, when an episode starts, then all 8 fish are inside the tank and at least 0.3 from the ball's centre.
- **TANK-03** Each fish's action is a steering direction in [−1, 1] × [−1, 1], scaled to a top speed of 0.015 per step (0.75× the ball's speed).
  - Given the action (1, 0), when the step runs, then the fish moves 0.015 in the +x direction, unless the wall stops it.
- **TANK-04** Fish can't leave the tank. A move that would cross the wall stops at the wall.
  - Given a fish touching the wall and steering outward, when the step runs, then the fish stays inside the tank.
- **TANK-05** A fish sees only what lies within 0.3 of it:
  - the ball's position and velocity relative to the fish;
  - the relative positions of up to 3 nearest other fish;
  - the distance and direction to the nearest point of the wall.
  
  Anything outside the radius is marked "not seen", so the observation always has the same size.
  - Given the ball 0.5 away, when the fish is observed, then the ball entries are marked not seen.
  - Given the ball 0.2 away, when the fish is observed, then its relative position and velocity are present.
- **TANK-06** A fish touched by the ball (centres closer than 0.13) is caught: it is done and removed for the rest of the episode.
  - Given a fish 0.12 from the ball's centre after a step, when the step ends, then that fish is done and gone from later steps.
- **TANK-07** Each fish gets +1 reward for every step it is still in the tank at the end of the step.
  - Given a fish not caught during a step, when the step ends, then its reward is +1.
- **TANK-08** The episode ends after 1,000 steps or when every fish is caught.
  - Given all 8 fish caught at step 600, when that step ends, then the episode is over.
- **TANK-09** Fish pass through each other. They don't collide.
  - Given two fish steering into the same spot, when the step runs, then both reach it.
- **TANK-10** The learner learns a policy that maps observations to continuous steering. It limits how far any single update can change the policy. All fish share one policy, and each fish's experience counts as separate samples.
  - Given a run, when the diagnostics are logged, then policy entropy and the size of each update's policy change are recorded.
- **TANK-11** The score is the mean number of steps a fish survives per episode (EVAL-01).
  - Given 100 test episodes, when scored, then the score is the mean survival steps over all fish and episodes.
- **TANK-12** The baselines are random steering and a scripted flee: swim straight away from the ball at top speed if it is seen, otherwise stay still. Both are bars for EVAL-03.
  - Given the ball seen directly east of a scripted fish, when it acts, then it steers (−1, 0).

**Edge cases & errors**
- The ball spawns overlapping where a fish would start → the fish are placed again until all are at least 0.3 away (TANK-02).
- Several fish are caught in the same step → all are removed that step, and each gets no reward for it.

### Predator–prey (`PREY`)
**Serves:** Goal 1, Goal 2
**Behavior:** The same tank, now with food pellets, 8 prey fish and one predator, and no ball. Prey must eat to keep their energy up while avoiding the predator.
- In **Phase A**, the predator is scripted and only the prey learn.
- In **Phase B**, prey and predator learn at the same time, and progress is judged by playing each side against the other side's earlier versions.

This teaches learning against an opponent that is also learning.

**Requirements**
- **PREY-01** The tank, fish movement, wall and vision rules are those of TANK-01 to TANK-05 and TANK-09, with no ball. There are 8 prey and 1 predator.
  - Given an episode start, when observed, then there are 8 prey and 1 predator inside a radius-1.0 tank, and no ball.
- **PREY-02** A food pellet appears at a random empty position every 10 steps, with at most 20 pellets present at once. A prey eats a pellet by touching it (centres closer than 0.04).
  - Given 20 pellets present, when the 10-step interval passes, then no new pellet appears.
- **PREY-03** Each prey starts with energy 1.0, which falls by 0.002 per step. Each pellet eaten adds 0.25, up to a maximum of 1.0. A prey that reaches 0 energy has starved: it is done and removed.
  - Given a prey that eats nothing, when 500 steps pass, then it starves at step 500.
- **PREY-04** The prey's observation adds to TANK-05: the predator's relative position and velocity if within 0.3, the relative positions of up to 3 nearest pellets within 0.3, and its own energy.
  - Given the predator 0.4 away, when a prey is observed, then the predator entries are marked not seen.
- **PREY-05** The predator moves at up to 0.018 per step (1.2× prey top speed) and sees within 0.4. After a catch it cannot catch again for 20 steps.
  - Given a catch at step 100, when the predator touches a prey at step 110, then no catch happens.
- **PREY-06** The predator catches a prey by touching it (centres closer than 0.06). The caught prey is done and removed.
  - Given the predator 0.05 from a prey with no cooldown, when the step ends, then the prey is caught.
- **PREY-07** Prey rewards: +1 per pellet eaten, −10 when caught, −10 when starved. Predator reward: +1 per catch.
  - Given a prey eating one pellet in a step, when the step ends, then its reward is +1.
- **PREY-08** The episode ends after 1,000 steps or when no prey remain.
  - Given the last prey caught at step 700, when the step ends, then the episode is over.
- **PREY-09** In Phase A, the predator is scripted. It chases the nearest prey it sees, and otherwise wanders in a random direction that changes every 50 steps. The prey learn with the Fish tank learner (TANK-10), sharing one policy.
  - Given a prey 0.3 north of the predator, when the scripted predator acts, then it steers north at top speed.
- **PREY-10** The prey score is the mean prey return per episode. The predator score is the mean catches per episode (EVAL-01).
  - Given 100 test episodes, when scored, then both scores are reported.
- **PREY-11** In Phase A, the prey baselines are random steering and a scripted prey: flee the predator at top speed if it is seen, otherwise swim to the nearest seen pellet, otherwise stay still. Both are bars for EVAL-03, and EVAL-04 applies.
  - Given the predator seen to the west and a pellet to the east, when the scripted prey acts, then it steers east.
- **PREY-12** In Phase B, prey and predator learn at the same time, each side with its own shared policy, using the Fish tank learner. The prey start from their final Phase A checkpoint. The predator starts untrained.
  - Given a Phase B run starting, when its settings are saved, then they name the Phase A prey checkpoint it started from.
- **PREY-13** Phase B saves a snapshot of each side at every 10% of its step budget, 11 snapshots per side including the start.
  - Given a finished Phase B run, when I list its snapshots, then each side has 11, labelled by training step.
- **PREY-14** A cross-play table plays every prey snapshot against every predator snapshot for 20 test episodes each, and reports the mean prey score and mean catches per pair.
  - Given 11 snapshots per side, when cross-play runs, then an 11 × 11 table of both scores is produced and drawn as a heatmap with the `dataviz` skill.
- **PREY-15** Phase B succeeds when both of these hold, each tested with the `null-hypothesis-testing` skill at the 5% level over 5 seeds:
  - the latest prey score higher against the latest predator than the starting prey do;
  - the latest predator catches more of the latest prey than the scripted predator does.
  - Given cross-play results from 5 seeds, when the test runs, then the report states both p-values and pass or fail.
- **PREY-16** If PREY-15 fails, Phase B still counts as done when the lesson note explains the failure using the cross-play table and learning curves, for example cycling, or one side collapsing.
  - Given a failed PREY-15, when the note's explanation cites the cross-play heatmap and names the failure pattern, then the world is reported as done.

**Edge cases & errors**
- No pellets are visible → the prey's pellet entries are all marked not seen.
- The predator and a pellet are at the same spot → the predator doesn't eat pellets. The pellet stays.
- All prey starve before step 1,000 → the episode ends. The predator's catches so far count.

## Quality requirements
- **QR-01** Each training run used for a pass result finishes within 60 minutes of wall-clock time on the MacBook Pro's CPU. This applies to Snake, Fish tank, Predator–prey Phase A and Phase B separately.
  - Checked from the run's start and end times in its log.
- **QR-02** No pass result needs a GPU, a paid service or a network connection.
  - Checked by running every pass configuration offline on the laptop CPU.
- **QR-03** The replay viewer plays the largest world (8 prey, 1 predator, 20 pellets) at 30 frames per second or more, side by side included.
  - Checked by measuring frames per second over a 1,000-step replay.
- **QR-04** Fish tank and Predator–prey use the same train, multi-seed, evaluate and replay commands as Snake, with only a different configuration name.
  - Checked by running each command on all three worlds.

## Assumptions
- Physical numbers (speeds, radii, energy and pellet rates) are starting values. If a world turns out trivial or impossible during its stage, they may change, recorded in the Changelog.
- Every comparison uses 5 training seeds.
- I write the explanation sections of the lesson notes. The lab only fills in results and charts.
- Training is deterministic only on the CPU. Runs on a rented GPU are not expected to match exactly.
