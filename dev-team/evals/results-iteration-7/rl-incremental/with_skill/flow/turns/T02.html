The direction is settled: hand-rolled DQN on Snake, with a curriculum, a tabular step first, ablations, and visuals built in, all on a small shared core. A quick stress-test before I write it down:

- **Feasibility:** no problem. Small-grid Snake with a compact view of the board trains in minutes on a laptop CPU, well inside your one-hour budget. No data is needed because the environment generates it.
- **The baseline is the real test.** Greedy-toward-food does fine early on, then traps itself once the snake gets long. Beating it means the agent learned to avoid itself, not just to chase food. That's the right bar, but it isn't guaranteed, so it goes under bets.
- **Tabular works only on a compact board view.** A lookup table over the whole grid would be far too big. It works over a few dozen yes/no features ("danger ahead?", "food to the left?"). That's also the bridge to DQN: same features, a net in place of the table.
- **Scope risk:** the shared core can grow into a framework. I'll put "only what Env 1 needs, made reusable" in the brief.

# Grid RL Lab

**Status:** Draft · **Last updated:** 2026-10-17

## The problem
I want to understand reinforcement learning (agents that learn by trial, error and reward), not just run it. Reading theory and calling library code hasn't made it stick. Building small environments and agents myself, then watching them learn, is how I'll learn it.

## Who it's for
Me: someone with some PyTorch and basic machine learning, who knows Q-learning only roughly. This is a personal learning project, not a product.

## Goals
1. I can explain why each agent works, because I built every piece myself.
2. Every agent is judged against honest baselines (random play and a simple scripted rule), not just "the number went up".
3. I can see learning happen: learning curves during training and replays of the trained agent.
4. Each new environment reuses one small shared core (environment interface, training loop, logging, replay viewer) instead of starting over.

## Constraints
- Laptop CPU only (Apple Silicon); each environment trains in under about an hour.
- Evenings and weekends, a few weeks per environment.
- Agents written from scratch in NumPy and PyTorch; libraries come later, only for comparison.
- The shared core holds only what the current environment needs.

## What success looks like
- Snake: the trained agent's learning curve clearly beats random play and a "move toward food" rule, across several training runs.
- I can watch a replay of the trained snake playing.
- I can write a short explanation of why it works, backed by experiments where I remove one piece (such as experience replay) and show what breaks.
- Starting a second environment doesn't mean rewriting the training loop or the viewer.

## What we're betting on
- Small-grid Snake is learnable on a laptop CPU in under an hour.
- The scripted baseline is beatable: it traps itself as the snake grows, and a learned agent can avoid that.
- Going step by step (a lookup-table agent on a tiny grid first, then a neural network on a larger one) teaches more than jumping straight to the network.

## Not doing
- Library agents (such as Stable-Baselines3) for now — comparison comes after my own version works.
- Advanced algorithms (policy gradients, Rainbow-style add-ons) in Snake — one concept per environment.
- Learning from raw pixels — compact board features keep training fast and debugging clear.
- Hyperparameter-search tooling, dashboards or experiment-tracking services — plain logs and plots are enough.
- Polish for other users — no packaging, docs site or leaderboard.
