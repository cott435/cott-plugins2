1	"""Dataset builder for a temporal-fusion-transformer style forecaster.
2	
3	Turns a long panel (one row per ticker and date) into fixed-length training windows. Each window has an
4	encoder part (the lookback) and a decoder part (the forecast horizon), and the inputs are split the way
5	TFT expects them:
6	
7	- static covariates: constant per ticker (sector, listing exchange, ...), categorical, encoded as ints
8	- known covariates: known in advance for every step, including the decoder steps (calendar features)
9	- observed covariates: only known up to the forecast origin (returns, volume, the engineered features)
10	
11	Targets come from a separate frame (see tft_targets.py) joined on (ticker, date).
12	"""
13	from __future__ import annotations
14	
15	from dataclasses import dataclass, field

17	import numpy as np
18	import pandas as pd

22	class WindowSpec:
23	    """Shape of one sample: ``lookback`` encoder steps followed by ``horizon`` decoder steps."""
24	    lookback: int = 63
25	    horizon: int = 5
26	    stride: int = 1
27	    static_cols: list[str] = field(default_factory=lambda: ["sector"])
28	    known_cols: list[str] = field(default_factory=lambda: ["dow", "month", "days_to_month_end"])
29	    observed_cols: list[str] = field(default_factory=lambda: ["log_ret", "log_volume", "range_pct"])

34	    """Known-in-advance covariates derived from the date only."""

51	        vocab[c] = {v: i for i, v in enumerate(cats)}

56	def normalise_observed(panel: pd.DataFrame, cols: list[str], window: int = 252) -> pd.DataFrame:
57	    """Per-ticker z-score of observed covariates using a trailing window (no future rows)."""
58	    p = panel.sort_values(["ticker", "date"]).copy()
59	    g = p.groupby("ticker")[cols]
60	    mu = g.transform(lambda s: s.rolling(window, min_periods=20).mean())
61	    sd = g.transform(lambda s: s.rolling(window, min_periods=20).std())
62	    p[cols] = ((p[cols] - mu) / sd.replace(0.0, np.nan)).fillna(0.0)
63	    return p

69	    Returns arrays keyed by name, with S samples:
70	        static   (S, n_static)              int64
71	        known    (S, lookback + horizon, n_known)
72	        observed (S, lookback, n_observed)
73	        target   (S, horizon, n_target)
74	        origin   (S,) the forecast-origin date of each sample (last encoder step)

full text
- **Purpose:** Turns a long (ticker, date) panel into fixed-length encoder/decoder windows for a TFT-style sequence forecaster, with static, known and observed inputs kept separate, plus a split by date.
- **Key parts:** `WindowSpec` dataclass (lookback=63, horizon=5, stride=1, static/known/observed/target column lists); `add_calendar_features(panel)`; `encode_static(panel, cols) -> (panel, vocab)`; `normalise_observed(panel, cols, window=252)`; `build_windows(panel, targets, spec) -> dict[str, np.ndarray]`; `split_by_origin(arrays, train_end, valid_end)`.
- **In → Out:** In: a long panel DataFrame with ticker, date, sector and feature columns, plus a targets DataFrame keyed on (ticker, date) that comes from tft_targets.py, which is not in this file. Out: arrays static (S, n_static) int64, known (S, L+H, n_known), observed (S, L, n_obs), target (S, H, n_tgt), plus origin (S,) and ticker (S,). These are then split into train, valid and test dicts.
- **Use for:** Building the dataset for neural return/volatility forecasters and the baselines they are compared against. Also a model for keeping known and observed inputs apart and for splitting on the forecast-origin date.
- **Caveats:**
  - `split_by_origin` has no embargo, so the last `horizon` train samples have targets that reach into the valid period, and likewise from valid into test. Overlapping stride-1 windows make this worse.
  - `encode_static` builds its vocabulary from the full sample, including test. An unseen or NaN category maps to NaN and then fails on `astype(int64)`.
  - Static values come from the first row of each ticker, so they are not point-in-time if a ticker's sector changes.
  - `build_windows` silently drops tickers shorter than lookback+horizon. Its inner merge silently drops rows with no target. It never checks that dates inside a window are contiguous, so windows can span gaps.
  - `normalise_observed` sets the first ~20 warm-up rows, and any row with zero std, to 0 with no flag.
  - Target alignment (`tg[enc_end-1 : ...]`) is only correct if `fwd_ret_1d` at date t means the return from t to t+1. That needs checking against tft_targets.py.
  - Default column names and window sizes are hard-coded.
  - Stride-1 copies use a lot of memory.
  - When there are no samples it returns an empty array of shape (0,) with the wrong number of dimensions.
  - No instructions addressed to an AI found in the text.
- **Stage guess:** S4. It is input preparation for a neural sequence forecaster, and the split by origin date suits out-of-sample forecast evaluation.
