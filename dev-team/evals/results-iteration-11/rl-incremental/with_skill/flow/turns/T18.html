### AD-07: Learning curves with Matplotlib from saved records
**Status:** Accepted · **Date:** 2026-10-18 · **Scope:** system
- **Context:** CURVE-01–CURVE-05 need one or more runs as lines, seed bands, baseline lines and labels for each ablation, drawn from records only. The scope rules out every other view (UR-18). EXPL-03 puts the chart on the notes page.
- **Decision:** `curves.plot_curves` reads `RunRecord`s and groups them by config minus seed. It draws each group's mean line with a min–max band, and each baseline as a labelled flat line. It saves a PNG with the Agg backend.
- **Alternatives:** Plotly HTML: interactive, but not needed, and a PNG embeds cleanly in a Markdown notes page. Seaborn: one more dependency to draw a mean and a band.
- **Consequences:** Charts are static PNGs. The band is min–max over the 5 seeds; the spread on evaluation points is the standard deviation over the 100 games.

### AD-08: The environment is passed to `Agent.act`, so the scripted baseline reads the true Snake state
**Status:** Accepted · **Date:** 2026-10-18 · **Scope:** system
- **Context:** BASE-02 moves along the axis with the larger gap to the food. The 11 facts say which way the food is but not how far, so the scripted agent needs the game state. The training loop, evaluation and replay must still treat every agent the same way (CORE-05, CORE-06).
- **Decision:** `Agent.act(obs, env, *, explore)` receives the environment it is playing. `baselines.ScriptedAgent` requires a `snake.SnakeEnv` and reads `env.state`; the random agent and the DQN ignore `env`.
- **Alternatives:** Adding food distances to the observation: changes SNAKE-06's 11 facts. An `info` dict on every step: untyped, and every environment would have to fill it.
- **Consequences:** The scripted agent is Snake-only. `registry` refuses it for any other environment and names the environment.

I added decision AD-09 and updated the contract for the issue test-planning raised. Both files are back to **Draft** and need your approval.

**The problem:** `study.compare_scores` required the full agent to have exactly 5 seeds × 100 games. But the spec says a stopped full-agent run is left out of the final comparison and named as incomplete, and `run_study` only fails if no full-agent run finished. So a study with 4 finished full-agent runs had no valid way to call it.

**AD-09 (Proposed): each comparison uses each side's finished seeds; an ablation with a failed seed is reported as missing**
- `compare_scores` now accepts 1–5 full-agent seeds × 100 games. An ablation still needs 5 × 100 and a baseline 1 × 100.
- Scores are paired by held-out game, using each side's average over its seeds for that game. This is the test TC-08 already describes.
- `run_study` passes in only the finished full-agent runs, lists the others under `incomplete`, and fails only if none finished.
- An ablation with any unfinished seed is still `missing` rather than compared on fewer seeds, as the spec's ablation edge case says (TC-10).
- `Comparison.method` states how many seeds each side used.

**Files changed:**
- `docs/architecture.md`: AD-09, one sentence added to the "Comparison method" risk, and a Changelog row.
- `docs/packages/rllab/contract.md`: the rules and errors for `study.compare_scores`, and the errors and test cases for `study.run_study`.

**Who's affected:** `study.compare_scores` is used by `study.run_study` and pipeline PL-04; `study.run_study` by `cli` and PL-04. No function names, signatures or step inputs/outputs changed, so nothing needs to go back to pipeline-design. All gap checks are clear and lint reports no errors.

**Your words:** no open requests; this doesn't change any of them.

**ASSUMPTIONS**
- When no full-agent run finished, `run_study` raises `RuntimeError` naming the runs. Before, the contract said only that the study "fails".
- `compare_scores` raises `ValueError` if either side has no rows or more than 5.
- The seed counts go in the existing `method` text rather than a new field on `Comparison`, so the type stays the same.
- I added a contract test case for `run_study`: the 2-seed corridor study with one full-agent run failing.

**Open questions:** none. test-planning may want a golden case for a stopped full-agent run, since TC-10 only covers a failed ablation run.

Do you approve, or want changes?
