# Idea: Features & ML on residual returns

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [../brief.md](../brief.md)

## In one sentence
This builds a fixed set of price- and volume-based candidate features and tests, with simple statistics first and a machine-learning model second, whether each one carries information about next-month market-removed returns beyond chance, so that I only build signals on features that survive an honest test.

## The problem
Feature research is where quantitative work most often fools itself. With about 500 names and 25 years of daily data, any flexible model will find "importance" in noise. Testing many features, horizons and models multiplies the false discoveries. Returns of stocks on the same day move together, so a naive null hypothesis that treats each stock-month as independent overstates significance many times over. And raw returns are dominated by the market mode, so a feature that merely tracks market beta looks predictive without being so. I need a process where a feature claim counts only when it beats a null built for this data, on years never used to choose it.

## Who it's for
Me, as the researcher, once the variance study (S2) has given me a trusted view of the return structure, and before I build any return forecast or paper-trading strategy.

## How it fits
- **Serves:** Goal 4. It is built on the same trusted data and S2's return-structure work, with no new data sources.
- **Touches:** research data access (`QUERY-01`–`QUERY-05`), the point-in-time universe (`UNIV-01`) and total returns (`PRICE-02`, `PRICE-04`). It reuses S2's monthly rebalance windows and eligibility (`STRUCT-01`, `STRUCT-02`) and its market-mode removal (`STRUCT-05`). S2 uses market removal only as a diagnostic; this idea uses it for the first time to build a target, so that requirement's scope widens. The spec's out-of-scope line on "return prediction, signal research" narrows to exclude only return forecasts used for trading. The variance-portfolios idea file is a frozen record and is not edited.
- **Brief changes:** None.
- **Stage:** New S3 (a roadmap stage on acceptance).

## Recommended direction
**Target.** At each monthly rebalance date, the eligible members' next-month total returns are stripped of the market mode. The market factors and their loadings are fitted on the trailing two-year window only (as RF-01, refitted per window), then applied to the following month's returns. The target is each name's residual return ranked across that month's names. Nothing about the following month is used to fit the loadings.

**Candidates.** A short, fixed list, written down before any test runs: short-term reversal (last month), 12-1 month momentum, trailing volatility, idiosyncratic volatility (from the trailing residuals), volume shock, the largest daily return in the last month, and beta to the market mode. Each is computed from data known at the rebalance date. Two calibration features join them: one of pure noise, and one real feature shuffled across names within each date. Both must come out as uninformative, or the test procedure is broken.

**Tests first, then the model.** Each feature's monthly rank correlation with the target (its information coefficient) is the baseline. A flexible model trained walk-forward on all features comes second; a feature's information gain is how much the model's out-of-sample fit drops when that feature is scrambled within each date. Every claim, univariate or model-based, is tested with the `null-hypothesis-testing` skill. The null distribution keeps stocks' same-day co-movement and the autocorrelation over time intact. All features and both methods go into one family for the multiple-testing correction. Feature distributions, their correlations with each other and their stability over time are characterised with the `data-analysis` skill.

**Known answer first.** As in S2, the whole procedure first runs on a synthetic panel with one planted feature of known effect size and several pure-noise features. It must find the planted one and reject the noise.

**Development and holdout.** 2002–2020 is for development: the features, the model's settings and the test design are fixed there, walk-forward. 2021–2026 is held out and touched once, for the final confirmatory test.

## Data
Everything comes from the S1 data version, read through as-of reads, with no new sources and no fundamentals. That's about 295 monthly rebalances × about 490 eligible names, roughly 145,000 name-months, of which about 66 months fall in the holdout. The labels are the next-month residual returns themselves. The baseline is the univariate information coefficient, and the null is set with `null-hypothesis-testing`. `data-analysis` owns the exploratory characterisation.

## Alternatives considered
- Automated feature generation over hundreds of transforms — mostly buys false discoveries under any honest correction.
- Mutual information as the only measure — kept as a possible extra, but it adds no model-based view of interactions.
- Raw returns as the target — the market mode would make beta-like features look predictive.
- Choosing the features or model settings on the full sample — look-ahead into the holdout.

## What success looks like
- The calibration features and the synthetic noise features are rejected as uninformative; the planted synthetic feature is found.
- A list of the candidate features, each marked as informative or not on the holdout after correction, with its information coefficient and model-based gain.
- Every claim records its test, its null construction and the size of the family it was corrected within.

## What we're betting on
- Price- and volume-based features carry some information about next-month residual returns in the S&P 500 after 2002, even if small.
- About 66 holdout months give enough power. A monthly information coefficient with a spread of about 0.10 needs a mean of about 0.025 or more to be detected, so smaller effects will read as "not significant".
- Market removal with a few factors leaves residuals that are mostly free of shared market moves.

## Not doing
- Fundamentals and alternative data — the brief's Not Doing list stands.
- Trading the features, portfolio construction from forecasts, or transaction costs — a later stage.
- Horizons other than one month.
- Deep learning or automated feature search.

## Open questions
- Is one month the right horizon, or should one week be tested too (doubling the family)?
- Should the ML model also have to beat the univariate baseline as a whole, or only report each feature's gain?
- How many market factors to remove for the target: S2's factor count per date, or a fixed k = 1?
- Is 2021–2026 the right holdout, given its limited power?
- Which model family: chosen in the architecture, but it should handle interactions and be trained walk-forward.
