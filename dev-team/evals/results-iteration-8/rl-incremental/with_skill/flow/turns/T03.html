# RL Lab

**Status:** Draft · **Last updated:** 2026-10-17

## The problem
I want to learn reinforcement learning (RL): agents that learn by trial, error and reward. Reading about it hasn't made it stick. Tutorials hand over finished code, so when an agent fails to learn I can't tell why. I'm also new to PyTorch, so I need a path where each new idea arrives on its own.

## Who it's for
Me, as a learner. I have basic familiarity with Q-learning, I'm new to PyTorch, and I work evenings and weekends on a laptop.

## Goals
1. Each environment teaches one RL concept, and I can explain in my own words why the agent works and what limits it.
2. I write every learning algorithm myself, one new idea at a time, so I always know which piece is wrong when learning stalls.
3. Every trained agent is judged on a learning curve against a random bot and a simple scripted bot, never on a feeling.
4. I can watch any trained agent play back, and see how it values its choices.
5. A new environment reuses the shared training, logging and replay pieces instead of rebuilding them.

## Constraints
- Laptop processor only, no graphics card. Training takes under about an hour per environment.
- Evenings and weekends; a few weeks per environment.
- Algorithms are hand-written. Libraries are allowed later only as a sanity check against my own results.
- No outside data. Every environment is a small 2D grid game the project builds itself.

## What success looks like
- For each environment, the trained agent clearly beats the random bot and matches or beats the scripted bot. The comparison uses repeatable runs with fixed random seeds.
- I can replay a trained agent and narrate what it does and where it fails.
- In the first environment (Snake), I've seen a lookup table succeed on a compact view of the board and fail on the raw grid, and a neural network handle both.
- The second environment starts from the shared pieces, not from a blank page.

## What we're betting on
- Learning one thing at a time (environment first, then table-based learning, then neural networks) is enough to keep me unstuck.
- Simple rewards (a reward for food, a penalty for dying, a step limit) are enough to learn from without heavy tuning.
- A small board is enough for a neural network to learn from the raw grid within the hour limit.

## Not doing
- Designing a framework before the first environment works: shared pieces come out of Snake, not ahead of it.
- Relying on ready-made RL libraries: writing the algorithms is the point.
- Growing boards and difficulty curricula: that's a concept for a later environment.
- A warm-up "Snake without a tail" level: the ladder already introduces one idea at a time.
- Cloud or graphics-card training: the hour-on-a-laptop limit keeps experiments quick.
- Chasing record scores or a polished game: understanding beats performance.
