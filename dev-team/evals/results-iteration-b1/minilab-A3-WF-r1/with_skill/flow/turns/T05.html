# Resume

Read when a build is recorded and this session has started no agents: a new session after a
stop, a crash or a closed terminal. No agent of the old session is still running, so every claim
is either finished work to land or a dead agent's to release. The loop is `loop.md`; stops are
`escalation.md`.

Everything the driver needs is on disk: `dt-build/` under the git common directory, the
`Dt-Landed:` trailers on `build/M<n>` (never commit subjects, which an agent could imitate), the
`tasks/todo.md` ticks, the findings in `tasks/plan.md` and the recorded go. Nothing from an
earlier conversation counts, approvals least of all.

## Steps

**1. Read the state.** `dt build status`. The main checkout must be on `build/M<n>` and clean; if
not, report it and stop (never stash, reset or switch yourself).

**2. Check the go.** It stands for this milestone and this plan version. If `go_current` in
`dt build status` is false, a Replan changed the tasks since: ask for a new go (what changed, the
halves left), record it with `dt build go --note "<their words>"`, and stop the turn until it comes.

**3. Reconcile, one row at a time:**

| `dt build status` shows | Do |
|---|---|
| a claim marked finished | `dt land <task> --role <role>`: the gate re-runs if no verdict matches, so finished work isn't lost. Branch on the result as `loop.md` says |
| a claim not finished, or a reservation | its agent died with the old session: `dt build release <task> <role>`; the half comes back through `dt ready` (tasks are XS or S, so redoing is cheap) |
| a tester half landed, its implementer not | nothing: the implementer half is ready |
| a review reserved but not recorded | `dt build release <checkpoint>.<pkg> reviewer`; `dt ready` lists the review again |
| a barrier unpassed, a Critical open, a half blocked | stays until the user decides (`escalation.md`); report it with the rest |

**4. Report, then continue.** One message: what landed before, what was re-landed or released
now, what is blocked and the decision it needs. With a decision pending and nothing ready, end the
turn there. Otherwise run the loop (`loop.md`).

## Example

```
$ dt build status
M1 · go recorded 2026-10-18 (plan unchanged) · landed 9/19 halves
claims: M1-T11 implementer finished · M1-T12 tester not finished · M1-T13 tester reserved
blocked: none · reviews: M1-T01.gridload passed · next checkpoint: after M1-T07

$ dt land M1-T11 --role implementer      → landed
$ dt build release M1-T12 tester
$ dt build release M1-T13 tester
```

> Resumed M1: 10/19 halves landed (M1-T11 implementer just now); M1-T12 and M1-T13 testers
> released, their agents died with the last session. Nothing blocked. Dispatching.

# Exit

Read when every task of the milestone has landed. The exit review, its fix tasks, a second exit
review over them, the user's yes, the merge. Each user gate ends a turn; run `dt build status` at
the start of each turn to see where you are. The loop is `loop.md`; stops are `escalation.md`.

```
exit review → findings → [fix tasks: build-planning Replan, the user] → loop → exit review again
  → [the user's yes] → merge build/M<n> → build-planning Advance
```

## Steps

**1. Exit review.** Once the last task lands, `dt ready` lists the exit reviewers (one per
package with changes over the milestone diff, one lead), which run the Milestone exit list too:
the Scope's Exit, every Covers ID tested, no stub left (`check.sh full --exit`), real providers in
system tests, the slow and perf tests. Spawn and record them as `loop.md` says. A Critical is a
stop (`escalation.md`).

**2. Fix tasks.** With the review recorded, show `dt build status`'s findings by severity and
point to the checkpoint blocks in `tasks/plan.md`. Important findings get fix tasks; Suggestions
and Nits only if the user asks. The tasks come from `build-planning` Replan, through its own gate;
on its approval it commits the plan on the build branch. The go covers one plan version, so ask
for it again for the fix tasks and record it with `dt build go`, then run the loop until they land. No findings needing a task:
step 4.

**3. Exit review again.** After the fix tasks land, `dt ready` lists the exit reviewers again,
over the fix tasks' landings plus the Milestone exit list. Record them as before. New Important
findings go back to step 2; repeat only with the user's yes, and say how many rounds have run.

**4. The user's yes.** One message, then **stop the turn**:
- the exit review's findings and each one's disposition (fix task landed, or won't fix and why);
- the Definition of Done (CONSTRAINTS.md, Done: the full list) and the Scope's `**Exit:**` line,
  each held or not, from the reviewers' lines;
- what merges: `build/M<n>` into the branch the build started from, with the landing count.

| The user says | Do |
|---|---|
| An unambiguous yes ("merge it") | Step 5 |
| A change, or a hedge ("looks fine I guess") | Not a yes. Ask what to change; a fix is a Replan (step 2) |

**5. Merge.** The one git the driver runs itself, only after that yes, from a clean main
checkout: `git switch <the branch the build started from>`, then `git merge --no-ff build/M<n>`,
each in its own Bash call. A conflict: `git merge --abort`, report it, stop. Never push. Then
`dt build prune`: it deletes the tests branches and the rejected halves' branches and worktrees.

**6. Hand on.** Say the milestone is built and merged, and that the next step is
`build-planning` Advance (exit checkpoint, archive), which offers `build-setup` Ratchet. Stop.
