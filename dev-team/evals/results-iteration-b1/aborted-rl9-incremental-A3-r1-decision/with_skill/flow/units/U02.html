134	### AD-09: A batch-first environment interface over agents, adopted before M1 is built
135	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `core`
136	- **Context:** CORE-01 now needs one interface for Snake (one agent, 3 discrete actions) and the fish tank (up to 16 fish, 2-D continuous actions). CORE-06 needs Snake and the corridor to behave as before. M1's plan is approved but no code exists yet.
137	- **Decision:** Every environment is batch-first over its agents. Observations are `(n_agents, *obs_shape)`, actions `(n_agents,)` discrete or `(n_agents, dim)` continuous, per `core.ActionSpace`. Rewards and per-agent `done` are `(n_agents,)`, and the game-level `terminated`/`truncated` stay booleans. Snake and the corridor are the `n_agents == 1` case. `core.Agent.act` takes and returns batches, and `core.Transition` carries per-agent arrays with an `active` mask. M1 adopts this interface before it is built: a Replan of its interface task, so Snake is never written against the old shape.
138	- **Alternatives:** A separate multi-agent protocol beside the single-agent one — two interfaces for `train`, `evaluate` and `replay` to handle, against CORE-07. Per-agent dicts (PettingZoo style) — flexible, but slow for 8 fish in NumPy and unneeded with a fixed agent count. Migrating after M1 is built — the honest "revise the core" lesson, at the cost of rewriting a finished milestone's core and agents.
139	- **Consequences:** AD-13 adds teams on top: each team is batch-first as above. Value learners and Snake baselines handle a batch of 1. CORE-06 is met by M1's golden cases passing on the new interface, with their expected values unchanged. `pipeline-design`, `test-planning` and `build-planning` revisit M1's types and plan before the build starts.

142	### AD-13: Teams in the core, adopted before M1 is built
143	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `core`
144	- **Context:** CORE-01 now needs environments with two teams of different sizes and views: predator-prey's 1-agent predator (19 values) and 6-agent prey (18 values). AD-09's batch-first arrays assume one observation shape per environment. M1 is approved but not yet built.
145	- **Decision:** `core.Env` declares `teams: Mapping[str, TeamSpec]`. Observations, actions, rewards and `done` are maps from team name to AD-09's batch-first arrays. Single-team environments use one team, `core.SOLO` (`"agents"`). One `core.Agent` acts for one team, and `train` and `evaluate` take one agent per team. `info` carries `score:<team>` per team, plus `score` for the first. M1 adopts this before it's built: a Replan of its interface task.

467	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `core`

5	## Overview

66	## Cross-cutting concerns
67	- **Reproducibility (RUN-03):** one seed feeds a single `np.random.Generator` and `torch.manual_seed`, passed down explicitly. PyTorch runs with one thread and deterministic algorithms (AD-08). No global random state.

A timing test trains each agent for 10,000 steps and extrapolates to its full step budget.
69	- **Laptop only (QR-06):** PyTorch is pinned to CPU. Nothing selects a GPU. Stable-Baselines3 is given `device="cpu"`, because its default `"auto"` would otherwise pick any GPU it finds.

85	### AD-01: Python 3.12, one package `rllab`
86	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** system
87	- **Context:** A solo learning lab with one install on one laptop. The brief wants a core reused across environments, not separately deployed parts.
88	- **Decision:** One Python 3.12 package, `rllab`, with one folder per component.
89	- **Alternatives:** A package per environment — no real boundary yet; the core would be guessed before the second environment exists. Python 3.13 — some scientific wheels lag.
90	- **Consequences:** Pin `requires-python = ">=3.12,<3.13"`. A later environment adds an `envs` module and a settings file, not a package. The contract runs past the 200-line guide for one package; that is accepted because tasks load only the sections they read. `reference` sits behind an optional extra, ready to split out if it ever needs its own install. It also stays one package with five or more pipelines and twelve components, at or above the ~3-pipeline and ~12-module Grow guides. All five are commands of one command line over the same run folders, and each has its own entry module, so their tasks never share a file. PyTorch stays because `agents` is its only importer.
91	
92	### AD-02: Hand-written agents on NumPy arrays and PyTorch tensors
93	**Status:** Accepted · **Date:** 2026-10-17 · **Scope:** `agents`
94	- **Context:** AGENT-06 needs the agents written by hand from array and tensor operations, with automatic gradients allowed. The lesson is value learning, not backpropagation.
95	- **Decision:** The table-based agent is pure NumPy. The neural agents use PyTorch tensors, `torch.nn` layers, autograd and the Adam optimizer. Everything RL-specific is written by hand in `agents`: the memory of past steps, sampling, the target copy, the learning targets, the loss and the exploration schedule.
96	- **Alternatives:** NumPy only, with hand-written backpropagation — more to learn, but debugging gradients would crowd out the RL lesson, and the CNN in AD-05 becomes a project of its own. JAX — capable, but less familiar CPU tooling on a Mac.
97	- **Consequences:** PyTorch is a dependency of `agents` only. Swapping in hand-written backpropagation later stays local to the network module.
