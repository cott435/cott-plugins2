## 2. Assumptions
- **Register opens its own loader:** the `register` step opens the loader from the registration's build id, so later pipelines only list the steps they call.
- **Repeated calls are listed once:** where a pipeline calls the same function twice, it gets one row. In PL-21, `register`, `decide` and `finish_claim` each run once per claim.
- **Two claims in PL-21:** forecasts are judged against baselines (FCST-04/05), then forecast portfolios against the S2 benchmark (FPORT-02).
- **One claim for all features in S3:** every feature is a candidate in one claim, so Holm corrects across all of them.
- **Factor count:** k = 1 (the market mode), fixed in the registration.
- **The extract ends before the final test period,** so training never sees it.
- **Paper fills:** a day's orders come from the previous close's guarded view and are filled at that day's close, so no orders need storing between days.
- **Benchmark paper book:** it re-estimates every 21 days on the trailing 252.
- **Agent strategies** trade with the seed-0 policy.
- **Diverged training:** the curve is saved in the bundle, and the evaluate pipeline records it through `RunHandle.fail`.
- **Bundles:** agents keep their own bundle module (`agents.bundle`) rather than depending on `forecast`.
- **`learn.train` and `learn.evaluate`** pick the entry by `kind`.
- **Web routing:** one router in `main.tsx` mounts all four web route sets.
- **Spine defaults:** the module names and spine values (e.g. EWMA λ = 0.94, about 10 initial features) are my choices.
