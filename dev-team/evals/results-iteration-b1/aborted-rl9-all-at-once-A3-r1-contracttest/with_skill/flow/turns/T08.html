### AD-12: A frozen step is checked for its stub only while its task is open
**Status:** Accepted · **Date:** 2026-10-18 · **Scope:** system
- **Context:** The M1 interface task froze every contract step as a stub raising `NotImplementedError('<task>')`, and its interface test asserted that raise for every step with no end date. The task that implements a step has to replace that stub, so its gate always failed: M1-T02 (`train.load_run_configs`) escalated a contract change on it, and M1-T03, T04, T05, T08, T09 and T17 stopped on the same check (build of 2026-10-18).
- **Decision:** A frozen step or class keeps its contract signature on every gate, and is held to its `NotImplementedError('<task>')` stub only while the task that the stub names is open in `tasks/todo.md`. Once that task lands, its section's signature, invariants and errors are what the gate holds it to.
- **Alternatives:** Keep the unconditional stub check: no step task can land. Drop the stub check from the interface test: an unimplemented step could then pass silently, which the gate's stub check (CR-02) already guards but the frozen test should agree with.
- **Consequences:** The interface test is re-frozen by a new interface task that `build-planning` Replan adds, its rows for open tasks unchanged. No signature, type or fixture changes, so no consumer changes.

**`docs/architecture.md`, new decision AD-12 (Proposed):** "A frozen step is checked for its stub only while its task is open".
- **Context:** M1-T01 froze each step as a stub raising `NotImplementedError('<task>')`, and its interface test required that raise with no end date. So the task that implements a step always failed its gate. M1-T02 asked for a contract change over it; T03, T04, T05, T08, T09 and T17 stopped on the same check.
- **Decision:** a frozen step or class must match its contract signature on every gate. It must raise its `NotImplementedError('<task>')` stub only while the task the stub names is open in `tasks/todo.md`. After that task lands, its contract section is what the gate checks.
- **Alternatives:** keep the check as it is, which means no step task can land. Or drop the stub check entirely, which lets an unimplemented step pass the interface test, though the gate's CR-02 check would still catch it.
- **Consequences:** a new interface task, added by `build-planning` Replan, re-freezes `tests/contracts/test_interface.py`. Rows for open tasks don't change. No signature, type or fixture changes, so no code that calls this function changes.
