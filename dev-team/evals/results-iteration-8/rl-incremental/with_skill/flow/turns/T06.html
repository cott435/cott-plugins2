# RL Lab — Spec

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [brief.md](brief.md)

## Summary
A Snake game on a grid, two ways for an agent to see the board, two hand-written learners (a lookup table and a neural network), and two baseline bots to judge them against. Agents are trained up a four-run ladder, evaluated against the bots with a significance test, watched in a replay viewer, and written up in a findings note per run. The training, logging, evaluation and replay pieces are shared so the next environment can reuse them.

## Users
| User | What they need to do |
|---|---|
| Learner (the project owner) | Train each agent on the ladder, compare it with the bots, replay its games, and explain what it learned and what limits it. |

## Scope
**In scope:** Snake game, Board views, Baseline bots, Table learner, Network learner, Training & evaluation, Replay viewer, Findings notes, Shared core.

**The ladder** (the four runs this stage delivers):

| Run | Learner | View | Board | Bar |
|---|---|---|---|---|
| L1 | Table | Compact | 10×10 | Clearly beats random; matches scripted |
| L2 | Table | Raw grid | 6×6 | Experiment: report the result, no pass bar |
| L3 | Network | Compact | 10×10 | Clearly beats random; matches scripted |
| L4 | Network | Raw grid | 6×6 | Clearly beats random; beats scripted |

**Out of scope:**
- A general framework designed ahead of Snake. The shared pieces are only what Snake needs.
- Ready-made reinforcement learning algorithms or components from a library.
- Comparison against an established reference implementation (a later stage).
- Growing boards or difficulty curricula.
- A tail-less warm-up Snake.
- Cloud or graphics-card training.
- A live view during training.
- Record scores, or a polished game for human players.
- Any outside data: all experience comes from the game itself.

## Features

### Snake game (`GAME`)
**Serves:** Goal 1, Goal 5
**Behavior:** A snake moves on a square grid. Each step the agent chooses one of three moves relative to its heading. Eating food grows the snake and scores a point. Hitting a wall or its own body ends the game. A game is cut off if the snake goes too long without eating.

**Requirements**
- **GAME-01** The board size is set per game; 6×6 and 10×10 are supported.
  - Given a board size of 6, when a game starts, then the playable area is 6×6 cells.
- **GAME-02** A game starts with a snake of length 3 in the centre of the board, plus one piece of food on a random empty cell.
  - Given a new 10×10 game, when it starts, then the snake has 3 cells, its head is in the centre, and the food is on a cell the snake doesn't occupy.
- **GAME-03** Each step accepts exactly one of three moves: straight, turn left, turn right, relative to the current heading.
  - Given a snake heading up, when the move is "turn left", then the head moves one cell to the left and the heading becomes left.
  - Given any move other than those three, when it's submitted, then the step is refused with an error and the game state doesn't change.
- **GAME-04** Moving the head onto food scores +1, grows the snake by one cell and places new food on a random empty cell.
  - Given food directly ahead, when the move is "straight", then the reward is +1, the length increases by 1 and new food appears on an empty cell.
- **GAME-05** Moving the head into a wall or into the snake's own body ends the game with a reward of −1.
  - Given a snake beside the right wall heading right, when the move is "straight", then the game ends and the reward is −1.
  - Given a snake whose body is directly to the head's left, when the move is "turn left", then the game ends and the reward is −1.
- **GAME-06** A step that neither eats nor collides gives a reward of 0.
  - Given an empty cell ahead, when the move is "straight", then the reward is 0 and the length is unchanged.
- **GAME-07** A game is cut off after 100 consecutive steps without eating. The cut-off is reported as distinct from dying, and gives a reward of 0.
  - Given 99 steps since the last food, when the 100th step neither eats nor collides, then the game ends, is marked "cut off" (not "died"), and the reward is 0.
- **GAME-08** Filling every cell of the board with the snake ends the game as a win.
  - Given a snake one cell short of filling the board, when it eats the last food, then the game ends marked "won".
- **GAME-09** The same seed produces the same game for the same sequence of moves.
  - Given two games started with seed 7, when both receive the same moves, then every food position, reward and ending is identical.

**Edge cases & errors**
- The head moves into the cell the tail is leaving on this step (not eating) → legal; the tail moves first, so no collision.
- A step is submitted after the game has ended → refused with an error; nothing changes.

### Board views (`VIEW`)
**Serves:** Goal 1
**Behavior:** The agent can see the board in one of two ways. The compact view is 11 yes/no facts about the immediate situation. The raw grid view is the whole board, with body, head and food marked separately.

**Requirements**
- **VIEW-01** The compact view gives 11 yes/no facts: danger straight, danger left, danger right; heading up, down, left, right; food up, down, left, right of the head.
  - Given a snake heading up with a wall directly above the head and food to the lower right, when the compact view is read, then "danger straight", "heading up", "food down" and "food right" are yes, and the other seven facts are no.
- **VIEW-02** "Danger" in the compact view means the move in that direction would end the game on this step, whether by wall or body.
  - Given the snake's own body cell directly to the head's right, when the compact view is read, then "danger right" is yes.
- **VIEW-03** The raw grid view shows every cell of the board, with body cells, the head cell and the food cell each marked separately.
  - Given a 6×6 game, when the raw grid view is read, then it covers all 36 cells, exactly one cell is marked head, exactly one is marked food, and the body marks match the snake's other cells.
- **VIEW-04** The raw grid view also shows the snake's current heading.
  - Given two otherwise identical boards where the snake heads up in one and left in the other, when both raw grid views are read, then they differ.
- **VIEW-05** Each training or evaluation run uses exactly one view, chosen when the run starts.
  - Given a run set to the compact view, when the agent acts, then it receives only the compact view.

### Baseline bots (`BOT`)
**Serves:** Goal 3
**Behavior:** Two fixed bots that don't learn give the bars each agent is judged against: one moves at random, the other follows a simple rule.

**Requirements**
- **BOT-01** The random bot picks each of the three moves with equal chance.
  - Given 30,000 random-bot moves, when they're counted, then each move makes up between 32% and 35% of them.
- **BOT-02** The scripted bot chooses, among the moves that don't end the game this step, the one that brings the head closest to the food. If every move ends the game, it moves straight.
  - Given food two cells ahead and a clear path, when the scripted bot moves, then it moves straight.
  - Given food to the left but a wall to the left, when the scripted bot moves, then it doesn't turn left.
- **BOT-03** Ties in the scripted bot's choice are broken in a fixed order (straight, then left, then right), so the bot is repeatable.
  - Given two moves equally close to the food and both safe, when the scripted bot moves twice from the same state, then it picks the same move both times, and it's the earlier one in that order.
- **BOT-04** Both bots are evaluated with the same procedure and on the same board size as the agent they're compared with (EVAL-04).
  - Given run L4 on a 6×6 board, when the comparison is made, then the bots' scores come from 6×6 games.

### Table learner (`TAB`)
**Serves:** Goal 1, Goal 2
**Behavior:** An agent that keeps a lookup table with one learned value per situation and move. It improves the table from every step it plays, explores at random early on and acts greedily later. It's written by hand from basic array operations.

**Requirements**
- **TAB-01** The table holds one value per (situation, move) pair. A situation not seen before starts with a value of 0 for every move.
  - Given a situation the agent has never seen, when its values are read, then all three are 0.
- **TAB-02** After each step, the value for the situation and move just taken moves toward the reward received plus the discounted best value of the next situation. If the game ended, it moves toward the reward alone.
  - Given a value of 0, a reward of +1, a game-ending step, a learning rate of 0.5, when the update runs, then the value becomes 0.5.
- **TAB-03** A cut-off game (GAME-07) is treated as not ended for the update, so the next situation's value still counts.
  - Given the step that triggered a cut-off, when the update runs, then it includes the discounted best value of the next situation.
- **TAB-04** Exploration starts fully random and falls on a set schedule to a set minimum chance of a random move.
  - Given a run's exploration schedule, when the chance of a random move is logged per game, then it starts at 1.0, never rises, and ends at the configured minimum.
- **TAB-05** The learner is written from basic array operations; no ready-made learning algorithm component is used.
  - Given the learner's code, when it's reviewed, then every learning step is the project's own code.
- **TAB-06** A table run reports how many distinct situations it saw.
  - Given a finished L2 run, when its results are read, then the count of distinct situations seen is reported alongside the scores.

### Network learner (`NET`)
**Serves:** Goal 1, Goal 2
**Behavior:** An agent whose move values come from a small neural network instead of a table. It learns from random batches of past steps held in a memory, against targets from a slowly updated copy of itself, while exploring as the table learner does. It's written by hand: the network and its gradients may use a general numerical library, but every reinforcement learning piece is the project's own.

**Requirements**
- **NET-01** Past steps (situation, move, reward, next situation, whether the game ended) are kept in a memory of fixed capacity. When it's full, the oldest step is dropped for each new one.
  - Given a memory of capacity 1,000 holding 1,000 steps, when a new step is added, then it still holds 1,000 steps and the oldest is gone.
- **NET-02** Each learning update uses a batch of steps drawn at random from the memory.
  - Given a memory holding 5,000 steps, when 1,000 batches are drawn, then steps from across the whole memory appear, not just the most recent.
- **NET-03** Learning doesn't start until the memory holds a set minimum number of steps.
  - Given a minimum of 1,000, when the memory holds 999 steps, then no learning update has happened.
- **NET-04** Learning targets come from a separate copy of the network that is refreshed from the learning network every set number of updates and is otherwise unchanged.
  - Given a refresh interval of 500 updates, when 499 updates have run since the last refresh, then the target copy's values are unchanged. After update 500 they equal the learning network's.
- **NET-05** A target uses the reward alone when the game ended, and the reward plus the discounted best target-copy value of the next situation otherwise. A cut-off counts as not ended (as in TAB-03).
  - Given a stored step that ended the game with reward −1, when its target is computed, then the target is −1.
- **NET-06** Exploration follows the same kind of schedule as the table learner (TAB-04).
  - Given a run's exploration schedule, when the chance of a random move is logged per game, then it starts at 1.0, never rises, and ends at the configured minimum.
- **NET-07** The same learner works with either view; only the size of its input changes.
  - Given the same learner settings, when L3 (compact) and L4 (raw grid) are started, then both run without changes to the learner.
- **NET-08** Every reinforcement learning piece (memory, sampling, targets, target copy, exploration, update rule) is the project's own code. A general numerical library may supply only the network's arithmetic and gradients.
  - Given the learner's code, when it's reviewed, then no ready-made reinforcement learning component is used.

### Training & evaluation (`EVAL`)
**Serves:** Goal 3
**Behavior:** Each ladder run trains an agent from a seed, records a learning curve, saves the trained agent, then evaluates it against both bots. The statistical comparison is done by the `null-hypothesis-testing` skill.

**Requirements**
- **EVAL-01** A training run is fully set by its settings: learner, view, board size, seed and learning settings. The settings are saved with the run.
  - Given a finished run, when its saved settings are used to start a new run, then the new run uses the same learner, view, board size and seed.
- **EVAL-02** Training records each game's score, length in steps, ending (died, cut off, won) and exploration chance.
  - Given a finished run of 2,000 training games, when its log is read, then it has 2,000 entries with those four fields.
- **EVAL-03** Each run produces a learning curve: score per training game, smoothed over the last 100 games, with the random and scripted bots' average scores shown as reference lines.
  - Given a finished L1 run, when its learning curve is opened, then it shows the smoothed score over training games plus two labelled horizontal lines for the bots.
- **EVAL-04** Evaluation plays 100 games per seed across 5 training seeds (500 games), with exploration turned off. Both bots play the same number of games on the same board size.
  - Given a ladder run, when it's evaluated, then 500 agent games, 500 random-bot games and 500 scripted-bot games are recorded, each with its score.
- **EVAL-05** "Clearly beats random": the agent's average score is higher than the random bot's, and the `null-hypothesis-testing` skill, given both sets of 500 evaluation scores, finds the difference significant at 5%.
  - Given L1's and the random bot's evaluation scores, when they're tested with that skill, then the run passes this bar only if the agent's average is higher and the result is significant at 5%.
- **EVAL-06** "Matches the scripted bot" (L1, L3): the agent's average score is at least 90% of the scripted bot's, and the `null-hypothesis-testing` skill, given both sets of scores, rejects at 5% the hypothesis that the agent is more than 10% worse.
  - Given L3's and the scripted bot's evaluation scores, when they're tested with that skill, then the run passes only if both conditions hold.
- **EVAL-07** "Beats the scripted bot" (L4): the agent's average score is higher than the scripted bot's, and the `null-hypothesis-testing` skill, given both sets of scores, finds the difference significant at 5%.
  - Given L4's and the scripted bot's evaluation scores, when they're tested with that skill, then the run passes only if the agent's average is higher and the result is significant at 5%.
- **EVAL-08** L2 is evaluated with the same procedure, but no bar applies. Its scores, test results and distinct-situation count (TAB-06) are reported as they are.
  - Given a finished L2 run, when its report is read, then it shows the comparison with both bots and the situation count, with no pass or fail.
- **EVAL-09** Each evaluation produces a summary: average score, spread and death/cut-off/win counts for the agent and both bots, plus each bar's pass or fail.
  - Given an evaluated L4, when its summary is read, then it lists these figures for all three players and the result of each applicable bar.
- **EVAL-10** Each trained agent is saved, and can be reloaded to play or be evaluated again without retraining.
  - Given a saved L3 agent, when it's reloaded and evaluated with the same seeds, then it gets the same evaluation scores.

### Replay viewer (`WATCH`)
**Serves:** Goal 4
**Behavior:** Any recorded game (from an agent or a bot) can be watched on the laptop screen, step by step or at a chosen speed, with the agent's value for each of the three moves shown at every step.

**Requirements**
- **WATCH-01** Any evaluation game can be saved as a replay and opened later.
  - Given a saved replay of an L1 evaluation game, when it's opened, then the first step's board is shown.
- **WATCH-02** The viewer steps forward and backward through the game one step at a time.
  - Given a replay at step 10, when "back" is chosen, then step 9's board is shown. When "forward" is chosen twice, then step 11's board is shown.
- **WATCH-03** The viewer plays the game automatically at an adjustable speed, from 1 to 20 steps per second.
  - Given playback at 5 steps per second, when 2 seconds pass, then the replay has advanced about 10 steps.
- **WATCH-04** For agent games, every step shows the agent's value for each of the three moves and marks the move taken.
  - Given a replay of an L3 game at any step, when it's shown, then three values labelled straight, left and right appear, and the move taken is highlighted.
- **WATCH-05** For bot games, the move values are shown as unavailable instead of being left out silently.
  - Given a replay of a scripted-bot game, when a step is shown, then the values area says the bot has no values.
- **WATCH-06** Each step also shows the step number, the score so far, the reward on that step and, on the last step, how the game ended.
  - Given the last step of a game that died, when it's shown, then the ending reads "died".
- **WATCH-07** A replay rebuilt from its seed and recorded moves is identical to the saved one.
  - Given a saved replay, when the game is replayed from its seed and moves, then every board, reward and ending matches.

**Edge cases & errors**
- A replay file is missing or damaged → the viewer says so plainly and opens nothing.
- A replay at its first step and "back" is chosen → it stays on the first step.

### Findings notes (`NOTE`)
**Serves:** Goal 1
**Behavior:** Each ladder run ends with a short written note, so "I can explain it" is something on paper rather than a feeling.

**Requirements**
- **NOTE-01** Each of L1–L4 has a findings note that includes its learning curve and its evaluation summary (EVAL-09).
  - Given a finished, evaluated run, when its note is opened, then the curve and summary are in it.
- **NOTE-02** Each note says in plain words what the agent learned, citing at least two replays watched.
  - Given L3's note, when it's read, then it describes at least two behaviours, each tied to a named replay.
- **NOTE-03** Each note says what limits the agent, with at least one replay showing the limit.
  - Given L1's note, when it's read, then it names a failure pattern (such as trapping itself) and points to a replay that shows it.
- **NOTE-04** The L2 note compares the distinct situations seen with L1's and explains the result.
  - Given L2's note, when it's read, then it reports both situation counts and gives a reason for the difference in performance.
- **NOTE-05** A closing Snake note compares all four runs and explains why the compact view and the raw grid give different results for each learner.
  - Given all four notes are done, when the closing note is read, then it has a four-run comparison and that explanation.

### Shared core (`CORE`)
**Serves:** Goal 5
**Behavior:** Training, logging, evaluation and the replay viewer work with any environment that offers the same few operations as Snake (start a game, take a move, see the board, know when it ended). A tiny second test environment proves it without growing into a framework.

**Requirements**
- **CORE-01** Training, logging, evaluation and replay depend only on the operations every environment offers, never on anything Snake-specific.
  - Given those shared pieces, when they're reviewed, then none of them uses Snake's rules, board or views directly.
- **CORE-02** A minimal test environment (a one-row corridor where the agent walks to a goal) can be trained, evaluated and replayed by the shared pieces without changing them.
  - Given the corridor environment, when a table learner is trained, evaluated and one game replayed, then all three work and the shared pieces' code is unchanged.

## Quality requirements
- **QR-01** A table-learner training run (L1, L2) finishes in ≤ 10 minutes on the laptop's processor, with no graphics card.
  - Timed on the project laptop with the run's real settings.
- **QR-02** A network-learner training run (L3, L4) finishes in ≤ 60 minutes on the laptop's processor, with no graphics card.
  - Timed on the project laptop with the run's real settings.
- **QR-03** Repeating a training run with the same settings and seed produces an identical learning curve.
  - Two runs of L1, and two of L3 shortened to 200 games, with the same seed, are compared entry by entry.
- **QR-04** Evaluating one ladder run against both bots (1,500 games) takes ≤ 5 minutes.
  - Timed on the project laptop.

## Assumptions
- Rewards are +1 for food, −1 for dying and 0 otherwise. A game is cut off after 100 steps without eating.
- The snake has three moves relative to its heading, so it can never reverse into itself.
- Compact-view runs use a 10×10 board. Raw-grid runs use 6×6, small enough for the network learner to stay within QR-02.
- L2 (table on the raw grid) is an experiment. It's expected to do poorly, but the spec requires only that it runs and reports.
- Learning settings (learning rate, discount, exploration schedule, memory size, refresh interval, number of training games) are chosen during the build and saved with each run (EVAL-01). They're not fixed here.

heading up, down, left, right; food up, down, left, right of the head.\n  - Given a snake heading up with a wall directly above the head and food to the lower right, when the compact view is read, then \"danger straight\", \"heading up\", \"food down\" and \"food right\" are yes, and the other seven facts are no.\n- **VIEW-02** \"Danger\" in the compact view means the move in that direction would end the game on this step, whether by wall or body.\n  - Given the snake's own body cell directly to the head's right, when the compact view is read, then \"danger right\" is yes.\n- **VIEW-03** The raw grid view shows every cell of the board, with body cells, the head cell and the food cell each marked separately.\n  - Given a 6×6 game, when the raw grid view is read, then it covers all 36 cells, exactly one cell is marked head, exactly one is marked food, and the body marks match the snake's other cells.\n- **VIEW-04** The raw grid view also shows the snake's current heading.\n  - Given two otherwise identical boards where the snake heads up in one and left in the other, when both raw grid views are read, then they differ.\n- **VIEW-05** Each training or evaluation run uses exactly one view, chosen when the run starts.\n  - Given a run set to the compact view, when the agent acts, then it receives only the compact view.\n\n### Baseline bots (`BOT`)\n**Serves:** Goal 3\n**Behavior:** Two fixed bots that don't learn give the bars each agent is judged against: one moves at random, the other follows a simple rule.\n\n**Requirements**\n- **BOT-01** The random bot picks each of the three moves with equal chance.\n  - Given 30,000 random-bot moves, when they're counted, then each move makes up between 32% and 35% of them.\n- **BOT-02** The scripted bot chooses, among the moves that don't end the game this step, the one that brings the head closest to the food. It improves the table from every step it plays, explores at random early on and acts greedily later. It's written by hand from basic array operations.\n\n**Requirements**\n- **TAB-01** The table holds one value per (situation, move) pair. A situation not seen before starts with a value of 0 for every move.\n  - Given a situation the agent has never seen, when its values are read, then all three are 0.\n- **TAB-02** After each step, the value for the situation and move just taken moves toward the reward received plus the discounted best value of the next situation. If the game ended, it moves toward the reward alone.\n  - Given a value of 0, a reward of +1, a game-ending step, a learning rate of 0.5, when the update runs, then the value becomes 0.5.\n- **TAB-03** A cut-off game (GAME-07) is treated as not ended for the update, so the next situation's value still counts.\n  - Given the step that triggered a cut-off, when the update runs, then it includes the discounted best value of the next situation.\n- **TAB-04** Exploration starts fully random and falls on a set schedule to a set minimum chance of a random move.\n  - Given a run's exploration schedule, when the chance of a random move is logged per game, then it starts at 1.0, never rises, and ends at the configured minimum.\n- **TAB-05** The learner is written from basic array operations; no ready-made learning algorithm component is used.\n  - Given the learner's code, when it's reviewed, then every learning step is the project's own code.\n- **TAB-06** A table run reports how many distinct situations it saw.\n  - Given a finished L2 run, when its results are read, then the count of distinct situations seen is reported alongside the scores.\n\n### Network learner (`NET`)\n**Serves:** Goal 1, Goal 2\n**Behavior:** An agent whose move values come from a small neural network instead of a table. It learns from random batches of past steps held in a memory, against targets from a slowly updated copy of itself, while exploring as the table learner does. It's written by hand: the network and its gradients may use a general numerical library, but every reinforcement learning piece is the project's own.\n\n**Requirements**\n- **NET-01** Past steps (situation, move, reward, next situation, whether the game ended) are kept in a memory of fixed capacity. When it's full, the oldest step is dropped for each new one.\n  - Given a memory of capacity 1,000 holding 1,000 steps, when a new step is added, then it still holds 1,000 steps and the oldest is gone.\n- **NET-02** Each learning update uses a batch of steps drawn at random from the memory.\n  - Given a memory holding 5,000 steps, when 1,000 batches are drawn, then steps from across the whole memory appear, not just the most recent.\n- **NET-03** Learning doesn't start until the memory holds a set minimum number of steps.\n  - Given a minimum of 1,000, when the memory holds 999 steps, then no learning update has happened.\n- **NET-04** Learning targets come from a separate copy of the network that is refreshed from the learning network every set number of updates and is otherwise unchanged.\n  - Given a refresh interval of 500 updates, when 499 updates have run since the last refresh, then the target copy's values are unchanged. After update 500 they equal the learning network's.\n- **NET-05** A target uses the reward alone when the game ended, and the reward plus the discounted best target-copy value of the next situation otherwise. A cut-off counts as not ended (as in TAB-03).\n  - Given a stored step that ended the game with reward −1, when its target is computed, then the target is −1.\n- **NET-06** Exploration follows the same kind of schedule as the table learner (TAB-04).\n  - Given a run's exploration schedule, when the chance of a random move is logged per game, then it starts at 1.0, never rises, and ends at the configured minimum.\n- **NET-07** The same learner works with either view; only the size of its input changes.\n  - Given the same learner settings, when L3 (compact) and L4 (raw grid) are started, then both run without changes to the learner.\n- **NET-08** Every reinforcement learning piece (memory, sampling, targets, target copy, exploration, update rule) is the project's own code. A general numerical library may supply only the network's arithmetic and gradients.\n  - Given the learner's code, when it's reviewed, then no ready-made reinforcement learning component is used.\n\n### Training & evaluation (`EVAL`)\n**Serves:** Goal 3\n**Behavior:** Each ladder run trains an agent from a seed, records a learning curve, saves the trained agent, then evaluates it against both bots. The statistical comparison is done by the `null-hypothesis-testing` skill.\n\n**Requirements**\n- **EVAL-01** A training run is fully set by its settings: learner, view, board size, seed and learning settings. The settings are saved with the run.\n  - Given a finished run, when its saved settings are used to start a new run, then the new run uses the same learner, view, board size and seed.\n- **EVAL-02** Training records each game's score, length in steps, ending (died, cut off, won) and exploration chance.\n  - Given a finished run of 2,000 training games, when its log is read, then it has 2,000 entries with those four fields.\n- **EVAL-03** Each run produces a learning curve: score per training game, smoothed over the last 100 games, with the random and scripted bots' average scores shown as reference lines.\n  - Given a finished L1 run, when its learning curve is opened, then it shows the smoothed score over training games plus two labelled horizontal lines for the bots.\n- **EVAL-04** Evaluation plays 100 games per seed across 5 training seeds (500 games), with exploration turned off. Both bots play the same number of games on the same board size.\n  - Given a ladder run, when it's evaluated, then 500 agent games, 500 random-bot games and 500 scripted-bot games are recorded, each with its score.\n- **EVAL-05** \"Clearly beats random\": the agent's average score is higher than the random bot's, and the `null-hypothesis-testing` skill, given both sets of 500 evaluation scores, finds the difference significant at 5%.\n  - Given L1's and the random bot's evaluation scores, when they're tested with that skill, then the run passes this bar only if the agent's average is higher and the result is significant at 5%.\n- **EVAL-06** \"Matches the scripted bot\" (L1, L3): the agent's average score is at least 90% of the scripted bot's, and the `null-hypothesis-testing` skill, given both sets of scores, rejects at 5% the hypothesis that the agent is more than 10% worse.\n  - Given L3's and the scripted bot's evaluation scores, when they're tested with that skill, then the run passes only if both conditions hold.\n- **EVAL-07** \"Beats the scripted bot\" (L4): the agent's average score is higher than the scripted bot's, and the `null-hypothesis-testing` skill, given both sets of scores, finds the difference significant at 5%.\n  - Given L4's and the scripted bot's evaluation scores, when they're tested with that skill, then the run passes only if the agent's average is higher and the result is significant at 5%.\n- **EVAL-08** L2 is evaluated with the same procedure, but no bar applies.
