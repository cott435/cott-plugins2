Contract-first pipelines: what's covered, what your brief adds, what's still open

dev-team already builds in the order your brief proposes: contracts, then a spine, then wiring, then thickening. Measured on minilab, a small prices-to-risk-report project, that order was not faster at this size. Its real weak point is gaps that only show up once real code runs. Your brief fixes most of the design gaps. Two of the most expensive failures in the eval are missing from both.

In plain terms

Done today

What dev-team does now

  • Writes every shared type as code, with a schema and a sample file, before any parallel work.
  • Builds fakes for each boundary with the contracts, so each step is tested alone.
  • Runs a spine, then wiring, then thickens, with agents in parallel and a review at phase ends.
  • Catches a missing field while the contracts are written, in about 2 minutes.
Your brief

What you suggested

  • Build one real source end to end before the rest.
  • One canonical record (Bar) that every source converts into.
  • Failures isolated per source and symbol, logged, with reruns that are safe to repeat.
  • Logging, stage counts and a FakeSource in the spine from day one.
  • Sources, symbols, dates and stages in config. Retries and rate limits as wrappers.
Proposed fixes

What fills the rest

  • Build the real slice before freezing the contracts. The brief's order freezes first.
  • One shared test suite that every source and its fake must pass.
  • Contract tests check shape only, never "this is still a stub". Review before the parallel wave starts.
  • Spell out the record's timezone, price adjustment, currency and version.
  • Rules for overlapping sources, shared rate limits, batch failure and daily backfill.

Protocol or ABC

Use typing.Protocol. Adapters don't need to import or inherit anything, mypy checks them, and third-party classes fit as they are. @runtime_checkable only checks that names exist, so the real runtime check is the shared test suite above: it checks behavior on every registered source. An ABC is only worth it if you want sources found automatically through subclassing, which your config-driven registry doesn't need.
