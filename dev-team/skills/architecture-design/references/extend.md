# Extend

Read when `dt status --skill architecture-design` reports Extend: the spec gained requirements (usually from a specced idea) or changed some. It ends at the Review Gate in `../SKILL.md`, following `writing-rules.md` throughout. Example: `examples-extend.md`.

1. Take the `uncovered` and `changed_since` IDs and the `spec_rows_pending` rows from `dt status`. Read the idea file each row cites for context.
2. **Grow check.** Check every Grow trigger in `shape.md`, and say at the gate which (if any) fired. If one fires, propose Grow to the user (one question, with your recommendation) before placing anything.
3. For each requirement, choose: an existing component covers it (add the ID to Covers), an existing component grows (update its contract), or a new component is needed (add it and its contract section, check the dependency direction). Components follow `components.md`, contracts `contracts.md`. Lines added to a code block (the storage or project layout) go inside it, before its closing fence.
4. Any new technical choice gets a new `AD-NN`, made, and checked against the Accepted decisions it touches, as `decisions.md` says.
5. Requirements *removed* from the spec: take their IDs out of Covers; if a component now covers nothing, propose removing it.
6. Consolidate: merge new risks into the one Risks list, and delete the risks this round resolved. Rewrite the Overview and any section still worded for an earlier stage so it describes the whole system. Every count, list and range the round changed is updated everywhere it appears: Overview, Covers cells (`claims` still covering "EDA-06, OOS-10" after later stages added 26 claim families), contracts (such as the kinds of test a log entry accepts), cross-cutting concerns (such as which claims a skill tests), section headings, and older decisions. That includes text the round didn't set out to touch. Search for stage lists ("Stages 2 and 3", "both studies"), superlatives the new parts falsify ("the top of the dependency chain") and "later stage" or "milestone" framing for stages that now exist. Delete notes on how the design got here, code comments included ("unchanged since the single-crop stage", "Since the field-photo stage, …", "Older … files load into this form").
7. Add one one-line Changelog row that cites the source files of `spec_rows_pending` (`writing-rules.md`). Set Status to Draft on every doc and contract changed, and run the Review Gate, highlighting only what changed.
