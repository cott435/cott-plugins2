Architecture is in Extend mode for S2. All 35 S2 requirements need a home, and the Grow check matters before anything is placed.

## Grow check
One trigger fires: **a new dependency stack the rest shouldn't carry.** S2 needs numerical libraries (SciPy, a quadratic-programming solver, a plotting library for the report charts) that `data`, `builder` and `server` never use. AD-01 and AD-15 already anticipated this: *"A later stage's research package joins the workspace depending on `data` only."* No other trigger fires: nothing runs or deploys on its own, and `server`'s contract is the only one near the size limit.

## The one decision: shape
**My recommendation: add a fifth package, `portfolio`** (Python package `qlab_portfolio`, command `qlab-portfolio`), which **depends on `data` only**:

```
web → server → builder → data
                portfolio → data      (new; nothing imports portfolio)
```

- **It holds all of S2:** the walk-forward harness, return structure, the 4 estimators, the 3 portfolio methods and the reports. That's about 6 modules and 1 to 2 pipelines, well inside the size limits.
- **New dependency rules, enforced by import-linter:**
  - `portfolio` may import only `data`.
  - `builder` and `server` may never import `portfolio`, because S2 has no app pages.
  - `data` still imports nothing.
- **Alternative:** put S2 inside `data`. It's rejected because it would make the read-side package that all research depends on carry SciPy and plotting, and blur the line AD-15 drew.

## What I'd decide next, unless you object (each becomes a decision record)
- **Numerical stack:**
  - NumPy and SciPy for eigendecomposition and HRP's hierarchical clustering.
  - The **OSQP** solver for long-only minimum variance. It's a fast, deterministic quadratic-programming solver that copes with a singular covariance (HARN-10).
  - Risk parity, constant-correlation shrinkage and Marchenko–Pastur denoising written from basic array operations, because no library offers the shrinkage target you chose.
- **Reading data:**
  - Load returns through the point-in-time loader once per run.
  - Ask `data` for the universe as known at each rebalance.
  - Strictly slice each window to dates on or before its rebalance.
  - Returns carry no future information (AD-05), and the HARN-04 property test guards the slicing.
- **Reports:** written to a run folder under the data home, with:
  - numbers as JSON, so CMP-06 can compare them exactly
  - a Markdown summary
  - static charts, made with matplotlib and following `dataviz`
- **Statistical tests:** done the way the `null-hypothesis-testing` skill specifies, built from NumPy. No extra statistics library is chosen up front; the skill decides the method when the tests are built.

Do you approve adding `portfolio` as a fifth package depending on `data` only? (Default: yes.)
