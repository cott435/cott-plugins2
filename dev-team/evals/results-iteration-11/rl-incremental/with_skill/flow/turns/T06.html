# RL Lab

**Status:** Accepted · **Last updated:** 2026-10-18

## The problem
Reinforcement learning (RL) is how an agent learns by trial and error from rewards. It is easy to read about and hard to really understand. Library code hides the parts that matter, and tutorials stop once the agent "works". The fastest way to learn it is to build small agents from scratch, in small 2D game environments, where each one teaches one idea and you can see it learn.

## Who it's for
Me: a solid Python programmer with some NumPy and PyTorch, who knows the basics of Q-learning (learning the value of each action in each state) and wants to learn RL by building it.

## Goals
1. For each environment, I can explain in my own words why the agent learns, and why each part of the algorithm matters.
2. Every agent is shown to learn: its learning curve beats a random agent and a simple scripted agent on the same games.
3. I can watch a replay of any trained agent playing.
4. A new environment reuses a shared core (environment interface, training loop, logging, replay viewer, learning curves) instead of starting over.

## Constraints
- Laptop CPU only, and under about an hour of training per environment.
- Free tools only.
- Evenings and weekends, a few weeks per environment, no deadline.
- Learning algorithms are written from scratch, not taken from a library.

## What success looks like
- The first environment, Snake, has an agent whose learning curve clearly beats both baselines, plus a replay of it playing.
- Turning off a key part of the agent visibly hurts its learning, and I can say why.
- The second environment, whatever it is, plugs into the shared core with small changes.

## What we're betting on
- Small, hand-picked descriptions of the game state ("danger ahead", "food to the left") are enough for an agent to learn well within an hour on a CPU.
- A shared core designed while Snake is the only example will still fit the next environment without a rewrite.
- Writing the algorithms myself teaches more than tuning a library would.

## Not doing
- Learning from raw pixels or the full grid image: much slower, and not the lesson I'm after.
- Comparing against library implementations, for now: a later step, once my own version works.
- Fancy views such as heatmaps of the agent's values: learning curves and replays are enough.
- Planning environments beyond Snake: the next one is chosen once Snake is done.
- Mastering Snake: agents that see only nearby danger tend to trap themselves, and that limit is fine.

# RL Lab — Spec

**Status:** Approved · **Last updated:** 2026-10-18 · **Brief:** [brief.md](brief.md)

## Summary
A lab of small 2D game environments where hand-written reinforcement-learning agents learn by trial and error. The first stage builds classic Snake, a hand-written value-learning agent that sees 11 yes/no facts about the game, random and scripted baselines scored on the same games, switches that turn parts of the agent off, learning curves and a replay viewer, all on a shared core the next environment reuses. See the [brief](brief.md) for why.

## Users
| User | What they need to do |
|---|---|
| The learner (sole user) | Train an agent on an environment, compare it with baselines and with its own ablated versions on learning curves, watch any agent play, and write down why it learns |

## Scope
**In scope:** Snake environment, shared core, value-learning agent, ablation switches, baselines, evaluation, run logging, learning curves, replay viewer, explanation notes.

**Out of scope:**
- Learning from raw pixels or the full grid image; the agent sees only the 11 hand-picked facts.
- Comparing against library implementations of the same algorithms (a later step).
- Views beyond learning curves and replays: no heatmaps of the agent's values, no dashboards, no other visualisations.
- Real environments beyond Snake; the next one is chosen once Snake is done. The core is tested with a tiny throwaway test environment only.
- Mastering Snake: the agent sees only nearby danger and may trap itself; no requirement asks it to fill the board.
- GPUs, paid tools and paid services.

## Features

### Snake environment (`SNAKE`)
**Serves:** Goal 2, Goal 3
**Stage:** S1
**Behavior:** Classic Snake on a 20 × 20 grid. The snake starts 3 cells long in the middle of the grid, heading right, with one food on a random empty cell. Each step the agent picks one of 3 moves relative to its heading: straight, turn left, turn right. Eating food grows the snake by 1 and places new food; hitting a wall or its own body ends the game. The score of a game is the number of food eaten.

**Requirements**
- **SNAKE-01** The game is played on a 20 × 20 grid with a snake that starts 3 cells long in the middle, heading right.
  - Given a new game, when it starts, then the snake occupies 3 adjacent cells in the middle of the grid, heading right, and exactly one food is on a cell the snake does not occupy.
- **SNAKE-02** Each step the agent chooses one of 3 moves relative to the snake's heading: straight, turn left or turn right.
  - Given the snake heading up, when the agent picks "turn left", then the head moves one cell left and the heading becomes left.
  - Given any heading, when any of the 3 moves is picked, then the snake never reverses into its own neck.
- **SNAKE-03** Moving the head onto the food grows the snake by 1 cell, adds 1 to the score and places new food on a random empty cell.
  - Given food directly ahead, when the agent moves straight, then the snake is 1 cell longer, the score rises by 1 and a new food appears on a cell the snake does not occupy.
- **SNAKE-04** Moving the head into a wall or into the snake's own body ends the game.
  - Given the head next to the right wall heading right, when the agent moves straight, then the game ends with its current score.
  - Given the head beside its own body, when the agent turns into it, then the game ends.
- **SNAKE-05** A game also ends when the snake goes 100 × its length steps without eating.
  - Given a snake of length 5 that has not eaten for 500 steps, when it takes another step without eating, then the game ends with its current score.
- **SNAKE-06** The agent observes exactly 11 yes/no facts each step: danger straight ahead, danger to the left, danger to the right (danger = wall or body in the adjacent cell); heading up, down, left, right; food is up, down, left, right of the head.
  - Given the head heading right with the wall in the next cell and food above-left, when the agent observes, then "danger straight", "heading right", "food up" and "food left" are yes and the other 7 facts are no.
- **SNAKE-07** Rewards are +10 for eating food, −10 for the game ending by collision or step limit, and 0 for every other step.
  - Given a step that eats food, when the reward is reported, then it is +10; given a step that ends the game, then it is −10; given any other step, then it is 0.
- **SNAKE-08** A game started with the same seed and played with the same moves unfolds identically, including every food position.
  - Given seed 7 and a fixed list of moves, when the game is played twice, then every frame, reward and the final score are identical.

**Edge cases & errors**
- The snake fills every cell → the game ends as a win with its score; no food is placed.
- Food would be placed on the snake → it is placed only on empty cells.
- The agent sends a move other than the 3 allowed → the step is refused with an error naming the allowed moves; the game is unchanged.
- A step is requested after the game has ended → refused with an error saying the game is over.

### Shared core (`CORE`)
**Serves:** Goal 4
**Stage:** S1
**Behavior:** Every environment offers the same small set of behaviors: start a game from a seed, take one move and report what happened, say how many facts it observes and how many moves it allows, and draw one frame for the replay viewer. The training loop, logging, learning curves and replay viewer use only these behaviors, so a new environment plugs in without changing them.

**Requirements**
- **CORE-01** Every environment can start a new game from a given seed and returns the first observation.
  - Given any environment and seed 3, when a game is started twice, then both first observations are identical.
- **CORE-02** Every environment takes one move and reports the next observation, the reward and whether the game has ended.
  - Given a running game, when a move is taken, then the next observation, the reward and the game-over flag are all reported.
- **CORE-03** Every environment reports its observation size and its number of allowed moves.
  - Given Snake, when asked, then it reports 11 facts and 3 moves.
- **CORE-04** Every environment draws a frame of its current state for the replay viewer.
  - Given a running Snake game, when a frame is requested, then it shows the grid, the snake, the food, the score and the step number.
- **CORE-05** The training loop trains any agent on any environment that offers CORE-01 to CORE-04, for a set number of games, with a given seed.
  - Given a tiny test environment (a 1 × 5 corridor where reaching the right end gives +1), when the training loop runs on it with no changes to the core, then training completes and the agent reaches the right end in ≥ 9 of 10 evaluation games.
- **CORE-06** Logging, learning curves and the replay viewer work on any environment that offers CORE-01 to CORE-04.
  - Given the tiny test environment, when a run is logged, its learning curve drawn and a game replayed, then each works with no changes to the core.

**Edge cases & errors**
- An environment is missing one of the 4 behaviors → the core refuses it at start-up and names the missing behavior.
- An agent returns a move outside the environment's allowed moves → the run stops with an error naming the move and the game step.
