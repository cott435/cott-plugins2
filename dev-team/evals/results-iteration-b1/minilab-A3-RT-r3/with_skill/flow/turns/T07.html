1	# Milestone shape: interface, step spines, wiring, system
2	
3	Read when writing a milestone's tasks. Examples: `examples-phase0.md`.
4	
5	A milestone is planned from its pipelines' steps: each step has one owner, one module and typed `In → Out`, so it is the unit of work. The plan freezes every boundary between steps first, so the work on both sides starts at once instead of queueing behind one spine. Every task carries `**Kind:**`:
6	
7	```
8	## Phase 0: Interface              interface (solo, first)       types, signatures, samples, fakes, exports, __main__
9	## Phase 1: Step spines            spine, one per step           each writes its owner module only
10	## Phase 2: Wiring and thicken     wiring, one per pipeline      its entry module, smoke test
11	                                   thicken (tasks.md)            each after its step's spine
12	## Phase 3: System                 system (solo, last)           fakes swapped for real providers
13	```
14	
15	Phases name the usual waves; the dependency graph (`tasks.md` step 9) decides what may start. Tester halves of split tasks start right after the interface.
16	
17	**a. Interface task** (`**Kind:** interface`, `**Step:** contract`, solo, `**Depends on:** —`). It freezes, as code, every boundary in the milestone whose two sides belong to different tasks:
18	- each contract `type` section the milestone's steps pass (`In → Out`), written into its owner's `types.py`, with a schema (pandera for a frame, JSON Schema across runtimes) and one sample per case in `tests/contracts/<component>.<Type>/`. A case naming a probe sample (`PB-01 samples/sync_added.json#0`) puts `PB-01:samples` in `Read:`; the task derives the type's sample from it, never copies it
19	- each new step's signature in its owner module, with the body `raise NotImplementedError("<task id>")` naming the task that replaces it
20	- for each function a pipeline calls from another pipeline or package (its `**Boundary:**` line): a fixture-backed fake serving its fixtures, where the caller's tests load it. A `call` edge to a contract symbol is mitigated by that fake; `none` there needs a reason (`dt lint`)
21	- for each object with behavior a step passes (a Protocol or class: `core.Dataset`, `runstore.RunWriter`) and each call into another component's function: the Protocol or signature plus a fixture-backed replay double in `tests/contracts/<component>.<Type>/`. The double is that type's sample, not a fake: the system task never swaps it
22	- each component's `__init__.py` exports, and the package's `__main__.py`: the dispatch from each pipeline's trigger to its entry function, whose signature it stubs naming the wiring task, in that pipeline's own entry module
23	
24	Not frozen: helpers, private functions, anything one task owns end to end, and boundaries an earlier milestone froze. `Read:` the type and boundary symbols. Acceptance: every sample validates against its type; every signature imports; each fake and replay double serves its fixtures. `Writes:` each component folder as one glob (`src/gridload/profile/**`) plus its contract folders; `task-size` doesn't count them. A milestone across packages may have one interface task per provider, all solo and first; interface tasks never depend on each other. When one runtime's types are generated from another's schema, the providing interface task runs the generator and writes the generated file too (its `Writes:` claims it).
25	
26	**b. Step spines** (`**Kind:** spine`, `**Step:** PL-NN.<function>`, solo, XS or S). One per new step, each depending only on the interface task: it replaces the stub naming it with the step's spine version from the step table. `Writes:` its owner module and that module's unit test, nothing else; steps sharing one module share one spine task. Acceptance: the step's input sample gives a schema-valid output; the signature is unchanged. A step another pipeline provides (`PL-01 as built`) gets no spine.
27	
28	**c. Wiring** (`**Kind:** wiring`, `**Step:** PL-NN`, solo). One per new pipeline: the entry function in the pipeline's own entry module (the layout's, never one module shared by several pipelines), so wiring tasks run side by side, and its smoke test. `__main__.py` is the interface task's. It depends on its pipeline's spines, since the smoke runs them (`order`, `none: integration: …`), never on their thicken tasks. A call to another pipeline or package runs against that boundary's fake, so wiring PL-02 never waits for PL-01. Acceptance: the smoke command runs end to end and is committed as the pipeline's smoke test; the pipeline's pre-build sections are replaced by a `dt layout` pointer (`dt land` runs `dt prebuild-clear` when the wiring lands).
29	
30	**d. System task** (`**Kind:** system`, solo, last). It swaps each fake for the real provider, in the entry its wiring wrote (a `file` edge), and runs every smoke command and the milestone's golden cases on the real chain; the boundary samples still validate against real output. Multi-package: one per new system pipeline, `**Step:**` that pipeline, `**Package:**` the owner of its first step, `**Reason:** system task`; the root has no pre-build sections, so no `dt layout` bullet. Single package: `**Step:**` the calling pipeline. A milestone with no fake has no system task.
31	
32	**Folds** keep the task count down. The pipeline's wiring depends on a fold task, so a fold is allowed only where that task is XS and the critical path doesn't grow. Record each on its task as `**Reason:** fold: <rule>`:
33	- A step with a golden case whose spine and thicken are both in the milestone, or whose spine version is its whole behavior, may be one split thicken task that replaces the stub itself; with a thicken folded in, its acceptance keeps the baseline selectable.
34	- A trivial step (pass-through, print) is built by its pipeline's wiring task; its stub names the wiring task.
35	
36	**Fakes and stubs.** A fake is allowed only where a pipeline calls another pipeline or package: both sides test against the same fixtures, so neither drifts from the contract unseen. Mocking a step is forbidden: a step's spine is the real baseline, and its consumer builds against the type's sample (for a Protocol or class, its replay double). The interface stubs are the floor's one stub carve-out (`build-setup`'s CR-02): allowed while the task they name is open; the gate fails on one naming a done task, the milestone exit on any.
37	
38	**Frozen means frozen.** Changing a frozen type, sample, signature or fake is a `contract-change`: `architecture-design` Revise, then a new interface task naming the symbol in `Read:`, never an edit to make a test pass. The bar enforces it (CR-09): once a contract folder exists at a task's base the implementer can't write it, and `dt guard` asks before any edit no open interface task covers. The re-freeze is that interface task, run by an implementer agent, never the main session: its `Writes:` names the frozen folders it changes, which opens them to it alone.
