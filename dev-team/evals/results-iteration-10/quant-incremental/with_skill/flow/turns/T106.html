# Revise: an oracle changes

An expected output or tolerance must change: the user corrected an example, a paper has an erratum, a contract changed the output type, or a tolerance proved wrong *for a stated reason*. "The build can't make it pass" is not a reason; that's a bug until the source says the oracle was wrong. A looser tolerance is an oracle change too.

1. Show the old and new expected value (or tolerance) side by side, with the source of the new one.
2. Edit `expected.json` (the `dt guard` hook asks the user) and the case section. Status to Draft.
3. At the gate, name the tasks that cite the case. They pause: while `tests.md` is Draft, `build-planning`'s `dt status` says `blocked`. After approval, `build-planning` Replan follows (`changed_since_plan` lists `tests.md`).

A case that no longer applies collapses to one line under Retired (form in `../examples.md`) and its fixture folder is deleted. Its ID is never reused.

Do you approve the new expected output?

## Open questions
- **PORT-18 tests a winner picked from four.** The winner is the estimate with the lowest mean, and it is then tested against sample. When two or three estimates are truly no better than sample, picking the lowest first raises the false-positive rate above 5%. TC-52 avoids this by construction (two estimates are clearly worse, so only factor and sample can win). Should PORT-18 account for the pick, e.g. by testing every non-sample estimate against sample with Holm across all of them, or by a max-statistic null? That is the spec's call (spec-writing), routed only on your say.
- **Shrinkage intensity has no oracle.** TC-38 checks the convex form and 0 ≤ δ ≤ 1, which the spine's δ = 0 also passes. Ledoit and Wolf's (2004) δ value needs a known output (a paper table or your own run) to pin it; until then, unit tests only.
- **HRP's tree split has no discriminating oracle.** Both PORT-12 examples (TC-43) also pass with plain inverse-variance weights, the spine. A case that tells them apart needs a source, e.g. a published HRP example.
