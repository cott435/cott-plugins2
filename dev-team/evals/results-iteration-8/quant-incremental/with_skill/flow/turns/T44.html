# Idea: Feature Information Gain

**Status:** Draft · **Last updated:** 2026-10-17 · **Brief:** [../brief.md](../brief.md)

## In one sentence
This adds a feature lab that measures whether any candidate feature predicts next-month residual returns beyond chance, so I learn whether a signal survives honest testing instead of believing one that doesn't.

## The problem
The platform exists to find out whether any signal survives honest testing, and so far it only judges risk. Price-based features on large US stocks have been mined for decades. Most published ones decay, and a home-built search finds false ones easily: features are tried until one works, overlapping returns inflate significance, and a "new" feature is often momentum or low volatility under another name. The likely honest answer is that nothing survives, and the lab has to make that answer trustworthy.

## Who it's for
Me, after the variance-first stage, with a validated snapshot and window-only residual returns already built.

## How it fits
- **Serves:** new Goal 7 (feature claims judged against a null)
- **Touches:** STRUC-03 (window-only residual returns, the target), SYNTH-01–SYNTH-04 (the planted-answer bench pattern it copies), WALK-01 (point-in-time windows), and the spec's out-of-scope line on return prediction and machine learning, which this narrows
- **Brief changes:** Goal 7 added
- **Stage:** New S3 (roadmap stage on acceptance)

## Recommended direction
**First, prove the test can say no.** Before any real feature is scored, the whole pipeline runs on panels with no signal and on panels with a planted signal of known strength. On pure noise it must flag features no more often than its stated false-discovery rate, and it must find the planted ones. If the test cannot stay quiet on noise, nothing it says on real data counts.

**Then, two measures on the same features.** Each feature is screened alone by its monthly rank correlation with next-month residual return, with no model. This is the baseline. A gradient-boosted model then uses all the features together. A feature's information gain is how much worse the model predicts on held-out months when that feature is shuffled within each date. Both measures are tested against a null made by shuffling the feature within dates, with a false-discovery correction across every feature ever tried. The null-hypothesis-testing skill owns that step.

**Known factors are a required control.** A feature counts only if it adds information beyond momentum, short-term reversal and low volatility, not just beyond the market.

**Pre-registration and a locked holdout.** Development uses 2005–2021. The feature list and test settings are written to a file and hashed before 2022 onward is opened, and the holdout is opened once. Every feature tried is logged, so the correction counts them all. Results go to a static research report, and features never feed the portfolios.

## Data
- The S1 snapshot: daily prices, volume, corporate actions and point-in-time S&P 500 membership from 2005, including delisted names. No fundamentals.
- Target: next-month residual return, from the S2 window-only factor removal, at each monthly date.
- About 200 development months × ~500 names ≈ 100,000 rows, plus about 45 holdout months.
- Evaluation: walk-forward folds by month within development, then the one-shot holdout. Baseline: the single-feature screens, and a model with the known factors only.

## Alternatives considered
- Screens only, no ML — kept as the baseline; misses interactions.
- Long-short portfolio of surviving features — brings costs and turnover back; later, if anything survives.
- Automated feature search over thousands of candidates — the trap the null exists to catch.
- Fundamentals as features — the brief keeps them out.

## What success looks like
- On no-signal panels, the flagged rate stays at or below the stated false-discovery rate; planted features of known strength are found.
- Every real feature reports its gain, null distribution, adjusted p-value and holdout result in one report.
- A "nothing survives" result is reported as plainly as a discovery.
- The holdout was opened once, and the hashed registration predates it.

## What we're betting on
- Shuffling a feature within dates is a fair null for cross-sectional prediction, given overlapping information across names.
- Monthly residual returns are not so noisy that a real but small effect is undetectable in about 200 months.
- The S2 residuals remove enough common structure that the target isn't just sector moves.

## Not doing
- Strategies, backtest Sharpe ratios or trading signals — this measures information, nothing more
- Feeding features into the S2 portfolios — they stay variance-only
- Fundamentals, alternative data or intraday features — prices and volume only
- Automated feature generation — every feature is written and registered by hand
- An app screen — the static report is enough

## Open questions
- Which known-factor definitions (lookbacks, skip month) are the control?
- How many features go into the first registration, and what false-discovery rate?
- Is 2022 onward long enough as a holdout, or should development end earlier?
- Shuffling within dates keeps the cross-section but ignores time dependence. Is a block-shuffle in time needed as well?
