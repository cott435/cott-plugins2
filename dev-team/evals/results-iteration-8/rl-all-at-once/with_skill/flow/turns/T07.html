# Shape: single package or multi-package

Read before proposing the shape, and when weighing Grow.

- **Single package** (proof of concept, library, one service, research code): `docs/architecture.md` plus `docs/packages/<pkg>/contract.md`. Components are modules, one subfolder each; decisions live in the one doc. 1-3 pages.
- **Multi-package** (a platform or monorepo of separately installed or deployed packages): a root `docs/architecture.md` system map with dependency rules, System pipelines and every decision (each scoped `system` or a package id), plus `architecture.md` and `contract.md` per package. Root 2-4 pages, each package 1-3.

Choose multi-package only for a real boundary: separate install, versioning or deployment, different runtimes or owners, or a dependency direction worth enforcing with tooling. **A proof of concept is almost always a single package.** Don't build the platform inside it: name the seams that would become packages ("the data loader is behind `DataSource` so it can move out") and stop there.

## Grow triggers

A single package grows into several when one of these fires. `grow_triggers` in `dt status` reports the measurable ones; judge the rest from the spec and idea file.

- New requirements bring a dependency stack the rest shouldn't carry (torch, torchvision).
- A one-way dependency is worth enforcing (data must never import models, to prevent leakage).
- A package exceeds ~3 pipelines or ~12 modules, or its docs no longer fit a 2,000-line agent context, or `dt lint` warns `grow-size` on one of them.
- A part runs or deploys on its own (a day-ahead forecast service).
# Components

Read when adding, changing or documenting components.

- **Each component:** one responsibility in a sentence, the spec IDs it covers, what it depends on.
- **Every live requirement is covered**, `QR-` and `DATA-` included; cross-cutting ones under Cross-cutting concerns.
- **Dependencies point one way.** Two components needing each other are one, or miss an interface.

# Contracts

Read when writing or changing a `contract.md`.

Write `docs/packages/<pkg>/contract.md`: the provider's promise to its consumers. Consumers read only this page, so it stands alone.

- **One `###` section per public symbol** (function, class, or type), headed `### <id>.<symbol>: <title>`. `<id>` is the package id. In a single package it is the component id, with sections grouped under `## <component>` (multi-package contracts drop that level and link the `architecture.md` beside them). The ID survives Grow, because the component id becomes the package id.
- **One symbol per heading.** Never `### train.train / train.train_seeds: …` or `### baselines.MajorityClass / LogisticBaseline: …`, however alike the symbols are: dt resolves `Read:` IDs and `dt context` packets only from a symbol's own heading. `dt lint` errors on these (`contract-heading`).

Freeze only what crosses: a helper's or a private function's types stay out.
- **Contract first:** the contract is defined before either side is built. **The provider owns it.**

A Protocol or class type's case is a replay double (a fixture-backed recording of the real object's calls, `a recorded 5-batch epoch`), and so is a function another component's step calls: it is the type's sample, not a fake. For each significant open choice (language, libraries, storage, deployment, data sources, model approach): 2-3 real options checked against the requirements that constrain them (`DATA-`; model criteria and baseline), and a recommendation. ## When it touches older decisions

Find every Accepted decision a new one touches: search the doc for the components, data, counts and names it changes.

- It reverses an old choice → supersede the old decision, which collapses to its superseded line.
- It changes part of an old choice → revise the old decision in place (*Accepted decisions stay true*). Examples: a third holdout added to a decision that set up two, or a new caller of an interface that a decision said only one study uses.
- It only adds a member to a set a shared decision governs (another claim family, another run folder) → add the member where the set is listed and cite the shared decision. Don't revise it (*Shared decisions state a rule*).

- **Decision IDs are permanent; superseded decisions shrink.** `AD-NN` IDs are never reused or renumbered, and the heading is never deleted. # RL Lab — Architecture

**Status:** Draft · **Shape:** Single package · **Last updated:** 2026-10-17 · **Spec:** [spec.md](spec.md)

## Overview
One Python package, `rllab`. Worlds (Snake, Tank, Hunt) implement one multi-agent `World` interface and know nothing about learning or drawing. A single training loop runs any mix of learners, scripted policies and frozen snapshots against a world, mapped by agent group. It writes a run folder with settings, CSV logs and snapshots. Evaluation, charts, replay, the co-evolution schedules, the library comparison and the lab-note tooling all read those run folders. The reference library is imported only by `compare`.

```mermaid
flowchart LR
  cli --> train & coev & evaluate & replay & charts & compare & notes
  coev --> train
  train --> evaluate
  train --> qtable & dqn & ppo
  qtable & dqn & ppo --> core
  evaluate --> core
  replay --> core
  snake & tank & hunt --> core
  tank & hunt --> fishsim
  compare -.->|only importer of the reference library| train
```

## Data
No external data. Every episode is generated from a seed.
- **Seeds:** training seeds are below 1,000,000; the 100 evaluation seeds are fixed at 1,000,000–1,000,099, and `train` refuses a seed in that range (EVAL-03).
- **Run folders:** `runs/<world>/<run-name>/` holds `settings.toml`, `meta.json` (seed, start and end time, wall clock, git commit), `episodes.csv`, `evals.csv`, and `snapshots/s000.pt` to `s100.pt`. Evaluation scores go in `scores/<snapshot>__<opponent>.csv`, and a tournament writes `tournament.csv` (AD-07).
- **Settings:** `configs/<world>/<run-name>.toml`. A break-it run is a copy of its intact settings with one switch turned off.
- **Lab notes:** `lab/<world>.md`, prose written by the owner, with generated results blocks (AD-12).

## Cross-cutting concerns
- **Speed (QR-01, QR-05):** worlds step with small NumPy arrays and no per-step allocation in hot paths. `train` runs N copies of a world in lockstep, so every learner acts on one batched forward pass (AD-06). PyTorch is pinned to 1 thread. A benchmark test checks QR-05 for every world, and `meta.json` records wall clock for QR-01.
- **Reproducibility (QR-03):** each world copy, learner and evaluation gets its own `np.random.Generator` from the run seed. Torch uses its own seeded generator, and deterministic algorithms are on. There is no global random state (AD-13).
- **CPU only (QR-02):** devices are always `cpu`. No code path checks for a GPU.
- **Errors:** settings validation, unknown names and bad actions raise `ValueError` with the offending name (WORLD-03, TRAIN-01). A run whose values become NaN stops, keeps its logs, and records the step in `meta.json`.
- **Testing:** pytest. Worlds get rule tests from hand-built states. Learners get small-world sanity tests (a 2-state chain learns its values). Import rules run in CI (AD-02).

## Decisions
### AD-01: Python 3.12, managed with uv
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** The owner works in Python. PyTorch, pygame-ce and Stable-Baselines3 all ship wheels for Apple Silicon on 3.12.
- **Decision:** Python 3.12, with uv for the environment and lockfile. `requires-python = ">=3.12,<3.13"`.
- **Alternatives:** 3.13 — some wheels lag. conda — heavier, and none of the dependencies need it.
- **Consequences:** One `uv sync` sets up the laptop. The reference library sits in an optional `compare` extra.

### AD-02: Import rules enforced by import-linter
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** Hand-written learners must not lean on a learning library (VALUE-01, VALUE-03, POLICY-01, CMP-03). Worlds must run headless and stay light (WORLD-04).
- **Decision:** Three rules, checked in CI. (1) Only `compare` may import the reference library or Gymnasium. (2) Learner components may import NumPy and the allowed PyTorch parts (AD-04), never `torch.distributions` or any RL library. (3) World components and `core` may not import PyTorch, pygame or matplotlib.
- **Alternatives:** Code review only — easy to slip. Separate packages — real boundaries, but overkill for one owner.
- **Consequences:** A learner must write its own distribution maths, such as the Gaussian log-probability in `ppo`. Each new component is added to the rule it falls under.

### AD-03: Own multi-agent world interface, not Gymnasium or PettingZoo
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** Tank and Hunt have many agents that drop out mid-episode (TANK-04, HUNT-03). Each agent group has its own observation and action form (WORLD-02, WORLD-03). Gymnasium is single-agent. PettingZoo's parallel API fits but adds a dependency to every world, and hides the loop the owner is here to learn.
- **Decision:** `core.World` takes and returns dicts keyed by agent id. Agents belong to named groups (`snake`, `fish`, `predator`, `prey`), and observation and action forms are declared per group. Single-agent worlds have one agent in one group.
- **Alternatives:** Gymnasium — needs wrappers for every multi-agent world. PettingZoo parallel API — close, but an extra dependency for little gain.
- **Consequences:** `compare` needs a small Gymnasium adapter per comparison setting (AD-11). Switching to PettingZoo later is an adapter, not a rewrite.

### AD-04: NumPy for worlds and the lookup table; PyTorch on CPU for network learners
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** VALUE-01 asks for basic array operations. VALUE-03 and POLICY-01 allow tensor operations, autograd and a standard optimiser. The owner is learning PyTorch.
- **Decision:** Worlds and `qtable` use NumPy only. `dqn` and `ppo` use PyTorch tensors, autograd, `torch.nn` layers (`Linear`, activations) and `torch.optim.Adam`. Losses, returns, advantages, clipping and distribution maths are written by hand.
- **Alternatives:** NumPy only, with hand-written backprop — most educational, but it doubles the work per learner. JAX — capable, but a second new framework to learn.
- **Consequences:** Observations cross from NumPy to tensors at the learner's edge. Networks are small MLPs, so CPU is enough.

### AD-05: One training loop, driven by a team of policies per agent group
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** One loop must serve the lookup table, the value network and the policy learner (TRAIN-01–TRAIN-04), and must also handle frozen opponents and two learners at once (COEV-01, COEV-02).
- **Decision:** A `Team` maps each agent group to a `Policy`: a learner, a scripted baseline, the random policy, or a frozen snapshot. The loop calls `act` in batches and passes each step to every learner in the team through `Learner.observe`. Each learner decides when to update: the value learners update every few steps, and `ppo` updates when its rollout buffer is full.
- **Alternatives:** One loop per algorithm — simpler for each one, but triples the logging and snapshot plumbing (Goal 4).
- **Consequences:** `coev` is a scheduler that builds teams and calls `train`. Learner internals stay private behind `observe`.

### AD-06: Copies of a world in lockstep, not natively vectorised worlds
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** QR-01 allows ≤ 60 minutes per headline run, and QR-05 needs ≥ 5,000 steps per second per world. Batched forward passes matter more for speed than the world code itself.
- **Decision:** Each world is written for one episode, so the rules stay readable. `train` runs N copies (8 by default) in lockstep, and resets each copy as its episode ends.
- **Alternatives:** Worlds vectorised over episodes in NumPy — faster, but much harder to read and test. Subprocess workers — the overhead outweighs the gain at this size.
- **Consequences:** The batch size per step is N × the agents in each group. If the simultaneous Hunt run misses QR-01, vectorising `fishsim` is the first lever.

### AD-07: Run folders with TOML settings, flushed CSV logs and five snapshots
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** TRAIN-01–TRAIN-04 and TRAIN-06 ask for runs that can be inspected and repeated, and that survive interruption.
- **Decision:** The layout is as in Data. Settings are parsed into frozen dataclasses that reject unknown keys. CSV rows are flushed as they are written. Snapshots are saved with `torch.save`, or as an NumPy `.npz` for `qtable`, at 0%, 25%, 50%, 75% and 100% of training steps. `train` refuses an existing folder unless `overwrite=True`.
- **Alternatives:** TensorBoard or Weights & Biases — powerful, but the logs become harder to read straight into `notes` and `charts`. Parquet — unnecessary at this size.
- **Consequences:** Every reader works from plain files. Headline runs are small enough to commit.

### AD-08: Beats-baseline verdicts built with the `null-hypothesis-testing` skill
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** EVAL-04, COEV-05–COEV-08 and the learners' "beats" requirements must each be shown to be more than chance, corrected per world.
- **Decision:** `evaluate.beats` takes the two score arrays paired by evaluation seed, plus the number of comparisons in that world's family. Its test is built with the `null-hypothesis-testing` skill, which picks the test statistic, null distribution and correction. The verdict records all three.
- **Alternatives:** A hand-picked t-test — it would replace the skill's procedure, which this project routes to the skill.
- **Consequences:** Each world declares its comparison family: Snake 4, Tank 4, Hunt 4.

### AD-09: pygame-ce replay window, drawing scene descriptions from worlds; MP4 via imageio
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** REPLAY-01–REPLAY-07 need a live window with keyboard controls, four panels and ≥ 30 frames per second (QR-04), plus optional video. Worlds must not depend on a drawing library (WORLD-04, AD-02).
- **Decision:** Each world returns a `core.Scene`: circles, cells, lines and text in world units. `replay` draws scenes with pygame-ce. It writes MP4 through imageio-ffmpeg, rendering off-screen when only a video is wanted.
- **Alternatives:** matplotlib animation — weak keyboard controls, and slow with four panels. pyglet or arcade — fine, but heavier for 2D primitives.
- **Consequences:** Adding a world means writing its `scene()`, nothing in `replay`.

### AD-10: Charts with matplotlib, styled with the `dataviz` skill
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** TRAIN-05, LAB-03, COEV-09 and CMP-04 need static charts that lab notes can embed.
- **Decision:** `charts` uses matplotlib to write PNG files into the run folder. Palette, marks and layout come from the `dataviz` skill.
- **Alternatives:** Plotly — interactive, but needs a browser and can't be embedded in a Markdown note.
- **Consequences:** Charts are regenerated from CSVs at any time.

### AD-11: Stable-Baselines3 as the reference library, one comparison setting per world
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** CMP-01–CMP-04 need an established implementation of the same kind of learner, trained on the same world, budget and seeds. It must work on a laptop CPU and stay out of the hand-written code (CMP-03).
- **Decision:** Stable-Baselines3 DQN and PPO, behind Gymnasium adapters in `compare`. Comparison settings: Snake uses the network value learner on the full view. Tank uses the single fish. Hunt uses the predator trained against the scripted prey. The same evaluation seeds are used, and the same `evaluate.beats` path where needed.
- **Alternatives:** CleanRL — excellent to read, but single-file scripts, not an importable library. RLlib — multi-agent support, but very heavy for a laptop.
- **Consequences:** Multi-agent settings (the school, both Hunt sides learning) are not compared, because the library is single-agent. Reference runs go in `runs/<world>/ref-*`.

### AD-12: Lab notes as Markdown with generated results blocks
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** LAB-05 needs each note's numbers to match the logs. LAB-02 and LAB-04 need a fixed structure for break-it entries.
- **Decision:** The owner writes the prose. Results live between `<!-- results:<run> -->` markers that `notes refresh` fills from run folders. Each break-it entry has `Removed:`, `Prediction:` and `Outcome:` fields, which `notes check` verifies.
- **Alternatives:** A notebook per world — hidden state, and its numbers drift from the logs. Hand-copied numbers — exactly what LAB-05 rules out.
- **Consequences:** Notes stay readable on their own, and cited numbers can't go stale without `notes check` failing.

### AD-13: Seeded generators passed down, deterministic torch on one thread
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** QR-03 needs identical evaluation scores from the same settings and seed on the same machine. EVAL-05 needs noise-free evaluation.
- **Decision:** The run seed spawns child generators for each world copy, each learner and evaluation, through `np.random.SeedSequence`. Torch gets `torch.manual_seed`, `use_deterministic_algorithms(True)` and `set_num_threads(1)`. `act(explore=False)` is deterministic for every policy.
- **Alternatives:** Multi-threaded torch — a little faster on bigger nets, but not bit-reproducible.
- **Consequences:** Results reproduce on the same machine, not necessarily across machines.

### AD-14: Ego-centric, fixed-size fish observations with visibility flags
**Status:** Proposed · **Date:** 2026-10-17 · **Scope:** system
- **Context:** TANK-07, TANK-08 and HUNT-07 give fish local sight with a variable number of visible things. Learners need a fixed observation size (WORLD-03).
- **Decision:** `fishsim.sense` returns positions and velocities in the fish's own frame (rotated by its heading), scaled by the tank radius. Each slot (ball, the k nearest fish, pellets, predator) carries a visible flag and is zeroed when nothing is there.
- **Alternatives:** World-frame coordinates — simpler, but harder to learn from, because the same situation looks different at every heading.
- **Consequences:** Observation sizes are fixed per group and declared in `WorldSpec`.

## Risks and open questions
- **Snake vs. the strong greedy baseline (VALUE-04):** a network learner beating "toward food, avoid instant death" within 60 minutes is not guaranteed. Mitigation: settings for observation scaling and step budget are tuned early. If it still loses, the spec's baseline or time limit is revisited with the owner.
- **The simultaneous Hunt run within 60 minutes (QR-01, COEV-05, COEV-06):** this is the heaviest run. Mitigation: AD-06's vectorisation lever, then the optional cloud GPU or CPU box allowed by the brief.
- **Reference-library adapters (AD-11):** Gymnasium 1.0 support in Stable-Baselines3 is assumed from the 2.4 line. The first `compare` task confirms it with a 1,000-step smoke run before the Snake comparison.

## core

### core.ActionSpace: type
`@dataclass(frozen=True) class ActionSpace: kind: Literal["discrete", "box"]; n: int | None; shape: tuple[int, ...]; low: float; high: float`
- **Invariants:** `discrete` → `n` ≥ 2 and `shape == ()`; `box` → `n is None`, `low < high`, actions are float32 arrays of `shape`
- **Boundary:** snake, tank, hunt, qtable, dqn, ppo, evaluate, compare · **Fixtures:** tests/contracts/core.ActionSpace/ · **Cases:** Snake's 3 discrete actions; a fish's 2-number box in [−1, 1]
- **Used by:** every world, every learner, evaluate, compare

### core.WorldSpec: type
`@dataclass(frozen=True) class WorldSpec: name: str; groups: dict[str, tuple[AgentId, ...]]; obs_size: dict[str, int]; action: dict[str, ActionSpace]; dt: float; max_steps: int`
- **Invariants:** every agent id belongs to exactly one group; `obs_size` and `action` have one entry per group; `AgentId = str`
- **Boundary:** snake, tank, hunt, train, evaluate, replay, compare, learners · **Fixtures:** tests/contracts/core.WorldSpec/ · **Cases:** Snake (one group `snake`); school tank (group `fish`, 8 ids); hunt (groups `predator` 1, `prey` 6)
- **Used by:** train, evaluate, replay, compare, qtable, dqn, ppo

### core.StepResult: type
`@dataclass(frozen=True) class StepResult: obs: dict[AgentId, np.ndarray]; reward: dict[AgentId, float]; done: dict[AgentId, bool]; over: bool; scores: dict[str, float] | None`
- **Invariants:** `obs`, `reward` and `done` hold exactly the agents that were active before the step; `obs` arrays are float32 of the group's `obs_size`; `scores` (one per group, as each world's spec defines its score) is set only when `over`
- **Boundary:** snake, tank, hunt, train, evaluate · **Fixtures:** tests/contracts/core.StepResult/ · **Cases:** a mid-episode Snake step; a school step where 1 fish is caught; the final Hunt step with scores
- **Used by:** train, evaluate, compare

### core.Scene: type
`@dataclass(frozen=True) class Scene: bounds: tuple[float, float, float, float]; shapes: tuple[Shape, ...]; caption: str` where `Shape = Circle | Cell | Line`, each with a colour role (`agent`, `hazard`, `food`, `wall`, `opponent`)
- **Invariants:** coordinates in world units inside `bounds`; no pixel sizes; colour roles only, never colours
- **Boundary:** snake, tank, hunt, replay · **Fixtures:** tests/contracts/core.Scene/ · **Cases:** a Snake grid frame; a tank frame with ball and 8 fish
- **Used by:** replay

### core.World: World protocol
```python
class World(Protocol):
    spec: WorldSpec
    def reset(self, seed: int) -> dict[AgentId, np.ndarray]: ...
    def step(self, actions: dict[AgentId, np.ndarray]) -> StepResult: ...
    def scene(self) -> Scene: ...
```
- **Invariants:** same seed → same first observations and, given the same actions, the same episode (WORLD-01); actions for done agents are ignored; runs headless
- **Errors:** `ValueError` naming the world and agent for an action outside its `ActionSpace`; `RuntimeError` if `step` is called after `over`
- **Boundary:** train, evaluate, replay, compare · **Fixtures:** tests/contracts/core.World/ · **Cases:** a recorded 20-step Snake episode; a recorded school episode where fish are caught
- **Used by:** train, evaluate, replay, compare

### core.make_world: World by name
`def make_world(name: str, **options: Any) -> World`
- **Invariants:** names are `snake` (options `view="compact"|"full"`), `tank` (`setting="single"|"school"`) and `hunt`; worlds register themselves on import of `rllab`
- **Errors:** `ValueError` listing the valid names for an unknown name, or the valid options for an unknown option
- **Used by:** train, evaluate, replay, compare, cli

### core.Policy: Policy protocol
```python
class Policy(Protocol):
    def act(self, obs: np.ndarray, *, explore: bool) -> np.ndarray: ...
```
- **Invariants:** `obs` is B×obs_size float32 for one group; returns B actions valid for that group's `ActionSpace` (B integers, or B×shape floats); `explore=False` is deterministic (EVAL-05)
- **Boundary:** train, evaluate, replay, coev · **Fixtures:** tests/contracts/core.Policy/ · **Cases:** a recorded batch of greedy-Snake actions; a recorded batch of flee-from-ball fish actions
- **Used by:** train, evaluate, replay, coev; implemented by every baseline and learner

### core.Transition: type
`@dataclass(frozen=True) class Transition: stream: np.ndarray; obs: np.ndarray; action: np.ndarray; reward: np.ndarray; next_obs: np.ndarray; done: np.ndarray; truncated: np.ndarray`
- **Invariants:** a batch of B rows for one group; `stream` is a stable id per (world copy, agent), so per-agent trajectories can be rebuilt; `truncated` marks a time-limit end, which is not a terminal state
- **Boundary:** train, qtable, dqn, ppo · **Fixtures:** tests/contracts/core.Transition/ · **Cases:** an 8-copy Snake batch with one death; a school batch where 2 streams end caught and 1 is truncated
- **Used by:** qtable, dqn, ppo

### core.Learner: Learner protocol
```python
class Learner(Policy, Protocol):
    def observe(self, batch: Transition) -> None: ...
    def metrics(self) -> dict[str, float]: ...
    def save(self, path: Path) -> None: ...
    @classmethod
    def load(cls, path: Path) -> "Learner": ...
```
- **Invariants:** `observe` decides by itself when to update; `metrics` returns the latest loss and diagnostic values; `load(save(x))` acts identically to `x` with `explore=False`
- **Errors:** `FloatingPointError` naming the step when a value becomes NaN or infinite
- **Boundary:** train, coev · **Fixtures:** tests/contracts/core.Learner/ · **Cases:** a recorded 200-step chain-world run of observe/act calls
- **Used by:** train, coev
